## Acceptance-criteria coverage
- Notification prefs read/update → **BE-1**
- Linked children list + link/unlink (family scope) → **BE-2** (extends P1-04)
- Change password + session invalidation → **BE-3** (reuses Identity)
- Current plan read → **BE-4**
- Persistence migrations → **BE-5**

## Contract to Frontend (P2-12-FE)
- Notification prefs DTO (per type × channel); linked-children list + link/unlink results; change-password result; current-plan DTO. All `BaseResponse<T>` (camelCase envelope), `Successed` flag, `NewResult(...)`.

## Notes
- **Module isolation:** all within Identity (or a thin Account feature) — cross-module only via `Shared.Contracts`. No Unit of Work; explicit transaction if multi-write.
- Reuses existing Identity `ChangePassword` + session services (BE-3) and P1-04 link/unlink (BE-2) — extend, don't duplicate.
- Payment-provider integration is out of scope (BE-4 is read-only/stub) — flag a follow-up payments story if checkout is needed. **Ask before adding any design pattern.**
