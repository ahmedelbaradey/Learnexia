## What already implements this
- `Parent/.../WeeklyReportGeneratorService` publishes **`Shared.Contracts.Parent.WeeklyRecapReadyIntegrationEvent`** when a weekly report is generated (skipped for zero-activity weeks — "recap nudge suppressed").
- `Notifications/.../Reengagement/WeeklyRecapReadyIntegrationEventHandler` consumes it and dispatches a **parent re-engagement nudge** ("your child's weekly report is ready") through the single `NudgeDispatcher` choke point (in-app inbox row + push, P9-07 arbitrated, fail-soft).
- Parent-child linkage + locale are respected by the existing re-engagement pipeline (the nudge targets the parent recipient).

## Acceptance-criteria coverage (all met by the above)
- Parent notified when a weekly report is generated → **WeeklyRecapReady event → WeeklyRecapReady handler → NudgeDispatcher** ✅
- Notification links to/opens the report → deep-link handled by **P9-02 tap routing (FE)** → the report screen (P5-05) ✅ (FE concern, not backend)
- Only linked parents notified → re-engagement pipeline targets the parent recipient ✅
- Failed delivery retried/logged → `NudgeDispatcher` is fail-soft + logs; push delivery isolated ✅

## Notes
- **No new backend work** — this task exists only to close the traceability gap (the story had no task file). If anything, a future enhancement is making the nudge's deep-link payload carry the specific report week for the FE to open directly (minor; currently opens the latest report).
