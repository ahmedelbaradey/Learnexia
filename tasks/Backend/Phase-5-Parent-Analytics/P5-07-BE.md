# P5-07 (backend) — Feed learning data back into the system (calibration loop)

> Story: [../../../user-stories/Phase-5-Parent-Analytics/P5-07-data-feedback-calibration.md](../../../user-stories/Phase-5-Parent-Analytics/P5-07-data-feedback-calibration.md)
> Phase 5 — Parent + Analytics · Epic: Analytics & Insights · SP: 5 · FR-PA-4 (SRS §4.7) · Module: **Learning** (all substrate is here) · mirror existing shapes.
> Barrier-to-entry BE7 "data network effect" (closes gap 3a-7) — turn collected-but-dormant signals into a compounding advantage.

## Decisions (lead, 2026-06-21)
- **Safety model = PROPOSE-ONLY + human promotion** (AC4). The calibration job writes **proposed** difficulty changes to a review queue; an admin promotes/rejects via the BE-5 API. **Authored content is never silently overwritten** — fully auditable + reversible. AI-generated questions are **auto-flagged** (not auto-served) since they're not human-authored.
- **Scope = FOCUSED SLICE this round** = BE-1 + BE-2 + BE-3 + BE-5 + BE-6 + BE-7. **DEFER BE-4** (config-driven adaptivity-threshold tuning, AC3) to a follow-up — it touches the live `AdaptivityEngine` and is lower-urgency.

## Current substrate (verified 2026-06-21 — all in the Learning module)
- `Domain/Entities/QuizQuestion.cs` — authored `DifficultyLevel` (`Domain/Enums/DifficultyLevel.cs`) + `GeneratedBy` (`Domain/Enums/GeneratedBy.cs`) provenance.
- `Domain/Entities/StudentAnswer.cs` (+ `Attempt.cs`) — per-answer signals (correctness, time, etc.); `IntegrationEventHandlers/HintUsedIntegrationEventHandler.cs` brings hint-usage in.
- `Domain/Services/AdaptivityEngine.cs` / `SkillAdaptivityAggregate.cs` / `Service/AdaptivityService.cs` — the P3-08 thresholds (AC3 target — DEFERRED this round).
- Job + engine pattern to mirror: the recommendation Hangfire job + `RecommendationEngine`/`RecommendationService` + `AddStudentRecommendation` migration.

- Empirical difficulty computed + recalibration when diverging from authored band → **BE-1 + BE-2** (as **proposals**, per the safety decision)

- Adaptivity thresholds tunable from data (config-driven) → **BE-4 (DEFERRED)**

## Notes
- **Learning-module scoped.** Reads only Learning-owned data (`StudentAnswer`/`Attempt`/`QuizQuestion`). If P5-03 analytics aggregates are useful later, via a read seam (no cross-module FK). No new module. Uses Learning's `UnitOfWorkBehavior` (per ADR-0001 — not rule #3's stale wording).
- **Mirror existing shapes** (rule #8): the recommendation Hangfire job + engine/service split; the admin controller + `BaseResponse` + resx pattern. Ask before any new design pattern.
- **Privacy is the headline risk:** aggregation runs over minors' answer data. Outputs must be question-level aggregates only — no child identifiers persisted or logged. security-auditor mandatory before the gate.
