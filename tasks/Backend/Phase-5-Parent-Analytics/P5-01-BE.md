# P5-01 (backend) — Weekly student report generator

> Story: [../../../user-stories/Phase-5-Parent-Analytics/P5-01-weekly-report-generator.md](../../../user-stories/Phase-5-Parent-Analytics/P5-01-weekly-report-generator.md)
> Brief: [../../../docs/briefs/P5-parent-read-api.md](../../../docs/briefs/P5-parent-read-api.md)
> Phase 5 · Module: **Parent** (owns the persisted report + read) · aggregates via the same P5-08 seams · Hangfire job

## Design rules (binding)
- Reuse the existing Hangfire recurring-job infra (mirror `SeatEnforcementJob` / `DunningRetryJob`: thin job → service, `[DisableConcurrentExecution]`, fail-soft per child).
- Aggregate via the **same `Shared.Contracts` read seams** added in P5-08 (XP, learning stats, mastery, weak areas) — no cross-module FK. Persist a `WeeklyReport` row per (child, week).
- Parent reads only their own children's reports (IDOR via `IParentChildQuery`). Option C, `BaseResponse<T>`, `ILoggerManager`, EN/AR.
