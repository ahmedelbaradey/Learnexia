# P5-08 (backend) — Parent-scoped per-child read API

> Story: [../../../user-stories/Phase-5-Parent-Analytics/P5-08-parent-scoped-read-api.md](../../../user-stories/Phase-5-Parent-Analytics/P5-08-parent-scoped-read-api.md)
> Brief: [../../../docs/briefs/P5-parent-read-api.md](../../../docs/briefs/P5-parent-read-api.md)
> Phase 5 · Module: **Parent** (controller + fan-out handlers) · cross-module reads via `Shared.Contracts` seams only (no FK)

## Design rules (binding)
- **Module isolation:** the Parent module references NO other module's projects. Every cross-module read goes through a `Shared.Contracts` interface seam with loose `int` ids. Mirror `GetUserActivitySummaryQueryHandler` (per-seam `try/catch` → graceful zero/empty on a source-module failure).
- **IDOR:** resolve `parentUserId` from the JWT (`ICurrentUserService`); authorize every per-child route with the existing `IParentChildQuery.IsParentOfChildAsync` BEFORE any fan-out. Never trust a child id from the body.
- `[Authorize(Roles = "Parent")]`, `BaseResponse<T>` / `Successed`, `ILoggerManager`, localized messages (EN+AR), Option C (handlers EF-free; reads via seams), MediatR CQRS queries (no `ValidationBehavior` for queries).
