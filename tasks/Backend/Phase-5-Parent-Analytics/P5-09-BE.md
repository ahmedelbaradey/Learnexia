# P5-09 (backend) — Per-child recommendation engine

> Story: [../../../user-stories/Phase-5-Parent-Analytics/P5-09-recommendation-engine.md](../../../user-stories/Phase-5-Parent-Analytics/P5-09-recommendation-engine.md)
> Brief: [../../../docs/briefs/recommendations-engine.md](../../../docs/briefs/recommendations-engine.md)
> Phase 5 · Modules: **Learning** (computes + persists + job + seam) · **Parent** (read endpoint). PR 1 of 2 (engine first; Lexi = P3-14, fast-follow).

## Design rules (binding)
- **Deterministic, FREE, reproducible** — NO LLM in the core; same inputs → same output. Pure `RecommendationEngine` (no I/O) + a thin `RecommendationService` (Option C, EF in Infrastructure).
- Three un-conflated signals: **Grade** (Identity) → scope; **mastery %** weak areas (P5-02 `WeakAreaDetectorService`, in-module) + **AdaptivityEngine** (`IAdaptivityService.GetTargetDifficulty`, in-module) → areas + difficulty; gamification level NOT used here. P3-13 `IStudentProfileService` enriches (in-module).
- Module isolation: cross-module reads via `Shared.Contracts` only (no FK). Mirror the existing daily job `StudentProfileRecomputeJob` + `ILoggerManager`, `BaseResponse`, localized keys.
