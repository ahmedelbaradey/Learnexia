> Story: [../../../user-stories/Phase-6-Stabilization/P6-01-performance-targets.md](../../../user-stories/Phase-6-Stabilization/P6-01-performance-targets.md)
> Phase 6 — Stabilization · Epic: QA & Stabilization · SP: 5 · **NFR-1** · mirror existing test-infra shapes.
> **Targets (NFR-1 / SRS §134):** core API responses **< 500 ms (p95)**; AI tutor responses **< 4 s**.

## Decisions (lead, 2026-06-21)
- **Harness = NBomber** (.NET-native load-test project in the solution — reuses the existing WebApplicationFactory/Testcontainers auth + seed helpers; asserts p95 thresholds in C#; `dotnet`-runnable; CI-runnable later once Actions billing is fixed).
- **Run scope = build harness + scenarios + SLO thresholds + run a LOCAL baseline + record results + fix quick-win hotspots.** Authoritative **production-scale** load and the **live AI <4 s** measurement = **devops** (no deployed env / no AI keys here) — documented as a run procedure, mirroring the AI Gate-B / flip-to-live pattern.
- **"Repeatable in CI or a documented harness" (AC4):** CI is currently blocked by the GitHub Actions billing issue → deliver a **documented run-script harness** now; CI wiring is a follow-up.

## Acceptance-criteria coverage
- Core API < 500 ms p95 + AI < 4 s confirmed → **BE-2** (API, measured) + **BE-3** (AI overhead local; live <4s = documented devops measurement)
- Realistic dataset + concurrency → **BE-1** (seed) + **BE-2** (concurrency level documented)
- Hotspots above target fixed or documented → **BE-5**
- Results recorded + repeatable (documented harness; CI later) → **BE-1** (run-script) + **BE-4** (report)

## Notes
- **Test-infra only for the harness** (`backend/tests/Learnexia.PerfTests`); BE-5 fixes touch real module code surgically (each re-measured + existing suites must stay green). No new module, no migration unless a fix demands an index (then a tiny Learning/other migration — flag it).
- **New package:** `NBomber` (centrally versioned in `Directory.Packages.props`). No other new deps.
- **Honesty:** local baseline numbers are **relative/directional** (in-process-ish, single box, test data) — they catch egregious hotspots and validate the harness, but the authoritative pass/fail comes from a **staging/prod-scale run (devops)**. The AI `< 4 s` target needs **live keys** → devops. Both documented as run procedures.
- Mirror the existing WebApplicationFactory/Testcontainers + seeder patterns (rule #8); ask before any new design pattern.
