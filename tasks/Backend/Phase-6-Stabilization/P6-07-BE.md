## Acceptance-criteria coverage
- Revoked-after-sign-out token rejected (401) → **BE-2** (+ BE-1 prereq)
- Change-password keeps current device, kills others → **BE-1 + BE-2** (existing keep-current logic now actually matches)
- Reset revokes all sessions → **BE-3**
- Admin suspend/delete revokes all sessions → **BE-3**
- SessionId mismatch fixed; no false rejections; read-only hot path → **BE-1 + BE-2**
- Fail-soft, bounded cost (store-outage policy documented; single read per request) → **BE-2 + BE-4**
- security-auditor PASS + suite green → **BE-5 + BE-6**

## Open decisions (for the lead)
- **BE-4:** store-outage policy — **fail-closed** (reject on Redis error; safest, but a Redis blip logs everyone out) vs **fail-open** (allow on error; availability-first, but a revoked token slips through during the outage). Recommend fail-closed in Production/Staging, fail-open/log in Development — confirm.
- **BE-1:** session-key threading shape — add a 3rd param to `CreateSessionAsync` (uses the claim as key) vs stop minting the claim in `GetClaims` and let the handler create the session then stamp the claim. The 3-param approach is the smaller, lower-risk change (claim minting stays where it is).

## Notes
- **Identity + Host scoped**, no cross-module references, **no new module, no DB migration** (sessions are Redis/`IDistributedCache`). No Unit of Work.
- **No new package.** Pure wiring + a read-only Redis lookup on the existing `ISessionManagementService`.
- **Do NOT** use ASP.NET security-stamp per-request validation — `UserManager.ChangePasswordAsync` bumps the stamp and would kill the caller's current device, breaking P2-12 + its tests.
- **Hot-path discipline:** the `OnTokenValidated` lookup must be read-only (no sliding-expiration write) and resolve the scoped `ISessionManagementService` from `context.HttpContext.RequestServices` (the bearer options are configured at singleton scope).
- **Prereq risk:** if BE-1 is wrong, *every* token is rejected — verify sign-in, parent-registration, and Google sign-in all persist a session keyed on the token's `"SessionId"` before merging.
