# P6-05 (backend) — Observability: logging, tracing, health checks, metrics

> Story: [../../../user-stories/Phase-6-Stabilization/P6-05-observability.md](../../../user-stories/Phase-6-Stabilization/P6-05-observability.md)
> Phase 6 — Stabilization · Epic: DevOps / Observability · SP: 3 · Module: **Host** (+ a small Shared.Kernel/AI seam for the gateway health check) · mirror existing shapes.
> **Chosen approach (lead 2026-06-21): OTLP exporter, config-gated** — wire OpenTelemetry tracing + metrics exporting via OTLP to a configurable endpoint, **no-op when the endpoint is unset** (mirrors the existing Redis-when-present / AI flip-to-live "wire it, gate on config, devops flips live" pattern). The Grafana dashboard + alerts themselves are **devops** (built on the OTLP stream + the P5-03 analytics endpoints), not backend code.

## Current state (verified 2026-06-21)
- **Health checks PARTIAL:** `Program.cs` already wires `AddHealthChecks` + `AddNpgSql` (`database`, hard-fail → 503) + `AddRedis` (`redis`, Degraded-tolerant, only when `ConnectionStrings:Redis` set), and maps `/health/live` (liveness, always 200) + `/health` (readiness). **Missing: an AI-Gateway dependency check** (story AC names "API, DB, Redis, and the AI Gateway").
- **OTel referenced-but-UNWIRED:** `Directory.Packages.props` already lists `OpenTelemetry.Extensions.Hosting`, `.Exporter.OpenTelemetryProtocol`, `.Instrumentation.AspNetCore`, `.Instrumentation.Http`, `.Instrumentation.Runtime` — but `Program.cs` has **no `AddOpenTelemetry()`**. Tracing + metrics are not started.
- **NLog wired** (`NLog` 5.4.0; `ILoggerManager`/`LoggerManager` is the logging seam per CONVENTIONS) — needs structured targets + trace-id/span-id correlation so logs join traces.

## Notes
- **Host-scoped** wiring; the only cross-module touch is a **read-only AI-gateway readiness seam** via `Shared.Contracts`/Shared.Kernel (no Ai-module project reference from Host beyond existing module-registration). No new module, **no DB migration**, no Unit of Work.
- **No new NuGet** — all OTel + health-check packages are already centrally versioned in `Directory.Packages.props`; just add the `PackageReference`s to `Host.csproj`.
- **Config-gated everywhere** (matches the codebase): OTel exporter no-op without `OpenTelemetry:Otlp:Endpoint`; integration suite (env Testing) and local dev run with zero collector and zero behavior change.
- **Security:** never emit secrets/PII (child names, emails, tokens, prompts) into spans/logs — reviewer checks this explicitly.
- Operational items (stand up the OTLP collector + Grafana, set the endpoint env, build dashboards/alerts) are **devops**, tracked in HANDOFF — not code tasks here.
