## Notes

- **KnowledgeNode/KnowledgeEdge:** already built in `learning` (P2-11, audited 2026-06-07). BL-04 adds only the `SkillKey` column (BE-11/BE-12/BE-13). The `curriculum` module is their LOGICAL OWNER (authors/validates the graph) but NOT their physical home. Cross-module access from `curriculum` goes through `Shared.Contracts` integration events / the Learning command seam — never a direct DbContext reference or EF navigation. See `docs/briefs/curriculum-system-of-record.md` §2.
- **BE-1 is conditional** on the lead's new-module decision (CLAUDE.md standing rule: never scaffold a new module without explicit sign-off). If option B (fold into `learning`), skip BE-1 entirely and reduce total estimate by 6 h.
- **NO inline vector column on `CurriculumChunk` (Decision D).** Embeddings live in the separate `chunk_embeddings_bge_m3` physical table (BE-7, C# entity `ChunkEmbeddingBgeM3`). This enables dual-model coexistence during embedding-model migrations. The `EmbeddingVectorRef` field from the original brief is replaced. Any implementation that adds an inline vector to `CurriculumChunk` is incorrect.
- **pgvector fixed-dimension constraint — critical:** `vector(1024)` is a **column-level fixed type**. A `vector(1024)` column cannot store a 1536-dim or 3072-dim embedding. `ALTER COLUMN` to change the dimension is not supported by pgvector. A `Dimension int` metadata field on the entity does NOT change the physical column constraint — it is documentation only. A future model with a different output dimension MUST use a new physical table (e.g. `chunk_embeddings_openai_3072` with `vector(3072)`, C# entity `ChunkEmbeddingOpenAi3072`). One table per (Model, Dimension). See `docs/briefs/curriculum-system-of-record.md` §4 for the dual-index migration path and `IsActive` semantics.
- **`IsActive` semantics:** `IsActive = true` on a `ChunkEmbeddingBgeM3` row marks BGE-M3 as the currently-served embedding model. Retrieval (P3-07) queries only the `IsActive=true` table. When a new model table is added and backfilled, flip `IsActive` atomically. Only one model is active at a time.
- **ANN index** (HNSW/IVFFlat on `chunk_embeddings_bge_m3.Vector`) deliberately deferred to BL-05/P3-07 when query patterns and chunk volume are known.
- **Provenance tree vs pedagogical tree:** `ContentSource`/`Chapter`/`ProvenanceMapping` are the provenance layer (Decision B). A chapter is NOT a unit. The pedagogical tree (`Grade → Subject → Unit → Lesson → Concept → Skill`) lives in `learning`. See `docs/briefs/curriculum-system-of-record.md` §1.
- **`CurriculumVersion` + P7-05:** the `CurriculumVersion` entity is the same entity P7-05's admin surface will manage. BL-04 models it; P7-05 adds the UI and the publish action that switches Status. Confirm with lead that the Status enum values are aligned (`Active` = `Published` in P7-05 language).
- **`KGSuggestion` is NOT `KnowledgeEdge`.** Suggested edges NEVER auto-flow into `KnowledgeEdge`. Admin approval (BL-03) is the only path from Suggestion to published edge. See `docs/briefs/curriculum-system-of-record.md` §5.
- **`Directory.Packages.props`** is a shared file — BE-2 must not run in parallel with any other story that edits it.
- **`Program.cs` / `.sln`** are shared files — if option A, BE-1 edits must be serialized (PARALLELISM.md).
- **SkillKey format:** `{SubjectCode}.grade{N}.{unitSlug}.{skillSlug}` (e.g. `math.grade4.fractions.add-unlike-denominators`). Slugify = lowercase, spaces→hyphens, strip non-alphanumeric except hyphens. Document in code comments.
- No api-tester stage for this enabler (no HTTP endpoints). Persistence smoke test (BE-6 revised) substitutes.
- No designer stage (backend/infra only, no UI surface).
