## Notes

- **Do NOT rebuild** `KnowledgeNode`, `KnowledgeEdge`, `SkillGraphValidator`, `KnowledgeGraphController`, `GetPrerequisitesOf`/`GetUnlockedBy` — all exist in P2-11. BL-03 only adds: (a) suggestion-queue build from BL-05, (b) admin review endpoints for suggestions, (c) `GetRelatedConcepts` if missing, (d) remediation traversal depth.
- **Decision E is the central invariant of this story:** the ONLY code path that writes to `KnowledgeEdge` is `ApproveKGSuggestionCommand` (BE-8), and it goes through `SkillGraphValidator.AssertAcyclic` first. LightRAG outputs go to `KGSuggestion`, period. The security-auditor verifies this invariant explicitly.
- **Acyclic validation:** reuse `SkillGraphValidator.AssertAcyclic` from P2-11. Applied at approval time (BE-8), not at suggestion-creation time (BE-3). A cycle rejection blocks the approval but does not affect other pending suggestions.
- **Idempotency for suggestions:** re-building does not create duplicate suggestions — check `(SourceNodeId, TargetNodeId, RelationshipType)` before inserting a `KGSuggestion` (skip if Pending or Approved already exists). Re-building after a rejection creates a new suggestion (the prior was explicitly rejected).
- **Hand-authored edge coexistence:** `ApproveKGSuggestionCommand` uses the existing `AddKnowledgeEdgeCommand` / insert-or-ignore semantics. The P2-11 unique constraint `UX_KnowledgeEdges_SourceTarget_Type` prevents duplicates — if a hand-authored edge already exists for the same (Source, Target, Type), the approval silently succeeds (edge already published, no harm).
- **Decision A — cross-module path for approval (if option A):** `ApproveKGSuggestionCommand` in the `curriculum` module cannot write to `LearningDbContext` directly. It emits a `CurriculumEdgeApproved` integration event (Shared.Contracts) → `learning` module handles it (validates acyclic + persists). If option B (all in `learning`), the command writes directly.
- **Neo4j:** explicitly deferred to Phase 3+ (SRS §6). BL-03 stays relational. `KGSuggestion` + `KnowledgeEdge` schema is designed to be Neo4j-migratable.
- **Security-auditor gate REQUIRED** (LightRAG/AI credentials + the Decision E invariant — no auto-publish path to KnowledgeEdge + acyclic validation bypass check).
- No designer stage; no student-facing UI for the suggestion-queue management (admin-only). The query endpoints (`GetRelatedConcepts`, remediation traversal) are student-readable and surfaced via the existing `KnowledgeGraphController`.
- **`KGSuggestion` entity is defined in BL-04 (BE-10)** — BL-03 only reads/writes to it. BL-04 must be complete before BL-03 runs.
