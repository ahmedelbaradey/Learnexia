## Architecture guardrails (read before coding)

- **Zero billing / energy side-effects.** Pause and unpause MUST NOT touch seat state, energy balances (subscription allowance or purchased reserve), ledger credit/debit rows, or billing dates. The ONLY writes are: (1) `ParentPauseState` field on the Billing child record, and (2) `ParentPause` / `ParentUnpause` audit-ledger entries.
- **Both spend-gate checks are independent.** The AI spend gate checks `SeatState.NoSeatLocked` (P10-15-BE-4) AND `ParentPauseState.Paused` (BE-4 below) as **two independent conditions** — either alone blocks AI spend. Do not short-circuit one if the other passes.
- **IDOR is the primary security risk.** Every command and query must verify the requesting parent owns the childId via the Billing-owned family membership — never trust the `childId` from the request body without this check.
- **Idempotent by definition.** Pausing an already-Paused child is a no-op (success, no ledger entry). Unpausing an Active child is a no-op. The service impl guards both.
- **No UoW (ADR 0001).** The two writes (state update + ledger append) run inside an **explicit transaction in the service impl (Infrastructure)**, never in a handler.
- **`ValidationBehavior` runs for `ICommand<>` only.** Commands get FluentValidation validators; the status query does not.

## Notes

- **IDOR is the critical security risk.** The security-auditor must verify: (1) parent can only pause/unpause their own children (family-scope authz in BE-3); (2) child JWT cannot call pause/unpause endpoints; (3) `childId` in URL is validated against the JWT's parent identity — never trusted raw.
- **Zero energy side-effects (hard invariant).** Security-auditor and reviewer must confirm the service impl in BE-3 writes no `EnergyDebit`, `EnergyCredit`, `AllocationForfeit`, or any balance-touching ledger type during pause or unpause. Allowed ledger types: `ParentPause`, `ParentUnpause` only.
- **Zero seat side-effects (hard invariant).** BE-3 must not write to the `SeatState` field, to the subscription/seat count, or to any seat-lifecycle column. The seat remains whatever state P10-14/P10-15 has set.
- **Two independent spend-gate checks.** The reviewer must confirm BE-4 does not replace the P10-15-BE-4 seat-state check — it adds a second guard after it. A child who is both `NoSeatLocked` AND `Paused` is blocked by the first check; the second check also fires for an `Active`-seat child who is `Paused`.
- **Shared.Contracts coordination.** BE-5 (`IChildAccessStateQuery`) must be designed so the Ai module can drop its current `ISeatStateQuery.IsChildSeatActiveAsync` call (P10-15-BE-6) and use `IsChildAccessAllowedAsync` instead — or the Ai module must call both. Agree the integration point with the P10-15 implementer before building BE-5 to avoid two seams doing similar work.
- **Ledger entry type enum.** Add `ParentPause` and `ParentUnpause` to the same `LedgerEntryType` enum extended by P10-16-BE-1. Coordinate to avoid a schema conflict in the migration sequence.
- **No UoW (ADR 0001).** The two writes in BE-3 (state + ledger) are inside a single explicit transaction in the Infrastructure service — never the handler.
- **Option C (CONVENTIONS §7).** All handlers in BE-6 inject `IPauseChildService` (for commands) or a thin service interface (for the query) — no `DbContext`, no `DbSet`, no EF in `Billing.Application`.
- **Serialize shared-file edits** (`Shared.Contracts` additions, `Shared.Resources` .resx, `Program.cs` DI) with concurrent P10-15/P10-16/P10-17 work per PARALLELISM.md.
- **Canonical mapping:** 13 wallet · 14 seats · 15 lifecycle · 16 redistribution · 17 refunds · **18 pause/unpause (this story)**.
