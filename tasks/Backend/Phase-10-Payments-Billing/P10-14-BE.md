## Acceptance-criteria coverage

- Plan defines INCLUDED seats (config) + max-seats ceiling; subscription tracks extra seats → **BE-1** (`IncludedSeats`/`PurchasedExtraSeats`) + **BE-3** (max-seats from config)
- Active seat count = `IncludedSeats + PurchasedExtraSeats` while billing-active (incl. grace) → drives P10-13 → **BE-3** (`GetActiveSeatCountAsync`)
- Parent views seat status (total/occupied/free + which children active) → **BE-9** (`GetSeatStatusQuery`)
- Only paid active seats generate entitlement energy; a child profile mints none → **BE-3** (count) consumed by P10-13 (no energy minted here)
- Buy N extra seats, monthly add-on, config price, web checkout only → **BE-6** (`StartSeatCheckoutCommand`, server-side price)
- Seat purchase confirmed only via verified, idempotent provider webhook; ledgered; failure adds nothing → **BE-7**
- Buying seats never creates purchased energy / never grants energy directly; no proration → **BE-7** (count-only increment)
- Cancel extra seat → stops future grants, starts grace, never refunds energy, never deletes child → **BE-8**
- Add-child reserves a seat FIRST via the Shared.Contracts seam; no free seat → clean reject, no child created; compensation on failure; idempotent → **BE-4** (seam) + **BE-5** (handler wiring)
- Cross-module via Shared.Contracts only, loose int ids, no FK → **BE-4** (seam shape) + **BE-5** (Parent uses seam only)

## Notes

- **LEAD GATE / OPEN NUMBERS (OQ-1):** included-seat count **per plan tier**, **max seats**, and **extra-seat monthly price** are open numbers — define as P10-12 (`IGlobalSettingsProvider`) keys; **never hard-code**. A **feature flag** to enable/disable extra-seat purchase is a lead call before BE-6.
- **OQ-2 (free-plan seats):** recommend free/included-only plans still expose their included seats but **cannot** buy extra seats (gate in BE-6 against plan tier). Confirm with lead + P10-05.
- **OQ-3 (seam shape — coordinate with P10-13):** the `ISubscriptionSeatContract` reserve/release/check methods and `GetActiveSeatCountAsync` must align with how P10-13's grant job reads the active-seat count. Lock the seam with P10-13 before BE-4.
- **OQ-4 (`Payment.Kind=Seat`):** recommend reusing `Payment{Kind=Seat}` + an immutable seat-purchase ledger row — no new `SeatPurchase` table. Extend `PaymentKind` if `Seat` is absent (coordinate the migration with P10-06/07). Confirm.
- **OQ-5 (grace marker location):** BE-8 records a grace marker but **does not enforce** — enforcement (NoSeat/Locked transitions, parent picking which children keep seats) is **P10-15**. Confirm the marker shape with P10-15.
- **Module isolation (rule 1):** Parent must reference **only** `Shared.Contracts/Billing.ISubscriptionSeatContract` — never any `Billing.*` project. Seam interface in `Shared.Contracts`, impl in `Billing.Infrastructure` (mirrors `IBillingSubscriptionContract`/`ICreditSpendService`). No cross-module FK — `ChildId`/`parentUserId` are loose ints.
- **No UoW (ADR 0001):** seat reservation (free-seat check + reservation insert), the webhook seat increment (subscription update + ledger append + payment flip), and the add-child reserve→create→activate flow are each atomic via **explicit transactions in the service**, never in a handler.
- **Localization (CONVENTIONS §10):** the no-free-seat rejection and all seat messages use `SharedResourcesKey.*` (AR+EN) — **no free-text string literals**; statuses are enums.
- **Security-sensitive:** money path (provider-verified webhook only; server-side price; idempotent) **and** child-data path (seat reservation gates child creation). `security-auditor` gate before the review gate; never log card data / PII / secrets (`ILoggerManager` only).
- **`ValidationBehavior` runs for commands only** — `StartSeatCheckoutCommand` / `CancelExtraSeatCommand` get FluentValidation validators; the seat-status query is validated inside the handler.
- Blocked by **P10-05** (Plan/Subscription) and **P10-06** (payment seam + webhook + `WebhookEvent`). Builds on **P10-01** (ledger) and the **P10-07** webhook pattern. Reads **P10-12** config. Feeds **P10-13** (active-seat count). The **CreditAccount→FamilyEnergyAccount** ownership migration is **P10-13**, not here.
