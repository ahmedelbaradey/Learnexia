## Acceptance-criteria coverage

- Payment via Egypt provider, no card data on our servers → **BE-3** (`IPaymentProvider` hosted-redirect; no PAN/CVV fields)
- Successful payment activates Premium + triggers P10-02 grant → **BE-5** (webhook handler, `SubscriptionActivated` event)
- Declined payment leaves plan unchanged → **BE-5** (`PaymentFailed` event, no state flip)
- Recurring billing + cancel → **BE-6** (cancel command) + **BE-8** (reconcile job)
- Webhooks idempotent (no double-activation/grant) → **BE-5** (`WebhookEvent` dedup)
- `Payment` record per charge attempt → **BE-4** + **BE-5**
- Webhook authenticated by provider signature → **BE-5** + **BE-7** (signature verify, JWT-free endpoint)

## Notes

- **Web checkout only — NO native IAP:** checkout is web (hosted/redirect); the native student app sells nothing. **COMPLIANCE (launch-gating):** Apple/Google normally require IAP for digital goods in native apps — routing to web is deliberate (PWA-first/"reader-app") and **must be validated against App/Play Store policy before native launch**; security-auditor flags it.
- **Annual cadence:** the charged amount (199 monthly / 1990 annual) is resolved server-side from `BillingPeriod` + P10-12 config; renewal extends the cycle by month or year accordingly. The monthly credit grant is unchanged for both cadences.
- **LEAD DECISION (OQ-1):** Paymob vs Fawry — block BE-3 and any provider-specific code on this. The interface shape above is final; the concrete adapter changes per provider.
- **OQ-2 (auto-renew):** if the chosen provider does not support true card-on-file recurring, AC4 falls back to renewal-reminder + re-checkout link. Flag to lead before BE-3.
- **OQ-4 (`WebhookEvent` table vs idempotency key on `Payment`):** recommend dedicated `WebhookEvent` table (implemented above). Confirm.
- **OQ-5 (Hangfire):** confirm Hangfire is the agreed scheduler and is already wired in the host or is introduced here. Confirm before BE-8.
- **OQ-7 (provider secrets):** API keys + webhook signing secret must be provisioned in the secret store before integration tests can hit a sandbox. Flag to lead/devops.
- **Serialization:** BE-2 migration must follow `BillingInitialCreate` (P10-05-BE-3) — coordinate per PARALLELISM.md; do not run concurrently on `BillingDbContext`.
- No UoW — webhook activation uses an explicit transaction (`Payment` status flip + `Subscription` flip + event emit must be atomic).
- `ValidationBehavior` on commands; never log card data/PII/secrets (`ILoggerManager` only).
- Blocked by **P10-05** (plan model + Subscription entity) and **P10-01** (credit ledger).
