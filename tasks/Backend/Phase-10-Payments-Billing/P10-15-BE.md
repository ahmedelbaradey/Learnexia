## Acceptance-criteria coverage

- Downgrade / seat-cancel / payment-failure start a grace window (not instant enforce), idempotent, config-driven length → **BE-2** (shared `ISeatGraceService`, called from P10-05/P10-13/P10-09)
- During grace seats stay active (children keep allocation + can spend) → **BE-2** + **BE-4** (lock state only flips on enforcement)
- Enforcement on grace expiry: compute over-limit, honor parent choice or default, lock over-limit children, never delete, ledger every move → **BE-3**
- NoSeat/Locked child has no allowance + cannot spend AI (graceful localized decline) → **BE-1** (state) + **BE-4** (spend gate) + **BE-3** (allocation forfeit)
- Locked child keeps progress/XP/history/achievements (no Identity/Learning touch) → **BE-3** (hard invariant — Billing-only writes)
- Already-spent energy never reclaimed; unspent forfeited per P10-14; purchased untouched → **BE-3**
- Parent chooses which children keep seats, validated ≤ paid active seats, family-scoped, ledgered → **BE-5** + **BE-7**
- Re-activate a locked child when a seat frees up → **BE-5** (`ReactivateChildSeatCommand`)
- Seat-state checkable cross-module without FK → **BE-6** (`Shared.Contracts` seam)
- EN+AR localized declines / messages → **BE-4** + **BE-5** (SharedResourcesKey, no literals)

## Notes

- **OQ-1 (RESOLVED 2026-06-16):** grace-period **length = fixed 7 days** (`GraceEndsAt = trigger_time + GetInt("seats.grace_days", 7) days`), applied **uniformly** to payment-failure, downgrade, and seat-cancel; **ONE clock = `Subscription.GraceEndsAt`** (no second timer). This **REPLACES** P10-09's `GraceEndsAt = CurrentCycleEnd` (`RefundService.cs` ~266 & 540) — migrate the P10-09 dunning tests accordingly. Seed `seats.grace_days = 7` + add to `ManagedKeys`. During grace, seats stay active.
- **OQ-2 (default selection tie-break):** when the parent has NOT chosen by enforcement time, recommend keep the **earliest-activated** seats (deterministic). Confirm the tie-break rule before BE-3; parent can always re-choose afterward (BE-5).
- **OQ-3 (grace re-trigger semantics):** if a second reduction event fires during an open grace window, recommend **no stacking** (single active window; do not shorten/extend). Confirm before BE-2.
- **OQ-4 (allocation forfeit destination):** unspent entitlement of a locked child is forfeited per **P10-13 allocation/reset rules** (returned to the family entitlement wallet `SubscriptionBalance` / dropped at the next cycle reset) — **never** converted to purchased. Confirm the exact forfeit path with the P10-13 owner before BE-3.
- **HARD INVARIANT (security-auditor must verify):** enforcement and locking are **Billing-only** writes — they MUST NOT delete a child or cascade into Identity / Learning / Gamification records. Child progress/XP/history/achievements are owned by other modules and stay intact.
- **Module isolation:** child id is a loose `int`; seat-state checks for the AI/Parent modules go through the `Shared.Contracts` seam (BE-6), never a direct Billing reference or FK.
- **Option C (CONVENTIONS §7):** all handlers (BE-5) inject **service interfaces** declared in `Billing.Application/Abstractions`; grace/enforcement/spend-gate logic lives in `Billing.Infrastructure/Services`; **no EF/DbContext/repository in Application**.
- **No UoW (ADR 0001):** enforcement (lock + forfeit + ledger) and choose-active (state flips + allocation + ledger) each run in a single **explicit transaction**; idempotency keys guard re-runs (Hangfire retry, repeated webhook). Concurrency: enforcement vs a concurrent parent choose-active must not double-lock/double-forfeit — guard with the per-family+cycle idempotency key.
- **`ValidationBehavior` runs for `ICommand<>` only** — `ChooseActiveChildren` + `ReactivateChildSeat` get FluentValidation validators; the status query does not.
- **No free-text string literals** — every parent/child-facing message is a `SharedResourcesKey` (EN+AR resx); states are enums.
- Builds on **P10-13** (wallet + per-child allocation rows + reservation seam + forfeit/reset rules), **P10-14** (seat model + reservation seam), **P10-05** (downgrade), **P10-09** (dunning/payment-failure — whose `GraceEndsAt = CurrentCycleEnd` this story replaces with the 7-day window), **P10-01** (immutable ledger). Keep seat-state contracts consistent with sibling **P10-16** (redistribution) / **P10-17** (refunds).
