| # | Decision | Recommendation |

| OQ-1 | Timezone source for per-child local midnight | **Server-side per-child timezone** from child profile; fall back to platform `TimeZoneId` if absent. |

| OQ-6 | Warning state vs copy split | **P10-04 returns typed `WarningState` enum (`None` / `DailyCapReached` / `LowEnergy`)**; P10-10 owns the localized copy (AR+EN). |

## Acceptance-criteria coverage

- Per-child-per-day counter tracks energy used; cap from **`IGlobalSettingsProvider`** (`provider.FreeDailyCap` / `provider.PremiumDailyCap` — not P10-11 `IBillingConfigReader`) → **BE-4**
- Soft semantics: cap reached → warning state + allows continuation (hard-stop OFF default); `HardStopEnabled` config → **BE-4, BE-5**
- Low-energy warning fires at threshold → `LowEnergy` flag in `EnergyStatusQuery` → **BE-4**
- Daily counter resets at child's local midnight (timezone-aware lazy reset); monthly pool untouched → **BE-2, BE-3**
- `BaseResponse<T>`/`Successed`; `ILoggerManager`; `ISystemClock` + timezone; reads P10-01 pool (no parallel balance); config from **`IGlobalSettingsProvider`** (P10-12) → **BE-4, BE-5**

## Notes

- **Coordination with P10-01:** the `DailyUsed`/`DailyUsedDateLocal` columns live on `CreditAccount` (P10-01's entity). If both stories are dispatched in the same wave, fold BE-1 into P10-01's `InitialBilling` migration. Otherwise run as a separate additive migration.
- **Coordination with P10-03:** `IncrementDailyUsage` (BE-5) is called inside the same explicit transaction as the `TryDebitAsync` in P10-03-BE-3 — the increment and the ledger debit are atomic together (column approach per OQ-3).
- **No new pool:** `DailyUsed` is an informational counter, not a second balance. The monthly `GrantedBalance + PurchasedBalance` (P10-01) remains the authoritative ceiling.
- **P10-10 consumes `EnergyStatusQuery`** (BE-4) to render the energy meter + warning copy. P10-04 returns typed state; P10-10 owns the AR+EN copy — do not mix localized strings into BE-4's output.
- `WarningState.None` is the default; the child app only shows warnings when state is `DailyCapReached` or `LowEnergy`.
