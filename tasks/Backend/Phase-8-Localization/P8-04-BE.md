## Acceptance-criteria coverage
- Parent-only, family-scoped change; student cannot → **BE-1**
- Explicit confirm flag or business-validation error → **BE-2**
- Update + post-commit event → **BE-1, BE-3, BE-4**
- Reset Math/Science only; Arabic/English untouched → **BE-5**
- Gamification retained → **BE-6**
- New `learning_language` claim on next sign-in → covered by P8-01-BE-4 (token re-issue)

## Notes
- **Cross-module via `Shared.Contracts` only** — no cross-module FK; the reset is driven by an integration event, not a direct call into Learning.
- **Destructive** (resets progress) + **child-data sensitive** → `security-auditor` blocks Critical/High before the reviewer gate.
- The "very clear warning" UX copy is FE (parent app); backend enforces the confirm flag and the reset semantics.
- **Open:** confirm fresh-start scope = Learning Math/Science attempts + mastery only (gamification retained) before coding BE-5.
