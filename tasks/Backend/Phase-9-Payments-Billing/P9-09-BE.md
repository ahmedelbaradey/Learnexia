## Acceptance-criteria coverage

- Failed recurring charge triggers dunning (retry schedule + parent notification) → **BE-2** + **BE-4**
- After N failures → downgrade to Free at cycle end (grace period) → **BE-2** (configurable N from P9-11)
- Pack refund claws back unspent credits only (clamped ≥ 0, never negative) → **BE-3**
- Subscription refund follows stated policy → **BE-3**
- All refunds are idempotent ledger entries → **BE-3** (`CreditTransaction.IdempotencyKey` + `WebhookEvent` dedup)
- Webhook events idempotent + reconciled → **BE-2** + **BE-3** (dedup on `ProviderEventId`)

## Notes

- **LEAD GATE (OQ-1):** clawback policy — for partially-spent pack: claw back unspent remainder only (≥ 0); for subscription refund: revoke access but do NOT claw back granted credits beyond policy. Block BE-3 on this.
- **OQ-2 (refund trigger):** provider-dashboard-only (→ webhook only, BE-5 not needed) vs in-app admin action (BE-5 needed). Confirm before BE-5.
- **OQ-3 (dunning params):** N failures, retry schedule, grace period — from P9-11 config. Confirm defaults with lead.
- **OQ-4 (recurring dependency):** dunning auto-retry (BE-4) requires P9-06 to have implemented true auto-renew (card-on-file). If provider can't auto-renew, BE-4 sends a re-checkout link instead. Coordinate with P9-06 provider decision.
- **OQ-5 (Notifications module):** dunning notifications use existing Notifications module via `Shared.Contracts` integration event — confirm the event contract shape.
- No UoW — refund clawback uses an explicit transaction (ADR 0001). Concurrency guard for negative-balance race is the primary correctness risk.
- Blocked by **P9-06** (Payment/Subscription/webhook seam) and **P9-01** (CreditTransaction ledger).
