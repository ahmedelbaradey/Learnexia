## Acceptance-criteria coverage

- Each active child gets plan allotment into `GrantedBalance` on the cycle date via `ApplyGrant` (Free = 100, Premium = 5000 from P9-11 config) → **BE-3**
- Granted pool stamped with `GrantExpiresAtUtc = end of cycle` → **BE-3** (passed into `ApplyGrant`)
- At rollover, unspent `GrantedBalance` zeroed via `Expire` row; `PurchasedBalance` untouched → **BE-3** (expire-before-grant in same pass)
- Re-running for same child+cycle is a no-op (DB unique constraint + `[DisableConcurrentExecution]`) → **BE-3**
- Mid-cycle plan change → next grant uses new tier; current cycle unchanged → **BE-3** (tier resolved at grant time from the seam)
- Job mirrors Gamification shape (DI scope, `ISystemClock`, `ILoggerManager`, `[DisableConcurrentExecution]`, fail-soft per child) → **BE-3, BE-4**
- Allotment from **`IGlobalSettingsProvider`** (P9-12 enabler, not literals and not `IBillingConfigReader`) → **BE-1, BE-3** (`provider.FreeMonthlyCredits` / `provider.PremiumMonthlyCredits`)

## Notes

- **Hard dependency on P9-01:** do not start BE-3 or BE-4 until P9-01 is merged and `ApplyGrant`/`Expire` primitives are available.
- The idempotency key scheme: `grant:{childId}:{cycleId}` for grants; `expire:{childId}:{priorCycleId}` for expiry — both rely on P9-01's `UX_CreditTransactions_IdempotencyKey` unique constraint. Define `cycleId` consistently (e.g. `yyyyMM` of the billing month).
- **P9-05 sequencing:** the `IBillingSubscriptionContract` stub (BE-2) decouples P9-02 from P9-05. When P9-05 ships, replace the stub implementation — no change to `BillingGrantJob`.
- **P9-12 sequencing:** grant amounts come from `IGlobalSettingsProvider` (P9-12 enabler) — there is no `BillingGrantOptions` and no `IBillingConfigReader`. `IGlobalSettingsProvider` must be available (P9-12-BE-3 merged) before `BillingGrantJob` is dispatched. Bootstrap defaults cover the period before the DB-backed provider is live.
- Hangfire connection (`ConnectionStrings:Hangfire`) must be configured (existing requirement since P1-07 per HANDOFF.md).
