## Acceptance-criteria coverage

- Admin can edit all named economy values; persisted in `GlobalSetting` store (P9-12) via `UpdateGlobalSettingCommand` → **P9-12-BE-5** (consumed by P9-11-BE-6)
- Every change creates an audit record (who/when/old→new) in `Moderation.AuditLog` → **P9-12-BE-5** (`IAuditLogWriter` call)
- Change takes effect at next read (post Redis cache invalidation); never retroactively re-charges past `Spend` rows → **P9-12-BE-4** (cache invalidation) + P9-01 immutable ledger
- Validation rejects negative costs, zero pack size, daily cap > monthly grant → **P9-12-BE-6** (`UpdateGlobalSettingValidator`)
- All endpoints admin-only (`[Authorize(AdminPolicy)]`; 403 for non-admin) → **P9-12-BE-8** (GlobalSettingsController) + **BE-6** (BillingConfigController if retained)
- `BaseResponse<T>`/`Successed`; `ILoggerManager`; `ValidationBehavior`; audit via P7 pattern → **P9-12-BE-5, P9-12-BE-6, BE-6**
- `IGlobalSettingsProvider` seam for P9-02/03/04/07 to consume config → **P9-12-BE-3**

## Notes

- **P9-11 is dispatched AFTER P9-12 is merged.** The entire billing-config backend (validation, audit, cache, admin write) is provided by P9-12. P9-11's only remaining implementer task is BE-6 (the reconciled controller thin wrapper).
- **Never-retroactive invariant (AC-3):** `GlobalSetting` rows are updated in place (mutable), but `CreditTransaction.Amount` ledger rows remain immutable (P9-01 rule). A config update changes future reads only. The audit trail (old→new in `Moderation.AuditLog`) is the traceability record; it is not a versioned effective-dated row. Confirm the lead accepts immediate-on-write (no scheduling) per P9-12 OQ-2.
- **Cross-module audit:** handled by P9-12's `UpdateGlobalSettingCommand` via `IAuditLogWriter` seam — `Billing` does not reference `Moderation.*` projects directly (CONVENTIONS rule 1).
- **P9-02/03/04/07 sequencing:** those stories now build against `IGlobalSettingsProvider` (P9-12-BE-3). `IGlobalSettingsProvider` must be merged before those stories' implementer agents are dispatched. `BootstrapDefaultGlobalSettingsProvider` provides hardcoded defaults during the build period before P9-12's DB-backed implementation is live.
- **No payment secrets in config:** `GlobalSettingKeys.ManagedKeys` (P9-12) does not include API-key / secret fields. Payment-gateway keys (P9-06) go in the secret store. Security-auditor will check P9-12.
- **Superseded tasks (BE-1..BE-5):** these tasks are retained in this file as superseded records (Status: 🔲, Est: 0 h) for traceability. They must NOT be dispatched to implementer agents. The planner's execution plan for P9-11 should skip BE-1..BE-5 entirely.
