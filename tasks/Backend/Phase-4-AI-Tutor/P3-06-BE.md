> **Backend only — no Frontend tasks.** Generated questions feed the existing quiz UI (P2-06-FE) and adaptive quizzes (P3-11). The "similar example" endpoint is student-facing (P3-12 UI).

> **AI Helper MVP — read first:** See `docs/briefs/ai-helper-mvp.md`. P3-06 now serves two purposes: (1) the existing **offline Batch API question generation** (admin-triggered, unchanged), and (2) a new **runtime "similar example" helper** implementing **intent #4 — "اديني مثال مشابه" (SimilarExample)**. The `SimilarExampleCommand` uses `ILearningContextProvider` for grounding; no context → refuse-and-redirect; instrumentation events emitted. The offline batch generation path is unaffected by the Helper scope constraint. Build order is NOT gated on P3-07 for the runtime path.

> **Status: 🔲 Not started.** Offline generation path: hard-blocked by P3-01 + P3-02 + P3-03. Runtime similar-example path additionally requires P3-03-BE-9 (`ILearningContextProvider`). P3-07 is NOT required at MVP for either path — seeded corpus is sufficient. LEAD GATE required on OQ-1/OQ-2/OQ-3 before dispatch.

## Acceptance-criteria coverage

### Part A — Offline question generation
- AC-1 (grounded): handler calls `ILearningContextProvider` / `IChunkRetrievalContract` + injects chunks into P3-03 prompt → **BE-4, BE-7**
- AC-2 (valid + typed): `QuizQuestionTypeValidation` + `AnswerComparator` shape check; Matching deferred (OQ-4); invalid output rejected/retried → **BE-4, BE-8**
- AC-3 (safety + traceability): every item passes P3-02 Safety Layer; `GeneratedBy.AI` tagged; safety failures logged → **BE-4, BE-8**; Opus QA pass flags low-quality items → **BE-9**
- AC-4 (DECLINE ON EMPTY — hard criterion): `Chunks` empty → `Declined_NoContext` immediately; no LLM call; no `QuizQuestion` written → **BE-4, BE-7**
- AC-5 (conventions): `BaseResponse<T>` / `Successed`; `ICommand<>` validated; `ILoggerManager`; explicit transaction for batch; no cross-module FK; module isolation → **BE-3, BE-4, BE-6, BE-7, BE-8**
- **Batch API primary** — offline generation via Batch API (Sonnet); completion handler persists results; no blocking wait → **BE-7, BE-8**
- **Opus QA pass** — surviving items validated by Opus in a separate offline Batch API pass → **BE-9**
- **Runtime exception path** — synchronous Sonnet call with quota check; decline-on-empty still enforced → **BE-7**

### Part B — Runtime similar example (intent #4)
- AC-6 (similar example grounded in active skill): `SimilarExampleCommand` uses `ILearningContextProvider`; prompt scoped to active skill; SSE stream delivered; Practice pool cache hit served when Approved entry available → **BE-10, BE-11, BE-13**
- AC-7 (refuse-and-redirect): empty `LearningContext.Chunks` → redirect response; no LLM call; tested explicitly → **BE-10, P3-04-BE-11**
- AC-8 (instrumentation): `HelpRequested`, `HelpDelivered`/`HelpDeclined { Intent=SimilarExample }` emitted → **BE-10**
- AC-9 (safety): P3-02 Safety Layer applied; no bypass → **BE-10**
- **Practice pool (R4)** — pool of N≥3 variations pre-generated per skill (BE-13); rotation ensures sequential requests return different examples; variation pool not enumerable via public API (security-auditor verifies); only `Approved` entries served → **BE-10, BE-13**
- **Cache invalidation (R6)** — PromptVersion bump, CurriculumVersion switch, and manual purge invalidate Practice pool entries; refill triggered after invalidation → **BE-14**

## Notes

- **Hard blockers (REVISED):** P3-01 (including BE-13 Batch API + BE-14 quota) + P3-02 + P3-03 (including P3-03-BE-9 `ILearningContextProvider`) must all be merged before BE-1 / BE-10 are dispatched. **P3-07 is NOT required** — seeded corpus is the MVP grounding source for both paths.
- **Cross-module seam (OQ-1):** `IChunkRetrievalContract` in `Shared.Contracts` is the only permitted cross-module bridge for the offline batch path; no direct project reference from Learning → Curriculum.
- **Matching deferral (OQ-4):** `ValidationBehavior` rejects any request containing `QuestionType.Matching` until CO-BE-1/2 land. Document in the command validator.
- **Decline-on-empty (AC-4)** is the headline criterion for api-tester and security-auditor: no fallback that silently free-generates when retrieval is empty. Preserved in the revised Batch API handler (BE-7) and enforced in `SimilarExampleCommandHandler` (BE-10).
- **Practice pool never 1:1 (R4 — Decision 3/OQ-H resolved: N=5 at MVP):** serving the same fixed example to every child who studies a skill defeats adaptive practice AND creates an answer-key/exam-integrity risk. The pool of **N=5 variations** (`VariationIndex` 0..4) + random rotation mitigates both. Configured via `AiGatewayOptions.PracticePoolSize` (default: 5; bump to ≥10 when the question bank is larger). `Practice` cache rows have `QuestionId = null` (Decision 4 — Practice type is not per-question). Security-auditor MUST verify: (a) variation pool is rotated (not always index 0); (b) pool is not enumerable via the public API; (c) pool size N=5 is enforced by the pre-generation job; (d) `PendingReview` entries are NOT served as cache hits.
- **Cost/abuse bounds:** the `Count` field must be validated (max cap, e.g. 20 per request); the batch size submitted to `IAiBatchGateway` must be capped. `SimilarExampleCommand` rate-limited per student per window (BE-11 reuses P3-04-BE-5 infra). Practice generation is the dominant recurring AI cost — monitor batch job volume and pool fill rate.
- **No UoW:** if persisting >1 question atomically in the completion handler, open an explicit `BeginTransactionAsync` block per ADR 0001.
- **`ai.generation_batches` table** (BE-8) is an additional migration in the `Ai` module schema.
- **Shared cache repo:** `IAiResponseCacheRepository` (defined in P3-04-BE-8) is injected into `SimilarExampleCommandHandler` and `PreGeneratePracticePoolJob`. No separate Practice cache entity or repository.
- **Security-auditor is a hard gate** for this story. Additionally covers: scope guard for SimilarExample (out-of-skill-context → redirect, no LLM call), no Opus call at runtime (audit config gate in BE-7), batch-job cost bounds, no secret leakage, **Practice pool rotation and non-enumerability (R4)**, `PendingReview` entries NOT amplified (R5).
