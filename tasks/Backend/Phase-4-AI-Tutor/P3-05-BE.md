> **Backend only — no separate FE task file.** The UI surface (hint bubbles, why-wrong chip, simplify action) is owned by P3-12 (AI Tutor UI).

> **AI Helper MVP — read first:** See `docs/briefs/ai-helper-mvp.md`. P3-05 implements **intent #2 — "اديني تلميح" (Hint)** and **intent #3 — "ليه إجابتي غلط" (WhyWrong)**. The `GetHintCommand` now carries a `HelperIntent` discriminator (`Hint` or `WhyWrong`). WhyWrong is **always runtime** (student's actual wrong answer is the dynamic input — no cache key). Both intents use `ILearningContextProvider`; no context → refuse-and-redirect. Instrumentation events emitted. Build order is NOT gated on P3-07 or BL-*.

> **Status: 🔲 Not started** — hard-blocked by P3-04 (explain pipeline) + P3-01 + P3-02 + P3-03 (including P3-03-BE-9 `ILearningContextProvider` seam). P3-07 is NOT required. Best built immediately after / alongside P3-04. LEAD GATE required on OQ-2/OQ-3/OQ-4 before dispatch.

## Acceptance-criteria coverage

- AC-1 (hint nudges, no reveal — intent #2): prompt forbids answer; OQ-4 post-generation check validates buffer excludes `CorrectAnswer`; level 1 nudges without revealing; cache-hit path is pre-validated → **BE-5, BE-11, BE-12**
- AC-2 (why-wrong — intent #3, always runtime): `HelperIntent.WhyWrong` path injects student's actual wrong answer; always calls gateway (no cache); two different wrong answers produce different responses (verified in api-tester) → **BE-5, BE-7**
- AC-3 (refuse-and-redirect for both intents): empty `LearningContext.Chunks` → redirect + `HelpDeclined`; no LLM call for either intent; tested in api-tester → **BE-5, P3-04-BE-11**
- AC-4 (escalation): server derives `CurrentHintLevel` (OQ-2b); handler prompts at correct specificity; next level returned in SSE metadata → **BE-5, BE-7, BE-11**
- AC-5 (simpler re-explanation): `SimplifyExplanationCommand` reuses explain pipeline with "lower reading level" directive; cache-first via `ConceptExplanationCache` → **BE-6**
- AC-6 (safety + personalization): Safety Layer (P3-02) applied; grade/age/language from JWT (P3-03); cache-hit path is pre-QA-passed → **BE-5, BE-6, BE-11**
- AC-7 (usage recorded): `HintUsedIntegrationEvent` published fire-and-forget (even on cache hit); Learning handler increments `StudentAnswer.HintUsed` + `Attempt.HintsUsedCount` → **BE-4, BE-5, BE-11**
- AC-8 (instrumentation + closed-loop): `HelpRequested`, `HelpDelivered`/`HelpDeclined` in handler; `PostHelpRetry`/`PostHelpSuccess` in `SubmitAnswerCommandHandler` → **BE-13**
- AC-9 (conventions): `[Authorize(Roles="Student")]`; JWT-derived context; streaming consistent with P3-04; `ILoggerManager`; module isolation; no progression decisions → **BE-1, BE-2, BE-5, BE-6, BE-7**
- **Cache-primary (Hint intent only)** — cache-hit path serves from `HintCache`; miss triggers gateway + async cache-write; WhyWrong always runtime → **BE-10, BE-11**
- **Offline pre-generation (Hint only)** — batch job populates `HintCache` (Hint intent) via Batch API (Sonnet) + Opus QA + no-reveal; WhyWrong excluded → **BE-12**
- **Quota enforcement** — `IAiUsageBudget` checked before LLM; `QuotaExhausted` degrades to closest cached hint (Hint) or generic nudge (WhyWrong) → **BE-11**

## Notes

- **Parallelizable with P3-04:** shares the same pipeline and DI registrations. Build together once the infra cluster lands; P3-04 should be merged or co-developed first since BE-5/BE-6/BE-11 reuse its patterns.
- **Cross-cluster deps (REVISED):** P3-01 (BE-12 prompt-caching, BE-13 batch gateway, BE-14 quota), P3-02, P3-03 (including P3-03-BE-9 `ILearningContextProvider` seam). **P3-07 is NOT required** — `SeededCorpusContextProvider` is the MVP grounding source.
- **`HintUsedIntegrationEvent` (BE-4)** is a cross-module event — the ADR 0002 direct-publish pattern applies; never a direct FK/DbContext reference from AiTutor → Learning. Fire on cache-hit too.
- **`IQuestionAnswerContract` (BE-3)** is a shared-file edit in `Shared.Contracts` — serialize against concurrent stories.
- **Answer-leakage risk (AC-1)** is the central pedagogical/safety risk. Mitigate with prompt instruction + post-check (OQ-4) in the batch job (BE-12) and the runtime handler (BE-11). Security-auditor HARD GATE reviews this.
- **WhyWrong intent (intent #3) is always runtime** — by definition the student's specific wrong answer is the unique input; no cache key can be formed. The batch pre-generation job (BE-12) explicitly excludes WhyWrong. Do not attempt to cache WhyWrong responses.
- **Max hint levels (OQ-5):** must be confirmed by the lead before BE-5/BE-12 are implemented (drives escalation boundary logic and batch job enumeration).
- **Haiku floor caution:** do NOT lower the `Hint` or `WhyWrong` task kind to Haiku without passing the P6-02 Arabic pedagogical quality eval. Current floor: Sonnet.
- **Security-auditor is a hard gate** (AI text shown to children). Audit covers: no-reveal enforcement, scope guard (refuse-and-redirect for both intents when no context), escalation/cost abuse, usage-signal integrity, quota enforcement, WhyWrong always runtime (audit that no cache path exists for it).
- **Closed-loop instrumentation (BE-13):** `PostHelpRetry`/`PostHelpSuccess` require an additive change to `SubmitAnswerCommandHandler` in the Learning module. This is a cross-module concern — coordinate with the Learning module owner (no cross-module FK; emit integration event pattern).
