## Notes

- **Parallelizable with P3-04:** shares the same pipeline, DI registrations, and the unified `IAiResponseCacheRepository`. Build together once the infra cluster lands; P3-04 should be merged or co-developed first since BE-5/BE-6/BE-11 reuse its patterns.
- **Cross-cluster deps (REVISED):** P3-01 (BE-12 prompt-caching, BE-13 batch gateway, BE-14 quota), P3-02, P3-03 (including P3-03-BE-9 `ILearningContextProvider` seam). **P3-07 is NOT required** — `SeededCorpusContextProvider` is the MVP grounding source.
- **Unified cache (R2):** `HintCache` entity and `IHintCacheRepository` are replaced by `AiResponseCacheEntry` / `IAiResponseCacheRepository` (defined in P3-04-BE-8, shared). No separate hint cache table or entity. BE-9 is a no-op if P3-04-BE-7 migration already applied.
- **WhyWrong is cacheable (R3 — Decisions 2, 4, 5 applied):** WhyWrong responses are cached via a compound key `(QuestionId, SHA256(NormalizedWrongAnswer), Language, AgeBand, PromptVersion, CurriculumVersion)`. The `WrongAnswerNormalizer` (BE-14) is **subject-aware** (Decision 5): strips tashkeel for Math/Science; preserves tashkeel for Arabic-language subject. The `AgeBandHelper` (BE-14) enables cross-student reuse. The `QuestionId` column (Decision 4) on each WhyWrong row enables precise indexed invalidation when a correct answer changes. Per-question storage cap = **`_globalSettings.GetInt("ai.cache.whyWrongVariantCap", 50)` distinct entries, LRU eviction** (Decision 2/OQ-G resolved; bootstrap default: 50) — enforced in BE-15. **Cap is read via `IGlobalSettingsProvider` at call time; DB-backed / admin-editable via P9-12.** The batch pre-generation job (BE-12) explicitly EXCLUDES WhyWrong (it is student-answer-specific, cached on-the-fly).
- **ReviewStatus gate (R5 — Decision 1/OQ-F resolved):** `GetApprovedAsync` always filters `ReviewStatus = Approved AND InvalidatedAt IS NULL`. Runtime-generated responses (Hint and WhyWrong) are stored with `ReviewStatus = Approved` if `Confidence ≥ _globalSettings.GetDecimal("ai.cache.autoApprovalConfidence", 0.85m)` (bootstrap default: 0.85; tunable — raise toward 0.90 if reviewers find many mistakes, lower toward 0.80 if quality is excellent). **`IGlobalSettingsProvider` is the single read point; never read from `AiGatewayOptions.AutoApprovalConfidenceThreshold` or a hardcoded constant. DB-backed + admin-editable via P9-12; bootstrap default applies until then.** `PendingReview` entries are NOT served as cache hits to other students.
- **Prompt-caching note:** Anthropic provider prompt-caching (`cache_control`) is a secondary lever applied on the miss path. For short hint prompts it may not fire (Haiku 4,096-token floor). Primary cost lever is the Redis + `AiResponseCache` hit.
- **`HintUsedIntegrationEvent` (BE-4)** is a cross-module event — the ADR 0002 direct-publish pattern applies; never a direct FK/DbContext reference from AiTutor → Learning. Fire on cache-hit too.
- **`IQuestionAnswerContract` (BE-3)** is a shared-file edit in `Shared.Contracts` — serialize against concurrent stories.
- **Answer-leakage risk (AC-1)** is the central pedagogical/safety risk. Mitigate with prompt instruction + post-check (OQ-4) in the batch job (BE-12) and the runtime handler (BE-11). Security-auditor HARD GATE reviews this.
- **Max hint levels (OQ-5):** must be confirmed by the lead before BE-5/BE-12 are implemented (drives escalation boundary logic and batch job enumeration).
