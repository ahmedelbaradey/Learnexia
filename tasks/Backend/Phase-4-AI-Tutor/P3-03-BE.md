> **Product-decision override (enforced — do NOT revert):** 4 subjects only — **Math, Science, Arabic, English. NO Social Studies template.**
>
> **Locked decisions (from lead — do not re-raise):**
> - **Q1 (inherited):** `Ai` module home (from P3-01). Prompt builder lives in `Ai.Application` / `Ai.Domain`.
> - **Q2 (weak-areas seam owner):** P3-03 defines a minimal `IStudentWeakAreasQuery` in `Shared.Contracts` with an empty default impl. P3-09 provides the real implementation later. Empty = degrade gracefully (AC4).
> - **Q3 (unsupported-subject behavior):** Return a typed `UnsupportedSubjectResult` (graceful error) rather than silently defaulting. The feature handler returns a user-facing error.
> - **Q4 (child grade/age/language seam):** Reuse an existing child-profile read seam if one exposes grade/age/language; otherwise add a minimal `IChildLearningProfileQuery` to `Shared.Contracts`. Reads current grade at request time (never stale — per-child grade transition).
> - **Q5 (Subject enum):** Local `Subject` enum constrained to 4 MVP subjects (Math, Science, Arabic, English) with a unit test asserting exactly these 4 members (no Social Studies). Reuse the Learning module's subject concept via `Shared.Contracts` seam if exposed; otherwise local enum.
> - **Q6 (no endpoint):** P3-03 is internal; no controller. First endpoint is P3-04.
> - **Q7 (template storage):** Code-as-config (string templates in the AI module) for MVP. Admin editing deferred.

## Notes

- **Build order:** P3-03 depends on P3-01 (`AiRequest` / `AiTaskKind` shapes) and soft-depends on P3-02 (for end-to-end wiring); it can be built in parallel with P3-02 against frozen P3-01 contracts. Build order is parallel with Gamification-FE / Parent work — NOT gated on P3-07 or BL-*.
- **No db-migration:** the prompt builder is stateless and pure — no entities, no tables. `SeededCorpusContextProvider` (BE-9) reads existing `KnowledgeNode`/`CurriculumChunk` rows; no new schema.
- **No HTTP endpoint:** api-tester not required. Coverage = unit tests (BE-4 selector, BE-5 language, BE-6 degradation, BE-7 assembly + determinism + FR-AI-6 guard + scope constraint, BE-9/10 provider).
- **Soft dependencies degrade gracefully:** `IStudentWeakAreasQuery` (P3-09 real impl later) ships as empty stub. `ILearningContextProvider` returns empty Chunks when no seeded content exists for the skill — callers treat empty as "no context" → redirect. AC4 is precisely this guarantee.
- **Security-auditor gate is mandatory** — prompt-injection hardening (fixed tone frame, context delimited as data), child PII minimization (grade/age only, no name/birthdate/identifiers), no prompt-body logging, FR-AI-6, scope-constraint frame present in all four intent templates.
- **No design pattern beyond a lookup:** `TemplateSelector` is a `Dictionary<(Subject, HelperIntent, Language), ISubjectTemplate>` lookup — not a Strategy/Factory pattern. Rule 8 is satisfied.
- `ILoggerManager` not `ILogger<T>` (rule 5). Module-isolation rule 1: reads cross-module data only through `Shared.Contracts` seams.
- **`LearningLanguageChangedIntegrationEvent`** already exists in `Shared.Contracts` — reuse the language concept.
- Templates are code-as-config (string constants). Admin-authoring UI is a future story. Templates must not be logged at info level.
- **Tone frame integrity invariant:** the child-safe tone frame is unconditionally prepended — no caller can omit it. Security-auditor verifies.
- **`ILearningContextProvider` is the key seam** (BE-9/BE-10): `SeededCorpusContextProvider` ships now; `RagContextProvider` (P3-07) swaps in via config. This is what makes the parallel build work. Do NOT make P3-03 depend on P3-07.
- **`HelperIntent` replaces `TutorTask`:** the old `TutorTask { Explain, Hint, GenerateQuestion }` is superseded. If `TutorTask` exists anywhere in the codebase, rename to `HelperIntent` in this PR. The four allowed intents are the complete, closed set.
- **Cross-reference:** `docs/briefs/ai-helper-mvp.md` governs the four allowed intents and the `ILearningContextProvider` seam definition.
