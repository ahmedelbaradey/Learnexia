## Notes

- **Depends on P3-09 → P3-08 → P3-11 (in that merge order).** P3-11 is the last of the difficulty chain.
- **`StartAttempt` is a hot, secured path.** The selection step must be purely additive — injected after existing lifecycle/language/active filters, not replacing them. Do not touch the resume/active-guard logic in the process.
- **Determinism on resume (AC4):** the `QuizSelectionEngine` sorts by `QuizQuestion.Id` before mixing so that a resume call with the same candidates + target produces the identical ordered list. This avoids storing chosen question IDs explicitly.
- **Null `lesson.SkillId`:** `IAdaptivityService` returns `IsDefault=true, Medium` for null skill → balanced mix, no error.
- **Thin pool:** if all questions have the same `DifficultyLevel`, selection is a no-op (returns all). Log a content-gap warning; never fail. Flag to content team in HANDOFF.
- **Pattern caution (rule 8):** plain static selection function + config options. No Strategy/Factory without asking the lead.
- **Question seed:** integration tests require a lesson seeded with Easy/Medium/Hard questions at varied ratios. Flag this to the api-tester agent.
- **Shared-file edits (serialize):** `StartAttemptCommandHandler.cs`, `AttemptConfig.cs`. Confirm no concurrent story (e.g. P7-04/P7-05) touches `StartAttempt` on a parallel branch.
