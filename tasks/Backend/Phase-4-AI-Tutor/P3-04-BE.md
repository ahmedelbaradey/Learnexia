## Lead decisions required before dispatch

| # | Question | Recommendation |
|---|---|---|
| OQ-1 | **Streaming mechanism (CLAUDE.md rule 8 — ask-first):** SSE (`text/event-stream`) vs `IAsyncEnumerable<string>` chunked vs WebSocket? | **SSE** — simplest for Expo/web; one-way; easy retry; errors return typed SSE `error` event |
| OQ-2 | **Streaming vs mandatory safety:** buffer-fully → safety-filter → then "stream" the pre-checked text (OQ-2a, safest); chunk-level filtering (OQ-2b); stream + post-hoc redaction (OQ-2c)? | **(a) buffer → filter → emit** — safest, provably satisfies AC-2; mitigate latency with cheap model routing |
| OQ-3 | Orchestration location/seam: which module owns the explain handler, and how does it reach Curriculum retrieval + Learning lesson context? | Dedicated **AI-tutor slice** in the `Curriculum` module (or new `AiTutor` slice); consumes Learning via `Shared.Contracts` lesson-info contract; consumes Curriculum retrieval in-process |
| OQ-4 | Tutor-interaction logging: `ILoggerManager` only vs a lightweight table for P7-11 / adaptivity? | `ILoggerManager` at MVP; fire-and-forget if a table is added (never blocks the stream) |
| OQ-5 | Empty-retrieval behavior for explain: decline or proceed with reduced grounding? | **Proceed with reduced grounding** — explain may use prompt-level grade/age/language + lesson title without curriculum chunks; must NOT fabricate specific curriculum facts |

## Notes

- **Streaming pattern is new** for this codebase (everything else is buffered `BaseResponse<T>`). CLAUDE.md rule 8 applies: confirm OQ-1 (SSE) with the lead before implementing BE-4.
- **Safety-buffering (OQ-2a):** the full response is buffered before any token is streamed to the child. This is slightly higher latency than chunk-level filtering but is the only provably safe option at MVP. Cache-hit path skips this (already safe — it is pre-QA-passed and `Approved`).
- **Cross-cluster deps (REVISED):** P3-01 (gateway + BE-12 prompt-caching + BE-13 batch gateway + BE-14 quota), P3-02 (safety), P3-03 (prompt builder + `ILearningContextProvider` seam from P3-03-BE-9). **P3-07 is NOT a cross-cluster dep for P3-04** — the `SeededCorpusContextProvider` is the MVP grounding source. P3-07 adds `RagContextProvider` later via config.
- **`ILessonContextContract` (BE-2)** is a shared-file edit in `Shared.Contracts` — serialize against any concurrent story touching that package.
- **Unified cache migration (R2):** `ConceptExplanationCache` is replaced by `ai.AiResponseCache`. The migration in BE-7 creates the single unified table for Explain, Hint, WhyWrong, and Practice types. P3-04-BE-7 migration may be combined with P3-05-BE-9 into a single migration file. All repository code references `AiResponseCacheEntry` and `IAiResponseCacheRepository` (not the former per-type repositories).
- **ReviewStatus gate (R5):** `GetApprovedAsync` always filters `ReviewStatus = Approved AND InvalidatedAt IS NULL`. The cache-write path sets `ReviewStatus` based on `Confidence ≥ AutoApprovalConfidenceThreshold` (from `AiGatewayOptions`). Pre-generated entries enter as `PendingReview`; only the Opus QA pass promotes to `Approved`.
- **Prompt-caching note:** Anthropic provider prompt-caching is a secondary cost lever (applied on the miss path via `cache_control` in BE-12 wiring). It will not fire on Haiku for short prompts (4,096-token floor). The primary cost lever is the Redis + `AiResponseCache` hit (zero AI tokens).
- **Parallelizable with P3-05:** P3-04 and P3-05 share the same pipeline, DI registrations, and the unified `AiResponseCache` repository.
- **Security-auditor is a hard gate** for this story (AI text shown to children). Audit covers: no-bypass under buffered-stream, prompt-injection via context/question, child-data minimization, no secret leakage, rate limits, quota enforcement correctness, **scope guard is enforced (refuse-and-redirect when no context, no out-of-scope explain reaches the LLM)**, and that `PendingReview` entries are NOT served as cache hits to other students.
- **Wire format — pinned contract (pin in HANDOFF.md before P3-12 FE dispatch):** `event: message` + `data: {"content":"<token>"}` (content chunks); `event: redirect` + `data: {"type":"lesson","targetId":"<skillId>"}` (no-context redirect); `event: error` + `data: {"code":"<ErrorCode>","message":"<safe message>"}` (failures); `event: done` + `data: [DONE]` (stream terminator). Provider output is **buffered → safety-filtered → only then streamed** as `event: message`. Never raw-passthrough unfiltered tokens to a child.
- **Cost routing:** runtime `Explain` calls use `claude-sonnet-4-6` (NOT Opus). The pre-generation job uses `claude-sonnet-4-6` (generation) and `claude-opus-4-8` (QA). Measure real prompts with `count_tokens` (model: `claude-haiku-4-5`) before locking pricing. Always verify current Anthropic model IDs before launch.
- **Cross-reference:** `docs/briefs/ai-cost-routing.md` governs all model-routing, cache (primary Redis lever + secondary Anthropic prompt-caching), quota, and Batch API decisions. `docs/briefs/ai-helper-mvp.md` governs the intent model, `ILearningContextProvider` seam, refuse-and-redirect rule, and closed-loop instrumentation.
