## Lead decisions required before dispatch

| # | Question | Recommendation |
|---|---|---|
| OQ-1 | Embedding model + dimension N (baked into schema): BGE-M3 (1024-d) vs OpenAI `text-embedding-3-small` (1536-d)? | Pin to whatever P3-01 AI Gateway standardizes |
| OQ-2 | Distance metric: cosine vs L2? | **Cosine** (`vector_cosine_ops`, `<=>`) — standard for normalized embeddings |
| OQ-3 | Embed query text via P3-01 AI Gateway or a direct typed HttpClient? | Route through AI Gateway (cross-cluster dep on P3-01) |
| OQ-4 | Vector index type: HNSW vs IVFFlat? | **HNSW** for seeded corpus; flag for tuning at BL-05 scale |
| OQ-5 | Internal service seam vs HTTP endpoint? | Internal service; optional dev-only HTTP endpoint for api-tester |
| OQ-6 | New `Curriculum` module vs fold into `Learning`? | **New module** (SRS/architecture explicit) — requires lead approval per CLAUDE.md ask-before-new-modules |
| OQ-7 | Similarity floor/threshold for "no relevant context"? | Empirically calibrated against the seeded corpus; must be non-zero to make empty-retrieval signal real |
| OQ-8 | Seed corpus source: hand-authored demo text or real curriculum samples from `info/`? | Thin representative slice per subject/grade; confirm scope |

## Acceptance-criteria coverage

- AC-1 (schema + extension): `CurriculumChunk` entity with `Embedding: vector(N)`, migration enables `CREATE EXTENSION IF NOT EXISTS vector`, applies against pgvector/pg17 → **BE-3, BE-4, BE-5**
