## Backend tasks
| ID | Task | Artifact | Deps | Est (h) |
|---|---|---|---|---|
| P1-02-BE-1 | Verify/adapt **`POST /api/Users/Authentication/Refresh-Token`** to issue a new access token from a valid refresh token (reuse `UserRefreshTokens`) | existing endpoint | P1-06-BE-* | 3 |
| P1-02-BE-2 | Verify/adapt **`POST /api/Users/Authentication/Sign-Out`** to invalidate the session in Redis (`SessionManagementService`) | existing endpoint | P1-06-BE-* | 2 |
| P1-02-BE-3 | Ensure expired/revoked refresh tokens return 401; confirm token policy (30-min access / 7-day refresh) | `AuthenticationService`, `JwtSettings` | P1-02-BE-1 | 2 |

## Acceptance-criteria coverage
- Refresh on expiry → new access token → **BE-1**
- Sign-out invalidates refresh token (Redis) → **BE-2**
- Expired/revoked refresh → 401 → **BE-3**

## Contract for Frontend (P1-02-FE)
- `Refresh-Token` accepts the refresh token, returns a new `JwtAuthResponse`. `Sign-Out` requires the access token (`[Authorize]`).

## Notes
- These endpoints **already exist** in the Identity module (architecture.md §4.1, §7.2). Work = verification + Npgsql/Redis wiring. Blocked by P1-06-BE.
