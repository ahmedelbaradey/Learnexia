## Acceptance-criteria coverage
- Quiz CRUD with ordered questions → **BE-1, BE-2**
- Add question, pick 1 of 4 types, enforce shape → **BE-3**
- Reject invalid per-type shape with clear error → **BE-3**
- Attach quiz to lesson/skill (Shared.Contracts, no FK) → **BE-4**
- Edit/remove question, order updates → **BE-2, BE-5**
- Admin-only access → **BE-1** (policy across controllers)

## Contract for Frontend (P7-04-FE)
- `GET /api/Assessment/Quizzes` → `BaseResponse<List<QuizDto>>`; `GET .../Quizzes/{id}` includes ordered `questions[]` (type, text, options, correctAnswer).
- `POST/PUT/DELETE /api/Assessment/Quizzes` and `.../Quizzes/{id}/Questions` → `BaseResponse<Guid>` / `BaseResponse<bool>`. Invalid per-type shape → `Successed=false` + message.
- `POST /api/Assessment/Quizzes/{id}/Attach` (lessonId | skillId) → `BaseResponse<bool>`.
- `PUT /api/Assessment/Quizzes/{id}/Questions/Reorder` → `BaseResponse<bool>`. All admin-only.

## Notes
- Quizzes/questions live in the **`assessment`** module; the lesson/skill association crosses to `learning` and so goes through `Shared.Contracts` only — **no cross-module FK**.
- Reuse the P2-06 4-type model + discriminator; mirror Catalog; `Successed`, `NewResult(...)`, `ILoggerManager`.
