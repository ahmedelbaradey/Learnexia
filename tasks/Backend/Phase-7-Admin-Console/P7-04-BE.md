## Acceptance-criteria coverage
- Quiz CRUD with ordered questions → **BE-1, BE-2**
- Add question, pick 1 of 4 types, enforce shape → **BE-3**
- Reject invalid per-type shape with clear error → **BE-3**
- Attach quiz to lesson/skill (intra-`Learning` association) → **BE-4**
- Edit/remove question, order updates → **BE-2, BE-5**
- Admin-only access → **BE-1** (policy across controllers)

## Contract for Frontend (P7-04-FE)
- `GET /api/Learning/Quizzes` → `BaseResponse<List<QuizDto>>`; `GET .../Quizzes/{id}` includes ordered `questions[]` (type, text, options, correctAnswer).
- `POST/PUT/DELETE /api/Learning/Quizzes` and `.../Quizzes/{id}/Questions` → `BaseResponse<Guid>` / `BaseResponse<bool>`. Invalid per-type shape → `Successed=false` + message.
- `POST /api/Learning/Quizzes/{id}/Attach` (lessonId | skillId) → `BaseResponse<bool>`.
- `PUT /api/Learning/Quizzes/{id}/Questions/Reorder` → `BaseResponse<bool>`. All admin-only.

## Notes
- Quizzes/questions live in the **`Learning`** module (P2-06 entities) — there is no `assessment` module in this codebase. The lesson/skill association is therefore **intra-module** (FK allowed within `Learning`); `Shared.Contracts` is not required here.
- Reuse the P2-06 4-type model + discriminator; mirror **Learning**; `Successed`, `NewResult(...)`, `ILoggerManager`.
- **Module isolation:** no cross-module FK (within-module FK to Lesson/Skill in `Learning` is fine); any cross-module data flows via `Shared.Contracts` only.
- **Policy:** `AuthorizationPolicies.AdminOnly` for now; promoting to granular `{Module}.{Action}` policies (via `Claims.GenerateModules()`) is a follow-up if the lead wants finer-grained authz.
