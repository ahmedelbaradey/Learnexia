## Acceptance-criteria coverage
- Every admin action writes actor/action/target/time/before-after → **BE-1, BE-3**
- Append-only & immutable; no edit/delete path → **BE-2, BE-3, BE-6**
- Paginated, searchable/filterable by actor/action/target/date → **BE-4**
- Export filtered log (CSV/JSON) → **BE-5**
- Admin-only read; non-admin → 403; view-only → **BE-6**
- Written by domain/integration events, not direct writes; from `FullAuditedEntity` → **BE-1, BE-3**

## Contract for Frontend (P7-12-FE)
- `GET /api/Audit/Log?actor=&actionType=&target=&dateFrom=&dateTo=&page=&pageSize=` → `BaseResponse<PagedResult<AuditLogDto>>` (`{ id, actor, actionType, target, occurredAt, before, after }`).
- `GET /api/Audit/Log/Export?<same filters>&format=csv|json` → file stream.
- No mutation endpoints — the log is read-only. Success flag spelled `Successed`.

## Notes
- Immutability is the core invariant: enforce at the DB layer (insert-only) and ensure no command/handler can mutate or delete entries. The handler reacts to `AdminActionPerformedEvent` emitted by admin actions (e.g. P7-09-BE-7) — callers never write the log directly.
- Before/after snapshots must avoid leaking sensitive child data beyond what accountability requires.
