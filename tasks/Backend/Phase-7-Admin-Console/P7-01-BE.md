# P7-01 (Backend) — Manage subjects & units

> Story: [../../../user-stories/Phase-7-Admin-Console/P7-01-manage-subjects-and-units.md](../../../user-stories/Phase-7-Admin-Console/P7-01-manage-subjects-and-units.md)
> Phase 7 — Admin Console · Epic: Admin — Curriculum Management · SP: 5 · SRS §3, FR-ADM-1 · Est. unit: hours
> Stack: .NET 10 `Learning` module, CQRS/MediatR, FluentValidation, Npgsql.

> **Reality check (harden + extend, not greenfield):** Existing Learning controllers (`SubjectsController` / `UnitsController`) already expose `Create` / `Update` / `Delete` endpoints, but they are currently **anonymous (live auth hole — see `docs/briefs/phase-7-admin-gap-analysis.md`)**, and `Subject` / `Unit` are missing the `SequenceOrder` + `IsActive` fields this story assumes. This story = add `[Authorize(AdminOnly)]` on the existing Create/Update/Delete + extend fields/commands where needed; **NOT greenfield.**

> **Phase 8 localization (merged to main):** `Subject` now carries `SubjectCode` (MATH/SCIENCE/ARABIC/ENGLISH) + `Language` (`ContentLanguage` Ar/En) with a UNIQUE `(GradeId, SubjectCode, Language)` constraint — **6 subject roots per grade** (4 codes, with Math & Science duplicated per language → the Ar/En split). Subject CRUD must set/respect both `SubjectCode` and `Language` and honour the unique key. Child entities (units/lessons/quizzes) inherit language from the owning Subject — there is **no language column below Subject**. Language-coverage (which `(code, language)` trees exist per grade) is folded into this story (BE-7).

## Acceptance-criteria coverage
- List subjects with grade/order/active (+ code/language) → **BE-1, BE-3, BE-7**
- CRUD units under a subject → **BE-2**
- Drag-reorder persists `SequenceOrder` → **BE-3, BE-4**
- Activate/deactivate, inactive hidden but preserved (delete = deactivate) → **BE-5**
- Reject delete of non-empty unit → **BE-6**
- Subject carries `SubjectCode` + `Language`; unique `(GradeId,SubjectCode,Language)` enforced → **BE-7**
- Per-grade language-coverage (which `(code,language)` trees exist) → **BE-8**
- Admin-only access → **BE-1, BE-2** (`AdminOnly` policy on existing controllers)

## Contract for Frontend (P7-01-FE)
- `GET /api/Learning/Subjects` → `BaseResponse<List<SubjectDto>>` (id, name, grade, subjectCode, language, sequenceOrder, isActive).
- `GET /api/Learning/Subjects/{id}/Units` → `BaseResponse<List<UnitDto>>`.
- `POST/PUT/DELETE /api/Learning/Subjects` and `.../Units` → `BaseResponse<Guid>` / `BaseResponse<bool>`. Create/Update carry `subjectCode` + `language`; duplicate `(grade,code,language)` → `Successed=false`.
- `GET /api/Learning/Subjects/Coverage?gradeId=` → `BaseResponse<SubjectLanguageCoverageDto>` (per `(code,language)` exists/missing vs the 6 expected roots).
- `PUT /api/Learning/Subjects/Reorder` (and `.../Units/Reorder`) accepts ordered id list → `BaseResponse<bool>`.
- `PUT /api/Learning/Units/{id}/Active` → `BaseResponse<bool>`. All admin-only.

## Notes
- Mirror the **Learning** reference module for command/query/controller shapes. `Successed` flag, `NewResult(...)`, `ILoggerManager`.
- **Localization (Phase 8, merged):** the 4 product subjects are now keyed by `SubjectCode` (MATH/SCIENCE/ARABIC/ENGLISH); each grade has **6 subject roots** because Math & Science exist per `Language` (Ar/En). UNIQUE `(GradeId, SubjectCode, Language)`. Children inherit language — **no language column below Subject**. Reuse the `ContentLanguage` enum (Learning Domain) and the existing `SubjectLanguageResolver` (Learning Domain/Services) rather than re-deriving language on reads.
- The 4 subjects are fixed by product decision — admins curate/grade-scope, not invent new top-level subjects.
- **Module isolation:** no cross-module FK; any cross-module data flows via `Shared.Contracts` only.
- **Policy:** `AuthorizationPolicies.AdminOnly` for now; promoting to granular `{Module}.{Action}` policies (via `Claims.GenerateModules()`) is a follow-up if the lead wants finer-grained authz.
