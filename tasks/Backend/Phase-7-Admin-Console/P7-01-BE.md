## Acceptance-criteria coverage
- List subjects with grade/order/active → **BE-1**
- CRUD units under a subject → **BE-2**
- Drag-reorder persists `SequenceOrder` → **BE-3**
- Activate/deactivate, inactive hidden but preserved → **BE-4**
- Reject delete of non-empty unit → **BE-5**
- Admin-only access → **BE-1** (policy applied across the controllers)

## Contract for Frontend (P7-01-FE)
- `GET /api/Learning/Subjects` → `BaseResponse<List<SubjectDto>>` (id, name, grade, sequenceOrder, isActive).
- `GET /api/Learning/Subjects/{id}/Units` → `BaseResponse<List<UnitDto>>`.
- `POST/PUT/DELETE /api/Learning/Subjects` and `.../Units` → `BaseResponse<Guid>` / `BaseResponse<bool>`.
- `PUT /api/Learning/Subjects/Reorder` (and `.../Units/Reorder`) accepts ordered id list → `BaseResponse<bool>`.
- `PUT /api/Learning/Units/{id}/Active` → `BaseResponse<bool>`. All admin-only.
