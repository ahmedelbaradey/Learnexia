## Acceptance-criteria coverage
- KPI cards (active users/retention/completions/engagement) over a range → **BE-2**
- Charts/trends + date-range + subject/grade breakdown → **BE-3**
- Aggregates only, no child PII, via read-model → **BE-1**
- Fast summary query, cached, no latency hit (NFR-1) → **BE-4**
- Admin-only access (non-admin 403) → **BE-5**
- Cross-module aggregated via contracts, no FK joins → **BE-1**

## Contract for Frontend (P7-10-FE)
- `GET /api/Admin/Analytics/kpis?from=&to=&subject=&grade=` → `BaseResponse<PlatformKpiSummaryDto>` (DAU/WAU/MAU, retention, lessonsCompleted, quizzesCompleted, avgSessionDuration, missionsCompleted).
- `GET /api/Admin/Analytics/trend?metric=&from=&to=&groupBy=` → `BaseResponse<KpiTrendDto>` (series of `{ bucket, value }`, optional per-subject/grade breakdown).
- All gated by the admin policy; `Successed` flag per envelope. Aggregates only — no per-child PII in these payloads.

## Notes
- Read/aggregate-only — no new write entities beyond the optional cached aggregate. Consumes P5-03 analytics events through a reporting read-model; cross-module metrics arrive via `Shared.Contracts` integration seams, never direct cross-module FK joins. Queries are not auto-validated (ValidationBehavior is `ICommand<>` only) — validate date-range/paging/breakdown inputs in the handler. This is the admin-facing complement to the operator KPI view in P6-05.
