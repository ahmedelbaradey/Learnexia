## Backend tasks
> **Approach (two options — lead decides):**
> 1. A new lightweight **`Analytics`** module subscribing to `Shared.Contracts` analytics events and maintaining a read-model.
> 2. Each producing module (Learning, Identity, Gamification, …) exposes admin-only summary endpoints that this dashboard aggregates client-side / via a thin façade.
> Either way: **no joins across module schemas**. Cross-module data flows via `Shared.Contracts` events only.

> **Dependency note:** P5-03 (analytics events backbone) is **not yet built**. P7-10 ships a thin slice that degrades gracefully (KPI cards return zero/empty) until P5-03 producers exist.

## Acceptance-criteria coverage
- KPI cards (active users/retention/completions/engagement) over a range → **BE-2**
- Charts/trends + date-range + subject/grade breakdown → **BE-3**
- Language (ar/en) breakdown dimension on KPIs/trends → **BE-6**
- Aggregates only, no child PII, via read-model → **BE-1**
- Fast summary query, cached, no latency hit (NFR-1) → **BE-4**
- Admin-only access (non-admin 403) → **BE-5**
- Cross-module aggregated via contracts, no FK joins → **BE-1**

## Contract for Frontend (P7-10-FE)
- `GET /api/Admin/Analytics/kpis?from=&to=&subject=&grade=&language=` → `BaseResponse<PlatformKpiSummaryDto>` (DAU/WAU/MAU, retention, lessonsCompleted, quizzesCompleted, avgSessionDuration, missionsCompleted).
- `GET /api/Admin/Analytics/trend?metric=&from=&to=&groupBy=` → `BaseResponse<KpiTrendDto>` (series of `{ bucket, value }`, optional per-subject/grade/language breakdown; `groupBy=language` → ar/en series).
- All gated by the admin policy; `Successed` flag per envelope. Aggregates only — no per-child PII in these payloads.

## Notes
- **Localization (Phase 8, merged):** content now splits Ar/En (`ContentLanguage`); add a **language dimension** to the aggregations so admins compare Ar vs En. Keep it aggregate-only and contract-sourced — language arrives on the analytics events, not via a cross-module join. No per-child PII.
- Read/aggregate-only — no new write entities beyond the optional cached aggregate. Consumes P5-03 analytics events through a reporting read-model; cross-module metrics arrive via `Shared.Contracts` integration seams, **never direct cross-module FK joins and never joins across module schemas**. Queries are not auto-validated (ValidationBehavior is `ICommand<>` only) — validate date-range/paging/breakdown inputs in the handler. This is the admin-facing complement to the operator KPI view in P6-05.
- **Dependency:** P5-03 (analytics events backbone) is **not yet built** — P7-10 ships a thin slice that degrades gracefully until P5-03 producers exist.
- **Approach:** lead to decide between (a) a new lightweight `Analytics` module that subscribes to events vs (b) per-module admin summary endpoints aggregated via a thin façade — both options preserve module isolation.
- Mirror the **Learning** module shape (not Catalog — Catalog was removed 2026-06-03, PR #84).
- **Policy:** `AuthorizationPolicies.AdminOnly` for now; promoting to granular `{Module}.{Action}` policies (via `Claims.GenerateModules()`) is a follow-up if the lead wants finer-grained authz.
