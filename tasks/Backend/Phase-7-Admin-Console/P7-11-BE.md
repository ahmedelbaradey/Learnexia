## Acceptance-criteria coverage
- Safety signal aggregates (blocked/flagged by reason/subject/language) over a range → **BE-2**
- Eval pass/fail rate per run + trend + threshold breach indicator → **BE-3**
- Tutor usage & cost (volume, tokens/cost, latency) by subject/grade → **BE-4**
- Drill-in list of recent blocked/flagged outputs, minimal PII → **BE-5**
- Aggregates via read-model, cross-module via contracts, cached, no latency hit → **BE-1, BE-6**
- Admin-only access (non-admin 403) → **BE-6**

## Contract for Frontend (P7-11-FE)
- `GET /api/Admin/AiSafety/signals?from=&to=&subject=&language=` → `BaseResponse<SafetySignalSummaryDto>` (totalOutputs, blockedCount/rate, flaggedCount/rate, breakdownByReason[]).
- `GET /api/Admin/AiSafety/evals?from=&to=` → `BaseResponse<EvalResultsDto>` (runs[] of `{ runId, passRate, failRate, threshold, breached, ranAt }`).
- `GET /api/Admin/AiSafety/usage?from=&to=&subject=&grade=` → `BaseResponse<TutorUsageDto>` (requestVolume, tokenCostSeries[], avgLatency).
- `GET /api/Admin/AiSafety/flagged?from=&to=&page=&pageSize=` → `BaseResponse<PagedResult<FlaggedOutputDto>>` (contentRef, verdict, reason, occurredAt).
- All gated by the admin policy; `Successed` flag per envelope. Surface only minimum safety data — no unnecessary child PII.

## Notes
- Read/aggregate-only — no new write entities beyond the optional cached aggregate. Consumes P3-02 safety verdicts, P6-02 eval results, and AI Gateway usage through a reporting read-model; cross-module data arrives via `Shared.Contracts` integration seams, never direct cross-module FK joins. Queries are not auto-validated (ValidationBehavior is `ICommand<>` only) — validate range/paging inputs in the handler. Child-safety sensitive: drill-in shows only what the admin needs to assess safety.
