# P7-05 (Backend) — Publish, version & preview curriculum content

> Story: [../../../user-stories/Phase-7-Admin-Console/P7-05-publish-version-preview-curriculum.md](../../../user-stories/Phase-7-Admin-Console/P7-05-publish-version-preview-curriculum.md)
> Phase 7 — Admin Console · Epic: Admin — Curriculum Management · SP: 8 · SRS §3, FR-ADM-4 · Est. unit: hours
> Stack: .NET 10 `Learning` module (covers both curriculum hierarchy and quizzes — there is no `assessment` module), CQRS/MediatR, FluentValidation, Npgsql.

> **Reality check (harden + extend, not greenfield):** Existing Learning controllers expose Create/Update/Delete but they are currently **anonymous (live auth hole — see `docs/briefs/phase-7-admin-gap-analysis.md`)**. This story adds the draft/published lifecycle on top of those entities — secure them via `[Authorize(AdminOnly)]` (covered by P7-01..P7-04) before exposing the publish/rollback endpoints.

## Acceptance-criteria coverage
- Edits accumulate as draft, not served to students → **BE-1, BE-4**
- Publish records a versioned snapshot (timestamp/author) → **BE-2, BE-3**
- Live vs pending-draft distinguishable → **BE-4**
- Preview draft as student without publishing → **BE-5**
- Revert/rollback restores previous published version → **BE-6**
- Admin-only access → **BE-5** (policy across publish/preview/rollback)

## Contract for Frontend (P7-05-FE)
- `GET /api/Learning/{type}/{id}?view=admin` → `BaseResponse<...>` with `liveVersion` + `draft` distinguished; `view=student` → latest published only.
- `POST /api/Learning/{type}/{id}/Publish` → `BaseResponse<int>` (new version no.).
- `GET /api/Learning/{type}/{id}/Preview` → `BaseResponse<...>` (student-rendered draft).
- `POST /api/Learning/{type}/{id}/Rollback` → `BaseResponse<int>`. `{type}` covers subject/unit/lesson/quiz — all under the `Learning` module. All admin-only.

## Notes
- Lifecycle + version rows live entirely in the `Learning` module (covers subject/unit/lesson/quiz — there is no separate `assessment` module). Publish/rollback are atomic multi-writes via an explicit transaction (no Unit of Work).
- Mirror **Learning**; `Successed`, `NewResult(...)`, `ILoggerManager`.
- **Storage:** preview/media references stay behind `Shared.Kernel.Storage.IStorageService`; no module-local MinIO.
- **Module isolation:** no cross-module FK; any cross-module data flows via `Shared.Contracts` only.
- **Policy:** `AuthorizationPolicies.AdminOnly` for now; promoting to granular `{Module}.{Action}` policies (via `Claims.GenerateModules()`) is a follow-up if the lead wants finer-grained authz.
