## Acceptance-criteria coverage
- Edit language/country → **BE-1**
- Grade override + curriculum re-scope → **BE-3, BE-4**
- History preserved (XP/badges/streaks/mastery) via event → **BE-2, BE-4**
- Reject invalid grade / unsupported language/country → **BE-1, BE-3**
- Old→new + actor + reason recorded + audited → **BE-5**
- Admin-only access (non-admin 403) → **BE-5**

## Contract for Frontend (P7-08-FE)
- `PATCH /api/Admin/Users/{childId}/profile` `{ language?, country? }` → `BaseResponse<AdminUserProfileDto>`.
- `POST /api/Admin/Users/{childId}/grade` `{ grade, reason, confirm }` → `BaseResponse<AdminUserProfileDto>`.
- Both gated by the admin policy; commands validated (ValidationBehavior on `ICommand<>`); `Successed` flag per envelope.

## Notes
- Reuses the **Identity** module — `UserManagementController` (already AdminOnly) is extended (NOT greenfield). Mirror the **Identity / Learning** module shape (not Catalog — Catalog was removed 2026-06-03, PR #84).
- **P5-06 dependency:** P5-06 (parent-driven grade transition) has not been built yet. P7-08 **introduces** the `ChildGradeChanged` contract in `Shared.Contracts` so when P5-06 lands it consumes the same seam. Grade override preserves XP/badges/streaks/mastery history via the event (no cross-module FK/write from Identity). No teacher role.
- **Policy:** `AuthorizationPolicies.AdminOnly` for now; promoting to granular `{Module}.{Action}` policies (via `Claims.GenerateModules()`) is a follow-up if the lead wants finer-grained authz.
