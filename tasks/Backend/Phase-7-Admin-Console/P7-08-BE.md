## Contract for Frontend (P7-08-FE)
- `PATCH /api/Admin/Users/{childId}/profile` `{ preferredLanguage?, country? }` → `BaseResponse<AdminUserProfileDto>` (UI/locale only — **not** the learning language).
- `POST /api/Admin/Users/{childId}/grade` `{ grade, reason, confirm }` → `BaseResponse<AdminUserProfileDto>`.
- `POST /api/Admin/Users/{childId}/learning-language` `{ learningLanguage, confirm }` → `BaseResponse<AdminUserProfileDto>`; **unconfirmed → HTTP 424** (switching hard-deletes Math/Science attempts); re-issues the `learning_language` claim.
- All gated by the admin policy; commands validated (ValidationBehavior on `ICommand<>`); `Successed` flag per envelope.

## Notes
- **Learning-language change (Phase 8, merged) — LOCKED DECISION: admin CAN change it.** Reuse the **existing** `IChildAccountService.ChangeLearningLanguageAsync` seam (the same one the parent flow P8-04 uses) — do **not** write `User.LearningLanguage` directly. The switch is **confirm-gated** (`424` when not confirmed, because it hard-deletes the child's Math/Science attempts for a fresh start), re-stamps the `learning_language` JWT claim, and publishes `LearningLanguageChangedIntegrationEvent`; the same downstream Learning/Gamification handlers apply the fresh-start side effects. This keeps two languages cleanly separate: `PreferredLanguage` (UI/locale, edited via the profile PATCH) vs `LearningLanguage` (content Ar/En, this dedicated command). Admin/family-scope authz + audit are mandatory.
- Reuses the **Identity** module — `UserManagementController` (already AdminOnly) is extended (NOT greenfield). Mirror the **Identity / Learning** module shape (not Catalog — Catalog was removed 2026-06-03, PR #84).
- **P5-06 dependency:** P5-06 (parent-driven grade transition) has not been built yet. P7-08 **introduces** the `ChildGradeChanged` contract in `Shared.Contracts` so when P5-06 lands it consumes the same seam. Grade override preserves XP/badges/streaks/mastery history via the event (no cross-module FK/write from Identity). No teacher role.
- **Policy:** `AuthorizationPolicies.AdminOnly` for now; promoting to granular `{Module}.{Action}` policies (via `Claims.GenerateModules()`) is a follow-up if the lead wants finer-grained authz.
