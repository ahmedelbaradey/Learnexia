## Acceptance-criteria coverage
- Edit language/country → **BE-1**
- Grade override + curriculum re-scope → **BE-2, BE-3**
- History preserved (XP/badges/streaks/mastery) via event → **BE-3**
- Reject invalid grade / unsupported language/country → **BE-1, BE-2**
- Old→new + actor + reason recorded + audited → **BE-4**
- Admin-only access (non-admin 403) → **BE-4**

## Contract for Frontend (P7-08-FE)
- `PATCH /api/Admin/Users/{childId}/profile` `{ language?, country? }` → `BaseResponse<AdminUserProfileDto>`.
- `POST /api/Admin/Users/{childId}/grade` `{ grade, reason, confirm }` → `BaseResponse<AdminUserProfileDto>`.
- Both gated by the admin policy; commands validated (ValidationBehavior on `ICommand<>`); `Successed` flag per envelope.

## Notes
- Reuses the **Identity** module. Grade override **preserves history** by re-using the same `ChildGradeChanged` contract as the parent-driven transition (P5-06) — re-scoping happens in the learning/gamification modules via the event, never via cross-module FK/write from Identity. No teacher role.
