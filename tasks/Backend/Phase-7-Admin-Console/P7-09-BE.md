## Acceptance-criteria coverage
- Paginated queue with source/submitter/ref/status → **BE-1, BE-4**
- Open item + automated signal, then approve/reject(reason)/flag → **BE-5, BE-6**
- Action transitions status + records admin/time/reason + emits audit event → **BE-6, BE-7**
- Filter by status/source/subject/grade/date + search → **BE-4**
- Admin-only; non-admin → 403 → **BE-8**
- Items via contracts, no cross-module FK; record from `FullAuditedEntity` → **BE-1, BE-3**

## Contract for Frontend (P7-09-FE)
- `GET /api/Moderation/Queue?status=&source=&subject=&grade=&dateFrom=&dateTo=&search=&page=&pageSize=` → `BaseResponse<PagedResult<ModerationItemDto>>` (`{ id, source, contentRef, submittedBy, status, safetyVerdict, createdAt }`).
- `GET /api/Moderation/{id}` → `BaseResponse<ModerationItemDetailDto>` (adds content preview + full safety verdict).
- `POST /api/Moderation/{id}/Review` `{ decision: 'Approve'|'Reject'|'Flag', reason? }` → `BaseResponse<ModerationItemDto>`; reason required for Reject. Success flag spelled `Successed`.

## Notes
- New `Moderation` module mirrors Catalog; queue + log queries paginate. Moderation is human-in-the-loop **on top of** the automated P3-02 Safety Layer — it does not replace it.
- Cross-module data comes from `Shared.Contracts` events only; never reference another module's projects or add FKs across modules.
