## Contract for Frontend (P7-03-FE)
- `GET /api/Learning/Skills/Graph?subjectId=&language=` → `BaseResponse<SkillGraphDto>` (nodes[], edges[] with source/target/type/strength); single-language tree.
- `GET /api/Learning/Skills/{id}/Prerequisites` and `.../UnlockedBy` → `BaseResponse<List<SkillDto>>`.
- `POST/PUT/DELETE /api/Learning/Skills` → `BaseResponse<Guid>` / `BaseResponse<bool>`.
- `POST /api/Learning/Skills/Edges` (source, target, type, strength) → `BaseResponse<Guid>`; `DELETE .../Edges/{id}` → `BaseResponse<bool>`. Cycle **or** cross-language edge → `Successed=false` with message. All admin-only.

## Notes
- This is the admin write path over the P2-11 hand-authored graph — reuse its `KnowledgeNode`/`KnowledgeEdge`, `SkillGraphValidator`, and prereq/unlock queries; do not duplicate them.
- **Localization (Phase 8, merged):** the skill graph is **per-language** — a node's language is inherited from its owning Subject tree (resolve via `SubjectLanguageResolver`). Edges may only connect nodes of the **same** `ContentLanguage` (no Ar↔En prerequisites); graph reads are scoped to one language at a time. There is no language column on `KnowledgeNode`/`KnowledgeEdge` — derive it.
- Mirror **Learning**; `Successed`, `NewResult(...)`, `ILoggerManager`. OCR pipeline (BL-01..05) out of scope.
- **Open design-pattern gate:** the visual graph-editor approach (state machine / strategy / observer for node-edge interactions) is still open per the P7-admin-console pipeline brief — design-pattern decisions wait for lead approval before implementation (per CLAUDE.md rule 8).
- **Module isolation:** no cross-module FK; any cross-module data flows via `Shared.Contracts` only.
- **Policy:** `AuthorizationPolicies.AdminOnly` for now; promoting to granular `{Module}.{Action}` policies (via `Claims.GenerateModules()`) is a follow-up if the lead wants finer-grained authz.
