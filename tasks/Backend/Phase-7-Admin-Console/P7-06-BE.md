## Contract for Frontend (P7-06-FE)
- `GET /api/Admin/Users?role=&status=&q=&page=&pageSize=` → `BaseResponse<PagedResult<AdminUserListItemDto>>`.
- `GET /api/Admin/Users/{id}` → `BaseResponse<AdminUserProfileDto>` (children include both `preferredLanguage` and `learningLanguage`).
- `GET /api/Admin/Users/{id}/family` → `BaseResponse<FamilyDto>` (children[] for parent, parents[] for child).
- `GET /api/Admin/Users/{id}/activity` → `BaseResponse<ActivitySummaryDto>`. All gated by the admin policy; `Successed` flag per envelope.

## Notes
- **Localization (Phase 8, merged):** a child now has two distinct language fields — `PreferredLanguage` (UI/locale preference) and `LearningLanguage` (`User.LearningLanguage`, the content language Ar/En that scopes Math/Science). Admin read projections must surface **both** so operators don't conflate them; the learning language is also carried in the `learning_language` JWT claim. Changing the learning language is **not** a profile edit — see P7-08.
- Reuses the **Identity** module — Identity already exposes a `UserManagementController` gated by `AdminOnly`; this story extends it (NOT greenfield). Mirror the **Identity / Learning** module shape (not Catalog — Catalog was removed 2026-06-03, PR #84).
- List queries are paginated (per conventions). Activity crosses modules → consumed via `Shared.Contracts` integration seams only, never direct FK. Queries are not auto-validated (ValidationBehavior is `ICommand<>` only) — validate paging/filter inputs in the handler.
- **Policy:** `AuthorizationPolicies.AdminOnly` for now; promoting to granular `{Module}.{Action}` policies (via `Claims.GenerateModules()`) is a follow-up if the lead wants finer-grained authz.
