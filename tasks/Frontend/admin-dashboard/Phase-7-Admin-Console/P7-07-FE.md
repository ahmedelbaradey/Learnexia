## Contract from Backend (P7-07-BE)
- `POST /api/Admin/Users/{id}/suspend` `{ reason }` → `BaseResponse<AdminUserProfileDto>`.
- `POST /api/Admin/Users/{id}/reactivate` `{ reason? }` → `BaseResponse<AdminUserProfileDto>`.
- `DELETE /api/Admin/Users/{id}` `{ reason, confirm, cascadeChildren? }` → `BaseResponse<bool>`.

## Notes
- **Suspend ≠ lockout:** admin **Suspend** is a deliberate governance state on `AccountStatus` (revokes existing sessions/tokens, blocks sign-in until reactivated) and is distinct from the **P1-13 failed-login lockout**, which is automatic, temporary, and not surfaced here. The UI copy must not conflate the two.
- All destructive actions require explicit confirmation; child accounts get extra warning copy (child-privacy). Errors (e.g. already-deleted) come back via the `BaseResponse` envelope (`Successed` flag + message) and are shown inline. Reuses shared packages; RTL/Arabic + English per project i18n.
