## Acceptance-criteria coverage
- Safety signal aggregates by reason/subject/language over a range → **FE-3** (+ FE-7)
- Eval pass/fail rate + trend + threshold-breach indicator → **FE-4**
- Tutor usage & cost by subject/grade → **FE-5**
- Drill-in list of recent blocked/flagged outputs, minimal PII → **FE-6**
- Aggregates only via read-model endpoints, cached → consumes aggregate endpoints (**FE-2**, + P7-11-BE)
- Admin-only access (non-admin redirect) → **FE-1**

## Contract from Backend (P7-11-BE)
- `GET /api/Admin/AiSafety/signals?from=&to=&subject=&language=` → `BaseResponse<SafetySignalSummaryDto>`.
- `GET /api/Admin/AiSafety/evals?from=&to=` → `BaseResponse<EvalResultsDto>` (runs[] with passRate/failRate/threshold/breached).
- `GET /api/Admin/AiSafety/usage?from=&to=&subject=&grade=` → `BaseResponse<TutorUsageDto>`.
- `GET /api/Admin/AiSafety/flagged?from=&to=&page=&pageSize=` → `BaseResponse<PagedResult<FlaggedOutputDto>>`. All admin-gated; read `Successed` from the envelope.

## Notes
- Built on the P1-10 admin shell; reuses shared packages for contract consistency. Read-only dashboard — no mutations. Charts are admin-facing (web). RTL/Arabic + English. Child-safety sensitive: the flagged-outputs drill-in shows only the minimum needed to assess safety — no unnecessary child PII.
