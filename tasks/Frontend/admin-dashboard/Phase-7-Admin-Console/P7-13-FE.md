## Contract from Backend (P7-13-BE)
- `POST /api/Admin/Gamification/children/{childId}/league-tier` `{ tier, reason, confirm }` → `BaseResponse<bool>`.
- `GET/POST/PUT/DELETE /api/Admin/Gamification/Badges[/{id}]` → `BaseResponse<List<BadgeDto>>` / `<Guid>` / `<bool>`.
- `GET/POST/PUT/DELETE /api/Admin/Gamification/Missions[/{id}]` → `BaseResponse<List<MissionDto>>` / `<Guid>` / `<bool>`.
- `GET/POST/PUT /api/Admin/Gamification/TimedEvents[/{id}]` + `.../{id}/activate` + `.../{id}/expire` → `BaseResponse<...>`.
- `POST /api/Admin/Gamification/children/{childId}/streak-freeze` `{ count, reason, confirm }` → `BaseResponse<bool>`.
- All admin-gated; invalid input / illegal state-transition → `Successed=false` + message.

## Notes
- These are **new write surfaces** on the Gamification module exposed through the admin console — child-affecting overrides (league tier, streak-freeze grant) require a reason + confirm and are sensitive (child data); catalog/timed-event edits are platform-config writes. All mutations go through `@learnexia/api-client` (NSwag) + TanStack Query and must invalidate the relevant caches. Every action is audited and shows up in the P7-12 audit log (new action types).
- Mirror the existing admin table/form/dialog shapes (P7-01/P7-07/P7-08); do not invent new abstractions. AdminOnly via `useAdminGuard` + middleware. TanStack Query v5 + Zustand v5; bilingual (react-i18next, ar/en) + RTL.
