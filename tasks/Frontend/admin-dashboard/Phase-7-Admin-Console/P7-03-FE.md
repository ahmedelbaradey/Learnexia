## Acceptance-criteria coverage
- Skill CRUD with threshold/time/owner → **FE-1**
- Graph scoped to a single `(subjectCode, language)` tree → **FE-2**
- Add prerequisite edge (same-language) → **FE-3**
- Cross-language edges prevented with clear message → **FE-4**
- Cycle rejected with clear error, no persist → **FE-4**
- List prerequisites-of / unlocked-by → **FE-5**
- Remove edge, graph re-renders → **FE-3**
- Admin-only access → guard + middleware (across pages)

## Contract from Backend (P7-03-BE)
- `GET /api/Learning/Skills/Graph?subjectId=` → `BaseResponse<SkillGraphDto>` (nodes[], edges[]).
- `GET .../Skills/{id}/Prerequisites` + `.../UnlockedBy` → `BaseResponse<List<SkillDto>>`.
- `POST/PUT/DELETE` Skills + `POST/DELETE .../Skills/Edges` → `BaseResponse<Guid>`/`<bool>`; cycle → `Successed=false` + message.

## Notes
- The skill graph is **per language tree**: skills belong to a subject's `(subjectCode, language)`, so the editor always works inside one tree and prerequisite edges must stay same-language (the parallel ar/en trees never link to each other). `Skills/Graph` is queried with that subject's id; identity/icons use `subjectCode`.
- Admin UI over the P2-11 hand-authored graph. Use a lightweight graph/canvas lib wrapped in a Tamagui-styled component; no new backend abstraction. TanStack Query v5 + Zustand v5; RTL/Arabic + English.
