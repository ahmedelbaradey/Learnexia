## Contract from Backend (P7-08-BE)
- `PATCH /api/Admin/Users/{childId}/profile` `{ preferredLanguage?, country? }` → `BaseResponse<AdminUserProfileDto>` (UI/communication language; applied directly).
- `POST /api/Admin/Users/{childId}/learning-language` `{ learningLanguage, confirm }` → `BaseResponse<AdminUserProfileDto>`; **hard-deletes Math & Science progress** — requires `confirm=true` or returns `Successed=false`.
- `POST /api/Admin/Users/{childId}/grade` `{ grade, reason, confirm }` → `BaseResponse<AdminUserProfileDto>`.

## Notes
- A child has **two** language fields: **PreferredLanguage** (UI/communication medium, changed freely) and **LearningLanguage** (the Math & Science learning medium). Per the locked decision, the admin **can** change LearningLanguage, but it is **confirm-gated**: changing it **hard-deletes the child's Math & Science progress**, so the UI must show an explicit **fresh-start warning** ("this resets the child's Math & Science progress, cannot be undone") and only call the BE with the confirm flag after explicit confirmation. (Arabic/English subject progress is unaffected since those are language-pinned.)
- Grade override mirrors the parent-driven transition (P5-06): the UI states clearly that curriculum re-scopes while XP/badges/streaks/mastery are preserved. Validation errors return via the `BaseResponse` envelope and show inline. Reuses shared packages; RTL/Arabic + English per project i18n.
