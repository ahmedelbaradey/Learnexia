## Contract from Backend (P10-15-BE)

- `GET /api/Billing/Seats/Status` → `{ successed, data: { paidActiveSeats, grace: { isActive, endsAt, reason } | null, children: [ { childId, name, seatState: "Active" | "NoSeatLocked" } ] } }`
- `POST /api/Billing/Seats/ChooseActive` body `{ childIds: number[] }` → `{ successed }`; rejects when `childIds.length > paidActiveSeats` (envelope error message).
- `POST /api/Billing/Seats/Reactivate` body `{ childId }` → `{ successed }`; fails when no free active seat.

## Notes

- **Parent-app surface only** — never render any seat/grace/locked UI on a child route; gate at the parent-only layout.
- **Locked ≠ deleted ≠ data loss** — copy must make clear the child keeps progress/XP/history/achievements and only AI help is paused. Avoid alarming wording.
- Seat counts, grace dates, and reasons come from the API (`useSeatStatus`) — **never hard-coded** in FE.
- Extends the **P10-05** Plan & billing surface and the existing parent child list; reuse existing card/badge/modal primitives. **Ask before any new design pattern** (CLAUDE.md rule 8).
- Hands off cleanly to sibling **P10-13/P10-14** seat/allocation UI (don't duplicate the allocation/redistribution controls — those are P10-14's surface).
