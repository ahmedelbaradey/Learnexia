## Scope note (for the frontend lead)

Two distinct surfaces:
1. **Parent area** — a pause/unpause toggle on the child card / per-child detail + a "Paused" badge in the child list. Parent-only; never visible on a child route.
2. **Child-facing blocked message** — shown in the student app when an AI Tutor call is declined because the child is paused. This is NOT a dedicated screen; it is the graceful error response rendered by the AI Tutor feature screen when the API returns the `ChildAccessPausedByParent` localized key. No parent controls on this surface.

The two states must look and read **distinctly differently** from the P10-15 NoSeat/Locked state — parents and children must be able to tell them apart at a glance.

## Contract from Backend (P10-18-BE)

- `GET /api/Billing/Children/{childId}/AccessStatus` → `{ successed: true, data: { childId, seatState: "Active" | "NoSeatLocked", parentPauseState: "Active" | "Paused", isAccessAllowed: bool } }`
- `POST /api/Billing/Children/{childId}/Pause` → `{ successed: true, data: { childId, parentPauseState: "Paused", changedAt } }`; idempotent (already Paused → successed: true, no-op).
- `POST /api/Billing/Children/{childId}/Unpause` → `{ successed: true, data: { childId, parentPauseState: "Active", changedAt } }`; idempotent (already Active → successed: true, no-op).
- AI Tutor endpoints (Explain / Hint / SimilarExample / Simplify) — when child is paused: `{ successed: false, message: "<localized ChildAccessPausedByParent key>" }` (NOT a 5xx; treated as a graceful decline by the error handler).
- Cross-account / IDOR rejection: `{ successed: false, message: "<localized ChildNotOwnedByParent key>" }` (parent can only act on own children; backend enforces).

## Notes

- **Distinct from P10-15.** Copy, badge color/icon, and UX flow for "AI access paused" (P10-18) must be visually distinct from "No active seat — AI help paused" (P10-15 NoSeat/Locked). Parents must be able to tell the two states apart. Confirm treatments in the FE-1 design spec before FE-4.
- **No billing or seat information on child surfaces.** The child-facing blocked message (FE-5) must never mention billing, seats, energy, or payment — only "your parent has paused your access, ask them to resume it".
- **No energy or billing values in the toggle UI.** The parent toggle and confirmation sheet must not display the child's energy balance, seat number, or billing dates — those belong to P10-14/P10-15 surfaces.
- **Reuse before inventing.** The confirmation sheet, action sheet, badge, and AI-decline component should reuse existing parent-area / AI Tutor primitives from P10-15-FE, P10-03-FE, and the existing child-card patterns. Ask before adding any new design pattern (CLAUDE.md rule 8).
- **Parent-only layout gate.** The pause/unpause toggle and Paused badge must be behind the parent-only layout (`(parent)/`). Confirm the route guard with the P10-15 implementation (which already gates parent surfaces).
- **Cache invalidation.** On pause or unpause mutation success, invalidate both `useChildAccessStatus(childId)` and the parent child-list query so the badge updates without a manual refresh.
- **E2E energy invariant (FE-7f).** The test must read the child's energy balance before pausing, assert it is unchanged after pausing (possibly 0 AI calls succeed), assert it is still unchanged after unpausing. This is the FE-side confirmation that the backend's "zero energy side-effects" invariant holds end-to-end.
- **Blocked-message integration point.** The AI Tutor feature screens likely already have a graceful-decline handler from P10-03/P10-04 (daily soft-cap warning) and from P10-15 (NoSeat/Locked decline). Extend that handler to discriminate the `ChildAccessPausedByParent` key and render FE-5's copy. Do not add a parallel error path.
- Coordinate i18n key namespacing with sibling P10-15-FE-7 (which adds `en.billing.seats.*` / `ar.billing.seats.*`) to avoid key collisions in the billing namespace.
- **Canonical mapping: 13 wallet · 14 seats · 15 lifecycle · 16 redistribution · 17 refunds · 18 pause/unpause (this story).**
