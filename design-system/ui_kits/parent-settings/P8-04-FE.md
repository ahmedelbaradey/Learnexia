# Design Spec — P8-04-FE Parent changes a child's learning language (fresh-start warning)

> Surface: **parent settings → Linked children** (`apps/student-app/app/(parent)/_components/settings/LinkedChildrenPanel.tsx`).
> Parent-only. Arabic-first / RTL default, dark theme default. Universal (Expo web + native).
> Mirrors the **existing destructive-confirm pattern** already in this file (`InlineUnlinkStrip`) and the existing overlay shapes (`EditChildSheet` RN-`Modal`, `RewardPopup` overlay). **No new design pattern is specified as decided** — see OPEN QUESTIONS for the one friction decision the lead must approve.

---

## 0. Source-of-truth grounding (what I read, what it constrains)

- **Architecture §5** (`docs/architecture/localization-architecture.md`): the change is **rare, parent-only, start-of-year**, family-scoped (foreign child → 403), **confirm-gated** (missing/false `confirmFreshStart` → **424**). On success it **hard-deletes the child's Math & Science attempts/mastery**; **Arabic/English progress + all gamification (XP/streak/badges) are retained**. Same-language request = **no-op success**.
- **Exact contract (verified in the regenerated client — the blocker is cleared):**
  `PUT api/Parent/Change-Learning-Language`, body `ChangeLearningLanguageCommand { childId: number, newLearningLanguage: string, confirmFreshStart: boolean }` → `ChangedLearningLanguageResponse { childId, newLearningLanguage }`.
  **⚠ The field is `newLearningLanguage`, NOT `learningLanguage`** (frontend hook P8-04-FE-1 must use this exact name).
- **Existing destructive pattern in-file:** `InlineUnlinkStrip` — an inline expandable strip (`$dangerSoft` bg, `borderStartWidth={3}` / `borderStartColor="$danger"`, ghost Cancel + a `$danger`-text confirm tap target ≥44px). Explicitly chosen over a dialog ("NOT a dialog per design spec §2.2"). **This is the local destructive grammar; we mirror it.**
- **Existing overlay shapes** (for the modal option): `EditChildSheet` = RN `Modal transparent animationType="slide"`, `$overlay` scrim, bottom sheet `$card` `borderTopStartRadius/EndRadius="$modal"` (24), drag-handle, ✕ close, `useSafeAreaInsets`. `RewardPopup` = absolute-fill `$overlay` centered card `borderRadius={24}`, `accessibilityViewIsModal`/`role="alert"`. **No reusable `<Modal>`/`<Dialog>` primitive exists in `packages/ui`** — confirm strips are inline; the only true overlay is EditChildSheet's raw RN Modal.
- **Tokens (verified, `packages/design-system/src/tokens/colors.ts`):** `danger #EF4444`, `dangerSoft rgba(239,68,68,0.18)`, `warning/accent #F59E0B`, `warningSoft rgba(245,158,11,0.18)`, `card #1E293B`, `bgElevated #111B33`, `overlay rgba(15,23,42,0.72)`, `fg1 #F8FAFC` / `fg2 #CBD5E1` / `fg3 #94A3B8`, `border rgba(255,255,255,0.08)`, `borderSubtle rgba(255,255,255,0.06)`. Radii: `$sm` 8 · `$button` 16 · `$card` 20 · `$modal` 24 · `$pill` 9999.
- **⚠ DATA GAP:** `LinkedChildResponse` exposes only `{ id, fullName, email }` — **NOT the child's current `learningLanguage`**, and **there is no `GET api/Parent/Child/{id}`**. The entry point cannot render the *current* learning language from `useMyChildren`. See **DESIGN GAPS** for the two options.

## 1. Decision: where this lives + which shape

**Home (confirmed):** **`LinkedChildrenPanel`** — the per-child management surface the brief and task name. NOT onboarding `EditChildSheet` (in-memory drafts, no backend). It already owns per-child Edit + Unlink affordances and the inline-strip pattern; learning-language change is a third per-child action of the same family but **higher consequence**.

**Shape (recommended): a per-child inline "Learning language" section that opens a true confirmation overlay (RN `Modal`), NOT a third inline strip.**
Rationale — friction tiering:
- Unlink uses an *inline strip* (reversible-ish; re-linkable).
- Change-learning-language **destroys Math/Science progress irreversibly**. The architecture calls it the app's clearest "are you sure" moment. An inline strip is too easy to fumble on a phone. It warrants a **focus-trapped modal** (mirroring `EditChildSheet`'s RN `Modal` overlay) so the consequence text is unavoidable and the confirm cannot be hit by a stray tap while scrolling.
- This is **mirroring `EditChildSheet`'s existing RN-`Modal` overlay shape**, not inventing a modal system — so it is allowed under CLAUDE.md rule 8. (The *type-to-confirm friction*, if chosen, IS a new pattern — flagged in OPEN QUESTIONS.)

So the composition is: **entry row (in panel) → language picker → confirm overlay (mirrors EditChildSheet) → success/error strip (mirrors existing in-panel strips).**

## 2. Entry point — per-child "Learning language" row (idle state)

Add **below** the existing `ChildCard` for each child (a new sibling block in the `children.map`, peer to the edit/unlink strips), low-prominence:

```
┌──────────────────────────────────────────────────────────────┐  (inside child block)
│  [ChildCard …]                                                 │
│  ┌──────────────────────────────────────────────────────────┐ │
│  │ 📘 Learning language            العربية / Arabic   [Change]│ │  ← new inline row
│  └──────────────────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────────────┘
```

- **Container:** `Stack flexDirection={rowDir}` · `alignItems="center"` · `justifyContent="space-between"` · `gap={12}` · `padding={14}` · `backgroundColor="$bgElevated"` · `borderRadius={14}` · `borderWidth={1}` · `borderColor="$borderSubtle"` · `marginTop={-4}` (matches `InlineEditForm`/`InlineUnlinkStrip` strip grammar). **NOT** danger-styled — idle is benign.
- **Leading label block:** label `parent.settings.learningLanguage.rowLabel` — `color="$fg2"` `fontSize={13}` `fontWeight=600` `fontFamily="$body"`; below it the **current value** `color="$fg1"` `fontSize={14}` `fontWeight=700`. No emoji decoration unless semantic — skip the 📘 if it isn't in the semantic set (it is **not**; per Brand law rule 9 the allowed set is 🔥❤️⭐🏆💎🎯 only). **Use a Lucide `languages`/`globe` line icon (2px stroke) or no icon — flag the icon choice.**
- **Action:** `Button variant="ghost" size="sm"` labelled `parent.settings.learningLanguage.change` ("Change" / "تغيير"). Ghost = low-prominence (this is rare, not a CTA). ≥44px target.
- **Current-value rendering depends on the DATA GAP resolution** (see gaps). If `learningLanguage` is unavailable, render a neutral picker prompt instead of a stale value (Option B copy below).

**Note (RTL technical-string rule):** the value is a *language name* (localized word), so it follows `writingDirection={direction}` — it is NOT a Latin technical string. Do not force LTR.

## 3. The picker (selecting a new language)

Tapping **Change** reveals the picker — **reuse the existing `Select`** (as `LinkedChildrenPanel`/`LanguagePanel` already do) with two options, OR the P8-01 learning-language picker if it was extracted to `packages/shared`/`packages/ui` (task says reuse it; confirm in OPEN QUESTIONS). Recommended: `Select` to match the sibling panels exactly.

- Options: `{ value: 'ar', label: t('onboarding.language.ar') }`, `{ value: 'en', label: t('onboarding.language.en') }` (same keys the edit form uses).
- Label: `parent.settings.learningLanguage.pickerLabel` — "Medium of instruction (Math & Science)" / "لغة دراسة الرياضيات والعلوم".
- Helper text under the picker (`$fg3`, 12px): `parent.settings.learningLanguage.pickerHelper` — clarifies this is the **learning** language, distinct from the app/UI language. (Same disambiguation concern as P8-01.)
- A **primary "Change Language" button** (size md) appears only once a value is selected.
  - **Same-language no-op (AC):** if the selected value equals the child's current learning language, the button is **disabled** (`opacity 0.4`, `disabled`, no glow) and a 12px `$fg3` hint shows `parent.settings.learningLanguage.noChange` ("This is already the learning language." / "هذه هي لغة الدراسة الحالية بالفعل."). The confirm overlay never opens for a no-op.
  - **If the current language is unknown (data gap, Option B):** we cannot detect the no-op client-side; rely on the BE no-op success and show the success copy. Flag.
- Pressing the enabled button **opens the confirmation overlay** (§4). The mutation does **NOT** fire here.

## 4. The fresh-start confirmation overlay (the heart of the story)

**Shape: mirror `EditChildSheet`** — RN `Modal visible transparent animationType="slide" onRequestClose={cancel}` with `$overlay` scrim. On native a bottom sheet; on web the same Modal renders a centered card. Drag handle + ✕ are optional here — for a destructive confirm, prefer the explicit Cancel/Confirm buttons as the only exits and **no backdrop-dismiss that loses the warning** (allow ✕ / Cancel / hardware-back = cancel only).

### 4.1 Layout (390 / 768 / 1024)
- **390 (phone):** bottom sheet, `maxWidth=100%`, `borderTopStartRadius/EndRadius="$modal"` (24), `paddingBottom={insets.bottom + 16}`, content `paddingHorizontal="$6"` (24), `paddingVertical="$5"`. Buttons stacked full-width (Confirm on top visually-first per reading order, Cancel below) OR a `rowDir` row if they fit — stack on phone for ≥48px targets.
- **768 / 1024 (tablet/web):** centered card (mirror `RewardPopup` centering: absolute-fill `$overlay`, `alignItems/justifyContent="center"`), card `borderRadius={24}`, `minWidth={320}` `maxWidth={420}`, `padding={28}`. Button row right-aligned (`justifyContent="flex-end"`), Cancel (ghost) then Confirm (danger).
- **Card surface:** `backgroundColor="$card"` (#1E293B — steps lighter, never darker), `borderWidth={1}` `borderColor="$borderStrong"` (rgba 0.16). Soft popup shadow (mirror RewardPopup shadow: `shadowColor="#000"` `shadowOpacity≈0.5` `shadowRadius≈48` `shadowOffset {0,16}`). Glass/blur is allowed here (floating overlay) but optional — keep simple, no blur dependency.

### 4.2 Anatomy (top → bottom, reading order)
1. **Danger marker + title row.** A `$danger`-tinted round chip (44×44, `borderRadius=9999`, `backgroundColor="$dangerSoft"`) holding a **Lucide `alert-triangle`** (2px stroke, `$danger`) — flag the icon (do not use a Unicode ⚠ glyph as an icon, Brand law rule 11). Title `parent.settings.learningLanguage.confirm.title` — `color="$fg1"` `fontSize={20}` `fontWeight=800` `fontFamily="$heading"`. Headline ≤6 words.
2. **From → To restatement.** A small `$bgElevated` `borderRadius={14}` block naming the change explicitly:
   `العربية ← English` (RTL: arrow points to the new value following reading order; reuse the `scaleX` arrow-mirror trick from ChildCard's chevron). Tokens: from `$fg3` strike-ish (no actual strikethrough — just muted), arrow `$fg3`, to `$fg1` `fontWeight=700`. Key `…confirm.fromTo` with `{from, to}` interpolation.
3. **Consequence statement — the unambiguous loss.** Two lines, the **loss line in `$danger`**, the **kept line in `$fg2`**:
   - Loss (icon-led, `$danger`, 14px, fontWeight 600): `…confirm.willReset` — "Your child's Math & Science progress will be reset — they start fresh in those subjects." Bold the resettable subjects.
   - Kept (`$fg2`/`$success`-tinted check, 13px): `…confirm.willKeep` — "Arabic, English, XP, streak and badges are kept."
   - Framing (`$fg3`, 12px): `…confirm.rareNote` — "Only do this at the start of a school year."
4. **Explicit-acknowledgement gate (friction — see OPEN QUESTIONS for level).** **Recommended: a required `CheckboxField`** (the existing `packages/ui` primitive) the parent must tick:
   `…confirm.ack` — "I understand Math & Science progress will be reset." The **Confirm button stays disabled (`opacity 0.4`) until the box is checked.** This maps the deliberate acknowledgement → `confirmFreshStart: true` and prevents accidental confirmation, while reusing an existing component (no new pattern).
   *(Alternative higher-friction: type-to-confirm the child's name — that IS a new pattern; flagged, do not build without approval.)*
5. **Actions row.**
   - **Cancel:** `Button variant="ghost" size="md"` — `common.cancel`. Always enabled (unless submitting). Closes overlay, no call.
   - **Confirm (destructive):** label `…confirm.cta` — "Reset & Change" / "إعادة التعيين والتغيير". **Destructive styling without a new Button variant** (mirror `InlineUnlinkStrip`'s approach): a tappable `Stack` `backgroundColor="$danger"` `borderRadius="$button"` (16, ALL buttons) `minHeight={48}` `paddingHorizontal={20}`, label `$fg1` 15px/700, `pressStyle={{ scale: 0.95 }}`, `disabled` → `opacity 0.4` + no press. (If the lead prefers a real `variant="danger"` Button, that is a small `packages/ui` addition — flagged.) This is the **only** control that fires the mutation with `confirmFreshStart: true`.

### 4.3 One-primary-action rule
The overlay's single primary action is **Confirm**. Cancel is secondary (ghost). The picker's "Change Language" button only *opens* the overlay; it is not a competing primary in the same view.

## 5. States (full matrix)

| State | Trigger | Visual |
|---|---|---|
| **idle** | default | §2 row showing current language (or neutral prompt if data gap). |
| **selecting** | tap Change | §3 picker revealed; "Change Language" disabled until a value chosen. |
| **no-op** | selected == current | "Change Language" disabled + `noChange` hint (`$fg3`). No overlay. |
| **confirm-open** | tap Change Language (different lang) | §4 overlay; Confirm disabled until ack checkbox ticked. |
| **submitting** | tap Confirm | `useChangeLearningLanguage.isPending` → Confirm shows spinner / `loading`, Cancel + checkbox disabled, overlay stays open & focus-trapped. Mutation sends `{ childId, newLearningLanguage, confirmFreshStart: true }`. |
| **success** | mutation success | Overlay closes; **in-panel success strip** appears (mirror existing: `$successSoft` bg, `$success` text, `borderRadius="$sm"`, `padding=12`, `accessibilityLiveRegion="polite"`, auto-clear ~4000ms). Copy `…success` — names new language **and acknowledges the reset happened**. Invalidate `useMyChildren` / `/Me` / child-family queries so the row reflects the new language. |
| **error (generic / 403 / 5xx)** | mutation error | Keep overlay open; `ServerErrorBanner` inside the overlay (mirror `InlineEditForm`'s use). `byStatus: { 403: '…error.forbidden', 424: '…error.confirmMissing' }` + generic fallback. Cancel still works. |
| **error (424 confirm missing)** | BE rejects without flag | Should be unreachable (UI gates the flag), but surface `…error.confirmMissing` defensively if it occurs. |
| **same-language at BE (no-op success)** | data-gap path only | Treat as success; show `…success` (BE returns no-op success per architecture). |

**Loading the panel / picker:** no extra loading skeleton needed beyond the panel's existing `common.loading`; the picker is local state.

## 7. RTL / i18n

- All rows: `flexDirection={rowDir}` (`row-reverse` in RTL), passed from `SettingsWeb` exactly like the sibling panels.
- Text: `writingDirection={direction}` + `textAlign={direction === 'rtl' ? 'right' : 'left'}` on every body string.
- The **from→to arrow** mirrors: render `›`/`→` with `scaleX={direction === 'rtl' ? -1 : 1}` (the ChildCard chevron trick) so it always points toward the *new* value in reading order. In `confirm.fromTo` the AR string uses `←` and the LTR uses `→`.
- Language **names are localized words**, not technical strings → follow `direction` (do NOT force LTR; the SecurityPanel forceLtr rule is for session IDs/dates only).
- Danger marker chip and Lucide icon glyphs are **not mirrored** (icon shapes are not flipped, per Arabic/RTL conventions).
- Modal layout mirrors: in RTL the action row reverses (Cancel/Confirm order follows `rowDir`), close ✕ flips side.

## 8. Accessibility / kid-UX (parent-facing, but still strict)

- **No accidental confirmation:** required ack checkbox gates Confirm; Confirm disabled state is real (`accessibilityState={{ disabled }}`); backdrop tap does NOT dismiss-and-lose — only explicit Cancel/✕/back cancels.
- **Focus trap:** modal uses `accessibilityViewIsModal` (mirror RewardPopup) + RN `Modal` (native focus handling) so keyboard/AT users can't tab to the panel behind it. Confirm + Cancel both reachable; Confirm clearly labeled with full intent (`accessibilityLabel` = the CTA, not just "OK").
- **Live regions:** success strip + error banner `accessibilityLiveRegion="polite"`; the consequence text is read in order (title → loss → keep → ack).
- **Targets:** every tappable ≥48px (Brand law rule 10); ghost Change button ≥44px.
- **Contrast:** `$danger #EF4444` on `$dangerSoft`/`$card` and `$fg1` on `$card` meet AA; the loss line uses `$danger` text + bolded subject names, not color alone (icon + weight reinforce).
- **Title is a question** ("Reset … Progress?") so screen-reader users grasp the stakes before reaching the buttons.

## 9. Motion (snappy, ≤800ms — Brand law rule 12)

- Picker reveal: slide+fade 200–250ms (match the inline-form reveal grammar).
- Overlay entrance: mirror `EditChildSheet` (`animationType="slide"`, native) / `RewardPopup` spring on web (`springs.popup`, `cubic-bezier(0.34,1.56,0.64,1)`) — but **subtle**, this is a warning not a celebration; no confetti, no glow, no overshoot bounce that feels playful. A gentle 150–200ms fade-in scrim + slide is enough.
- Confirm press: `pressStyle={{ scale: 0.95 }}` 80ms.
- **No celebratory motion on success** — a destructive reset is acknowledged calmly; the success strip just fades in. (Confetti/glow are reserved for genuine wins; resetting progress is not one.)

## 12. DESIGN GAPS / OPEN QUESTIONS (for the lead)

1. **[BLOCKER for the entry point] Current learning language is not available on the client.** `LinkedChildResponse = { id, fullName, email }` only, and there is **no `GET api/Parent/Child/{id}`**. So §2 cannot show the child's *current* learning language, the §3 client-side no-op guard can't run, and the from→to restatement can't name the "from".
   - **Option A (preferred):** backend exposes `learningLanguage` on `LinkedChildResponse` (or a child-detail GET). Small BE change; unblocks the full UX. **Recommend this.**
   - **Option B (no BE change):** drop the "current value" + client no-op + "from" in the restatement; the picker just asks "choose the medium of instruction", and we rely on the BE same-language no-op success. The warning then reads "→ {{to}}" only. Degrades the clarity of a high-consequence screen. **Need a decision.**

2. **Confirmation friction level — pick one (I recommend the checkbox):**
   - (a) **Required ack checkbox** gating a `$danger` Confirm — *recommended*; reuses existing `CheckboxField`, no new pattern, strong enough for a deliberate parent action.
   - (b) **Type-to-confirm** (type the child's name or the new language) — strongest, but **a NEW pattern** → needs explicit approval per CLAUDE.md rule 8 before the frontend builds it.
   - (c) Plain destructive Confirm (no ack) — too weak for an irreversible reset; not recommended.

3. **Modal vs inline strip.** I recommend a focus-trapped overlay (mirror `EditChildSheet`) over a third inline strip, because the action is irreversible and an inline strip on a scrolling phone screen is easy to mis-tap. Confirm the lead agrees, since the in-file precedent (`InlineUnlinkStrip`) is inline. (Either way it's mirroring an existing shape — no new pattern.)

4. **Destructive Confirm: ad-hoc `$danger` Stack vs a new `Button variant="danger"`.** The in-file precedent (`InlineUnlinkStrip`) uses an ad-hoc `$danger`-text tappable Stack to avoid a new variant. A reusable `variant="danger"` in `packages/ui` would be cleaner and is likely wanted elsewhere — but it's a (small) new variant → ask first.

5. **Picker source.** Task says reuse the P8-01 learning-language picker "if extracted to `packages/shared`/`packages/ui`". If it was extracted, use it; otherwise use `Select` (matches sibling panels). Confirm where it landed.

6. **Icons.** Entry-row icon and the danger marker should be **Lucide line icons** (`languages`/`globe`, `alert-triangle`) per Brand law rule 11 — NOT Unicode glyphs or non-semantic emoji. Confirm the Lucide set is wired in the app (flagged as the standard substitution).
