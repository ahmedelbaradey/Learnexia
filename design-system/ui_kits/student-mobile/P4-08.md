# Design Spec — P4-08 Gamification Screens & Motion

> Phase-3 closer for the player-facing surface. Five surfaces (3 routes + 2 overlay families) + seven motion sequences that finally make the silent P4-02..P4-07 engines *visible*. Token-only, dark-default, AR/RTL-first. Inherits the W13 dashboard grammar (`W13-home-dashboard.md`) — same screen padding (`$space-6` = 24), same `maxWidth: 720` cap on web, same `$card` / `$cardSoft` / `$borderStrong` chrome, same brand-law rules (radii bucketed, gradients reserved, glow on CTA + reward only, never darken on press).
>
> **Locked decisions in scope** (recap from `docs/plans/P4-08.md`): D1 — full route scope; D2 — single combined `RewardOverlay` card; D3 — Skia particles in this PR; D4 — hand-written DTOs in `packages/api-client/src/manual/gamification.ts` (read for actual field shapes).
>
> **Hand-written DTO shapes** (canonical for this spec — `packages/api-client/src/manual/gamification.ts`):
> - `StudentProfileDto` → `{ totalXp, currentLevel, xpIntoCurrentLevel, xpToNextLevel }`
> - `BadgeStateDto` → `{ code, iconKey, rarity, triggerType, threshold, rewardXp, isEarned, awardedAtUtc }`
> - `MissionStateDto` → `{ code, iconKey, titleKey, cadence, targetType, target, rewardXp, progress, status, periodStartUtc, periodEndUtc, completedAtUtc }`
> - `MyMissionsResponse` → `{ daily: MissionStateDto[], weekly: MissionStateDto[] }`  *(weekly is an ARRAY, not a single object — verified against the manual file; spec treats `weekly[0]` as the canonical weekly card and reserves the array shape for future expansion)*
> - `LeagueStandingDto` → `{ rank, displayName, weeklyXp, isMe }`
> - `MyLeagueResponse` → `{ tier, periodKey, periodStartUtc, periodEndUtc, myRank, myWeeklyXp, standings, promotionCutoffRank, demotionCutoffRank }` *(field name is `tier`, not `currentTier`; cutoff names are `promotionCutoffRank` / `demotionCutoffRank`, not `Cutline`)*
> - `BadgeRarity` enum string: `'Common' | 'Rare' | 'Epic' | 'Legendary'`
> - `LeagueTier` enum string: `'Bronze' | 'Silver' | 'Gold' | 'Diamond'`
>
> **Catalog assumption** (cross-checked with brief): 10 catalog badges. Captures show 8 of 8 — design spec is faithful to the BE contract (10), and the counter copy is `{earned} of {total}` driven by `myBadgesResponse.badges.length`.

## 2. Per-surface specs

### 2.1 Surface S1 — Badge collection (`/(child)/badges`)

**Goal:** Show all 10 catalog badges as a 3-column grid. Earned = full color + rarity halo. Locked = desaturated + lock glyph. Tap earned → detail bottom-sheet; tap locked → same sheet showing trigger criteria.

**Captures:** `mobile/17-badges.png` · `mobile-ar/17-badges.png`.

#### Layout — 390 portrait (mobile primary)

```
SafeArea top + 16
TopBar (back chevron leading + title centered — see Header anatomy below)
  ↓ 16
PageHeader row (🏆 + H1 "Badges" + caption "{n} of {total} earned · Collect them all")
  ↓ 20
BadgeRarityStrip (single rounded card, 4-column count row: BRONZE / SILVER / GOLD / LEGEND)
  ↓ 16
BadgeGrid (3 cols × 4 rows for 10 items — bottom row 1-cell short, grid keeps fixed cell width)
  ↓ bottom safe area + 24
```

- Horizontal screen padding: 24 (`$space-6`).
- Web/tablet: `maxWidth: 720`, `alignSelf: center`. At ≥ 720 the grid promotes from 3-col to 4-col (capture shows 3-col on phone; 4-col on tablet matches the W13 "scale on wider canvas" rule). When 4-col, 10 items become 4 + 4 + 2.
- One primary action per screen: the grid itself (each cell is a tap target). No floating CTA.

#### Header anatomy

- TopBar (logical row): back chevron (leading) `Lucide ArrowLeft` 24px `$fg1`, 44×44 tap target → `router.back()`. No title in the system bar — the H1 lives below.
- PageHeader row (`flexDirection={isRtl ? 'row-reverse' : 'row'}`, `alignItems: 'flex-end'`, gap 10):
  - 🏆 trophy glyph 28px (semantic — brand law allows this exact glyph for trophy slot). Not mirrored RTL.
  - H1 "Badges" / "الشارات" — 28/800 Poppins/Cairo `$fg1`, `lineHeight: 1.1`, `letterSpacing: -0.01em`.
- Sub-caption below header (12/500 `$fg3`): `child.badges.subtitle` = `"{{earned}} of {{total}} earned · Collect them all"` / `"{{earned}} من {{total}} مكتسبة · اجمعها كلها"`. Caller pre-interpolates Eastern-Arabic numerals in AR.

#### BadgeRarityStrip — new primitive

A single card `padding 14px 16px`, radius `$card` 20, bg `$card`, border 1px `$border`, shadow `$shadow-soft`, with a horizontal row of **4 columns** (no dividers, even spacing). Each column:
- Big number top: weight 800, size 24, `tabular-nums`, color per rarity (see token table — `$streak` for BRONZE, `$fg2` for SILVER, `$accent` for GOLD, `$purple` for LEGEND). AR uses Eastern-Arabic numerals.
- Label bottom: 10/700 uppercase tracking `0.04em`, `$fg3`. EN: BRONZE / SILVER / GOLD / LEGEND. AR: بروبز / فضّة / ذهب / أسطورة.

(Capture shows this strip with `2 / 2 / 1 / 0` counts under the header. Faithful.)

#### BadgeGrid

- Container: `flexDirection: row`, `flexWrap: wrap`, `gap: 12` both axes.
- Cell width: `(containerWidth - 2*gap) / 3` so 3 fit per row exactly. On tablet `/ 4`.
- Cell height: matches width (square chrome) `+` text block ≈ 132 total.
- Each cell is a `Pressable` rendering the `Badge` primitive with state-driven props.

**Per-cell anatomy** (matches existing `Badge` primitive — no fork):

| Element | Earned (Common/Rare/Epic/Legendary) | Locked |
|---|---|---|
| Cell bg | `$card` | `$card` |
| Cell border | 1px `$border` | 1px `$border` |
| Cell radius | `$card` 20 | `$card` 20 |
| Cell padding | 14 vertical, 8 horizontal | same |
| Cell shadow | `$shadow-soft` (resting) — `$shadow-primary-glow` IF `isNewlyEarned` is true | `$shadow-soft` |
| Disc | 74×74 (existing Badge `DISC` constant), radial gradient by rarity → `gradientStops.badge{Bronze/Silver/Gold/Legendary}` | 74×74, flat `$cardSoft` fill, 🔒 glyph 28px `$fg4` |
| Disc glow (ambient halo behind the disc) | `boxShadow: 0 0 24px <rarity-glow>` (existing `Badge.GLOW` map values) | none |
| Title under disc | 14/800 `$fg1`, single line | 14/800 `$fg4`, single line |
| Sublabel | EARNED (10/700 uppercase tracking 0.04em, color = rarity fg) OR "{N} DAYS" / "TOP {n}%" for milestone-suffix badges (per capture) | LOCKED (10/700 uppercase `$fg4`) |

| any + `isEarned=false` | `locked` | (n/a — flat `$cardSoft`) | (n/a) | `$fg4` |

**Newly earned highlight** (per capture row 3 `All-Star` cell): the cell that matches a code in `useDashboardDiff(...).newBadges` renders with a 2px `$primary` (#4F46E5) outer border, the cell shadow upgrades to `$shadow-primary-glow`, and the existing `Badge` `isNewlyEarned` prop fires the pop-in animation (Motion M2). One render cycle only — the diff hook clears after consumption.

#### Tap behavior

- Earned cell: opens `BadgeDetailSheet` with title (BE-localized via `iconKey`/`titleKey` lookup — for P4-08 we render the code in title-case fallback when no localized title is wired yet), rarity, description, "Earned on {date}" line. Date uses Eastern-Arabic numerals in AR; technical timestamp strings stay LTR.
- Locked cell: opens `BadgeDetailSheet` with title, rarity, description, and a **criteria caption** computed from `triggerType` + `threshold`:
  - `FirstLesson` → `child.badges.criteria.firstLesson` = "Complete your first lesson." / "أكمل أول درس لك."
  - `StreakThreshold` (threshold=N) → `child.badges.criteria.streakThreshold` = "Reach a {{n}}-day streak." / "حافظ على سلسلة من {{n}} أيام."
  - `LevelThreshold` (threshold=N) → `child.badges.criteria.levelThreshold` = "Reach Level {{n}}." / "وصول إلى المستوى {{n}}."
- Toast fallback when sheet not yet implemented (D1 doesn't require detail sheet content polish; minimal title + criteria are mandatory).

#### `BadgeDetailSheet` — new

- Tamagui `Sheet` snapping to ~55% of screen height (or content-fit, whichever smaller).
- Backdrop: `$overlay` (`rgba(15,23,42,0.72)`).
- Body bg: `$card`, radius top corners `$modal` 24, padding 24 horizontal × 20 vertical.
- Composition: drag handle (3×40 pill `$borderStrong` self-centered, top 8) → big `Badge` variant for visual identity (locked vs earned variant) → title 20/800 `$fg1` → rarity pill (use existing `Badge variant="boss"` chrome but bg + label color follow the rarity row colors above) → description body 14/500 `$fg2`, line-height 1.5 → criteria/awarded caption 13/500 `$fg3` (Eastern-Arabic numerals in AR) → primary `Button variant="primary"` "Got it" / "حسناً" full-width, 48 tall.

#### `MissionTotalRewardCard` — new primitive

(Faithful to the "+125 XP" hero stripe in capture 15.)

- Full-width card, height 96, radius `$modal` 24, padding `18 horizontal × 18 vertical`.
- Background = `$gradReward` (`linear-gradient(90deg, #F59E0B, #EF4444)`). This is the only Reward-gradient use on this screen — sanctioned by brand law because the card *is* the reward summary.
- Shadow: `$shadow-soft` resting; **no** glow (Reward gradient already carries the visual energy).
- Inner row: `flexDirection={isRtl ? 'row-reverse' : 'row'}`, alignItems center, gap 14.
  - Leading 🎁 glyph on 56×56 disc, bg `rgba(255,255,255,0.18)`, fg 28px (semantic — gift = reward).
  - Body column (flex 1):
    - Big title: `"+{{totalRewardXp}} XP"`, 28/800 `$fg1`, `tabular-nums`. AR keeps the `+` LTR and uses Eastern-Arabic for the number: `"+١٢٥ نقطة"`.
    - Sub-line: `child.missions.totalReward.subline` 12/500 `$fg1` at 90% opacity. EN: "Plus a Silver badge if you finish all" / AR: "وشارة فضّيّة إن أكملت الكل". This sub-line is HIDDEN when no chained-badge reward is configured for the day (BE doesn't expose this field as of P4-08; render only when caller passes a non-empty `chainedBadgeName` prop — defaults hidden).

**`MissionStatusPill` — new sub-primitive** (small status chip used for explicit status callouts when not implied by chrome): pill, padding `4×10`, radius `$pill`, 10/800 uppercase tracking `0.04em`. Color map: NotStarted → bg `$cardSoft` fg `$fg3`; InProgress → bg `$primarySoft` fg `$primaryLight`; Completed → bg `$successSoft` fg `$success`; Expired → bg `rgba(239,68,68,0.13)` fg `$danger` (strike-through optional).

**Progress bar inside the card** (when `status === 'InProgress'` and `progress` set):
- 6px tall, radius pill, track `$bg`, fill `$gradXp`, `direction: ltr` wrapper (brand law — progress L→R).
- Caption trailing: "`{current} of {target}`" 12/700 `$fg2`, `tabular-nums`. AR uses Eastern-Arabic numerals: `"٦ من ١٠"`.

**Card outer chrome** (default — unchanged from MissionBanner spec):
- padding 16 vertical × 18 horizontal, gap 12 row, radius `$card` 20, bg `$card`, border 1px `$borderStrong`, `$shadow-soft`.
- minHeight 80; the whole card is a tap target when `onPress` is set.

**Weekly mission card emphasis** (capture distinguishes Weekly visually):
- Wrap the weekly card in a 2px `$accent` border instead of 1px `$borderStrong`.
- Section eyebrow above the card reads "WEEKLY MISSION" / "مهمة الأسبوع" (12/700 uppercase tracking 0.04em, color `$accent` instead of `$fg3` to signal the upgrade).
- The reward XP pill on weekly cards renders with the `gradLevelup` gradient (`#A855F7 → #6366F1`) — sanctioned for the weekly summary because weekly missions are bigger emotional moments.

## 4. Reduce-motion strategy

The single source of truth is `useReduceMotion()` (new — `packages/ui/src/hooks/useReduceMotion.ts`):
- On RN: wraps Reanimated's exported `useReducedMotion()` (RN 3.16+).
- On web: reads `window.matchMedia('(prefers-reduced-motion: reduce)')`.
- Returns `boolean`. Re-renders on change.

Every animated component MUST branch on this hook:

| Component | Reduce-motion behavior |
|---|---|
| `XPBar` (M1) | `animated` prop ignored; fill renders at target instantly. XP-full glow flash skipped. |
| `Badge` (M2) — when `isNewlyEarned` | Pop-in skipped; renders at scale 1, opacity 1. |
| `ConfettiLayer` (M3) | `active` forced to `false`; canvas not rendered. |
| `QuestionCard` (M4) | translate sequence skipped; 250ms `borderColor` red-flash substituted. |
| `StreakFlame` (M5) | Continuous pulse disabled. Ignite sequence replaced with 200ms opacity-tween. |
| `Hearts` (M6) | Rotation + shards skipped; pure 200ms opacity fade. |
| `LeaguePromotionSheet` (M7) | Sheet slide skipped (`from={{translateY: 0}}` → `animate={{translateY: 0}}`). Tier badge zoom skipped. Sparkles skipped. |
| `RewardOverlay` entrance | Skip spring/scale. 200ms opacity-only fade-in. Auto-dismiss timer extends 5s → 8s. |
| `PracticeModeBanner` entrance | Skip translate-Y slide; opacity-only fade-in 200ms. |
| `HeartsDepletedSheet` entrance | Same as M7 — no slide; instant appearance with opacity fade. |

**Test seam**: every animation MUST be unit-testable by mocking `useReduceMotion` to return `true` and asserting the static state is rendered. Snapshot tests in the plan's Batch-5 list verify this.

1. **`dir="rtl"` propagated from `useLocale().direction`** (existing W11 hook). No physical L/R props in any new code.
2. **`flexDirection`**: `isRtl ? 'row-reverse' : 'row'` on every horizontal stack. Never hardcode `row-reverse`.
3. **Logical spacing**: `paddingStart` / `paddingEnd` / `marginStart` / `marginEnd` / `borderStartWidth` / `borderEndWidth`. No `paddingLeft` etc.
4. **Progress bars**: ALWAYS wrapped in `<View style={{direction:'ltr'}}>` — brand law (progress reads L→R universally). Applies to MissionBanner progress, MissionTotalRewardCard internal bars (none today, but the rule stands), XPBar fill, LeagueTierBanner countdown bar (none today), reward overlay XP bar.
5. **Numerals**:
   - Eastern-Arabic numerals (٠١٢٣٤٥٦٧٨٩) for in-line reading text: badge counts, rank numbers, mission progress (`٦ من ١٠`), days-left (`٣ أيام متبقّية`), heart minute countdown.
   - **LTR exception** (W13 brand law): technical XP counter strings like `"820 / 1000 XP"` stay Latin and wrap in `dir="ltr"`. Applies to Reward overlay XP bar, league row XP value, MissionTotalRewardCard "+125 XP" (the number part), reward row XP increments.
   - Brand name "Learnexia" stays Latin + `dir="ltr"` (no occurrence in P4-08 surfaces, but inherited).
6. **Arrows**:
   - Promotion/demotion zone arrows (`↑` `↓`) are **NOT** mirrored — they always point to the top/bottom of the list (semantic).
   - "Level X → Y" chevron arrows: `→` LTR / `←` RTL.
   - TopBar back chevron: `Lucide ArrowLeft` LTR → swaps to `Lucide ArrowRight` RTL (Lucide does not auto-mirror; swap the import).
   - Per W13 §6 rule, the chevron in CTAs ("Continue", "See standings", "Keep Going") swap glyph at the component level.
7. **Avatars / icon discs**: NOT mirrored. The avatar gradient and badge disc gradients keep their identity in both locales.
8. **Captures audit**:
   - `mobile-ar/16-league.png` (League): tier banner trophy disc is on the LEFT (logical trailing in RTL). Spec captures this — trophy on logical trailing edge.
   - `mobile-ar/17-badges.png` (Badges): grid auto-mirrors via `flexWrap`. First cell on the logical leading edge (right in AR). PageHeader 🏆 sits next to the H1 on the leading edge.
   - `mobile-ar/18-hearts.png` (Hearts): hearts row shows empty hearts on the LOGICAL leading edge (left side in AR) — because RTL flips the row, the "lost first" hearts end up on the leading side. Spec respects the existing `Hearts` primitive's RTL behavior (W13 §6).
   - `mobile-ar/14-mission-completed.png` (the reward overlay variant): note this capture is in EN in the mobile-ar set — the AR twin specifically for the Mission Completed celebration does not exist in the kit. Designer flags as a kit gap; spec ships AR by mirroring the EN capture conventions verbatim with translated copy.
9. **Visual review checklist** (mandatory for reviewer batch):
   - Each new route renders against the matching `mobile-ar/*.png` capture.
   - `RewardOverlay` opens in both locales: backdrop covers full screen, card centered, reward rows ordered top-to-bottom in both locales (vertical stack — no RTL flip needed).
   - `PracticeModeBanner` shield icon stays on logical leading edge in both locales.

## 9. Open questions / design gaps

All P1–P4 plan decisions are locked. The following items are FRESH design gaps surfaced by this spec — none block the frontend batch starting; all are tracked for HANDOFF + token-promotion follow-up.

1. **Tier gradient tokens** — `gradients.tierBronze/Silver/Gold/Diamond` proposed. Ship literal CSS via `GradientFill` until promoted. Flag in PR.
2. **`gradients.avatarFire`** for rank-1 standing avatar disc — propose token. Ship literal until promoted.
3. **`$warningSoftStrong` (0.28-alpha)** for PracticeModeBanner border + countdown disc. Currently inline. Mirror of `$primarySoftStrong` precedent.
4. **`$dangerSoftXp` (0.13-alpha)** for Expired mission status pill bg. Currently using `$dangerSoft` (0.18) as fallback. Aligned with `$xpSoft`/`$streakSoft` 0.13 KPI tints.
5. **`$borderOverlay` (rgba(255,255,255,0.12))** — used inline in `RewardPopup` and now `RewardOverlay`. Promote to token; aligned with `$borderStrong` (0.16) and `$borderSubtle` (0.06).
6. **`durations.slowAnimated` = 600ms** — XPBar's M1 fill needs 600ms but `durations.slow` is 400ms. Either add a 600ms token or pass `duration: 600` literal. Designer recommends adding a new key for celebratory fills.
7. **`nextRefillAtUtc` on dashboard payload** — `HeartsDepletedSheet` needs this; current `DashboardDto` does NOT expose it. Either expand `DashboardDto` (backend touch) OR use fallback "Next heart soon" copy. **Plan locked DTO patching for P4-08-FE-0 — recommend including this field, but NOT a blocker.**
8. **AR twin of `14-mission-completed.png`** is missing from `mobile-ar/` (the EN capture lives there). Kit gap; not a blocker — spec ships AR-mirroring of the EN capture.
9. **Mission `titleKey` localization wiring** — BE returns the key string (e.g. `"mission.daily_3_lessons.title"`); the i18n resources file must include each per-mission seed. Coordinated with the P4-06 BE seed. Not new design work; flagged so FE doesn't try to hard-code titles.
10. **Avatar initial from `"Student #N"`** — when the display name is purely anonymized, the initial fallback rule (use the digit after `#`) is unusual. Designer-accepted because it preserves anonymity. Alternative: use a constant glyph (🎓) for all avatar discs. **Decision: ship the digit-initial; revisit when real names are exposed (which the privacy decision says they won't be).**

**Batch 1 (motion infra) is UNBLOCKED** — all motion specs reference tokens that exist (or have a safe literal fallback). The `useReduceMotion` and `useDashboardDiff` hook shapes are fully specified above. Real Skia ConfettiLayer spec is complete (40/60 particles, gravity, 2000ms lifetime, palette by rarity).
