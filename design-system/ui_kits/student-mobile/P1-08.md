## 1. Token Mapping Table

Every `--lx-*` CSS custom property mapped to a proposed Tamagui token name and its resolved concrete value. Tokens are authored in `packages/design-system/src/tokens/index.ts` and registered via `createTamagui({ tokens })`.

### Notation

- "Resolves via var()" = the CSS source uses a `var()` reference; the resolved hex/rgba value is given here and MUST be used directly in Tamagui (Tamagui does not evaluate CSS var references).
- Flag "NO VALUE IN CSS" = the var is referenced elsewhere but has no assignment in `colors_and_type.css`.

## 3. RTL and Accessibility Rules

### 3a. RTL Wiring

**Source of truth for direction detection:** `@learnexia/shared/i18n` — functions `isRtlLocale`, `directionForLocale`, `applyWebDirection`, `applyNativeRtl`. Do NOT re-implement.

**`LearnexiaProvider` in `packages/design-system/src/rtl/index.ts`:**
- Wraps `TamaguiProvider` from Tamagui
- Accepts a `locale: string` prop
- On mount and on `locale` change:
  - Calls `directionForLocale(locale)` to get `'rtl'` or `'ltr'`
  - On web: calls `applyWebDirection(locale)` (sets `document.documentElement.dir` and `lang`)
  - On native: re-exports `applyNativeRtl` for the app to call with `I18nManager` — the provider itself does NOT call it (native reload required; app controls the trigger)
  - Selects active font: `locale === 'ar'` → Cairo (display) / Tajawal (body); else Poppins (both)
  - Passes selected font family names into TamaguiProvider's theme

**`useDirection(locale: string): Direction` hook:** calls `directionForLocale(locale)` from shared. Returns `'rtl' | 'ltr'`. Components call this to flip layout-direction-sensitive props.

**Native reload caveat (document in JSDoc on `LearnexiaProvider`):**
> `I18nManager.forceRTL` only takes full effect after an app reload. When switching to Arabic on native, call `applyNativeRtl` from `@learnexia/shared/i18n` and trigger an app restart via `react-native-restart`. The `LearnexiaProvider` does not import native modules — the app injects them.

### 3b. Logical Layout Props

Every component in `packages/ui` must use Tamagui's logical spacing/positioning props, never directional `left`/`right`:

| Avoid | Use instead |
|---|---|
| `marginLeft` / `marginRight` | `marginStart` / `marginEnd` |
| `paddingLeft` / `paddingRight` | `paddingStart` / `paddingEnd` |
| `left` / `right` (absolute) | `start` / `end` (absolute logical) |
| `alignSelf: 'flex-start'` (when direction-aware) | pass `direction` prop and conditionally flip |
| `flexDirection: 'row'` for directional sequences | `flexDirection: direction === 'rtl' ? 'row-reverse' : 'row'` for explicit RTL flip |

Tamagui `$start` and `$end` shorthand props map to `marginStart`/`marginEnd` (confirm Tamagui version API — if not available, use `marginStart`/`marginEnd` directly).

### 3c. Kid-Accessibility Baseline

Applied to ALL interactive components. Documented in `packages/ui/src/accessibility.md`.

| Rule | Specification |
|---|---|
| Touch target minimum | `minHeight: 48, minWidth: 48` on all Pressable/touchable roots. Where the visual element is smaller (e.g. a heart icon at 30px), add `hitSlop: { top: 9, bottom: 9, left: 9, right: 9 }` to reach 48px effective area. |
| Focus ring | On web: `box-shadow: 0 0 0 2px #4F46E5, 0 0 0 6px rgba(99,102,241,0.45)` on `:focus-visible`. On native: `accessible={true}` + `accessibilityRole` on all interactive elements. |
| High contrast pairings | `$fg1` (#F8FAFC) on `$primary` (#4F46E5) ≥ 4.5:1. `$fgInverse` (#0F172A) on `$secondary` (#22C55E) ≥ 4.5:1. `$fg1` on `$danger` (#EF4444) ≥ 4.5:1. All text-on-card combos use `$fg1`/`$fg2` on `$card`/`$bg`. |
| Single primary action | Per screen, only one Button with `variant="primary"` is the high-emphasis element. Secondary/Ghost/Success/Danger are supporting. Document this as a usage rule. |
| Press feedback | Every pressable must have a visible state change: scale `0.95` via Reanimated, OR color/bg change, OR elevation change — never a silent press. |
| Visible loading state | Button in `loading` state shows a spinner (Reanimated animated opacity pulse on a circle); label is hidden or replaced. |
| Accessible labels | All non-text interactive elements (heart icon, streak flame, XP bar) must have `accessibilityLabel` prop required in TypeScript. |
| One action per screen | Design pattern note (not enforced by component): screen layouts should contain at most one `variant="primary"` Button visible without scrolling. |

| Disabled | `opacity: 0.4`; `pointerEvents: 'none'` | None |
| Loading | Spinner (Reanimated opacity pulse, 600ms loop) replaces label; button remains interactive-looking but not pressable (`disabled` internally) | Reanimated `withRepeat(withTiming(0.3, { duration: 300 }), -1, true)` on spinner opacity |

#### Sizes

| Size | Height | Horizontal padding | Font size | Touch target |
|---|---|---|---|---|
| `sm` | 40px | `$4` (16px) | 14px | Add `hitSlop: {top:4, bottom:4}` |

Font: display family, weight 700, letter-spacing 0.01em.

#### RTL

No layout flip needed (button label is center-aligned). Icon+label row: use `XStack` with logical spacing. Leading/trailing icon placement uses `marginEnd`/`marginStart`. If button contains a directional chevron icon, flip it when `direction === 'rtl'`.

#### A11y

- `accessibilityRole="button"`, `accessibilityState={{ disabled, busy: loading }}`
- `accessibilityLabel` prop required (no default)
- Contrast: `$fg1` on `$primary` ≥ 4.5:1. `$fgInverse` on `$secondary` ≥ 4.5:1. `$fg1` on `$danger` ≥ 4.5:1.

#### Hover state (web only)

## 7. Design Gaps and Open Questions

These are unresolved items the frontend implementer must decide and document in code (no silent assumptions).

**Gap 1 — Font file path strategy for native**
The brief (Blocker 3) says the implementer should either register fonts from `design-system/fonts/` directly or copy to `packages/design-system/assets/fonts/`. Recommendation: copy the required weights into `packages/design-system/assets/fonts/` so the package is self-contained and portable. Required weights to copy: Cairo (Regular, Medium, SemiBold, Bold, ExtraBold, Black — 6 files); Tajawal (Regular, Medium, Bold, ExtraBold — 4 files); Poppins (Regular, Medium, SemiBold, Bold, ExtraBold, Black — 6 files + italic variants as needed). Decision must be documented in `packages/design-system/src/fonts/index.ts` JSDoc.

**Gap 2 — Missing token for disabled/muted color `#64748B`**
The components-buttons.html and components-badges.html both use `#64748B` for disabled text and locked badge labels, but this color has no `--lx-*` token in `colors_and_type.css`. It falls between `$fg3` (`#94A3B8`) and `$fgInverse` (`#0F172A`). Implementer must decide: (a) add a `$fg4: '#64748B'` token to `packages/design-system/src/tokens/index.ts` and flag it as a "gap-fill" token not in the CSS spec, or (b) use `$fg3` (`#94A3B8`) as the closest existing token. Document the choice.

**Gap 3 — XP bar fill gradient discrepancy**
`components-xp-bar.html` renders the fill bar with `linear-gradient(90deg, #FACC15, #FB923C)` (yellow → orange), but the canonical token `--lx-grad-xp` is `linear-gradient(90deg, #22C55E, #4F46E5)` (green → indigo). The `gradients.html` spec and `Components.jsx` both confirm green → indigo. Implementer must use `gradXp` (`#22C55E → #4F46E5`) as the authoritative fill gradient. The yellow color (`$xp`) is for the XP counter label only. If the yellow-orange fill is desired for a "streak bonus" state, that is a future spec item — do not add it to P1-08.

**Gap 4 — Missing tokens for inline color values**
Several color values used in component previews lack CSS var assignments:
- `#64748B` — disabled/muted text (see Gap 2)
- `#A5B4FC` — light indigo, used for chip text in AITutorBubble and tutor name; closest is `$primaryHover` (`#6366F1`) but `#A5B4FC` is lighter (the 300 shade of indigo). Add `$primaryLight: '#A5B4FC'` as a gap-fill token, or derive via opacity from `$fg1` — document the choice.
- `#E9D5FF` — Legendary badge label color (light purple, purple-200 shade). Add `$purpleLight: '#E9D5FF'` as a gap-fill token.
These three colors appear in the preview HTML but have no `--lx-*` variable. Implementer must add them as undocumented token extensions and note them clearly.

**Gap 5 — Backdrop blur on native**
`AITutorBubble` (AI variant) and `RewardPopup` both use `backdropFilter: blur()` for a frosted glass effect. On web this is CSS-native. On React Native, this requires either `@react-native-community/blur` or Skia blur (via `@shopify/react-native-skia`). Decision: use Skia blur canvas layer for the blur effect on native (consistent with the already-added Skia dependency); fall back to a semi-transparent background without blur if Skia is not available. Implementer decides and documents.

**Gap 6 — Hearts recovering animation timing**
The `components-hearts-streak.html` preview shows a refill timer label but does not specify the recovering animation. This spec defines a pulsing opacity loop on empty hearts when `recoveringIn` is set, but the pulse parameters (speed, amplitude) are not in the kit. Implementer decides: `opacity: [0.35, 0.55, 0.35]`, duration `$durSlow` (400ms) per cycle. Document the choice.

**Gap 7 — AITutorBubble tail implementation**
The preview uses CSS `border-radius` on one corner to create the chat bubble tail effect (`borderBottomLeftRadius: 4px`). This is not a true "tail" triangle. A proper chat bubble tail is either a CSS `::before` pseudo-element (web only), an SVG triangle, or a Skia path. Implementer decides: for cross-platform consistency, use the same corner-radius technique as the preview (flatten one corner to 4px). If a proper triangular tail is desired, it is a visual enhancement not required by the spec.

**Gap 8 — RewardPopup backdrop-blur border radius mismatch**
The preview uses `border-radius: 28px` but the token is `$modal` (24px). Use 24px (the token). The 4px difference is not visually meaningful for this component.

**Gap 9 — Legendary badge hue-rotate animation on native**
The preview uses CSS `filter: hue-rotate()` in a `@keyframes` loop. On native, this requires Skia `ColorMatrix` animation. The implementer should use a Skia canvas layer for the legendary badge on native, or accept a static legendary badge without hue animation on native (with the animation on web only). Document the decision.

## 8. Theme Default Confirmation

Dark theme is the default game-world palette. All 8 in-scope components (Button, Card, XPBar, Hearts, StreakFlame, Badge, AITutorBubble, RewardPopup) render on the dark theme surface by default.

Light theme usage: none of the 8 components are designed to appear on the light surface (`$bgLight`) in the student app. The light theme is defined in Tamagui and available for future parent-dashboard screens (P2/P3 stories), but the `LearnexiaProvider` defaults to dark.

The `TamaguiProvider` `defaultTheme` prop must be `"dark"`.
