## 0.1 Motion token reference (from `packages/design-system/src/tokens/motion.ts` + `colors_and_type.css`)

All timings below are token literals. The frontend must reference these tokens, not hard-coded numbers.

| Token (TS) | Token (CSS) | Value | Usage |
|---|---|---|---|
| `durations.fast` | `--lx-dur-fast` | 120ms | shake oscillation half-period, press feedback |
| `durations.base` | `--lx-dur-base` | 240ms | page transitions, mission-complete row pulse |
| `durations.slow` | `--lx-dur-slow` | 400ms | heart-break settle, glyph swap settle |
| `durations.celebrate` | `--lx-dur-celebrate` | 700ms | XP bar fill, confetti burst lifetime |
| `springs.pop` | — | `{ damping: 10, stiffness: 200 }` | Badge pop-in 0→1.15→1, reward icon entrance |
| `springs.settle` | — | `{ damping: 14, stiffness: 150 }` | Heart-break scale settle |
| `springs.popup` | — | `{ damping: 12, stiffness: 180 }` | RewardPopup card entrance |
| `easings.easeOut` (CSS) | `--lx-ease-out` | `cubic-bezier(0.16,1,0.3,1)` | XP bar fill, transitions |
| `easings.easeSpring` (CSS) | `--lx-ease-spring` | `cubic-bezier(0.34,1.56,0.64,1)` | Pop, badge overshoot |

The **motion infra** (`useReduceMotion`, `ConfettiLayer`, `RewardPopup`, and the Moti/Skia lazy loaders) is already present in `packages/ui`. See §7 (FE-7) for the full picture.

## 0.2 Layout constraint (all screens)

- Mobile primary: 390 wide, safe-area top/bottom applied.
- Horizontal scroll padding: 24px (`--lx-space-6`).
- Content `maxWidth: 720`, `alignSelf: center` (Expo web responsive — W13 precedent).
- Tab screens: clear `CHILD_TAB_BAR_CLEARANCE + insets.bottom` at content bottom.
- Push screens (xp, streak, hearts): no tab bar; `insets.bottom + 24px` at content bottom.
- One primary action per screen (Brand Law §10).
- Touch targets minimum 48×48px.

### §1.2 Hero XP bar fill (post-popup dismiss)

Source: `preview/mobile-level-progress.html`

- Track: 12px height, `borderRadius: 9999` (pill), `backgroundColor: $bgElevated` (#111B33)

### §1.3 Hero level count-up (post-popup dismiss)

After `onDismiss` when `!reduceMotion`:
- Hero level number runs a `requestAnimationFrame` count-up from `celebration.fromLevel` to `celebration.toLevel` over 600ms (`COUNT_UP_MS` literal — not a named token, kept as constant in screen).
- Font: `fontSize: 48` (`--lx-size-display`), `fontWeight: 800`, `fontFamily: $heading`, `fontVariant: ['tabular-nums']`
- Color: `$fg1`, rendered on a 160×160 `$primarySoft` disc (`backgroundColor: rgba(79,70,229,0.18)`)
- Reduce-motion: jump directly to `toLevel`, no animation

### §1.4 Confetti palette for level-up

`ConfettiLayer` (already ships in `packages/ui/src/internal/ConfettiLayer.tsx`):

### §5.2 Heart-break animation (wrong-answer arrival via `?lost=1`)

This is the most complex motion in the hearts screen. From the brand law (§12) + hearts.tsx implementation:

**Sequence on the most-recently-lost heart slot** (`breakingIndex = hearts` — the first empty index):

```
Phase 1 — Scale up + glyph swap at 80ms:
  MotiView from={{ scale: 1, opacity: 1 }}
           animate={{ scale: [1.2, 1], opacity: [1, LOST_OPACITY (0.3)] }}
  spring: { scale: springs.settle, opacity: { type: 'timing', duration: durations.slow } }
  At t=80ms (HEART_BREAK_SWAP_MS): glyph changes ❤️ → 💔 via setTimeout
  At t=80ms + durations.slow (480ms): glyph settles back to ❤️ (lost state)
```

**Reduce-motion fallback:**
- No MotiView wrapper
- Instant gray-out: `opacity: LOST_OPACITY` rendered immediately
- No glyph swap

**Note on `durations.slow`** (400ms): the glyph settles back to ❤️ (the lost state consistent with other empty hearts) so the row stays visually uniform. The 💔 glyph is only a mid-animation flash.
