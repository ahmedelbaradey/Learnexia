**Surface:** `apps/admin-dashboard` (Next.js 15, App Router, desktop-first)
**Token authority:** `packages/design-system/src/tokens/` + `design-system/colors_and_type.css`
**Design system version:** P1-08 baseline (tokens + `Button` + `Card` from `packages/ui`)
**Locale scope:** English (LTR) primary for v1; providers wired for RTL/AR (see Section 5).

## 2. Design Principles for the Admin Surface

The admin dashboard is an **operator/professional surface**, not a gamified student screen. Apply the same token system but with restraint:

- No confetti, no XP bars, no streak flames, no mascot.
- Dark palette retained (same `$bg`, `$card`, `$primary` tokens) — dark is the design-system default.
- Typography is Poppins (EN) / Cairo (AR) at conservative weights. No `lx-display` (48px) size on this surface.
- Motion is minimal: form field focus transitions, button press scale, skeleton shimmer, and a single loading spinner. No celebratory animations.
- Spacing is denser than the kid app: cards may use `$4` (16px) padding, not forced to `$6` (24px) everywhere.
- One primary action per page (Sign-In button on login; sign-out is a secondary/ghost action in the shell).

## 3. Screen: Admin Sign-In Page (`/login`)

### 3a. Layout

This is a **centered-card, full-viewport** layout. No side nav, no top bar — this is the pre-auth gate.

**Desktop (≥ 1024px — `$laptop` breakpoint)**

```
[Full-viewport column, bg $bg (#0F172A), min-height 100vh]
  [Centered container, max-width 440px, margin: auto, padding-top: $16 (64px)]
    [Logo — design-system/assets/logo.svg, height 36px, margin-bottom $8 (32px)]
    [Login Card — Card variant="default", padding $8 (32px), radius $modal (24px)]
      [Heading "Admin Sign In" — H2 style]
      [Subheading — optional muted label, body-sm, $fg3]
      [Spacer $6 (24px)]
      [Username / Email field]
      [Password field]
      [Error banner — conditional, danger state]
      [Spacer $6 (24px)]
      [Sign In button — Button variant="primary", size="full"]
    [Fine print — "Authorised personnel only", $fg3, body-sm, centered, margin-top $4]
```

**Tablet (768–1023px — `$tablet` breakpoint)**

Same card layout. Max-width drops to 400px. Padding-top reduces to `$10` (40px). Logo is the `logo-mark.svg` (icon only, 40px square) instead of the full wordmark to conserve horizontal space.

**Phone / narrow (< 768px — `$sm` breakpoint)**

Full-bleed: card becomes flush to the viewport edges. Padding-top `$6` (24px). Card uses `borderRadius: 0` at `$sm` (override `$modal` radius — card fills the screen). Logo centered above card, 28px height. This is a secondary use case; the admin tool is desktop-primary.

### 3b. Component Composition — Login Card

```
LoginCard
  ├── Logo                    → <img src="design-system/assets/logo.svg" /> (Next <Image />)
  ├── Heading "Admin Sign In" → <Text> fontFamily="$heading" fontSize={$6=24px} fontWeight="700" color="$fg1"
  ├── Subheading (optional)   → <Text> fontFamily="$body" fontSize={$3=14px} color="$fg3"
  ├── UsernameField           → AdminInputField (admin-local, see §3d)
  ├── PasswordField           → AdminInputField with type="password" + toggle icon
  ├── ErrorBanner             → AdminErrorBanner (admin-local, see §3e) — conditional
  └── SignInButton            → Button (packages/ui) variant="primary" size="full"
```

**Card tokens:**
- Background: `$card` (`#1E293B`)
- Border: `1px solid $border` (`rgba(255,255,255,0.08)`)
- Border-radius: `$modal` (24px) — overrides Card's default `$card` (20px); use inline `borderRadius="$modal"` prop
- Shadow: `shadowFloat` (`0 8px 24px rgba(0,0,0,0.25)`)
- Padding: `$8` (32px) all sides

### 3c. Sign-In Page States

| State | Visual |
|---|---|
| **Default** | Fields empty, no error banner, button enabled |
| **Typing (field focus)** | Input border turns `$borderFocus` (`#4F46E5`), focus ring `0 0 0 2px #4F46E5, 0 0 0 6px rgba(99,102,241,0.25)` — see §3d |
| **Loading (submitting)** | Button renders `loading={true}` state (Spinner replaces label, button not pressable). Username + password fields get `disabled` styling (`opacity 0.5, pointerEvents none`). |
| **Invalid credentials** | ErrorBanner appears below password field. Copy: EN "Incorrect username or password." / AR "اسم المستخدم أو كلمة المرور غير صحيحة." Fields retain values. Button re-enabled. |
| **Non-admin / forbidden** | ErrorBanner with forbidden variant. Copy: EN "Access denied. This portal is for administrators only." / AR "الوصول مرفوض. هذه البوابة مخصصة للمسؤولين فقط." |
| **Network / server error** | ErrorBanner with error variant. Copy: EN "Something went wrong. Please try again." / AR "حدث خطأ ما. يرجى المحاولة مرة أخرى." |
| **Redirect skeleton** | Full-page loading skeleton (see §6) — shown when `authStore.status === 'unknown'` and the guard has not resolved yet. Sign-in page itself is visible only when status is `signed-out`; if status is `signed-in` the guard redirects to `/dashboard` immediately. |

### 3d. Admin-Local Component: `AdminInputField`

This is a **new admin-local primitive** (lives in `apps/admin-dashboard/components/AdminInputField.tsx`). It is NOT a `packages/ui` component because the kid-facing `packages/ui` has no text input component and adding one in scope of this story is out of bounds.

**Anatomy:**
```
[Field root — YStack, gap $1 (4px)]
  [Label — Text, fontSize 12px, fontWeight 600, color $fg3, textTransform uppercase, letterSpacing 0.06em]
  [Input wrapper — XStack, height 48px, bg $card (#1E293B), border 1px solid $border,
                   borderRadius $sm (8px), paddingHorizontal $4 (16px), alignItems center]
    [Input element — native <input>, flex 1, bg transparent, color $fg1, fontSize 15px,
                     fontFamily $body (Poppins), outline none]
    [Trailing icon slot — optional, 20px, color $fg3]  ← password toggle eye icon
  [Hint text — conditional, Text fontSize 12px, color $danger]  ← only on error state
```

**States and tokens:**

| State | Border | Box shadow | Label color |
|---|---|---|---|
| Default | `1px solid $border` (`rgba(255,255,255,0.08)`) | none | `$fg3` |
| Focus | `1px solid $borderFocus` (`#4F46E5`) | `0 0 0 2px #4F46E5, 0 0 0 6px rgba(99,102,241,0.25)` | `$fg3` |
| Error | `1px solid $danger` (`#EF4444`) | `0 0 0 2px #EF4444, 0 0 0 4px rgba(239,68,68,0.2)` | `$fg3` |
| Disabled | `1px solid $border`, `opacity 0.5` | none | `$fg3` |
| Filled (value present, no focus) | `1px solid $borderStrong` (`rgba(255,255,255,0.16)`) | none | `$fg3` |

Source: mirrors `design-system/preview/components-input.html` spec (`.focus` and `.err` classes).

**Password toggle:** a 20px eye/eye-off SVG icon button, color `$fg3`, hover `$fg2`. Toggle button is 32×32px with negative margin to avoid expanding the field height; meets 44px hitSlop via padding.

**Props (TypeScript interface):**
```
interface AdminInputFieldProps {
  label: string;
  name: string;
  type?: 'text' | 'email' | 'password';
  placeholder?: string;
  error?: string;
  disabled?: boolean;
  // react-hook-form compatible
  value?: string;
  onChange?: React.ChangeEventHandler<HTMLInputElement>;
  onBlur?: React.FocusEventHandler<HTMLInputElement>;
}
```

**Motion:** border-color and box-shadow transition at `120ms cubic-bezier(0.16,1,0.3,1)` (`$durFast`, `$easeOut`).

**RTL:** `direction: 'rtl'` on the input wrapper when locale is AR, so the label/placeholder text aligns right. Eye icon moves to the start side in RTL (logical `marginStart: 0, marginEnd: $2`).

**A11y:** `<label>` element for association. `aria-invalid="true"` on the native input when in error state. `aria-describedby` pointing to the hint text element id. Focus ring visible at `:focus-visible`. Min height 48px already satisfied by the 48px input wrapper.

### 3e. Admin-Local Component: `AdminErrorBanner`

Lives in `apps/admin-dashboard/components/AdminErrorBanner.tsx`.

**Anatomy:**
```
[Banner root — XStack, gap $3 (12px), padding $4 (16px), borderRadius $sm (8px),
               border 1px solid (variant-dependent), alignItems flex-start]
  [Icon — 20px SVG or emoji: danger variant = warning triangle, forbidden variant = lock]
  [Text — Text, fontSize 14px, color $fg1, lineHeight 1.5]
```

**Variants and tokens:**

| Variant | Background | Border | Icon color |
|---|---|---|---|
| `error` (invalid credentials / server) | `$dangerSoft` (`rgba(239,68,68,0.18)`) | `1px solid rgba(239,68,68,0.3)` | `$danger` (`#EF4444`) |
| `forbidden` (non-admin) | `rgba(168,85,247,0.15)` (purple-soft, near `$purpleSoft`) | `1px solid rgba(168,85,247,0.3)` | `$purple` (`#A855F7`) |
| `warning` (network) | `$warningSoft` (`rgba(245,158,11,0.18)`) | `1px solid rgba(245,158,11,0.3)` | `$accent` (`#F59E0B`) |

**Motion:** banner entrance — CSS `opacity: 0 → 1` + `translateY: -4px → 0` over `240ms $easeOut`. Applied via a small CSS animation class (since this is a Next.js web app, a CSS `@keyframes` approach is appropriate and avoids native-only Moti).

**A11y:** `role="alert"` so screen readers announce the error immediately. No `aria-live` needed since `role="alert"` implies `aria-live="assertive"`.

## 5. Route Guard and Auth States

### 5a. Auth status → visual mapping

The `useAdminGuard` hook produces one of three states. Each maps to a distinct visual:

| Auth status | Roles check | Visual rendered |
|---|---|---|
| `'unknown'` (hydrating) | — | Full-page loading skeleton (§5b) |
| `'signed-out'` | — | Redirect to `/login` (no content rendered) |
| `'signed-in'` + has admin/superadmin role | passes | Dashboard shell + children |
| `'signed-in'` + does NOT have admin/superadmin role | fails | Redirect to `/login` (role gate fires) |

The guard is **client-side only** (sessionStorage not readable at Next.js edge). This is documented as an accepted limitation. No protected content should flash during the `'unknown'` window — the skeleton prevents this.

### 5b. Loading Skeleton

Displayed when `authStore.status === 'unknown'` — covers the entire viewport, preventing a flash of the protected shell or the login redirect.

**Skeleton layout (mimics the shell outline):**

```
[Full viewport — bg $bg (#0F172A), display flex, flexDirection row]

  [Left column skeleton — width 240px, bg $bgElevated]
    [SkeletonBlock: 28px height (logo placeholder), margin $6, rounded]
    [SkeletonBlock × 2: nav items, height 44px each, margin $4 horizontal, rounded $button]

  [Right column — flex 1, flexDirection column]
    [Top bar skeleton — height 64px, bg $bgElevated]
      [SkeletonBlock: width 100px, height 16px, absolute right $6, rounded]
      [SkeletonBlock: width 80px, height 32px, absolute right (100px + $4), rounded]
    [Content area — padding $8]
      [SkeletonBlock: width 40%, height 24px, rounded (heading)]
      [SkeletonBlock: width 60%, height 16px, marginTop $4, rounded (subheading)]
```

**Skeleton shimmer animation:**

A repeating horizontal shimmer sweep using CSS `@keyframes`:
```
@keyframes lx-shimmer {
  0%   { background-position: -200px 0; }
  100% { background-position: calc(200px + 100%) 0; }
}
```
Each `SkeletonBlock`:
- Background: `linear-gradient(90deg, $card (#1E293B) 0%, $cardSoft (#334155) 50%, $card (#1E293B) 100%)`
- `background-size: 400px 100%`
- Animation: `lx-shimmer 1.4s ease infinite`

This is a CSS animation (not Moti/Reanimated) — appropriate for a Next.js web target.

**Admin-local component:** `apps/admin-dashboard/components/AdminLoadingSkeleton.tsx`

**A11y:** `role="status"`, `aria-label="Loading, please wait"` (EN) / `"جارٍ التحميل، يرجى الانتظار"` (AR). `aria-live="polite"`.

## 7. RTL / i18n

### Language selector

v1 ships **English as the default** for the admin dashboard. The `LearnexiaProvider` (from `packages/design-system/src/rtl/index.tsx`) is wired in the root layout with `locale="en"` initially. A locale toggle is not required for this story — providers are wired so AR can be added later.

### RTL structural flips (if AR locale is active)

| Element | LTR | RTL |
|---|---|---|
| Side nav | Left column | Right column |
| Side nav active indicator | `3px solid $primary` on left edge | `3px solid $primary` on right edge (use `borderInlineStart`) |
| Top bar layout | Identity + sign-out on the right | Identity + sign-out on the left |
| Input labels/placeholders | Left-aligned | Right-aligned (`dir="rtl"` on input) |
| Error banner icon | Leading (left) | Leading (right, logical) |
| Avatar initials | Left of name | Right of name |

Use CSS logical properties throughout the admin app:
- `margin-inline-start` / `margin-inline-end` instead of `margin-left` / `margin-right`
- `padding-inline-start` / `padding-inline-end`
- `border-inline-start` for the active nav item indicator
- `inset-inline-start` / `inset-inline-end` for absolute positioned elements

**Fonts:**
- EN locale → `'Poppins', system-ui, sans-serif` (display + body)
- AR locale → `'Cairo', system-ui, sans-serif` (display/headings), `'Tajawal', system-ui, sans-serif` (body/labels)

Font loading: the admin app uses CSS `@font-face` loaded via the Next.js root layout global stylesheet (Next handles font optimization). The fonts are available in `packages/design-system/assets/fonts/` and `design-system/fonts/`.

### Token consumption method in Next.js

In this Next.js admin app, Tamagui tokens are consumed via:
1. **Tamagui-styled components** (for `Button` and `Card` from `packages/ui`) — tokens like `$primary`, `$card`, `$fg1` work via the `TamaguiProvider` + `@tamagui/next-plugin`.
2. **CSS custom properties** — for the admin-local components that are plain React/HTML (e.g. `AdminInputField`), use CSS module classes or a small inline `style` object referencing the resolved hex values from `colors_and_type.css` (which is a plain CSS file importable in Next.js via a global import).
3. **CSS `@keyframes`** — for shimmer and error banner animations; placed in the admin app's global CSS file.

**Recommendation for admin-local components:** use `colors_and_type.css` CSS variables (`var(--lx-primary)`, etc.) in a Next.js CSS module. This avoids Tamagui's styled overhead for simple web-only components and keeps the build straightforward.

## 11. Design Gaps and Open Questions

**Gap 1 — No icon set for side nav placeholders.**
`design-system/assets/icons/` contains only `flame.svg`, `heart.svg`, and `star.svg` — gamification icons not suitable for admin nav items. The admin nav needs generic UI icons (book, document, etc.). For this story, use emoji (`📚`, `📄`) or a minimal inline SVG square as a placeholder. Flag for a future icon library story.

**Gap 2 — Nav drawer state management at tablet breakpoint.**
The icon-rail + drawer overlay design at tablet width requires a state variable (`isNavOpen: boolean`) in `AdminShell`. The spec defines the layout but the exact drawer animation (slide-in from left/right per locale) is implementation-defined. Suggested: `translateX(-100%)` → `translateX(0)` over `240ms $easeOut` for LTR; `translateX(100%)` → `translateX(0)` for RTL. This is a CSS transition, no Moti needed.

**Gap 3 — Top bar page title slot.**
The `AdminTopBar` has a page title slot. For the landing page it reads "Dashboard". How this slot is populated for future admin pages (e.g. "Curriculum") is not defined in this story. Suggested pattern: each child page passes its title via a React context or a Next.js layout metadata approach. Not in scope for P1-10 — the frontend agent may hardcode "Dashboard" for now.

**Gap 4 — Locale toggle for admin.**
Open question from the brief: does the admin dashboard ship AR/EN toggle in v1 or English-only? The spec wires the providers for RTL readiness but defaults to English. If the lead requires a locale toggle in the top bar for v1, it is an additional `AdminLocaleToggle` component (a simple EN/AR text button). Not designed here pending lead confirmation.

**Gap 5 — Password "Forgot password" flow.**
The brief is explicit: no self-registration, no public admin registration. "Forgot password" is out of scope (admins are seeded/invited; password reset is an ops task). Confirm with lead that no forgot-password link is needed even in v1. This spec includes no such link.

**Gap 6 — `AdminInputField` vs `@tamagui/input`.**
Tamagui ships an `Input` primitive (`@tamagui/input`) that would work in a Next.js build. The admin-local `AdminInputField` wraps a native `<input>` element for simplicity and to avoid a potentially large additional dependency. If the frontend agent prefers to use `@tamagui/input` (which is part of the `tamagui` full package, not `@tamagui/core`), they may do so — provided `@tamagui/input` is added to `apps/admin-dashboard/package.json` without touching `packages/*`. The visual spec in §3d remains the authority regardless of implementation approach.

**Gap 7 — `logo.svg` color on dark background.**
The `design-system/assets/logo.svg` may contain light or dark variants of the wordmark. The admin login page and side nav use it on a dark background (`$bg` or `$bgElevated`). The frontend agent must verify that the logo SVG renders correctly (light wordmark) on the dark surface. If not, request a dark-variant asset or apply CSS `filter: invert(1)` as a stopgap (flag this).
