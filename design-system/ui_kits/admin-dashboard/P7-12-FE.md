# Design Spec — P7-12 Admin Action Audit Log Viewer

**Surface:** `apps/admin-dashboard` (Next.js 15, desktop-first, dark theme)
**Route:** `app/(admin)/audit/page.tsx`
**Token authority:** `design-system/colors_and_type.css` + the shipped `--lx-*` variable set
**Shell authority:** `P7-admin-users-wave.md` (same AdminShell, same token language — everything below is additive)
**Locale:** English-first, RTL-ready (all copy has AR slot; no live toggle this wave)
**Theme:** dark by default (`$bg #0F172A`)
**Read-only invariant:** ZERO mutation affordances anywhere on this surface. No edit, delete, restore, or any form submission. The audit log is immutable; the UI must reflect that unconditionally.

> No new screenshot captures exist for admin console screens. All specs are derived from the token set, the shipped `users/page.tsx` four-state pattern (the direct mirror), and the P7 admin wave spec. This is not a gap — it is the same condition as all prior admin wave specs.

---

## Admin surface design principles (carry-forward — enforce identically)

All principles from `P7-admin-users-wave.md` §"Admin surface design principles" apply without exception:

1. No gamification chrome — no XP bars, no reward gradients, no confetti, no mascot.
2. No Level-Up / Reward / XP gradient fills on any element.
3. Motion minimal: hover 120ms, dialog 200–240ms, skeleton shimmer 1400ms. No spring easing.
4. One primary action per screen — here there is NO primary action (read-only). The concept of a CTA button does not apply.
5. Typography: Poppins (EN) / Cairo (AR display headings) / Tajawal (AR body).
6. Density: compact table, card padding `$4` (16px) or `$6` (24px) per element.

**Filter state wiring:** each filter change resets `PageNumber` to 1 immediately, then fires the hook. The admin-id numeric input is treated as a string in state (`''` = no filter, non-empty = parseInt → `AdminUserId` query param). The action-type and target-type selects send the raw string value on the wire (`ActionType`/`TargetEntityType` params).

**Note on high-volume read actions (OQ5):** `User.Searched` and `User.Viewed` (P7-06) are emitted on every admin search/view and may dominate the default feed. This spec defaults to showing all action types (no pre-filter). The action-type dropdown is grouped and prominent; admins can filter away read-only noise. Product should monitor whether a "mutations only" default filter is needed. Flag as a follow-up product decision.

**AR numeral rule for pagination:** the AR copy `"الصفحة {N} من {T}"` uses Eastern-Arabic numerals for `N` and `T` in inline reading text (per Arabic/RTL conventions), but the outer `<span>` is `dir="ltr"` because it is a technical position indicator. Use `Intl.NumberFormat('ar-EG').format(currentPage)` for AR pagination text.

**AR numeral rule for admin IDs, entity IDs, event GUIDs:** ALWAYS Latin numerals + `dir="ltr"`. These are technical identifiers, never reading text.

## PART O — Design Gaps and Open Questions

**OQ1 (resolved — deferred) — Export.** Backend has no export endpoint. Export is not built. PR must record the AC gap. Follow-up: backend story for `GET /api/Admin/Audit/Log/Export`. See §L.

**OQ2 (resolved) — Backend contract.** FE codes to the merged contract: `GET /api/Admin/Audit/Log`, single `details` string, no `before/after`, no export, `AuditLogDto` as in §F.1. The stale task file contract is superseded by the brief.

**OQ3 (resolved) — Detail shape.** Inline row expand (no `/audit/[id]` route). Rationale: no backend single-entry `GET /api/Admin/Audit/Log/{id}` endpoint exists; the already-fetched row data is sufficient; deep-linking is not a compliance requirement. See §E.

**OQ4 (resolved — copy for now) — Shared primitives.** `useDebounce`, `Pagination`, `SkeletonRow`, `selectStyle` are copied from `users/page.tsx` into the audit page. No extraction to shared admin components in this wave (same decision as Wave 2). Flag for a future extraction sprint.

**OQ5 (noted, not resolved) — High-volume read actions.** `User.Searched` and `User.Viewed` may dominate the default feed. Spec defaults to showing all (product decision). See §B.2 note.

**OQ6 (resolved) — `details` rendering.** Try `JSON.parse` → pretty-print if success, else plain text. Never HTML. Never `dangerouslySetInnerHTML`. See §E.1.

**Gap 1 — No admin icon set.** Same as prior waves. `AdminSideNav` uses `🔍` emoji placeholder for the audit item. Lucide `scroll-text` is the recommended replacement if an icon set is introduced.

**Gap 2 — `auditResultCount` pluralization.** The EN string "entries" is invariant (used as a suffix: "42 entries"). AR "سجل" is also invariant in this usage (number + word without full pluralization inflection). If grammatically correct AR pluralization is required (سجل / سجلّان / سجلات), it is a follow-up localization task — the current spec uses the simple suffix form consistent with how `usersResultCount` is handled in `P7-admin-users-wave.md`.

**Gap 3 — `targetEntityId === 0` display.** Batch/multi-row actions emit `targetEntityId = 0`. The spec renders `"—"` in the Target ID cell and omits the `#0` chip. If the backend changes this convention to `null` in a future sprint, the FE condition changes from `> 0` to `!= null`.

**Gap 4 — Copy-to-clipboard progressive enhancement.** `navigator.clipboard.writeText` requires a secure context (HTTPS or localhost). The admin dashboard runs on localhost in dev (secure) and HTTPS in production. No fallback needed; the button is omitted on environments where the API is unavailable. The optional nature of this feature means the frontend agent may choose to omit the copy button entirely with no spec violation.

**Gap 5 — Pagination in AR locale.** The page-info text in AR should use Eastern-Arabic numerals for the page numbers (they are reading text: "الصفحة ١ من ٣"). The implementation uses `Intl.NumberFormat('ar-EG').format(n)` for the AR locale. Latin numerals for the EN locale. The container `dir` should be `ltr` since the string reads left-to-right as a navigation label even in Arabic.
