# Design Spec — P7-13 Gamification Admin Overrides
## Surface: `apps/admin-dashboard` (Next.js 15, desktop-first, dark theme, Wave 3)

**Token authority:** `design-system/colors_and_type.css`
**Shell authority:** `design-system/ui_kits/admin-dashboard/P1-10.md` + `P7-admin-users-wave.md`
**No new screenshots exist** for admin console screens. All specifications derive from the established admin shell tokens, the P7-users-wave design spec primitives, the merged backend controller DTOs/validators, and the `--lx-*` token set.
**Locale:** English-first, RTL-ready (all copy has AR slot; single build-time `ADMIN_LOCALE`, no runtime toggle — consistent with Waves 1–2).
**Theme:** dark by default (`--lx-bg` `#0F172A`).

---

## Admin surface design principles (inherited, enforced here)

1. No gamification chrome on this surface. No XP bars, confetti, streak flames, mascots, or reward gradients.
2. No Reward or Level-Up gradient fills on any element.
3. Motion is minimal: hover transitions 120ms `--lx-ease-out`, dialog entrances 200ms fade+translate, skeleton shimmer. No spring overshoot.
4. One primary action per page.
5. Typography: Poppins (EN). Cairo (AR display/headings). Tajawal (AR body). Max heading: H2 24px (`--lx-size-h2`).
6. Table density: compact. Cards may use `$4` (16px) padding where tight.

## PART N: Accessibility Specification

1. **Guard:** `useAdminGuard` loading state renders `AdminLoadingSkeleton` with `role="status"` `aria-label={strings.loadingLabel}` — no protected content flash.
2. **Tables:** `<caption className="sr-only">` on every `<table>`; `<th scope="col">` on all headers; `aria-live="polite"` on the results region (`id="results-region"`); `aria-busy={isFetching}` on the region during refetch; `data-testid` on each `<tr>` for e2e.
3. **Forms:** every input has a visible `<label>` via `htmlFor`; required fields have `aria-required="true"` and a visual `*` marker; errors linked via `aria-describedby`; `role="alert"` on error spans; `aria-invalid` on invalid fields.
4. **Dialogs:** `role="dialog"` `aria-modal="true"` `aria-labelledby={titleId}` on the card; focus trap via the established `getFocusableElements` pattern; ESC closes (cancel path); no backdrop dismiss; focus returns to trigger on close.
5. **Confirm buttons:** `aria-disabled="true"` (not HTML `disabled`) when gating conditions unmet — keeps button focusable for screen readers. Visual: `opacity 0.4`.
6. **Toggle-active buttons:** `aria-busy="true"` while PATCH in-flight; spinner replaces label text but a `.sr-only` span preserves the label for AT.
7. **Touch targets:** all interactive elements ≥ 44px height; icon-only buttons use `aria-label`.
8. **Color contrast:** all text-on-background combinations use the established `$fg1/#F8FAFC`, `$fg2/#CBD5E1`, `$fg3/#94A3B8` on `$card/#1E293B` — verified to meet WCAG AA (7.4:1, 5.2:1, 3.5:1 respectively).

## Design Gaps and Open Questions

**Q1 — RESOLVED (locked):** Student picker for league-tier + freeze is the existing `users/[id]` detail page. No new picker. Entry point is the secondary Actions card Gamification Overrides subsection, only visible when `isStudent === true`.

**Q2 — OPEN (freeze balance read gap):** No endpoint exposes `FreezeBalance` for admins. The `GrantStreakFreezeDialog` renders `strings.gamFreezeBalanceUnavailable` in an informational notice strip. Flag to lead: a minimal BE addition (`GET api/Admin/Gamification/children/{childId}/streak-freeze` or extending `AdminActivitySummaryDto` with `freezeBalance`) would improve the UX. Does not block the FE build.

**Q3 — TRACKED (create returns Id=0 pre-fix):** All three create mutations must never navigate by returned id or optimistically insert. Always invalidate + refetch the list. The spec enforces this explicitly. Fix status with the BE lead — non-blocking for FE.

**Q4 — RESOLVED:** `MissionType` has exactly `Daily=1` and `Weekly=2`. The `MissionForm` cadence select has exactly two options. No "weekly-challenge" option. If product wants it, it is a BE enum change (out of scope).

**Q5 — TRACKED (league-tier caveat):** `useUserActivity → league.tier` is the weekly cohort tier and may be null or lag behind the actual `StudentXpProfile.CurrentTier`. The dialog displays it as best-effort with the `strings.gamLeagueTierCaveat` note. The override itself writes `CurrentTier` on the BE. No FE change needed, but the copy must set expectations.

**Gap: `--lx-focus-ring-admin` token.** The existing admin components reference `var(--lx-focus-ring-admin)` in inline styles (confirmed in `GradeOverrideDialog.tsx` and `ReasonField.tsx`). This token is NOT in `design-system/colors_and_type.css` (which only defines `--lx-focus-ring`). It is presumably defined in `apps/admin-dashboard/globals.css`. The frontend agent must ensure it is defined before using it in the new components. Suggested value (from the P7-users-wave spec §A.3): `0 0 0 2px #4F46E5, 0 0 0 6px rgba(79,70,229,0.25)`. Flag if absent.

**Gap: `--lx-focus-ring-error` token.** Also referenced in `ReasonField.tsx`. Same caveat — must exist in `globals.css`. Suggested value: `0 0 0 2px #EF4444, 0 0 0 4px rgba(239,68,68,0.20)`.

**Gap: `AdminStrings` success variant banner.** The `AdminErrorBanner` `variant="success"` was identified as a design gap in the Wave-1 spec (§D.3) and proposed to be added then. Verify it was actually added before using it for gamification override success banners. If not yet added: `backgroundColor rgba(34,197,94,0.15)`, `borderColor rgba(34,197,94,0.30)`, icon `check-circle` at `#22C55E`.

**Gap: Timed event description fields not in list DTO.** `TimedEventListItemDto` does NOT include `descriptionEn/descriptionAr`. The list page cannot show description. For the edit form, the FE would need to either store the last-known description in local state (from the create) or fetch the full event detail to pre-fill the description. If there is no `GET .../TimedEvents/{id}` endpoint, the description fields in the edit form cannot be pre-filled from the list DTO. Flag to the lead: either add a detail endpoint (`GET api/Admin/Gamification/TimedEvents/{id}`) or accept that description cannot be pre-filled in edit mode and admins must re-enter it. This is an OPEN QUESTION for the frontend agent to raise before building `TimedEventForm` edit mode.

**Gap: `AdminConfirmDialog` `retire` and `expire` variants SVG icons.** The `ArchiveIcon` SVG is already in `AdminConfirmDialog.tsx` (used for the existing `archive` variant). The `retire` variant can reuse `ArchiveIcon`. The `expire` variant needs a `ClockIcon` SVG inline function to be added. The `gamification-override` variant needs a `ShieldIcon` inline SVG (distinct from `ShieldCheckIcon` in `GradeOverrideDialog` — just the plain shield outline).

**No new abstractions introduced.** All patterns mirror existing: `SubjectForm` → forms; `GradeOverrideDialog` → override dialogs; `AdminConfirmDialog` → confirm patterns; `ActiveBadge` → status display; `StatusBadge` → tier/status pills. CLAUDE.md rule 8 satisfied.
