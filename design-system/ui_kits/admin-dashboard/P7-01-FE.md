# Design Spec — P7-01-FE Manage Subjects & Units

**Surface:** `apps/admin-dashboard` (Next.js 15, desktop-first, dark theme)
**Token authority:** `design-system/colors_and_type.css` (`--lx-*`)
**Visual baseline:** `design-system/ui_kits/admin-dashboard/P7-admin-users-wave.md` (Wave 1 spec — carry all conventions forward)
**Code baseline:** `apps/admin-dashboard/app/(admin)/users/page.tsx` + `components/AdminShell`, `AdminConfirmDialog`, `StatusBadge`, `AdminErrorBanner`, `AdminSideNav`
**Locale:** English-first (`ADMIN_LOCALE = 'en'`); AR strings authored statically; no live toggle
**Theme:** dark by default (`$bg #0F172A`)

> **No screenshot captures exist** for the admin console curriculum surface. All specifications are derived from the Wave-1 token and component baseline, the P7-01 brief DTOs, and the `--lx-*` token set. This is the same approach used for the Wave-1 spec and is documented there.

> **Lifecycle (Draft/Published/Archived) is NOT in scope.** P7-01 exposes only `IsActive (bool)`. P7-05 owns the `LifecycleBadge` / `CurriculumLifecycleControl`. Every subject row and unit row/detail carries a **P7-05 Lifecycle Slot** (specified in §S5 below) — an empty reserved area that P7-05 can drop `LifecycleBadge` into without touching P7-01 components.

## Admin surface design principles (inherited from Wave 1 — unchanged)

1. No gamification chrome — no XP bars, confetti, reward gradients, streak flames.
2. Dark canvas by default (`#0F172A`). Cards step lighter (`#1E293B` → `#334155`). No darkening on interaction.
3. Motion is minimal: hover transitions 120ms, dialog entrances 200ms fade+translate, skeleton shimmer. No spring overshoot.
4. One primary action per screen.
5. Typography: Poppins (EN). Cairo (AR display/headings). Tajawal (AR body). Max heading H2 24px on this surface.
6. Density: `$4` (16px) card padding where tight. Tables are compact.
7. Semantic `<table>` always — no CSS-grid table substitutes.
8. Focus ring: `--lx-focus-ring` = `0 0 0 2px #4F46E5, 0 0 0 6px rgba(99,102,241,0.45)` on all interactive elements.

## S1 — Nav: Curriculum link in `AdminSideNav`

### What changes
The existing `curriculum` item in `NAV_ITEMS` is currently `kind: 'placeholder'` with `aria-disabled`. This must be promoted to `kind: 'real'` with an active-aware link.

### Updated entry

```typescript
{
  kind: 'real',
  key: 'curriculum',
  label: strings.navCurriculum,   // EN: 'Curriculum' / AR: 'المناهج'
  icon: '📚',                     // Design Gap: emoji placeholder — see Gap 1
  href: '/curriculum/subjects',
}
```

Active detection: `pathname === item.href || pathname.startsWith('/curriculum/')` — covers both the subjects list and the `[id]` subject-detail route.

### Active state tokens (unchanged from Wave 1, §B.6)

| Token | Value |
|---|---|
| Background | `$primarySoft` = `rgba(79,70,229,0.18)` |
| Border start | `3px solid $primary (#4F46E5)` via `borderInlineStart` (RTL-safe) |
| Icon color | `$primary` — applied to the emoji wrapper (emoji inherits; Lucide svg `stroke`) |
| Label weight | `fontWeight 600` |
| Label color | `$fg1` (`#F8FAFC`) |

Inactive hover: `backgroundColor $card (#1E293B)`, transition `120ms --lx-ease-out`.

### Icon note
The emoji `📚` is used here purely as a placeholder because no admin Lucide icon set exists (Design Gap 1, inherited from Wave 1). The front-end agent should use a Lucide `book-open` SVG (2px stroke, 18px, rounded caps) instead of the emoji character, exactly as the Wave-1 `users` item should use Lucide `users`. Both are currently emoji placeholders; the admin Lucide icon gap is tracked but not fixed here.

## S6 — Reorder: keyboard-first `ReorderableList`

### Decision (D2 from the plan)

No drag-and-drop library. Keyboard-first reorder with move-up/move-down controls. This is the mandated default (CLAUDE rule #8 — no new dep without explicit lead approval). The implementation is a thin reorder utility alongside each ordered list, not a compound component.

### Reorder entry point

The reorder affordance appears on the Subject list page (scoped to one language tree when a grade + a single language are both selected) and on the Subject detail page (units list, always scoped to one subject).

#### Reorder activation model

Reorder mode is **not a separate mode toggle** — the move controls are always visible when reorder is enabled (grade selected + single language selected for subjects; always for units). This avoids hidden affordances.

When reorder is disabled (language = "all" on subjects list), the move controls have `aria-disabled="true"`, opacity 0.4, cursor not-allowed.

### Move controls anatomy

Each reorderable row gains two additional icon buttons at the inline-start of the Order cell (before the order number):

```
[Reorder cell — flexDirection row, alignItems center, gap $2 (8px)]
  [Move Up button — data-testid="subject-{id}-move-up" / "unit-{id}-move-up"]
    height 28px, width 28px, borderRadius $sm (8px)
    backgroundColor transparent, border 1px solid $border
    icon: Lucide chevron-up, 14px, $fg3
    hoverStyle: backgroundColor $card, color $fg1
    disabled: first item in list → aria-disabled="true", opacity 0.4, cursor not-allowed
    aria-label: EN "Move {name} up" / AR "تحريك {name} للأعلى"
  [Move Down button — data-testid="subject-{id}-move-down" / "unit-{id}-move-down"]
    same geometry, icon: Lucide chevron-down
    disabled: last item in list → aria-disabled="true", opacity 0.4
    aria-label: EN "Move {name} down" / AR "تحريك {name} للأسفل"
  [Order number — fontSize 13px, color $fg3, tabular-nums, ltr, minWidth 24px, textAlign center]
```

### Reorder interaction

1. User presses Move Up or Move Down on a row.
2. Client-side: swap the item with its neighbor in local state immediately (no server call yet). The list re-renders with the new order — fast visual feedback.
3. A "Save order" button appears in the section header (inline-end of the "Units" heading row, or in the subjects controls bar), amber-toned, with a brief status message:
   ```
   [Save order button]
     height 36px, paddingHorizontal $4 (16px), borderRadius $button (16px)
     backgroundColor rgba(245,158,11,0.15), border 1px solid rgba(245,158,11,0.3)
     color $accent (#F59E0B), fontSize 13px, fontWeight 600
     icon: Lucide save, 14px, $accent, inline-start
     hoverStyle: backgroundColor rgba(245,158,11,0.25), border-color $accent
     pressStyle: scale 0.95 80ms
     EN: "Save Order" / AR: "حفظ الترتيب"
     data-testid: "subjects-save-order" / "units-save-order"
   ```
4. When the user presses "Save Order":
   - Button goes to loading state (spinner, aria-busy)
   - Calls `useReorderSubjects({ subjectIds: [ordered ids] })` or `useReorderUnits({ unitIds: [ordered ids] })`
   - Body shape: `{ subjectIds: number[] }` / `{ unitIds: number[] }` — array position = new `sequenceOrder`
   - On success: `queryClient.invalidateQueries(queryKeys.adminCurriculum.subjects(...))` or `.units(subjectId)` — server state is now authoritative; the button disappears
   - On error: `AdminErrorBanner variant="error"` in the section + roll back local state to server state
5. If the user navigates away with unsaved reorder state, the reorder is discarded. No dirty-state prompt (the server state is never at risk — only local UI order was changed).

"Save Order" button is a second action alongside "New Unit/Subject" — the screen temporarily has two actions when reorder is pending. This is acceptable because they are in different zones (section header vs page header) and serve distinct operations.

### `aria-live` for reorder announcements

Wrap the ordered list container with an `aria-live="polite"` region. After each move-up/down:
- Screen reader announces: EN "{name} moved to position {N} of {total}" / AR "{name} نُقل إلى الموضع {N} من {total}"
- Use Eastern-Arabic numerals for N and total in AR
- The announcement is emitted via a visually-hidden `<span aria-live="polite" className="sr-only">` that is updated on each swap

### Reorder guard (cross-tree prevention)

The subjects list reorder is gated by:
1. A grade must be selected (cannot reorder across grades)
2. Language must NOT be "All" (cannot reorder across language trees)

When language = "All": move controls are `aria-disabled="true"`, tooltip on hover reads EN "Select a single language to enable reorder" / AR "اختر لغة واحدة لتمكين إعادة الترتيب". The `data-testid` for the reorder controls still exists (for E2E tests to assert disabled state).

Units reorder is always enabled on the detail page (units are inherently single-subject = single language tree).

## S9 — Active toggle (no confirm dialog)

Decision D-OQ-confirm-depth: deactivate/activate does NOT require a confirm dialog — it is reversible in one click.

The toggle icon buttons in rows call `useSetSubjectActive` / `useSetUnitActive` directly on press. In-flight state:
- The toggle button shows a 14px spinner (replaces the icon), `aria-busy="true"`, pointer-events none
- The row dims to opacity 0.6 during the in-flight call
- On success: invalidate; `ActiveBadge` updates to reflect new state; no toast/banner needed (the badge change is the feedback)
- On error: `AdminErrorBanner variant="error"` above the table (same position as the list-level error). Message from `error.message`. Row returns to its previous state.

## S11 — RTL / i18n notes

**Layout mirroring:** All `flex-direction: row` containers use logical properties (`margin-inline-start/end`, `padding-inline`, `border-inline-start/end`, `inset-inline-start/end`) so they flip under `dir="rtl"`. The breadcrumb chevron uses Lucide `chevron-right` in LTR and `chevron-left` in RTL — specify `dir`-aware icon selection in the breadcrumb component.

**Strings:** The `ADMIN_LOCALE = 'en'` constant means AR strings are authored and reviewed statically. Runtime RTL is blocked this wave. All AR strings above are in the spec; the E2E runner verifies their presence statically.

**Numerals:** Grade numbers and sequence orders in AR reading text use Eastern-Arabic numerals (٠١٢٣٤٥٦٧٨٩). XP counters, technical numeric IDs, and pagination (`Page N of M`) use Latin numerals with `dir="ltr"` wrapping. The sequence-order cell in tables is always `dir="ltr"` with `font-variant-numeric: tabular-nums`.

**Coverage panel grade number:** the heading "Language Coverage — Grade {N}" in AR formats N as an Eastern-Arabic numeral for reading text context.

**Tables:** `textAlign: start` on `<th>` (logical property) — right-aligned in RTL. Progress bars and order numbers: wrap in `dir="ltr"`.

**Forms:** `<select>` options for SubjectCode and Language display the same bilingual labels across locales. The selected grade uses `gradeLabel1`..`gradeLabel6` which already have full Arabic ordinal words in the AR map.

**Dialog actions row:** in RTL, the Cancel button appears on the right (inline-end) and Confirm on the left (inline-start). This follows the `AdminConfirmDialog` convention — use `flex-direction: row-reverse` or `justify-content: flex-start` + logical order under `dir="rtl"`.

**Subject name display:** the subject `name` field is free-text authored by the admin and may be in Arabic or English. The admin enters it in whichever language the content uses. No `dir` override needed on the name cell — it inherits page direction but the admin can author it bilingually.

## S12 — Accessibility

- **Semantic table:** `<table>` with `<thead>` / `<tbody>` / `<th scope="col">` / `<td>` throughout. No CSS-grid substitute.
- **`aria-live="polite"`** wrapper around the results area (subjects list + units list) so state changes (load → results, filter change) announce to screen readers.
- **`aria-live="polite"` sr-only span** for reorder position announcements (§S6).
- **Focus management:** modal dialogs focus the first interactive field on open; on close, return focus to the trigger. `AdminConfirmDialog`'s `getFocusableElements` pattern reused for `SubjectForm` and `UnitForm`.
- **ESC closes** all modal dialogs (cancel path only, never confirms).
- **`aria-disabled` not `disabled`** for disabled buttons in reorder mode (disabled buttons are not focusable; `aria-disabled` keeps them reachable for screen-reader users who need to understand why they are inactive).
- **Focus ring:** `--lx-focus-ring` on all interactive elements (`button`, `select`, `input`, `[tabindex]`).
- **Row keyboard navigation:** table rows have `tabIndex={0}`, `role="button"`, respond to Enter and Space for navigation to the detail page (exact same pattern as `UserRow` in `users/page.tsx`).
- **Reorder a11y:** move-up/down buttons have descriptive `aria-label` per row. `aria-disabled` on first/last rows. Position announcement on each move.
- **Coverage slots:** the gap treatment uses color, dashed border, and text "Missing" together — color is never the only signal (a11y Brand Law rule).
- **Touch targets:** all interactive elements ≥ 44px in height (table row = minHeight 52px; action icon buttons = 32px width/height but immediately adjacent and grouped — acceptable for desktop-first admin context).
- **`data-testid` attributes:** every interactive element carries a `data-testid` for the E2E harness.
- **`aria-label` on icon-only buttons:** every action button without visible text has an `aria-label` that includes the subject/unit name.
- **Coverage panel `aria-expanded`:** the collapsible panel header has `aria-expanded` on the trigger button and `aria-controls` pointing to the panel body.

## Design Gaps and Open Questions

### Gap 1 (inherited from Wave 1) — Admin icon set
No Lucide icon set is installed for the admin nav yet. The spec calls for Lucide `book-open` on the Curriculum nav item, `book-plus` on the Subject form create icon, `layers-plus` on the Unit form create icon. These are inline SVGs following the same `<svg width="20" height="20" viewBox="0 0 24 24" fill="none" aria-hidden="true">` pattern used in `AdminConfirmDialog`. No new npm package is needed — inline SVG paths suffice for this story.

### Gap 2 — Coverage panel collapse persistence
The spec says the coverage panel starts collapsed and expands on click. Whether this collapsed state persists across navigation (e.g. via `useState` only vs. `sessionStorage`) is left to the frontend agent's discretion. Recommend: `useState` only (no persistence); panel starts collapsed on every page visit.

### Gap 3 — Grade label for coverage panel heading
The coverage heading interpolates the grade number: "Language Coverage — Grade {N}". The `gradeNumber` field from `SubjectLanguageCoverageReportDto` is an integer (1–6). In EN, format as "Grade 3". In AR, format as "الصف ٣" using Eastern-Arabic numerals. The `gradeLabel1`..`gradeLabel6` strings cannot be used here because they render the full word form ("الصف الأول") — the panel heading needs the shorter "الصف ٣" format. Frontend agent: use `Intl.NumberFormat('ar-EG').format(gradeNumber)` for the AR numeral, prefixed with the `subjectsDetailGradePrefix` string.

### Gap 4 — AR LanguageBadge labels
The short AR labels for `contentLangAr` and `contentLangEn` corrected inline in §S10: `'عر'` and `'إن'` respectively. Frontend agent: use these values, not the placeholder `'ع'`.

### Gap 5 — Grade edit lockout in SubjectForm
The spec notes that in edit mode, changing `gradeId` could break the `(GradeId, SubjectCode, Language)` unique constraint if the new combination already exists. The spec leaves the grade editable and relies on server validation (HTTP 400 / `Successed=false` with "duplicate tree" message surfaced inline via `AdminErrorBanner`). If the lead wants to lock the grade select in edit mode, that is a one-line confirm. Default: editable, server validates.

### Gap 6 — Reorder "Save Order" button positioning conflict
When the reorder pending state is active (unsaved moves exist), the subjects list controls bar has a "Save Order" button alongside the existing "New Subject" button. The spec places "Save Order" in the controls bar and "New Subject" in the page header. These occupy different vertical zones, so there is no layout conflict. On the units detail page, "Save Order" appears in the units section header (inline-end, beside the unit count). The frontend agent should ensure both buttons are keyboard-reachable and visually distinct.

### Gap 7 — `useGrades()` hook duplication
The brief says "check whether a usable grades hook already exists before adding one." The frontend agent must search `packages/api-client/src/hooks/` before creating a new `useGrades.ts`. If a `useGrades` or equivalent grades-list hook exists from a different story, reuse it. If not, create it following the `useSearchUsers` hook shape.

### Open Question OQ-1 (resolved in spec)
D-OQ-1 list paging: Grade-scoped with `PageSize=12`. Implemented as specified above.

### Open Question OQ-2 (resolved in spec)
D-OQ-lang-filter: Client-side language filter. Implemented as the `SubjectLanguageFilter` tab control.

### Open Question OQ-3 (resolved in spec)
D-OQ-confirm-depth: Plain confirm for delete, no confirm for toggle. Implemented in §S8 and §S9.

### Open Question OQ-4 (resolved in spec)
D8 optimistic updates: Invalidate-only for all mutations except reorder. For reorder, local state is updated optimistically (the move is visible instantly) but server state is written only on "Save Order". On server error, local state rolls back to server state. This is the D8 pattern specified in the plan.
