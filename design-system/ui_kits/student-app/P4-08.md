## 0.1 Motion foundation (batch 2a — B0-mot, gates everything below)

What already exists on `main` (do NOT rebuild — extend):
- `packages/ui/src/components/RewardPopup/` — `RewardVariant = 'xp' | 'badge-unlock' | 'level-up'`, props
  `{variant, xpAmount, title, subtitle?, badgeVariant?, visible, ctaLabel?, onDismiss, locale?, accessibilityLabel}`. This **is** the celebration popup for B1/B4/B5 — reuse.
- `packages/ui/src/internal/ConfettiLayer.tsx` — Skia seam; renders **nothing on web** today. 2a must add the
  **web particle fallback** (absolutely-positioned 8×12px rounded-2px rects, palette = `CONFETTI_COLORS`
  (`$primary $secondary $accent $xp $heart $purple`), transform rotate −40°…60°, positions per
  `preview/mobile-confetti-trophy.html`; animate fall+fade 700ms `--lx-dur-celebrate`). 4–8 particles for
  correct-answer bursts; 12–24 for RewardPopup (kept light for low-end devices, NFR-7).
- `packages/ui/src/components/Badge/` (`bronze|silver|gold|legendary|locked|boss` + `isNewlyEarned` pop-in),
  `XPBar` (`animated` prop), `StreakFlame`, `Hearts`, `MissionBanner`, `AttemptSummaryCard` — all reused below.
- Salvage **by copy** from the retired `feat/P4-08-gamification-screens-motion` branch (plan L5):
  `useReduceMotion` (wraps `AccessibilityInfo.isReduceMotionEnabled` + web `prefers-reduced-motion`,
  → `packages/ui/src/hooks/useReduceMotion.ts`) and `useDashboardDiff` (compares consecutive
  `useDashboard()` snapshots, emits `{leveledUp, streakAdvanced, newBadges[], missionCompleted}` events for 3c
  → `packages/api-client` or app-level hook, frontend's call — mirror the branch shape, no new abstraction).
- New TanStack hooks (2a, single api-client regen, NSwag `CustomOperationIds={Controller}Me` preserved):
  `useMyBadges` → `GET /api/Gamification/Badges/Me` (`MyBadgesResponse.badges: BadgeStateDto[]`),
  `useMyMissions` → `GET /api/Gamification/Missions/Me` (`MyMissionsResponse.daily/weekly: MissionStateDto[]`),
  `useMyLeague` → `GET /api/Gamification/Leagues/Me` (**plural**; `MyLeagueResponse`).
  ⚠️ `GET /api/Gamification/Profile` is generated as `profileGET2(): Promise<void>` — the swagger lacks a typed
  200 response. **B1 reads XP/level/hearts from `DashboardDto` instead** (xp, level, hearts, inPracticeMode,
  streak, freezeBalance, badgesCount, recentBadges, dailyMissions, weeklyMission, activeTimedEvents,
  leaguePreview — all typed). Flag the untyped Profile response to the lead/backend (gap G-1, §10).

### Motion vocabulary (used by name in the per-screen sections; all values are brand law / `motion` tokens)

| Name | Recipe | Reduced-motion fallback |
|---|---|---|
| **xp-fill** | bar width animates to target over **700ms** (`durations.celebrate`, inside the 600–800 brand window) `easings.easeOut`; on reaching 100%: fill swaps to `gradXpFull` + glow flash `--lx-shadow-xp-glow` 240ms in/out | render at target instantly; glow shown statically 500ms |
| **count-up** | number ticks from old → new over 600ms, tabular-nums (no layout shift), weight 800 | jump to final value |
| **badge-pop** | scale 0 → 1.15 → 1 (`easings.easeSpring` / `springs.pop`), then slow shimmer (hue-rotate ±20° 3s loop, per `components-badges.html` `.legendary`) | fade-in 240ms, no shimmer |
| **confetti-burst** | ConfettiLayer §0.1; ≤700ms; never blocks input | none |
| **heart-break** | lost heart: scale 1 → 1.2, swap ❤️→💔 80ms, then `grayscale(1) opacity(0.3)` settle (`springs.settle`); paired with the quiz shake (±6px, 60ms, ×2) already in AnswerFeedbackStrip | instant gray-out, no shake |
| **flame-loop** | 🔥 scale 1 → 1.04 → 1, 1.5s infinite + `drop-shadow(0 0 14px rgba(251,146,60,0.7))` (`--lx-streak-glow` family) | static flame with glow |
| **popup-in** | RewardPopup existing entrance (scrim `$overlay` + blur, card scale `springs.popup`) | fade-only |
| **screen-in** | route transition slide+fade 250–300ms (`durations.base` + 60) | fade-only |

Every screen below: data via the named TanStack hook only (no API calls in components), shimmer skeleton =
`$cardSoft` blocks at final geometry (W13 precedent), error strip = the W13 dashboard error pattern
(`$dangerSoft` strip + ⚠️ disc + Retry ghost), `useReduceMotion` consulted before any §0.1 motion.
Layout: 390 single column, 24px (`$space-6`) screen padding; ≥768 same stack centered `maxWidth: 720` (W12/W13
precedent); content bottom padding includes the TabBar clearance (B0-nav §3). All screens sit under the TabBar
group; **secondary screens (`xp`, `streak`, `hearts`, `attempts`) are `href:null` push screens** with the W12
`ScreenHeader`-style back affordance.

## 1. B1 — XP & Level screen + level-up moment (`app/(child)/xp`)

Entry: tap the XP value / XP bar in `DashboardHeader` (3c wires; until then deep-link only).

Composition (top→bottom):
1. **Level hero** — `lx-display`-scale number: "Level 5" (`fontSize 48 / weight 800 / $fg1`, AR "المستوى ٥"
   Cairo, Eastern-Arabic numeral) over a soft radial `$primarySoft` glow disc; eyebrow `lx-small` uppercase
   `$fg3` "YOUR LEVEL" / "مستواك".
2. **Level progress card** — transcribed from `preview/mobile-level-progress.html`:
   header row: "📈 Level 5 → 6" (17px/700 `$fg2`) ↔ "850 / 1000 XP" (17px/700 `$fg2`, tabular-nums,
   **kept Latin digits + `dir="ltr"` in AR** — technical-string exception); bar height 12px, track `$bg`-family
   `#1E2030`→ use `$bgElevated`, radius `$pill`, fill `gradXp` (`linear-gradient(90deg,#22C55E,#4F46E5)`) +
   `inset 0 1px 0 rgba(255,255,255,0.3)` highlight; footer row 13px `$fg3`: "85% to next level" ↔ "150 XP left".
   Footer percentages use Eastern-Arabic numerals in AR ("٨٥٪ للوصول للمستوى ٦" — exact string family from
   `mobile-ar/05-home.png`). Bar **stays LTR** in RTL (`direction:ltr` wrapper — progress reads L→R universally).
   Reuse `packages/ui` `XPBar` with `animated` (xp-fill motion) — extend it with the footer captions rather than
   building a sibling.
3. **Total XP stat tile** — `KPIStatCard` (`icon="⭐" value="1,240" label="Total XP" accent="$xp"`), value 800
   tabular-nums (Latin digits, LTR).
4. (reserved) recent XP history — **out of scope** (no endpoint); do not mock.

Level-up moment: when `useDashboardDiff` reports `leveledUp` (or quiz summary returns a level boundary),
mount `RewardPopup variant="level-up"` — title **"Level Up!"** / **"ارتقيت في المستوى!"** (cheat sheet), subtitle
"You reached Level 6" / "وصلت إلى المستوى ٦", xpAmount = XP gained, CTA "Keep Going" / "واصل التقدم"
(`preview/ar-reward-popup.html` literal). Popup disc uses `radialGradients.badgeGold`; level-up accents use
`gradLevelup` (`#A855F7→#6366F1`) — the ONLY places the level-up gradient appears. Sequence: popup-in →
confetti-burst → count-up on the level number → on dismiss, the screen's XP bar runs xp-fill from old→new.
Dashboard reflects immediately: invalidate the dashboard query key on quiz complete (AC: cache invalidation).

States: loading (hero + card skeletons), error (strip + retry), zero-state (Level 1, 0/100 XP — bar at 0%, no
glow). i18n namespace `gamification.xp.*`.

## 2. B2 — Streak screen (`app/(child)/streak`)

Entry: tap the 🔥 streak chip in `DashboardHeader`.

Composition:
1. **Flame hero** — from `preview/components-hearts-streak.html` Streak panel, scaled up: 🔥 at 64px with
   flame-loop + `drop-shadow(0 0 14px rgba(251,146,60,0.7))`; number "7 days" `fontSize 36 / 800 / $streak`
   (AR "٧ أيام" Cairo, Eastern-Arabic); meta line 12px `$fg3` **"Keep it alive!"** / **"حافظ عليها!"**
   (cheat-sheet voice "Keep your streak alive 🔥"). Eyebrow `lx-small` "STREAK" / "السلسلة".
2. **Week row (calendar)** — 7 day-discs (40×40, `$pill`): past-qualifying day = `$streak` bg + white ✓;
   today-qualifying = `$streak` + flame-loop micro; today-not-yet = `$borderStrong` outline + `$fg3` day initial;
   future = `$card` + `$fg4`. Day labels 11px/700 uppercase `$fg3` (AR weekday letters, Tajawal). Row direction
   follows reading direction (it's a list of days, not a progress bar — RTL flips it).
   **Design gap G-2:** the dashboard only sends `streak: number` + `freezeBalance` — no per-day qualifying
   history. Render the week row **derived**: last `min(streak,7)` days filled backwards from today. Flag to
   backend for a real history endpoint later; do not invent an API.
3. **Longest streak tile** — `KPIStatCard` (`icon="🔥" label="Longest streak" accent="$streak"`).
   **Design gap G-3:** longest streak is not in `DashboardDto` — omit the tile until the field exists (do NOT
   stub a fake number); reserve the slot in code with a TODO.
4. **Freeze balance chip (B8)** — pill on the hero card, trailing edge: ❄️ + count, bg `rgba(56,189,248,0.18)`
   (`$gem` family soft), fg `$gem`, 14px/800 tabular-nums. Copy under it (12px `$fg3`):
   "Freezes save your streak automatically when you miss a day" /
   "تحمي المجمِّدات سلسلتك تلقائيًا عند تفويت يوم". Earned-only — **no buy/spend UI** (plan B8 AC). Data:
   `DashboardDto.freezeBalance`. ❄️ is an addition to the semantic emoji set — flagged (G-4).

Streak-advanced feedback: on `useDashboardDiff.streakAdvanced`, the hero flame does badge-pop + the day-disc for
today flips to filled with a 240ms spring; toast-free (the moment lives on the reward popup after the lesson —
`subtitle "Streak protected · Hearts saved"` / "تمت حماية سلسلتك · القلوب محفوظة" per `components-reward.html`).
States: loading/error/zero (streak 0 → copy "Start your streak today!" / "ابدأ سلسلتك اليوم!", flame at 40%
opacity grayscale). i18n `gamification.streak.*`.

## 9. Cross-cutting

- **RTL:** every screen `dir`-driven; headings Cairo, body Tajawal; Eastern-Arabic numerals for prose counts
  (days, "x of y"), **Latin + LTR for XP counters and `n / m XP` strings**; progress/XP bars LTR-locked; emoji
  and avatar discs never mirrored; "→" becomes "←".
- **A11y / kid-UX:** touch targets ≥48px; every interactive element `accessibilityRole` + localized label;
  RewardPopup announces via existing `accessibilityLabel`; counts always rendered as digits (voice rule);
  one primary action per screen (XP screen: none/informational; Hearts: Practice Mode; Missions: the hero;
  League: none; Badges: none); all motion gated by `useReduceMotion`; no blocking animation >800ms.
- **Performance (NFR-7):** confetti ≤24 particles; flame-loop and shimmer are transform/opacity only; lists are
  plain maps (≤30 league rows) — no virtualization needed.
