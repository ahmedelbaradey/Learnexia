## 1. Global Layout Conventions (all P1-09 screens)

### Breakpoints (from `packages/design-system/src/media.ts`)

| Key | Condition | Reference width | Usage |
|---|---|---|---|
| `sm` | maxWidth 767px | 390px phone | Single-column stacked layout |
| `tablet` | minWidth 768px | 768px tablet | Max-width 480px centered form card |
| `laptop` | minWidth 1024px | 1024px laptop | Max-width 480px form card + illustrative side panel (decorative, Phase 2) |

**Phone (390):** Full-width screen, `$bg` canvas, single column, content padded `$6` (24px) horizontally. Screen header (back nav + title) at top. Primary Button pinned to bottom with `$6` bottom safe area.

**Tablet (768):** Centered card on `$bg` canvas. Card: `Card` component (`variant="default"`, `$card` bg), max-width 480px, padding `$8` (32px) all sides, `$card` radius 20px, `shadowFloat`. Card centered vertically with `$8` top offset from top safe area. No bottom-pinned button — button is inline at bottom of card.

**Laptop (1024):** Same centered card as tablet (same max-width 480px). Left half reserved for decorative branded illustration (dots pattern + logo-mark SVG + mascot silhouette) — Phase 2 only; for P1-09 render a `$bgElevated` panel with centered `logo-mark.svg` at 80px and the tagline. Right half: the form card.

**Native (iOS/Android):** Same as phone layout. Respect safe area insets with `SafeAreaView`. Keyboard-aware scroll: wrap form in `KeyboardAvoidingView` (behavior `padding` on iOS, `height` on Android).

### Color surface baseline

All screens use the dark game-world palette by default (`defaultTheme="dark"` in `LearnexiaProvider`):

| Role | Token | Hex |
|---|---|---|
| Canvas | `$bg` | `#0F172A` |
| Card | `$card` | `#1E293B` |
| Nested / soft card | `$cardSoft` | `#334155` |
| Primary action | `$primary` | `#4F46E5` |
| Success | `$success` | `#22C55E` |
| Danger / error | `$danger` | `#EF4444` |
| Reward / accent | `$accent` | `#F59E0B` |
| Heading text | `$fg1` | `#F8FAFC` |
| Body text | `$fg2` | `#CBD5E1` |
| Muted / label | `$fg3` | `#94A3B8` |
| Disabled text | `$fg4` | `#64748B` |
| Border default | `$border` | `rgba(255,255,255,0.08)` |
| Border focus | `$borderFocus` | `#4F46E5` |

### Typography (locale-driven)

| Locale | Display (H1/H2/H3) | Body | Notes |
|---|---|---|---|
| English (`en`) | Poppins 700–900 | Poppins 400–600 | LTR, `textAlign: 'start'` |
| Arabic (`ar`) | Cairo 700–900 | Tajawal 400–600 | RTL, `textAlign: 'start'` (flips to right in RTL) |

Font activation is handled by `LearnexiaProvider`'s `locale` prop. Components read the active font from `useLocaleFonts()` if they need to override; otherwise Tamagui theme picks the correct family automatically.

### RTL conventions (all screens)

- All layout uses logical props only: `marginStart`/`marginEnd`, `paddingStart`/`paddingEnd`, `start`/`end` (absolute), never `left`/`right`.
- `flexDirection` for directional rows: `direction === 'rtl' ? 'row-reverse' : 'row'` via `useDirection(locale)`.
- `textAlign`: always `'start'` — maps to left in LTR, right in RTL automatically in React Native with `writingDirection`.
- On web: `document.documentElement.dir` and `lang` are set by `LearnexiaProvider`'s `applyWebDirection` call.
- On native: language switch to Arabic requires `applyNativeRtl()` (sets `I18nManager.forceRTL(true)`) followed by `react-native-restart` restart. See Screen 10 for the language-switch UX.
- Icons that have directionality (chevrons, arrows, back buttons): flip via `scaleX: direction === 'rtl' ? -1 : 1`.

### Kid-accessibility baseline (all screens)

- Minimum touch target: `minHeight: 48, minWidth: 48` on all `Pressable` / button elements. Use `hitSlop` where visual size is smaller.
- One primary action per screen (one `Button variant="primary"` visible without scrolling).
- Focus ring on web: `focusRing` shadow token (`0 0 0 2px #4F46E5, 0 0 0 6px rgba(99,102,241,0.45)`).
- Every interactive element: `accessibilityRole` + `accessibilityLabel`.
- Error messages: minimum font size 14px, `$danger` color, placed immediately below the erroring field.
- Loading state: spinner replaces button label, button non-interactive.
- Press feedback: scale `0.95` on press (all buttons), 120ms `easeOut`.

## 2. New Primitive Specifications

### 2.1 TextField / FormField

**Preview source:** `design-system/preview/components-input.html`
**Target:** `packages/ui/src/components/TextField/index.tsx`

This is the single reusable labelled text input for all auth and onboarding forms. It is universal (Expo + web).

#### Anatomy

```
[FormField Root — YStack, gap $1 (4px)]
  ├── [Label — Text, $fg3, 12px, weight 600, uppercase, letterSpacing 0.06em, font: Cairo/Poppins per locale]
  ├── [Input Row — XStack, position: 'relative']
  │     ├── [Input — TextInput / Input styled, height 52px, bg $card, border 1px $border,
  │     │          borderRadius 14px, color $fg1, font 15px body, paddingStart 14px, paddingEnd 14px]
  │     └── [Trailing Icon — optional, absolute end side: toggle icon for password, 24px]
  └── [Error Row — XStack, gap $1, marginTop 2px] (only visible when error is set)
        ├── [Error Icon — small '!' circle, 14px, $danger color, optional]
        └── [Error Text — Text, $danger, 12px, weight 400]
```

Note: `borderRadius: 14px` is from the `components-input.html` preview (not a named token — falls between `$sm` 8px and `$card` 20px). Define this as a local constant `inputRadius = 14` within the component. Do NOT introduce a new global token for a single-use value.

#### Props

| Prop | Type | Default | Notes |
|---|---|---|---|
| `label` | `string` | required | Displayed as uppercase label above input |
| `value` | `string` | required | Controlled value |
| `onChangeText` | `(text: string) => void` | required | onChange handler |
| `placeholder` | `string` | optional | Placeholder text; uses `$fg3` color |
| `error` | `string \| undefined` | `undefined` | If set, renders error state |
| `secureTextEntry` | `boolean` | `false` | Password mode — shows toggle eye icon |
| `keyboardType` | `KeyboardTypeOptions` | `'default'` | Passed through to native TextInput |
| `autoCapitalize` | `string` | `'none'` | Default none for email/username fields |
| `autoComplete` | `string` | optional | Native autocomplete hint |
| `disabled` | `boolean` | `false` | Dims the field, non-interactive |
| `testID` | `string` | optional | Test identifier |
| `accessibilityLabel` | `string` | optional | Falls back to `label` if not set |
| `direction` | `'ltr' \| 'rtl'` | from context | Layout direction; caller passes `useDirection(locale)` result |

#### States

| State | Border | Background | Shadow | Notes |
|---|---|---|---|---|
| Default | `1px solid $border` (`rgba(255,255,255,0.10)`) | `$card` (`#1E293B`) | none | Matches `components-input.html` `.input` style |
| Focus | `1px solid $borderFocus` (`#4F46E5`) | `$card` | `0 0 0 4px rgba(99,102,241,0.25)` | Matches `.focus` in preview |
| Error | `1px solid $danger` (`#EF4444`) | `$card` | `0 0 0 4px rgba(239,68,68,0.20)` | Matches `.err` in preview; shows error text below |
| Disabled | `1px solid $border` | `$bgElevated` (`#111B33`) | none | `opacity: 0.5`, `pointerEvents: 'none'` |
| Filled (value present) | `1px solid $borderStrong` | `$card` | none | Slightly stronger border to signal content |

#### Password Toggle

When `secureTextEntry={true}`:
- Display an eye icon (open/closed SVG or `icons/` asset) at the end of the input row, absolute positioned `end: 14px`.
- Icon size: 20px, color `$fg3`. On tap: toggle secure/plain text. Icon changes to eye-slash when text is visible.
- Touch target: `minHeight: 48, minWidth: 48` (use `hitSlop`).
- `accessibilityRole="button"`, `accessibilityLabel`: `t('auth.showPassword')` / `t('auth.hidePassword')`.

#### RTL behavior

- Label text: `textAlign: 'start'` (naturally right-aligned in RTL locale).
- Input text: `textAlign: 'start'`. For Arabic input content the OS handles RTL text rendering.
- Trailing icon (password toggle): always at the `end` side (logical prop), which is left in RTL.
- Error text: `textAlign: 'start'`.

#### A11y

- `accessibilityLabel` = `label` prop value (or explicit override).
- On error: `accessibilityHint` = error string, or use `accessibilityLiveRegion="polite"` on the error text.
- `accessibilityRole="none"` on the YStack wrapper; the inner `TextInput` is natively accessible.

### 2.2 Select / GradePicker

**Preview source:** no existing preview — specified here from scratch in token language.
**Target:** `packages/ui/src/components/Select/index.tsx`

A universal controlled picker. On native: renders a `Picker` from `@react-native-picker/picker` wrapped in a styled pressable. On web: renders a custom styled dropdown overlay (no native `<select>` — visual consistency). Alternatively, use a Tamagui `Sheet` bottom sheet with a scrollable list of options — this is the recommended cross-platform strategy.

#### Anatomy

```
[Select Root — YStack, gap $1 (4px)]
  ├── [Label — same as TextField label: Text, $fg3, 12px, uppercase, weight 600]
  ├── [Trigger Row — Pressable, height 52px, bg $card, border 1px $border,
  │         borderRadius 14px, paddingStart 14px, paddingEnd 14px]
  │     ├── [Value Text — Text, $fg1, 15px] (or [Placeholder Text — $fg3] when nothing selected)
  │     └── [Chevron Icon — 20px, $fg3, absolute end side; flips in RTL via scaleX=-1 in LTR shows down, in open state rotates 180deg]
  └── [Error Text — same as TextField, only when error set]

[Options Sheet — Tamagui Sheet or Modal overlay]
  └── [Options List — ScrollView + YStack]
        └── [Option Row — Pressable, height 52px, paddingStart $4, paddingEnd $4,
                  bg $card on default; bg $primarySoft + text $primary on selected;
                  bg $cardSoft on hover/focus]
              ├── [Option Label — Text, $fg1, 15px, weight 500]
              └── [Check Mark — Icon, 20px, $primary, absolute end side] (selected row only)
```

#### Variants

**`GradePicker`** — a pre-configured `Select` with options 1–6:

| Grade value | EN label | AR label |
|---|---|---|
| 1 | Grade 1 | الصف الأول |
| 2 | Grade 2 | الصف الثاني |
| 3 | Grade 3 | الصف الثالث |
| 4 | Grade 4 | الصف الرابع |
| 5 | Grade 5 | الصف الخامس |
| 6 | Grade 6 | الصف السادس |

Labels come from the `onboarding` i18n namespace (not hardcoded in the component). The component accepts an `options: Array<{ value: string | number; label: string }>` prop; `GradePicker` is a thin wrapper that injects the grade options from `GRADES` + `t('onboarding.grade.{n}')`.

**`LanguageSelect`** — a pre-configured `Select` with options `ar` / `en`:

| Value | EN label | AR label |
|---|---|---|
| `ar` | Arabic / عربي | عربي |
| `en` | English | إنجليزي |

This is used in the Add-Child form to set the child's preferred language. Since it appears inside an Arabic or English UI, show both labels in the option text: "عربي / Arabic". `value` written to form state is the locale code string.

#### Props

| Prop | Type | Notes |
|---|---|---|
| `label` | `string` | Uppercase label above trigger |
| `value` | `string \| number \| null` | Controlled selected value |
| `onChange` | `(value: string \| number) => void` | Selection handler |
| `options` | `Array<{ value: string \| number; label: string }>` | Option list |
| `placeholder` | `string` | Shown when `value` is null |
| `error` | `string \| undefined` | Error string below trigger |
| `disabled` | `boolean` | Grays out trigger |
| `direction` | `'ltr' \| 'rtl'` | For icon and text alignment |
| `accessibilityLabel` | `string` | Falls back to `label` |

#### States

| State | Trigger border | Notes |
|---|---|---|
| Default | `$border` | Normal closed state |
| Open | `$borderFocus` + `0 0 0 4px rgba(99,102,241,0.25)` | Sheet/dropdown visible |
| Selected | `$borderStrong` | Value present |
| Error | `$danger` border + error text | Same as TextField error |
| Disabled | `$border`, `opacity: 0.5` | Non-interactive |

#### Sheet (cross-platform option list)

- `Tamagui Sheet` bottom sheet with `snapPoints={['50%', '90%']}`, `modal={true}`.
- Header: label text + close `X` button (top-end corner).
- Options list: `FlatList` or `ScrollView` with `YStack`.
- Each option row: `minHeight: 52px`, `paddingHorizontal: $4`.
- Selected option: background `$primarySoft`, text color `$primary`, checkmark icon at end.
- On web at laptop breakpoint: render as a positioned dropdown (`YStack absolute`) below the trigger rather than a bottom sheet.
- Sheet background: `$card` (`#1E293B`), `borderRadius: $modal (24px)` at top corners, shadow `shadowPopup`.

#### RTL

- Trigger row: value text `textAlign: 'start'`. Chevron at `end` (logical).
- Option rows: option label `textAlign: 'start'`. Checkmark at `end`.
- The Sheet/dropdown itself has `dir` attribute set on web; on native the RTL is inherited from the global `I18nManager` state.

#### A11y

- Trigger: `accessibilityRole="combobox"`, `accessibilityState={{ expanded: isOpen }}`, `accessibilityLabel`.
- Sheet/modal: `accessibilityViewIsModal={true}` on native.
- Each option: `accessibilityRole="radio"`, `accessibilityState={{ selected: isSelected }}`.
- Min touch target: 52px height (inherently ≥ 48px).

### 2.3 ProgressSteps

**Preview source:** no existing preview — specified here.
**Target:** `packages/ui/src/components/ProgressSteps/index.tsx`

Used in the onboarding wizard header to show "Step N of M".

#### Anatomy

```
[ProgressSteps Root — XStack, gap $2 (8px), alignItems: 'center', justifyContent: 'center']
  └── [Step Dot × totalSteps — View]
        Completed step: width 24px, height 8px, borderRadius $pill, bg $primary, opacity 1
        Current step:   width 32px, height 8px, borderRadius $pill, bg $primary + glow shadow, opacity 1
        Future step:    width 24px, height 8px, borderRadius $pill, bg $card, border 1px $border
```

The "current" dot is wider (32px vs 24px) to create the visual emphasis. All dots have the same height (8px) and pill radius. This matches a common modern wizard pattern.

#### Props

| Prop | Type | Notes |
|---|---|---|
| `currentStep` | `number` | 1-based current step index |
| `totalSteps` | `number` | Total number of steps |
| `accessibilityLabel` | `string` | e.g. "Step 2 of 3" |

#### Motion

Step advance: the current dot expands from 24px to 32px width via `withTiming(32, { duration: durBase })`. Completed dots shrink from 32px to 24px. Use Reanimated `useSharedValue` for the width of each dot.

#### RTL

In RTL, the step dots are still rendered left-to-right visually (progress direction is always LTR in terms of step order). Do NOT reverse the dot order for RTL — the progress concept is universal. The component does not need a RTL flip.

#### A11y

- `accessibilityRole="progressbar"`, `accessibilityValue={{ min: 1, max: totalSteps, now: currentStep }}`, `accessibilityLabel`.
- Dots are decorative: `accessible={false}` on each dot.

### 2.4 ChildCard

**Preview source:** no existing preview — specified here, extending `Card` from packages/ui.
**Target:** `packages/ui/src/components/ChildCard/index.tsx`

Used in both the multi-child list editor (onboarding) and the My-Children screen.

#### Anatomy

```
[ChildCard Root — Pressable wrapping Card, variant="default", minHeight 72px]
  └── [Content Row — XStack, gap $3 (12px), alignItems: 'center', padding $4 (16px)]
        ├── [Avatar — View, width 44px, height 44px, borderRadius $pill,
        │         bg: gradient from $primarySoft to $cardSoft]
        │     └── [Initials — Text, $fg1, 18px, weight 700, textAlign 'center']
        ├── [Info — YStack, flex 1, gap $1]
        │     ├── [Name — Text, $fg1, 16px, weight 600]
        │     └── [Meta — Text, $fg3, 13px] (grade + language, e.g. "Grade 3 · Arabic")
        └── [Actions — XStack, gap $2]  (context-dependent, see variants)
```

#### Variants

**`editable`** (onboarding list editor — before submit): Actions = Edit icon button (pencil, 24px, `$fg3`) + Remove icon button (trash, 24px, `$danger`). Edit opens a bottom sheet to edit the child's details.

**`status`** (after submit — per-child success/failure): Actions replaced by a status badge:

- Failure: `$danger` X icon in a 24px `$dangerSoft` circle + error label below the card (small, `$danger`, 12px).

**`selectable`** (My-Children screen — child switcher): Right side shows a chevron icon (`$fg3`, 20px). When this child is the active child: card background becomes `$bgElevated`, left border accent `4px $primary` at `start` side (logical), no chevron (replaced by checkmark).

**`linking`** (Link-Child flow — result): Read-only display of the child that was linked, with a `$success` badge.

#### Props

| Prop | Type | Notes |
|---|---|---|
| `variant` | `'editable' \| 'status' \| 'selectable' \| 'linking'` | required |
| `child` | `{ fullName: string; grade?: number; language?: string }` | required |
| `status` | `'idle' \| 'success' \| 'error'` | For `status` variant |
| `errorMessage` | `string \| undefined` | Per-child error in status variant |
| `isActive` | `boolean` | For `selectable` variant — is this the selected child |
| `onPress` | `() => void` | For selectable/editable tap |
| `onEdit` | `() => void` | For editable variant |
| `onRemove` | `() => void` | For editable variant |
| `accessibilityLabel` | `string` | required |

Avatar initials: take the first character of each word in `fullName`, up to 2 characters. E.g. "Ahmed Mohamed" → "AM". Always uppercase.

#### RTL

Content row reverses: `flexDirection: direction === 'rtl' ? 'row-reverse' : 'row'`. Avatar on start side (right in RTL). Actions on end side (left in RTL). All text `textAlign: 'start'`.

#### A11y

- Root Pressable: `accessibilityRole="button"`, `accessibilityLabel` = child's name + status.
- Edit/Remove icon buttons: `accessibilityRole="button"`, `accessibilityLabel` = `t('onboarding.editChild')` / `t('onboarding.removeChild')`.
- Min touch target: 48px (card height 72px inherently exceeds this).

## 3. Routing Guard States — What the User Sees

The root `app/_layout.tsx` + `useAuthRoute` hook control screen display based on `authStore.status`. The designer spec mandates these visual states to prevent content flash:

| `authStore.status` | `Me` data available | Visual shown | Route target |
|---|---|---|---|
| `unknown` | No | Splash/boot screen (Screen 1) | Stay on splash |
| `signed-out` | No | Redirect to login | `/(auth)/login` |
| `signed-in` | No | Splash persists while `useMe` fetches | Stay on splash (skeleton) |
| `signed-in`, role = `parent`, `hasChildren = false` | Yes | Redirect to onboarding | `/(onboarding)/add-child` |
| `signed-in`, role = `parent`, `hasChildren = true` | Yes | Redirect to parent dashboard | `/(parent)` |
| `signed-in`, role = `student` | Yes | Redirect to child home in child's language | `/(child)` |

**No content flash rule:** The splash screen must remain visible until `authStore.status` transitions away from `unknown`. Do NOT render `null` or a blank screen during the `unknown` phase — always show the splash.

**Silent-refresh failure:** When the API interceptor fires `onSignOut`, `authStore.signOut()` sets `status = 'signed-out'`. The routing guard then redirects to login. The flash message ("Your session expired. Please sign in again.") is passed via Expo Router search params or a lightweight `flashMessageStore` (simple Zustand store with `{ message: string | null }`). The login screen reads and displays it once, then clears it.

## 4. Screen Specifications

---

### Screen 1 — Splash / Boot

**Route:** `app/index.tsx`
**Purpose:** Brand identity display while `authStore.hydrate()` runs and the routing guard determines the target route. Also shown while `useMe` is fetching for an already-authenticated user.
**Tone:** Neutral brand — neither parent-facing nor kid-facing (shown before role is known).

#### Layout (390 / 768 / 1024 / native)

All breakpoints: full-screen `$bg` canvas, centered vertically and horizontally. No header, no navigation. Identical on all breakpoints.

```
[Screen — YStack, flex 1, bg $bg, alignItems 'center', justifyContent 'center', gap $8 (32px)]
  ├── [Logo — Image, logo.svg, width 160px, height auto]
  ├── [Mascot — Image, mascot-owl.svg, width 120px, height 120px] (decorative, not on every state)
  └── [Loading Indicator — custom animated dots OR Spinner primitive]
        Three dots, $primary color, staggered pulse animation (see Motion below)

[Flash Message — YStack, position 'absolute', bottom $12 (48px), width '80%', centered]  (only on session-expired redirect)
  └── [Message Card — Card variant="soft", padding $4, borderRadius $card]
        └── [Text — $fg2, 14px, textAlign 'center'] "Your session expired. Please sign in again."
```

**Logo asset:** `design-system/assets/logo.svg` — displayed at 160px wide. On native: use `Image` with `require()`. On web: `<img>` or `Image` from `expo-image`.

**Mascot:** `design-system/assets/mascot-owl.svg` at 120px. Optional — shown only if there is no session-expired flash message (clean boot). Hide the mascot when showing the session-expired message to maintain visual hierarchy.

#### Loading Indicator — Dot Pulse

Three 10px diameter circles, color `$primary` (`#4F46E5`), gap `$2` (8px).
Staggered opacity/scale animation (Moti):
- Dot 1: opacity `0.3 → 1.0 → 0.3`, scale `0.8 → 1.0 → 0.8`, duration 600ms, delay 0ms, loop infinite.
- Dot 2: same, delay 150ms.
- Dot 3: same, delay 300ms.

`accessibilityLabel="Loading"`, `accessibilityRole="progressbar"` on the dots container.

#### States

| State | Visual |
|---|---|
| `unknown` (default) | Logo + mascot + dot pulse |
| `signed-in` (fetching Me) | Logo + dot pulse (no mascot — give space to pulse) |
| `session-expired` (flash param present) | Logo + dot pulse + flash message card at bottom |

#### RTL

Logo and mascot are centered — no RTL flip. Flash message text: `textAlign: 'start'` (right-aligned in Arabic automatically). Dot pulse: LTR order (left to right) regardless of locale — this is a brand animation, not content.

#### Copy slots

| Key | EN | AR |
|---|---|---|
| `common.loading` | Loading… | جارٍ التحميل… |
| `auth.sessionExpired` | Your session expired. Please sign in again. | انتهت جلستك. يرجى تسجيل الدخول مجدداً. |

#### Motion

Logo entrance (on first paint): `opacity: 0 → 1`, `translateY: 8 → 0`, `duration: durSlow (400ms)`, `easeOut`.
Mascot entrance: same but delayed 150ms.
Dot pulse: as described above (Moti loop).
Exit: on `status` change, the whole screen fades out (`opacity: 1 → 0`, `duration: durBase (240ms)`). Use `Animated` on the `View` root or wrap with a `MotiView` exit animation.

| Piece | Package | File |
|---|---|---|
| Screen component | `apps/student-app` | `app/index.tsx` |

#### Submit flow (loop per child)

When "Add Child(ren) and Continue" is pressed:
1. Button enters loading state.
2. For each child in the list: call `useAddChild` one at a time (sequential loop).
3. As each call completes:

4. After all calls complete (success or partial failure):
   - If all succeeded: route to `/(onboarding)/complete` (Screen 7).
   - If partial failures: show a banner "Some children could not be added. Please fix the errors and try again." The failed children remain in error state. ### Screen 10 — Language Switch UX (Native Restart Prompt)

**This is not a standalone screen route — it is an overlay/dialog pattern triggered when a language change requires a native app restart.**

**Context:** On native iOS/Android, changing the app language from English to Arabic (or vice versa) requires calling `I18nManager.forceRTL(true/false)` and then restarting the app (`react-native-restart`) for the layout direction to take full effect. Web does not require this — `applyWebDirection` is immediate.

**Trigger locations:**
- Language selector inside Add-Child form (selecting "ar"/"en" for the child — this changes the child's `preferredLanguage`, not the parent's app locale, so NO restart is triggered here).
- App-level language setting (if added in a settings screen, Phase 2). The P1-09 scope does NOT include a settings screen, but the child's locale is applied after login (`useMe.preferredLanguage`). On native, if the child's locale differs from the current `I18nManager` state, the restart prompt appears.

#### Restart Prompt Anatomy

```
[Modal Overlay — YStack, position 'absolute', fill, bg $overlay, alignItems 'center', justifyContent 'center']
  └── [Dialog Card — Card variant="default", maxWidth 320px, padding $6, gap $4, borderRadius $modal]
        ├── [Title — Text, $fg1, 18px, weight 700, textAlign 'center']
        │     EN: "Restart to change language"   AR: "أعد التشغيل لتغيير اللغة"
        ├── [Body — Text, $fg2, 14px, textAlign 'center', lineHeight 1.6]
        │     EN: "The app needs to restart to apply the new language settings."
        │     AR: "يحتاج التطبيق إلى إعادة التشغيل لتطبيق إعدادات اللغة الجديدة."
        └── [Button Row — XStack, gap $3, justifyContent 'center']
              ├── [Cancel — Button variant="ghost", label "Later" / "لاحقاً"] → dismiss, keep current locale
              └── [Confirm — Button variant="primary", label "Restart" / "إعادة التشغيل"] → applyNativeRtl + RNRestart
```

This dialog appears on top of the current screen. It does not push a new route. The dialog state is managed in the app's local state (or a lightweight Zustand boolean `restartPromptStore`).

**UX decision (designer recommendation):** Do NOT restart automatically without user consent. The prompt must be explicit. If the user taps "Later", the locale change is NOT applied on native — the setting is deferred to the next manual attempt or next login. Record the intent in a lightweight persistent flag (e.g. `AsyncStorage` key `pendingLocale`) and apply on next cold launch.

#### Motion

Dialog entrance: Moti `animate={{ scale: [0.9, 1], opacity: [0, 1] }}`, spring `popup` (`damping: 12, stiffness: 180`). Overlay fade: `opacity: 0 → 0.72`, `durBase`.

## 11. Design Gaps / Open Questions

**Gap 1 — Onboarding complete step (designer addition)**
The plan routes from add-child directly to `/(parent)` on success. This spec adds a `/(onboarding)/complete` screen for a cleaner "all done" moment. Flag to frontend agent: if the plan change is not accepted, remove Screen 7 and route directly to `/(parent)/index.tsx` from the submit handler. Adjust `ProgressSteps` totalSteps to 1 in that case.

**Gap 2 — Grade labels in Arabic numerals**
The spec uses ordinal Arabic text ("الصف الأول"…) for grade labels. Confirm with product/content whether Arabic-Indic numerals (١, ٢…) should be used instead of Arabic words. If so, update `onboarding.grade.*` i18n keys accordingly. No token change required.

**Gap 3 — Child avatar art**
The `ChildCard` avatar uses initials in a gradient circle as a placeholder. Final product may use child-specific avatar illustrations (animal characters, etc.) from a later design phase. For P1-09, initials-based avatar is the spec; the `ChildCard` component should accept an optional `avatarUri` prop for future use (renders `Image` instead of initials if provided).

**Gap 4 — Country field is a free-text input**
The spec treats `country` as a `TextField` (free text). The plan/backend require a non-empty string. A future improvement would be a `CountryPicker` (searchable select from a country list). For P1-09: plain `TextField` with `autoCapitalize: 'words'` is sufficient. Flag to frontend: `addChildSchema` validates country as non-empty string — no enum.

**Gap 5 — `flashMessageStore` is a new tiny Zustand store**
The plan does not explicitly define this. This spec introduces it as the mechanism for the session-expired flash message on the login screen. Frontend agent should create it as a 2-field store: `{ message: string | null; setMessage: (m: string | null) => void }` in `packages/shared/src/stores/flashMessageStore.ts`. Alternative: pass the message via Expo Router search params — simpler but couples routing to message presentation. Designer preference: the store approach is cleaner for any-to-any message passing.

**Gap 6 — `restartPromptStore` scope**
The restart prompt is only relevant on native and only when locale changes. For P1-09, the only locale change that triggers it is the child's preferred language differing from the current native RTL state after login. The `restartPromptStore` controls whether the dialog is visible. This is a new store in `packages/shared`. Alternatively, this can be local component state in `app/_layout.tsx` since it doesn't need to be globally shared. Frontend agent to decide: if purely local, no shared store needed.

**Gap 7 — Sign-out failure UX**
The spec says "even if `useSignOut` API call fails, always call `authStore.signOut()`". This means the user is signed out locally even if the backend call fails (the refresh token may still be valid on the server — a security tradeoff). This matches the plan's intent (sign-out must always succeed locally). Flag to security-auditor for review: is it acceptable to not invalidate the server session on network failure? The backend still invalidates the token on the next use attempt via the token refresh mechanism.

**Gap 8 — No "Forgot password" flow**
The login screen deliberately omits a "Forgot password" link. Parent-driven onboarding means parents set child passwords — a child who forgets their password asks their parent to reset it. Parent password reset is a Phase 2 feature. No placeholder link should be shown to avoid user confusion.

**Gap 9 — `inputRadius: 14px` is not a named token**
The `components-input.html` preview uses `border-radius: 14px` for inputs, which falls between `$sm` (8px) and `$card` (20px). This spec recommends a LOCAL constant `inputRadius = 14` inside `TextField` and `Select` components rather than a new global token. If the design system team decides to formalize this as `$input` radius token in `packages/design-system`, that is a token library change that should be tracked as a gap-fill (similar to Gap 2 in P1-08).

**Gap 10 — `parent` i18n namespace not in current NAMESPACES array**
`resources.ts` currently defines `NAMESPACES = ['common', 'auth']`. P1-09 adds `onboarding`, `parent`, `child`. The `defaultNS` stays `common`. The `NAMESPACES` array type and the `resources` object both need extension. Frontend agent: extend both in the same `resources.ts` file; update the TypeScript type `Namespace` to include the new values.
