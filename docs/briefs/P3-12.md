# Pipeline Brief — P3-12: Interact with the AI Tutor UI (student app)

> **AI Helper MVP context:** See `docs/briefs/ai-helper-mvp.md`. P3-12 surfaces exactly the **four allowed helper intents** as distinct, labeled affordances — no open-ended chatbot input. It also surfaces the **redirect state** when the Helper declines (no context). The four intents map to specific UI affordances: (1) "اشرح السؤال" (explain button/chip), (2) "اديني تلميح" (hint button), (3) "ليه إجابتي غلط" (why-wrong chip, appears after a wrong answer with the student's submitted answer), (4) "اديني مثال مشابه" (similar example chip). There is NO free-text chatbot input field. The redirect state ("خلينا نكمل...") must have its own UI treatment. Build order is parallel with Gamification-FE / Parent work — NOT gated on BL-* or P3-07.

## Summary & traceability
- **Task (1 line):** Build the **student-app AI Helper surface** — exposing exactly the **four scoped intents** (Explain, Hint, WhyWrong, SimilarExample) as distinct labeled actions, streaming responses with a typing animation, showing **contextual hint bubbles** on wrong answers with a **"simpler explanation"** action and a **"why is my answer wrong"** chip (carrying the student's actual wrong answer), a **"similar example"** chip, the **redirect state** when no context is available, rendering correctly in **Arabic (RTL) + English**, reusing the existing **`AITutorBubble`** component, and handling loading/error/redirect states gracefully — with no free-text chatbot input.
- **User story:** [user-stories/Phase-4-AI-Tutor/P3-12-ai-tutor-ui.md](../../user-stories/Phase-4-AI-Tutor/P3-12-ai-tutor-ui.md) — *"As a student, I want a friendly tutor interface with live typing and hint bubbles…"*
- **FE task file:** **MISSING** — no `tasks/Frontend/student-app/Phase-4-AI-Tutor/P3-12-FE.md`. Flag to lead.
- **FR-IDs:** **FR-AI-1** (explain on demand — consumes P3-04) + **FR-AI-2** (hints/simplify — consumes P3-05).
- **BRD goal:** **G1 (engagement)** + **G2 (learning outcomes)** — help feels conversational and encouraging.
- **Phase / Epic / SP:** Phase 4 — AI Tutor (Week 6–7) · Epic **AI Tutor UI** · 5 SP · `frontend` / `ai` / `tutor`.
- **UI surface:** **YES → this is the only FE story in the cluster → it NEEDS a designer (Design Spec) stage before the frontend batch**, and a **frontend-e2e-tester** stage after.
- **Build position:** **LAST in the cluster.** Hard-blocked by **P3-04 (explain)** + **P3-05 (hints/simplify)**; ideally also P3-06 (if generated-question surfacing is in scope — it is not for MVP). Consumes the streaming wire format that P3-04/05 publish.

## Business context & value
- **Who benefits:** the **student** — the tutor stops being a static text blob (today the `AITutorBubble` renders the lesson's static `explanation`) and becomes a live, conversational helper; the **parent** indirectly (a friendly, safe tutor builds trust + retention).
- **Value:** this is the visible payoff of the entire P3 AI cluster — all the backend (gateway, safety, prompt, RAG, explain, hints) is invisible until this surface makes it tangible. The typing animation + hint bubbles are the engagement mechanics (G1) that make asking for help feel safe and encouraging rather than like admitting failure.
- **Success measure:** a student can ask the tutor to explain a concept and watch it stream in with a typing animation; on a wrong quiz answer, a hint bubble appears with a "simpler explanation" action; everything renders correctly in Arabic (RTL) and English; provider errors show a gentle retry, not a crash.

## Current-state findings (reality in code)
1. **`AITutorBubble` already exists and is purpose-built for this** (`packages/ui/src/components/AITutorBubble/index.tsx`): `variant: 'ai' | 'student' | 'hint'`, a **built-in Moti typing indicator** (renders when `message === null` and `variant==='ai'`), **chips** (for "simpler explanation" / hint-level actions), a `locale` prop, and **full RTL** handling (logical radii, row flip). **P3-12 should reuse this, not rebuild it.** The story AC even mandates "uses the AI Tutor bubble component."
2. **The bubble is currently rendered statically** in the lesson screen (`apps/student-app/app/(child)/lessons/[lessonId].tsx`) with the lesson's static `explanation` text — W12 left it as "no live AI until P3-04." P3-12 wires it to the live explain/hint streams.
3. **The hint button is a disabled stub** today (W12: "Hint button visible-disabled with 'Hint coming in v2' helper — TODO P3-05"). P3-12 enables it once P3-05's endpoint exists.
4. **No streaming consumption exists in the FE yet.** FRONTEND_ARCHITECTURE notes TanStack Query is "later AI streaming" — the streaming consumer (SSE/`fetch` reader) is **new FE work**, dependent on the wire format P3-04 chooses (cross-cluster — see Dependencies).
5. **No NSwag methods exist** for the tutor endpoints (they don't exist on the backend yet). Like W12, the streaming endpoints likely won't be cleanly typed by NSwag (streaming responses aren't standard NSwag fetch returns) → expect **hand-rolled api-client hooks** for the stream (OQ-3).
6. **Established FE patterns to mirror:** the W12 lesson/quiz wave (`docs/briefs/W12-P2-05-06-07-FE.md`) — `useLocale().direction` for RTL, i18n keys (EN+AR), tokens-only, TanStack Query hooks in `@learnexia/api-client`, primitives in `@learnexia/ui`, discriminated-union view-state (no XState — rule 8).

## Acceptance criteria (testable, FE-scoped)
1. **A1 (streaming + typing):** The explain UI **streams** the response and shows a **typing animation** while tokens arrive (reuse `AITutorBubble`'s `message={null}` typing indicator until first token, then progressively render the streamed text).
2. **A2 (four intents as distinct affordances — no chatbot input):** The UI surfaces exactly four labeled action affordances — no free-text input field. (a) "اشرح السؤال" (explain button, available on lesson screen). (b) "اديني تلميح" (hint button, appears on wrong answer). (c) "ليه إجابتي غلط" (why-wrong chip, appears after a wrong answer and passes the student's actual submitted answer to P3-05). (d) "اديني مثال مشابه" (similar example chip, calls P3-06 `SimilarExampleCommand`). Hint escalation still works: requesting another hint escalates (calls P3-05 with the next hint level).
3. **A3 (redirect state):** When the Helper returns a redirect response (no context available — "خلينا نكمل تحدي [skill] الحالي..."), the UI shows the redirect copy in the `AITutorBubble` (not an error state, not a crash). The redirect text is i18n (EN+AR). Test: trigger a no-context response from the BE → redirect copy displayed in bubble, no error UI shown.
4. **A4 (RTL + EN + bubble component):** The interface renders correctly in **Arabic (RTL)** and **English** (`useLocale().direction`, logical positioning, i18n keys EN+AR) and **uses the `AITutorBubble` component**.
5. **A5 (loading + error):** Loading and error states are handled — a provider/gateway error shows a **gentle retry** affordance (not a crash); a network/stream interruption is recoverable. Redirect state is NOT an error — it is a friendly copy in the bubble.
6. **A6 (conventions):** Tokens-only (no raw hex/px), logical RTL (start/end, no left/right), i18n-only (no hardcoded strings), child JWT (the surface lives under `(child)/` routes), no Strategy/state-library introduced without lead approval (rule 8). No open-ended free-text chatbot input (scope constraint from `ai-helper-mvp.md`).

## Handoff → frontend
- **Branch:** `feat/P3-12-ai-tutor-ui`.
- **api-client hooks (new, in `@learnexia/api-client`):**
  - `useExplainStream(...)` — consumes P3-04's streaming explain endpoint. Hand-rolled SSE consumer. Exposes `{ text, isStreaming, isRedirect, redirectCopy, error, retry }`. The `isRedirect` flag surfaces the no-context redirect state as a distinct UI condition (not an error).
  - `useHintStream(...)` — consumes P3-05's hint endpoint (`intent=Hint`); carries `questionId`/`attemptId` + hint level; exposes `{ text, isStreaming, isRedirect, currentHintLevel, nextHintLevel, error, retry }`.
  - `useWhyWrongStream(...)` — consumes P3-05's hint endpoint with `intent=WhyWrong`; carries `questionId`, `attemptId`, and `wrongAnswer` (the student's submitted answer — read from the quiz state, NOT from a text input); exposes `{ text, isStreaming, isRedirect, error, retry }`.
  - `useSimilarExampleStream(...)` — consumes P3-06's `SimilarExample` endpoint; carries `skillId`, `questionId?`; exposes `{ text, isStreaming, isRedirect, error, retry }`.
  - Set `hintUsed:true` on the next `SubmitAnswer` (W12's `useSubmitAnswer`) when a hint/why-wrong was delivered — OR rely on BE recording it via `HintUsedIntegrationEvent` (confirm which — OQ-4 in P3-05).
- **UI:** reuse `AITutorBubble`. Add the **redirect state variant**: when `isRedirect=true`, render the `redirectCopy` in the bubble (friendly copy, not an error color). The four action affordances are labeled chips/buttons — **no free-text input field**. New primitives → `packages/ui/src/components/` with barrel re-export.
- **Screen/integration:** wire the live explain stream into the lesson screen's existing `AITutorBubble` slot (replace the static `explanation`); wire hint / why-wrong / similar-example into the W12 `AnswerFeedbackStrip` wrong-answer state; replace the disabled "Hint coming in v2" stub.
- **i18n:** add EN+AR keys for all four action labels ("اشرح السؤال", "اديني تلميح", "ليه إجابتي غلط", "اديني مثال مشابه"), hint-level labels ("Hint {{n}} of {{max}}"), simplify action, redirect copy, error/retry. Extend `packages/shared/src/i18n/resources.ts`.
- **Rules:** tokens-only, logical RTL via `useLocale().direction`, i18n-only, **no XState / state library** — discriminated-union + `useState`/`useReducer` (mirror W12). **Stop and ask (rule 8)** before introducing any streaming/state abstraction library. **No free-text chatbot input** (scope constraint).

## Open questions / assumptions / risks
- **OQ-1 (surface placement — designer):** dedicated tutor screen vs in-lesson panel vs bottom-sheet over the lesson? Recommend an **in-lesson / over-lesson surface** at MVP (explain is contextual to a lesson/concept), with a possible standalone "Ask Lexi" entry later. Designer recommends; lead confirms.
- **OQ-2 (streaming wire format — cross-cluster, KEY):** P3-04/05/06 must publish the exact stream format (SSE event shape, sentinel, error event, **redirect event**). The FE streaming consumer is built **to that contract** — so **P3-04's OQ-1 (SSE vs IAsyncEnumerable) gates this story's hooks.** Block the frontend batch until it's pinned. **The redirect event is new** — P3-04's committer must document it in HANDOFF.md alongside the normal stream events.
- **OQ-3 (typed vs hand-rolled hooks):** NSwag won't cleanly type streaming endpoints. **Hand-rolled streaming hooks** confirmed. The four intent hooks share a common streaming base (the redirect-aware `useStreamingText` abstraction).
- **OQ-4 (web SSE vs native):** Expo universal — `EventSource` on web; `fetch`+`ReadableStream`/polyfill on native (one small abstraction, no library — rule 8). Flag the native streaming caveat.
- **OQ-5 (hint-level UI source):** BE returns current/next level (P3-05 OQ-2). FE just displays "Hint n of N." Confirmed alignment with P3-05.
- **OQ-6 (generated-question surfacing):** the "generate me practice questions" affordance (P3-06 batch path) is NOT in scope for this UI. The "similar example" affordance (P3-06 runtime intent #4) IS in scope. Confirmed per `ai-helper-mvp.md` §7.
- **OQ-7 (redirect / empty-context UX):** the redirect copy is defined in `ai-helper-mvp.md §4` ("خلينا نكمل تحدي [skill] الحالي، أو اختار درس العلوم."). Designer authors the bubble treatment (friendly copy, not error state). The `[skill]` placeholder is filled by the BE (carried in the redirect event payload).
- **OQ-8 (why-wrong data flow):** the `useWhyWrongStream` hook sends the student's actual submitted wrong answer to P3-05. This answer is already known to the FE (it was just submitted via `useSubmitAnswer`). Confirm the hook reads from the quiz state (not from a text input field — there is none). Lead confirm.
- **Risk — hard blockers:** the most-downstream story in the cluster; needs P3-04 + P3-05 + P3-06 (SimilarExample endpoint) merged. P3-07/RAG is NOT required — the seeded corpus path is sufficient for the UI to be functional.
- **Risk — streaming on Expo native** (OQ-4) is the trickiest FE bit; budget for it. Web PWA (the e2e target) is the simpler path.
- **Risk — scope creep:** no free-text input must be shipped. The designer must not include a chatbot text field. The AC-6 / A6 criterion enforces this and must be reviewed explicitly.
