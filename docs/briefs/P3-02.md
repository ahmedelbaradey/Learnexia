## ⚠️ Read this first

1. **There must be NO bypass path.** AC1 is absolute: *"Every AI-generated response passes through the Safety Layer before display — no bypass path exists."* This is an **architectural invariant**, not a feature flag. The clean way to guarantee it is to make the Safety Layer the **only** way AI content exits the gateway/AI module — i.e. P3-04..07 consume a *safe* result type that can only be produced by passing through safety. **The implementer must not let any feature call the gateway and skip safety.** Flagged as the headline of the security-auditor gate.
2. **Depends on P3-01.** The Safety Layer wraps the gateway's request/response flow. It cannot be wired until P3-01's `IAiGateway` contract is frozen. Design can proceed in parallel; wiring is sequential.
3. **Pattern + module-location decisions inherit from P3-01.** If P3-01 created an `Ai` module (Q2 there), the Safety Layer lives in the same module (`Ai.Application`/`Ai.Domain`). A pipeline/decorator shape around the gateway is a design pattern → **inherits the rule-8 "ask first"** approval (Q3 here). The implementer must not introduce a decorator/pipeline pattern unilaterally.

## Business context & value

- **Who benefits:** the **parent** (the story persona — trust that the tutor never shows harmful content) and the **child** (protected from toxic/inappropriate/fabricated output). Secondarily the **business** — a single child-safety incident is existential for a kids' EdTech product; this layer is the primary mitigation (BRD §106) and the legal/compliance backbone (NFR-10 under-13 handling).
- **Why it matters now:** it must exist **before** any AI content reaches a student, so it is a hard prerequisite for the entire tutoring surface (P3-04 explain, P3-05 hints, P3-06 question generation). Building tutoring features first and bolting safety on later would create exactly the bypass path AC1 forbids.
- **Success measurement (from AC):**
  - Every AI response flows through safety before display — proven by the fact that the *only* safe-content type is produced by the layer (no handler can emit raw gateway output).
  - A known-toxic / age-inappropriate / hallucinated sample (from the eval set) is **blocked or regenerated** and never returned; the event is logged with the failing check.
  - A safe sample passes through unchanged.
  - The eval/test set runs green in CI and is the regression harness P6-02 expands.
- **Layered defense (FR-ADM-8):** the Safety Layer is the **automated** first line; the P7-09 moderation queue is the **human** second line on top of it. This story builds the automated layer + the event log both lines share.

## Acceptance criteria (verbatim from story + testable backend gates)

From `P3-02-ai-safety-layer.md`:

1. **AC1 — Every AI-generated response passes through the Safety Layer before display — no bypass path exists.**
   - Backend gate: the AI module exposes content to consumers **only** as a safety-checked result. No public method returns raw gateway output. **Architecture test:** the only producer of the "safe AI content" type is the Safety Layer; `IAiGateway` is not directly consumable by feature handlers outside the AI module (or is consumed only by the safety pipeline). Grep/arch gate enforces no handler reaches the raw gateway.
2. **AC2 — The layer filters for toxicity, age-appropriateness, and likely hallucination.**
   - Backend gate: three composable checks — `IToxicityCheck`, `IAgeAppropriatenessCheck`, `IHallucinationCheck` (names indicative). Each returns a typed verdict (`Pass` / `Block` / `NeedsRegeneration`) with a reason code. Implementation may use a moderation model/API + heuristics; the **hallucination** check is grounded against the RAG context (P3-07) where available — flag the dependency (Q4): for P3-01..03 cluster, hallucination check may start as a lighter heuristic and tighten once RAG lands.
3. **AC3 — Given content fails a check, then it is blocked/regenerated and never returned to the student; the event is logged.**
   - Backend gate: on a failing verdict the pipeline either (a) requests a regeneration from the gateway (bounded retry — e.g. 1–2 attempts) and re-checks, or (b) returns a typed safe-fallback (a child-safe "I can't help with that right now" message), **never the unsafe content**. Every block/flag writes a structured event (student/actor, check that failed, reason code, action taken, model, timestamp). **No unsafe content is ever logged in a way that re-exposes it** (log reason codes/hashes, not the raw toxic text, unless the moderation queue explicitly needs a quarantined copy — Q5).
4. **AC4 — The filter behavior is covered by a test/eval set (expanded in Phase 6, P6-02).**
   - Backend gate: a committed eval set (curated safe + unsafe samples per check category, Arabic + English) runs in CI; each sample asserts the expected verdict. This is the regression harness P6-02 extends. The eval set is the acceptance artifact the reviewer checks.

## Handoff → backend-feature

Mirror the AI-module shape established in P3-01 (or the Shared seam). `BaseResponse<T>`/`Successed` where a handler is involved; `ILoggerManager` (rule 5). **Do not introduce a decorator/pipeline pattern until Q3 is approved** (rule 8) — name it to the lead.

- **No-bypass invariant (AC1):** make `SafeAiResult` the only AI-content type leaving the AI module. Prefer a `GenerateSafeAsync` facade that internally calls `IAiGateway` then screens — so callers *cannot* obtain raw output. Add an architecture test asserting no feature handler references `IAiGateway` directly.
- **Three checks (AC2):** `IToxicityCheck`, `IAgeAppropriatenessCheck`, `IHallucinationCheck`, each pluggable, each returning a typed verdict + reason code. Compose them in a deterministic order; short-circuit on first `Block` (or run all to collect all reasons — Q7).
- **Block/regenerate/fallback (AC3):** on failure, attempt bounded regeneration via the gateway (cap from options), re-screen; if still failing, return the child-safe localized fallback (ar/en). **Never return or surface the unsafe content.** Write a `SafetyEvent` for every block/flag.
- **Eval set (AC4):** CI-run harness asserting verdicts on curated ar+en samples; this is the reviewer's acceptance artifact.
- **Latency (NFR-1):** keep checks inside the 4-second budget — prefer a fast moderation classifier / cheap-tier model over a heavy second full-LLM round-trip; run independent checks concurrently where safe.
- **Hardening:** no raw unsafe text in general logs; secrets for any moderation provider sourced from secret config; bounded regeneration (no infinite regen loop); deterministic fallback copy.

## Handoff → security-auditor

**Mandatory run — this is THE most security/child-safety-critical story in the AI phase.** Per CLAUDE.md, Critical/High findings block. Specific focus:

- **No-bypass (AC1):** verify there is genuinely no path to obtain AI content without passing safety. This is the top finding category — a bypass is a Critical.
- **Child-safety completeness (FR-AI-4 mandatory):** confirm toxicity + age-appropriateness + hallucination checks are all wired and enabled by default (not behind a flag that can be turned off in prod).
- **Unsafe-content handling:** verify unsafe content is never returned to the client AND never written to general logs in raw form (only reason codes / hashes; any quarantined copy is access-controlled and PII-minimized).
- **Moderation provider secrets:** keys from secret store, never literals/logs.
- **Fail-closed:** if a safety check errors/times out, the layer must **fail closed** (block + fallback), never fail open (return unscreened content). Verify the error path defaults to safe.
- **Regeneration bound:** no unbounded regen loop (cost/latency DoS).
- **Log PII:** `SafetyEvents` carries minimal student reference (plain int), no name/email, no prompt/response body by default.

## Handoff → api-tester

Runs **only if P3-02 exposes an HTTP endpoint.** As scoped, P3-02 is an **internal layer with no public endpoint** (first AI endpoint is P3-04). **Recommendation: no controller → api-tester not required for P3-02**; coverage is the eval-set harness + unit/architecture tests. Confirm with Q6.

Test gates the implementer must provide regardless:
- Each check: known-bad sample → `Block`/`Regenerate`; known-good → `Pass` (ar + en).
- Block path: unsafe gateway output → student receives fallback, never the unsafe text; `SafetyEvent` written.
- Regenerate path: first output unsafe, regenerated output safe → safe output returned; one regen attempt logged.
- **Fail-closed:** check throws/times out → layer blocks (returns fallback), does not leak unscreened content.
- **No-bypass architecture test:** no handler obtains raw `IAiGateway` output.
- Eval set runs green in CI.

## Open questions for the lead (priority order)

**Q1 (inherited from P3-01) — AI-module location + in-process vs Python.** P3-02 lives wherever P3-01 lands. Resolve P3-01 Q1/Q2 first.

**Q2 — Moderation implementation: hosted moderation API vs LLM-as-judge vs heuristics.** Options: (a) a dedicated moderation endpoint (OpenAI/Anthropic moderation), (b) a cheap-tier LLM acting as a safety judge, (c) heuristic/keyword + classifier hybrid. **Recommendation: hybrid — fast classifier/moderation-endpoint for toxicity + age-appropriateness (latency-friendly), and a cheap-tier LLM-as-judge for the nuanced cases**, all behind the `ICheck` interfaces so it can evolve. **Lead confirm the approach + provider.**

**Q3 (pattern approval) — Pipeline/decorator shape around the gateway.** Making safety the only exit (no-bypass) is cleanest as a decorator/facade over `IAiGateway` (`GenerateSafeAsync`). Per rule 8 this needs sign-off. **Recommendation: approve a facade (`ISafetyLayer.GenerateSafeAsync`) that owns the gateway call + screening** — it makes AC1 structurally enforceable. Name it to the lead.

**Q4 — Hallucination-check strength + input-screening split.** (a) The hallucination check is strongest when grounded against RAG context (P3-07), which lands later. **Recommendation: ship a lighter hallucination heuristic now (e.g. uncertainty/ungrounded-claim cues) and tighten in P3-07.** (b) Does the Safety Layer also screen *input* (prompt-injection / unsafe student input), or is input-hardening solely P3-03's job (fixed system frame + restricted instructions)? **Recommendation: P3-03 owns prompt-construction hardening; the Safety Layer adds a light input screen for overtly unsafe student input.** **Lead confirm the split.**

**Q5 — Quarantine raw unsafe content for the moderation queue, or store reason-codes only?** P7-09's human reviewers may need to see *what* was blocked. **Recommendation: store reason-code + a hash by default; add an access-controlled, PII-minimized quarantine store only if/when P7-09 requires the body** — do not put raw toxic text in general `SafetyEvents`/logs. **Lead confirm.**

**Q6 — Persist `SafetyEvents` now, or structured-log only?** **Recommendation: persist a minimal, PII-light `ai.SafetyEvents` table now** (P7-09 + P7-11 genuinely need queryable rows; it is cheap and append-only) — but without the raw content body. If the lead prefers to defer persistence to P7-11, structured-log for now. **Lead confirm.**

**Q7 — Check composition: short-circuit on first block, or run all checks to collect every reason?** **Recommendation: run all enabled checks (collect all reason codes) for richer logging/analytics, unless latency budget forces short-circuit** — concurrent execution keeps it inside NFR-1. **Lead confirm.**

**Q8 — Streaming + safety.** P3-04 streams responses to the UI. Screening a streamed response is harder (can't screen the whole thing before the first token). **Recommendation: for streamed tutor output, buffer-and-screen in safe-sized chunks or screen-then-stream a pre-screened response; finalize the streaming-safety contract with P3-04.** Flag now so P3-04 doesn't assume token-by-token passthrough. **Lead/architect decision.**

### Assumptions

- P3-01's gateway is merged and exposes a regeneration-capable call (re-prompt the same request).
- A moderation provider/classifier is available with ar+en coverage (Arabic-first per NFR-5 — verify the chosen provider handles Arabic toxicity/age checks acceptably; this is a quality risk).
- The child-safe fallback copy is localizable (ar+en) via the existing resource mechanism.

### Risks (top 3)

- **R1 — A bypass path slips in.** A later feature calls the gateway directly and skips safety. **Mitigation: structural no-bypass (safety is the only content exit) + architecture test + security-auditor Critical gate.**
- **R2 — Arabic-language safety quality gap.** Many moderation models are weaker in Arabic; a toxic Arabic response could pass. **Mitigation: ar-specific eval samples (AC4), choose an ar-capable provider, fail-closed on low-confidence. Flag as a quality risk for the lead.**
- **R3 — Fail-open on error.** If a check throws/times out and the code returns the content anyway, the whole layer is defeated. **Mitigation: fail-closed default (block + fallback on any check error/timeout); security-auditor verifies.**
