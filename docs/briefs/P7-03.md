## Business context & value
- **Who benefits:** **admin** maintains the prerequisite graph that drives student unlock/mastery progression; **students** get a correct, acyclic, language-pure unlock path.
- **Value:** today the graph is hand-authored only by `LearningSeeder` (per-language Math prereq graphs, P8-02). This story replaces seed-only authoring with an admin write API, with the integrity guarantees (acyclic, single-language) enforced server-side.
- **Success measure:** an admin adds/removes prerequisite edges; cycles are rejected with a clear error and not persisted; cross-language edges are rejected; prerequisites-of/unlocked-by reads work per language tree.

## Acceptance criteria (testable)
1. Create/edit a Skill persists name, mastery threshold, estimated time, owning concept/lesson. *(Skill CRUD largely exists — see below; verify and gate.)*
2. Add a prerequisite edge → a `KnowledgeEdge` (Prerequisite/Related + `Strength` 0.0–1.0) is created between two nodes.
3. An edge whose two nodes resolve to **different language trees** (e.g. `ar` node ↔ `en` node) is **rejected** ("edge must stay within one language tree") and not persisted — the graph is per-language; no Ar↔En prerequisites.
4. An edge that would create a **cycle** is rejected ("would create a cycle") and not persisted — **reuse `SkillGraphValidator.AssertAcyclic`** (runs over Prerequisite edges; `InvalidOperationException` → mapped to `Successed=false`).
5. For a skill/node, "prerequisites of X" and "skills unlocked by X" are listed (reuse the P2-11 `GetPrerequisites`/`GetUnlockedBy` queries), scoped to one language.
6. Remove an edge deletes it; subsequent `GetGraph` reflects the removal.
7. `GetGraph` returns nodes[] + edges[] for a subject/skill, single-language (optional `language` filter or derived from the chosen subject).
8. All mutations admin-only (`AdminOnly`); non-admin → 403.

## Affected modules & data (new vs existing)
**Module:** `Learning` only. Schema: `learning`.

**Existing (verified — do NOT re-create):**
- `KnowledgeNode` (`Name`, `NodeType`, `SubjectId`, `GradeId`, `Difficulty` int 1–5, `SkillId?`, source/target edge navs) + filtered unique index on `SkillId`.
- `KnowledgeEdge` (`SourceNodeId`, `TargetNodeId`, `RelationshipType` Prerequisite/Related, `Strength` decimal(5,4) default 1.0, Restrict on both FKs).
- **`SkillGraphValidator.AssertAcyclic(IEnumerable<KnowledgeEdge>)`** (Domain/Services) — three-color DFS over Prerequisite edges; throws `InvalidOperationException` with offending source→target. **Reuse as-is.**
- `KnowledgeGraphController` with `GET Prerequisites/{nodeId}` + `GET UnlockedBy/{nodeId}` (both `[Authorize]`). The `GetPrerequisitesQuery`/`GetUnlockedByQuery` handlers exist.
- `Skill` entity (`Name`, `MasteryThreshold`, `EstimatedTimeMinutes`, `ConceptId`, `Lessons`) + `SkillsController` Create/Update/Delete — **already `[Authorize(AdminOnly)]`** (verified). Full Skill command/validator stacks exist.
- `SubjectLanguageResolver` (Domain/Services) for deriving a node's language via its owning Subject.

**Net-new (this story):**
- **Edge authoring commands** `AddKnowledgeEdgeCommand` / `RemoveKnowledgeEdgeCommand` (`Application/KnowledgeEdges/*`) — none exist today (P2-11 shipped reads only).
- **`GetGraphQuery`** returning nodes + edges for a subject/skill, single-language (`SkillGraphDto { nodes[], edges[] }`).
- **Cross-language edge guard** in the AddEdge handler: resolve both nodes' owning-Subject `Language` (via `SubjectLanguageResolver`/the node's `SubjectId`) and reject mismatches → `Successed=false`. Runs alongside the acyclic check.
- **Optional `language` filter** on the graph reads (BE-7), or derive from the chosen subject.
- Possibly minor new skill props (BE-5) — only if needed; likely a no-op migration since Skill already carries threshold/time. **Verify before adding a migration.**

## Handoff → backend-feature
- **Commands:** `AddKnowledgeEdgeCommand(SourceNodeId, TargetNodeId, RelationshipType, Strength)`, `RemoveKnowledgeEdgeCommand(EdgeId)`. AdminOnly.
- **Acyclic reuse:** in the AddEdge handler, load all existing Prerequisite edges + the proposed one and call `SkillGraphValidator.AssertAcyclic`; catch `InvalidOperationException` → `BaseResponse` with `Successed=false` + clear message (do not let it 500).
- **Cross-language guard:** resolve each node → owning Subject `Language`; if the two differ → `Successed=false`. Reuse `SubjectLanguageResolver`/the Subject `Language` column; there is **no language column on the graph entities** — derive it.
- **Queries:** `GetGraphQuery(subjectId?/skillId?, language?)` → `SkillGraphDto`; reuse existing `GetPrerequisitesQuery`/`GetUnlockedByQuery` for the prereq/unlock lists.
- **Controller:** add edge-author routes to a controller (extend `SkillsController` per the FE contract `POST/DELETE /api/Learning/Skills/Edges`, `GET /api/Learning/Skills/Graph` — or `KnowledgeGraphController`; match the task's FE contract). AdminOnly on mutations.
- **Event seam:** publish `AdminActionPerformedEvent` on edge add/remove + skill mutations for P7-12 audit. **⚠️ Contract not yet in `Shared.Contracts`** — depends on the P7-01 decision (introduce there, reuse here).
- **Conventions:** `BaseResponse<T>`, `NewResult(...)`, `Successed`, `ILoggerManager`. **Do not duplicate** P2-11's `KnowledgeNode`/`KnowledgeEdge`/`SkillGraphValidator` — reuse.
- **No design pattern.** Mirror existing Learning command/query/handler shapes only.

## Open questions / assumptions / risks
- **Q1 (Skill↔Node mapping for edge authoring):** the FE contract talks about edges "between two skills," but edges physically connect `KnowledgeNode`s (a node optionally wraps a Skill via `SkillId`). Confirm whether the AddEdge command takes **node ids** (recommended — matches the relational model) or **skill ids** (requires resolving Skill→Node, and erroring when a skill has no node). **Assumption:** node ids in the command; the FE resolves skill→node. Flag for lead.
- **Q2 (auto-create node on skill create):** should creating a Skill auto-create a wrapping `KnowledgeNode`, or is node creation a separate admin step? P2-11 nodes were seeded. **Assumption:** node creation is separate/seeded for now; this story authors edges over existing nodes. Flag for lead.
- **Q3 (AdminActionPerformedEvent):** same cross-wave contract dependency as P7-01 — introduce in P7-01, reuse here, or defer.
- **Risk:** the acyclic check must include **all existing** Prerequisite edges (not just the new one) — loading only the proposed edge would miss transitive cycles. Test with a 3-node A→B→C, then C→A.
- **Risk:** cross-language guard depends on every node having a resolvable owning Subject; a node with a dangling `SubjectId` should fail closed (`Successed=false`), not 500.
