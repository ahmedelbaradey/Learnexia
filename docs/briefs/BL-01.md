## Business context & value

- **Who benefits:** the **admin / content team** directly (they ingest real textbooks/worksheets so the platform stops relying on hand-seeded chunks). The **student** benefits indirectly — every uploaded, parsed, embedded document widens the corpus the AI tutor retrieves from and the curriculum the prerequisite graph is inferred from. No parent or student surface in BL-01.
- **Value:** BL-01 is the *front door* of the entire Curriculum Intelligence pipeline. Nothing downstream (BL-02 parse, BL-05 ingest/embed, BL-03 KG-suggest) can run until a document exists in storage and a `parse` job is on the outbox.
- **Success measure:** an admin POST of a valid PDF/DOCX/image returns 201 with a `CurriculumDocument` in `Received` status; the object lands in the curriculum storage bucket under a GUID key; exactly one `PipelineJobs` row (`JobType='parse'`, `Status='Pending'`) exists for it; an invalid file (wrong magic bytes / over the size cap) returns 422; a non-admin gets 403; list/detail expose the document's status.

## Handoff → backend-feature

> **Mirror `UploadAvatarCommandHandler` exactly** — validation order, 422 on invalid file, `ServerError<T>` on exception, store **key not URL**, stream-based upload via `IStorageService`. Do not invent a different upload pattern (CLAUDE.md rule 8).

### BE-3 — `CurriculumFileValidator` + `CurriculumUploadConfiguration` (NET-NEW)
- `Application/Features/CurriculumDocuments/Validators/CurriculumFileValidator.cs` — static validator extending the `AvatarImageValidator` magic-byte pattern to:
  - **PDF**: `%PDF-` (`25 50 44 46 2D`).
  - **DOCX**: ZIP/PK header `50 4B 03 04` (DOCX is a zip — matches any OOXML/zip; pair with the declared content-type `application/vnd.openxmlformats-officedocument.wordprocessingml.document` as a secondary guard — flag to security-auditor).
  - **Images**: JPEG (`FF D8 FF`), PNG, WEBP (reuse the avatar signatures).
- Allow-list of declared content-types mapped to a `CurriculumFileType` enum; magic-byte detection returns the true type or null.
- `Infrastructure/Configuration/CurriculumUploadConfiguration.cs` — `MaxFileSizeBytes` (config-driven; see Open Q3), bound from a new appsettings section (e.g. `"CurriculumUpload"`).
- Invalid → localized 422 validation failure, never a 500.

### BE-4 — `UploadCurriculumDocumentCommand` + handler + validator (NET-NEW)
- `Application/Features/CurriculumDocuments/Commands/UploadCurriculumDocument/` — command carries the file (`IFormFile` at the controller boundary, passed as stream + metadata into the command) + `GradeId`, `SubjectId`, `Language`, `Country`.
- Handler (mirror `UploadAvatarCommandHandler`): (1) resolve admin user from JWT via `ICurrentUserService`; (2) presence/size → 422; (3) declared content-type allow-list → 422; (4) magic-byte detection → 422; (5) upload stream via `IStorageService.UploadFileAsync(stream, guidKey, detectedContentType, length, <curriculum bucket>, ct)`; (6) on storage failure → `ServerError<T>`; (7) persist `CurriculumDocument` with `Status = Received`, `ObjectKey = result.FilePath`; (8) **BE-5** write the `PipelineJobs` row; (9) return 201 with the new document id/status.
- Use `CurriculumDbContext.SaveChangesAsync(userId)` (audit-stamping override), **not** the base.

### BE-5 — Outbox enqueue (NET-NEW, inside the BE-4 handler — DB-outbox, NOT MediatR)
- After the document is saved, add a `PipelineJob`: `JobType='parse'`, `Status='Pending'`, `DocumentId = <new doc id>`, `PayloadJson = {"object_key":"<key>","content_type":"<detectedType>"}`, `CreatedAt = now`, `RetryCount = 0`.
- The FK needs the document's identity, so: save the document, then add+save the job inside an explicit transaction (`BeginTransactionAsync`) so a job-write failure rolls back the document — honoring the No-UoW rule's "explicit transaction for atomic multi-writes." See Open Q7.
- **Do NOT publish a MediatR integration event** — MediatR is in-process and cannot reach the Python worker (§4b).

### BE-6 — `ListCurriculumDocumentsQuery` (NET-NEW)
- `Application/Features/CurriculumDocuments/Queries/ListCurriculumDocuments/` — paged, filterable by `Status`, `GradeId`, `SubjectId`. `CurriculumDocumentListDto` + AutoMapper `ProjectTo`. Returns `BaseResponse<PagedList<CurriculumDocumentListDto>>`. Admin-only. Do NOT expose `ObjectKey` in the list DTO (least exposure).

### BE-7 — `GetCurriculumDocumentQuery` (NET-NEW)
- Detail view: all fields incl. `Status`, `StatusReason`. `CurriculumDocumentDto` + mapping. Admin-only. Whether to expose the raw `ObjectKey` vs a presigned preview URL → flag to security-auditor; recommend NOT returning the bare key (mirror the avatar read-path which presigns).

### BE-8 — `CurriculumDocumentsController` (NET-NEW)
- `Api/Controllers/CurriculumDocumentsController.cs : AppControllerBase`, `[Route("api/curriculum/documents")]`.
- **Class-level `[Authorize(Roles = "Admin,SuperAdmin")]`** (the convention used by Identity/Parent admin endpoints — verified `[Authorize(Roles = "Parent,Admin,SuperAdmin")]` in `ParentController`; `Admin`/`SuperAdmin` seeded by `RoleSeeder`). Confirm exact role names in Open Q6.
- Endpoints: `POST /` (multipart upload → 201), `GET /` (paged list), `GET /{id}` (detail → 404 if missing). All `NewResult(await Mediator.Send(...))`.
- The controller assembly is **already** registered via `AddApplicationPart(typeof(CurriculumModule).Assembly)` — no new `AddApplicationPart`.

## Handoff → security-auditor (REQUIRED — file upload + admin authz)
Audit before the reviewer gate. Focus:
- **Authz:** `[Authorize(Roles=...)]` enforced on every endpoint (CLAUDE.md rule 6 — policies exist but aren't auto-enforced; the role attribute is the guard). No IDOR on detail/list.
- **Upload safety:** magic-byte validation present and ordered *before* storage; DOCX-as-zip caveat; size cap enforced server-side (not just declared `Content-Length`); object stored under a GUID key with the **detected** content-type; original filename never used as the storage key (path-traversal / content-sniffing).
- **Storage exposure:** object key not leaked to non-admins; prefer presigned read path over returning the bare key.
- **PayloadJson:** no secrets / no unsanitized client input beyond `object_key` + `content_type` lands in the outbox row the Python worker trusts.

## Open questions / assumptions / risks (with recommendations)

**Q1 — Storage bucket for curriculum files.** `MinIOConfiguration.DefaultBucket = "avatars"`; the task file says upload to a `curriculum` bucket; no curriculum bucket setting exists today. **Recommendation:** add a `CurriculumBucket` (e.g. `"curriculum"`) — a new property on `MinIOConfiguration` or a field on `CurriculumUploadConfiguration` — and ensure it is created at bootstrap. Do NOT reuse the avatars bucket (mixes child-PII avatars with curriculum docs; different lifecycle/ACL). **Lead to confirm** bucket name + who creates it (bootstrap vs ops).

**Q2 — Wire `KGSuggestion.SourceCurriculumDocumentId` FK now?** BL-04 left it a nullable plain int with NO FK *because `CurriculumDocument` did not exist* (`KGSuggestion.cs` L48-50). It now exists. **Recommendation: do NOT add the FK in BL-01.** It is out of BL-01's AC scope, pulls a BL-03 concern forward, and is a no-value migration on an empty table. Flag as a **BL-03 follow-up** (decide FK vs plain int when the suggestion-write path is built). **Lead to confirm** defer.

**Q3 — Max file-size cap + large-file handling.** Avatar cap is 2 MB; textbooks can be 50–100 MB. **Recommendation:** config-driven `MaxFileSizeBytes` defaulting to ~100 MB, with the Kestrel/form multipart body-size limit raised for the upload route only (not globally), and **stream** the upload to storage (do not buffer the whole file in memory). **Lead to confirm** the cap; flag the memory risk to security-auditor + planner.

**Q4 — `PipelineJob.Id`: `bigserial` vs int.** §4b specifies `bigserial`; existing curriculum PKs are `int` identity. **Recommendation:** `int` identity for module consistency (job volume is low at MVP; rows are deleted/archived on completion). **Lead to confirm** (low-stakes).

**Q5 — `PipelineJob.Status`/`JobType` as enum vs string.** §4b/task file model them as varchar strings so the Python worker reads plain text. **Recommendation:** persist as **strings** (`HasConversion<string>()` or string consts) — the string values are the cross-process contract; **NOT** `HasConversion<int>()` (Python would have to know the int mapping). **Lead to confirm.**

**Q6 — Exact admin role name(s).** Verified roles: `Admin`, `SuperAdmin` (seeded by `RoleSeeder`; `ParentController` uses `"Parent,Admin,SuperAdmin"`). **Recommendation:** `[Authorize(Roles = "Admin,SuperAdmin")]`. **Lead to confirm** `SuperAdmin` is also allowed (recommended) and that no separate permission policy is required.

**Q7 — Atomicity of doc + job write (BE-5).** The FK `PipelineJob.DocumentId → CurriculumDocuments.Id` needs the document's identity. **Recommendation:** save the document, then add+save the job inside an explicit `BeginTransactionAsync` so a job-write failure rolls back the document (No-UoW rule's explicit-transaction guidance). This is the one place BL-01 needs an explicit transaction. **Confirm** with planner/reviewer.

**Assumptions:** MinIO/storage enabled in the target env (`MinIOConfiguration.Enabled`); the `Curriculum.IntegrationTests` harness can drive the upload endpoint (boots module + storage, or mocks `IStorageService`); `Admin`/`SuperAdmin` roles seeded in the test JWT issuer.

**Risks:**
- **Large-file memory (highest):** a 100 MB upload must stream, not buffer in memory (ties to Q3).
- **DOCX magic-byte = generic zip:** the PK header matches any zip; rely on declared content-type + extension as a secondary guard; flag residual risk to security-auditor.
- **Migration ordering:** `AddPipelineJobsTable` must follow `AddCurriculumDocumentTable` (FK target); both append after `AddKGSuggestionTable`.
- **Snapshot conflicts:** both migrations mutate `CurriculumDbContextModelSnapshot.cs`; keep the db-migration pass single-threaded.
