# Pipeline Brief — Wave 11 FE (P2-02-FE + P2-03-FE) Browse subjects & navigate the skill tree

## Summary & traceability
- **One-line scope:** ship the student's **Subjects browse loop on the web (Expo universal, web-first)** — a Subjects list scoped to the child's grade → a per-subject screen with two views (Lessons grid + Skill tree) — wired to the merged backend (P2-02 + P2-04 + P2-03 boss flag). No lesson player, no quiz, no home dashboard.
- **User stories (source of truth):**
  - `user-stories/Phase-2-Learning-Core/P2-02-browse-subjects-and-lessons.md` (SP 3, FR-LR-1, FR-LR-2)
  - `user-stories/Phase-2-Learning-Core/P2-03-navigate-skill-tree.md` (SP 5, FR-LR-2)
- **Task files:**
  - `tasks/Frontend/student-app/Phase-2-Learning-Core/P2-02-FE.md` (FE-1 Subject Selection, FE-2 Subject detail / lessons, FE-3 Empty state)
  - `tasks/Frontend/student-app/Phase-2-Learning-Core/P2-03-FE.md` (FE-1 SkillTree view + 4 states, FE-2 tap behaviour + why-locked sheet, FE-3 RTL + gestures)
- **Phase / wave / epic:** Phase 2 — Learning Core; **Wave 11** (first all-FE wave on top of fully-merged Phase-2 BE); Learning Module epic.
- **BRD goal:** **G1** (engaging, personalized learning experience) — subject discovery + tree navigation are the front door to the learning loop. Secondary **G2** (clear progression at a glance).
- **Product-decision overrides (applied):** **4 subjects** (Math / Science / Arabic / English — Social Studies removed); parent-driven onboarding (student lands here with a JWT seeded by the parent); no teacher role; per-child grade transition preserves history (the FE just reads the current grade — it doesn't care about transitions). RTL/Arabic is the **default** locale.

## Business context & value
- **Who benefits:** the **student** (signed-in child) — opens the app, sees their 4 grade-scoped subjects, picks one, sees either the unit→lesson list ("what is there to do") or the skill tree ("how does it all connect, what's locked, what's next"). Indirectly the **parent** (children actually engage with grade-appropriate content) and the **product team** (P2-05 lesson player has somewhere to launch from).
- **Value:** the closing FE for Phase 2 (Wave 11 alone). Without these two screens the student-app is a placeholder home + mascot. After Wave 11 the student can navigate the seeded curriculum end-to-end (4 subjects × 6 grades × ~2–5 units × ~2–3 lessons each = 162 lessons / 162 skills / 66 bosses), see lock state, and read **why** a lesson is locked.
- **Success measured by:**
  - A seeded G1 student lands on `(child)/index.tsx` and sees **exactly 4** subject rows (Math/Science/Arabic/English) — never 5, never another grade's content.
  - Tapping a subject shows its units → lessons in `SequenceOrder`; the boss lesson (last per unit) is visually distinct.
  - Switching to the Skill tree shows concepts → skills with the 4 visual states (Locked / Available / Completed / Boss) sourced from `NodeState` + `IsBoss`.
  - Tapping a Locked node never navigates; instead it surfaces the `MissingPrerequisites` from the BE in a friendly "you need {RequiredAccuracy}% on {PrereqSkillName}" sheet.
  - Renders correctly in Arabic (RTL) and English (LTR), token-only colors, no raw hex.

## Acceptance criteria (FE-scoped, testable)

### P2-02-FE — Browse subjects and lessons
- **AC-02-FE-1 — Subject Selection list.** On `(child)/index.tsx`, a signed-in student sees **exactly the 4 MVP subjects** scoped to their grade (Math, Science, Arabic, English). Social Studies must never render. Each row uses the design-system "subject row" pattern (icon tile + name + caption + chevron). A small grade caption ("Grade {n}") appears in the header when the student's grade is known. Tapping a row navigates to `(child)/subjects/[subjectId]`.
- **AC-02-FE-2 — Subject detail (Lessons view).** On `(child)/subjects/[subjectId]` (Lessons tab/segment), the units render in `SequenceOrder` ascending, each with their lessons in `SequenceOrder` ascending. Each `LessonInUnitDto` is rendered as a lesson card showing: title, difficulty, lock state (driven by `State`, NOT the obsolete `IsLocked`), and a small **Boss** badge when `IsBoss === true`. A completed lesson (`State === 2`) renders a "Completed" treatment; available (`State === 1`) renders the active CTA; locked (`State === 0`) renders dimmed + lock glyph.
- **AC-02-FE-3 — Empty state.** When the BE returns 200 with an empty `Units` collection (or all units have empty `Lessons`), the screen renders a friendly "Coming soon — no lessons yet" empty state using existing tokens — NOT an error. A 404 from the BE (unknown subject id) renders a separate "Subject not found" state with a back action.
- **AC-02-FE-4 — Tap behaviour.** Tapping an Available or Completed lesson navigates to `(child)/lessons/[lessonId]` (stub destination — P2-05-FE owns the actual screen; for Wave 11 the route renders a placeholder "Lesson player coming soon" screen with the lesson id, see `Out of scope` §10). Tapping a Locked lesson MUST NOT navigate; it opens a "Why locked?" sheet sourced from `LessonInUnitDto.MissingPrerequisites`.
- **AC-02-FE-5 — Loading + error states.** Each query renders a loading skeleton (shimmer or 3-row placeholder) and a friendly error retry on `useQuery.isError`.

### P2-03-FE — Navigate the skill tree
- **AC-03-FE-1 — Skill tree render.** On `(child)/subjects/[subjectId]` (Tree tab/segment) the subject's concepts → skills render as a connected vertical path (matching `screenshots/mobile/09-skill-tree.png` + `screenshots/mobile-ar/09-skill-tree.png`). Each skill node renders one of **four visual states** composed from the BE pair `(SkillNodeDto.State, derived HasBoss)`:
  - `Locked` (state 0) → grey lock chrome.
  - `Available` (state 1) → glowing purple/primary "current" chrome with the pencil icon.
  - `Completed` (state 2) → green ✓ with star mastery indicator.
  - `Boss` → distinct boss chrome (🔥 / crown / flame token) — see §7 "State + locks" for the composition rule.
- **AC-03-FE-2 — Tap behaviour.**
  - Tapping a Completed node opens its lesson (`LessonIds[0]` → `(child)/lessons/[lessonId]` stub).
  - Tapping an Available node opens its lesson (same).
  - Tapping a Locked node MUST NOT navigate; it surfaces `SkillNodeDto.MissingPrerequisites` in a friendly sheet ("You need {RequiredAccuracy}% on {PrereqSkillName} — you're at {CurrentAccuracy}%").
- **AC-03-FE-3 — RTL + LTR.** The tree renders right-aligned in Arabic, left-aligned in English. Logical flex props only (`flexDirection={isRtl ? 'row-reverse' : 'row'}`), no positional left/right. Captures `09-skill-tree.png` (LTR) and `09-skill-tree.png` (AR) are the visual gates.
- **AC-03-FE-4 — Mastery percent header.** The screen header shows "{SubjectName} · {ConceptName?}" + "Unit {x} of {y} · Mastery {z}%" — Wave 11 ships the subject+concept line; the mastery % is computed from the tree's `Completed` count vs total skill count as a placeholder (no new BE call). This matches the LTR/RTL screenshots.
- **AC-03-FE-5 — Loading + error states.** Tree skeleton on `isLoading`; friendly retry on `isError`. Anonymous (401) → bounce to login (existing auth guard handles this already).

### DTO surface (confirmed)
- **`StudentSubjectDto`**: `{ id:int, name:string, gradeNumber:int }`. The `gradeNumber` (not `gradeId`) is the human-facing 1–6 — useful for showing "Grade {n}" in the header.
- **`UnitWithLessonsDto`**: `{ unitId:int, name:string, sequenceOrder:int, lessons: LessonInUnitDto[] }`.
- **`LessonInUnitDto`**: `{ lessonId:int, name:string, difficulty:DifficultyLevel(enum int), sequenceOrder:int, isLocked:bool [obsolete — IGNORE], skillId?:int, state:NodeState(int), isBoss:bool, missingPrerequisites: MissingPrerequisiteDto[] }`.
- **`ConceptNodeDto`**: `{ conceptId:int, name:string, skills: SkillNodeDto[] }`.
- **`SkillNodeDto`**: `{ skillId:int, name:string, masteryThreshold:int, estimatedTimeMinutes:int, state:NodeState(int), lessonIds:int[], missingPrerequisites: MissingPrerequisiteDto[] | null }` — **`MissingPrerequisites` is `null` when the call was anonymous** (no JWT). Wave 11 requires auth on `Tree`/`Lessons`, so the FE can expect non-null for signed-in students; still defensive-code it.
- **`MissingPrerequisiteDto`** (positional record): `{ prereqSkillId:int, prereqSkillName:string, prereqNodeId:int, requiredAccuracy:int (0..100), currentAccuracy:double (0.0..100.0) }`. The FE renders: **"You need {requiredAccuracy}% on {prereqSkillName} — you're at {Math.round(currentAccuracy)}%."**
- **`NodeState`** enum is emitted as a plain JSON int (confirmed in P2-02 tests + HANDOFF — "no `JsonStringEnumConverter` registered"). Values: `0 Locked, 1 Available, 2 Completed`. **No `Boss=3`** — boss is the orthogonal `IsBoss` bool on `LessonInUnitDto` (not on `SkillNodeDto`). See §7.
- **`DifficultyLevel`** (Learning.Domain enum): `Easy=1, Medium=2, Hard=3` (assumption — confirm during api-client regen).

### Envelope
- All three endpoints return `BaseResponse<T>` with the camelCase `"successed": true` flag (load-bearing config — HANDOFF). The existing `unwrapEnvelope(...)` helper handles this; new hooks follow the `useMe` pattern verbatim.

    BossBadge.tsx                      (tiny "BOSS" pill; tokens-only)

**Recommendation: Option A — Tabs (segmented control) inside the subject screen.**

Reasoning:
- The subject is the **noun**; Lessons vs Tree are **views** of the same subject (curriculum data). A tab pattern keeps the back stack clean (one push from Subjects, not two), and a Tree user often wants to flip to Lessons (a flat list) and back without re-loading.
- The `(child)/subjects/[subjectId]/_layout.tsx` segment idiomatically composes a `Tabs` (we already have `@learnexia/ui/Tabs` for the Settings screen pattern — reuse it inside the subject screen header).
- The skill-tree screen capture (`09-skill-tree.png`) has a bottom tab bar already ("Home / Skills / Quests / League / Me"); that bar is a future P2-09 main-nav concern, not the Lessons/Tree split. The Lessons/Tree split goes **above** that bar in the screen body.
- Alternative B (separate routes `subjects/[id]` + `subjects/[id]/tree`) would add stack depth and force the user to "navigate" rather than "switch". Reject.

Decision is **proposed** here for the planner/designer to confirm against the screenshots; if the designer's mockup says "two distinct routes", the structure flips to Option B trivially.

## State + locks (composition rule)

### Four visual states on the **skill tree** (P2-03-FE-1)
The story names four states ("locked, unlocked, completed, boss"). The BE delivers a **3-state enum `NodeState` + an orthogonal `IsBoss` bool**. **Composition rule the FE uses to render the four visual categories:**

| Visual category | Composition |
|---|---|
| `Locked` (grey lock) | `state === 0` AND not boss (or boss — boss chrome is decorative even when locked; see below) |
| `Available` (purple glow / pencil) | `state === 1` AND not boss |
| `Completed` (green check + stars) | `state === 2` AND not boss |
| `Boss` (🔥 / crown chrome) | **derived for skill nodes:** `skill.lessons.some(l => l.isBoss)` — the SkillNode has no `HasBoss`/`IsBoss` (decision Q8 in `briefs/P2-03.md`: skipped). The FE must cross-reference: load both `useSubjectSkillTree(id)` and `useSubjectLessons(id)`; for each `SkillNodeDto.skillId`, mark it `hasBoss = true` if any lesson with `skillId === skill.skillId` has `isBoss === true`. |

**Important interplay:** a boss skill can also be Locked, Available, or Completed. The chrome composes as `(state, isBoss)` — e.g. a Locked boss shows the boss flame **on top of** the lock chrome (designer to mock the priority). The four-state phrasing in the story is the user-facing taxonomy, not an exclusive partition — see `briefs/P2-03.md` Q4 (NodeState stays at 3 values).

**Cross-reference cost note:** because the FE makes both calls already (one for each tab), the boss-derivation is a free in-memory join (no extra request). The designer/planner may decide to push a `HasBoss` rollup to BE later (Q8) — out of scope for Wave 11.

### Four visual states on the **lessons grid** (P2-02-FE-2)
Simpler — `LessonInUnitDto` carries both `state` and `isBoss` directly. The card composes:
- `state === 0` → Locked variant (dim, lock glyph, **non-interactive** — tapping shows Why-locked sheet).
- `state === 1` → Active variant (primary CTA chrome).
- `state === 2` → Completed variant (green, mastery glyph).
- `isBoss === true` → adds a "BOSS" pill on top of any variant (boss chrome is orthogonal — see Q4 in `briefs/P2-03.md`).

### "Why locked?" UX (P2-02-FE-4 + P2-03-FE-2)
- Tap a Locked lesson card OR Locked skill node → open `WhyLockedSheet` (bottom sheet on mobile, dialog on web).
- Sheet content: list of `MissingPrerequisites` entries, each rendered "You need {requiredAccuracy}% on {prereqSkillName} — you're at {Math.round(currentAccuracy)}%."
- Empty `missingPrerequisites` (defensive): show a generic "Locked — finish the previous lesson first" line.
- Localize: `t('child.subjects.whyLocked.title')`, `t('child.subjects.whyLocked.needLine', { requiredAccuracy, skillName, currentAccuracy })`, etc. — add to `packages/shared/src/i18n` AR + EN.

### Tap → navigate (Available / Completed)
- Tap Available or Completed lesson card → `router.push('/(child)/lessons/' + lessonId)` — **stub** (the route exists but renders a placeholder screen — see §10).
- Tap Available or Completed skill node → if `lessonIds.length === 0`, no-op (defensive); else `router.push('/(child)/lessons/' + lessonIds[0])`. The "which lesson" rule is "first lesson by id" today (the BE returns `lessonIds` unsorted per HANDOFF — `SkillNodeDto.LessonIds` ordering today is `sk.Lessons.Select(l => l.Id)`). Wave 11 picks `lessonIds[0]`; if multiple lessons per skill matter UX-wise, route to the Lessons tab pre-scrolled to the skill (defer).

## RTL + theming
- **Arabic-first.** The product's default locale is Arabic (HANDOFF). `useLocale()` already provides `isRtl`, `direction`, `locale` — mirror the `(child)/index.tsx` placeholder pattern.
- **Logical flex.** Every horizontally-oriented stack uses `flexDirection={isRtl ? 'row-reverse' : 'row'}` (existing app convention). No `marginLeft`/`marginRight` — use `marginStart`/`marginEnd` (Tamagui logical props).
- **Tokens only.** Every colour comes from `@learnexia/design-system` tokens. No raw hex. Subject icon background tints come from a per-subject token map (e.g. `subjectMath` / `subjectScience` / `subjectArabic` / `subjectEnglish` — designer to confirm or use the existing preview-card colours).
- **Dark theme is default** (per HANDOFF).
- **Writing direction:** every `Text` with user-language content carries `writingDirection={direction}` (existing pattern in `(child)/index.tsx`).
- **Eastern-Arabic numerals** in Arabic — `Mastery 45%` becomes `الإتقان ٤٥٪` (matches `mobile-ar/09-skill-tree.png`). Existing i18n helper handles numeral conversion; verify it's wired into the new screens.
