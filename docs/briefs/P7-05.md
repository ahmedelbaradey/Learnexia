# Pipeline Brief — P7-05 Publish, version & preview curriculum content (Backend)

> Analyzer brief, 2026-06-08. Backend-only slice of the Phase-7 Admin Console **Curriculum wave** — the capstone story. Grounded in `docs/briefs/phase-7-admin-gap-analysis.md`, the HANDOFF "P7 — gap analysis + modular spec refit" + Phase-8 + IStorageService sections, and a fresh read of the live `Learning` source tree. **Locked:** lifecycle/versioning lives entirely in the **`Learning` module** (no `assessment` module); `AdminOnly` policy; bilingual `(SubjectCode, Language)` per-tree operations; shared `IStorageService`. Do not re-open.

## Summary & traceability
- **Task (one line):** Add a **draft→published lifecycle with versioning and a student-eye preview** across the `Learning` curriculum hierarchy (subject/unit/lesson/quiz) — net-new `LifecycleState` + `ContentVersion`, atomic publish/rollback (explicit transaction), student reads filtered to the latest published version, admin reads exposing live+draft, and per-`(SubjectCode, Language)`-tree publish/coverage.
- **User story:** `user-stories/Phase-7-Admin-Console/P7-05-publish-version-preview-curriculum.md` (SP 8).
- **BE task file:** `tasks/Backend/Phase-7-Admin-Console/P7-05-BE.md` (BE-1..BE-8).
- **FR / SRS:** FR-ADM-4 (publish/version/preview), SRS §3. BRD goal: **G3** (safe editing; only vetted content reaches students).
- **Phase/epic:** Phase 7 · Epic *Admin — Curriculum Management*. Post-MVP.
- **Module:** `Learning`. **Depends on P7-01..P7-04** (the content being versioned) and the P8-02 language-tree model.

## Business context & value
- **Who benefits:** **admin** edits safely (draft) and controls exactly what students see (publish); **students** only ever receive vetted, published, language-correct content.
- **Value:** the curriculum is a student-facing, high-stakes asset. Today every edit is immediately live (the P7-01..04 mutations write straight to the served entities). This story introduces the safety lifecycle — draft accumulation, versioned publish, preview, rollback — the highest-value governance layer of the curriculum wave.
- **Success measure:** an admin edits → changes stay draft (not served); publishes → a versioned snapshot is recorded (timestamp + author) and students get it; previews a draft as a student would (correct RTL/LTR per language tree) without publishing; rolls back to the previous version; sees per-language publication coverage and gaps.

## Acceptance criteria (testable)
1. Editing a curriculum item (subject/unit/lesson/quiz) accumulates in a **draft** state and is **not served to students** until published.
2. Publish records a new `ContentVersion` (version no., `publishedAt`, `publishedBy`) and students begin receiving it; **publish acts on one `(SubjectCode, Language)` tree** — publishing `ar` does not publish its `en` sibling.
3. A per-grade **publication-coverage** read shows, per `SubjectCode`, whether `en` is published in parallel with `ar`, flagging one-sided coverage (e.g. `ar` Math published, `en` Math still draft).
4. A published item with newer draft edits exposes **both** the live version and the pending draft distinguishably (admin read).
5. Preview renders a draft **as a student would**, in that tree's language (RTL `ar` / LTR `en`), **without publishing**.
6. Rollback restores the previous published `ContentVersion` **for that `(SubjectCode, Language)` tree only** (atomic).
7. Publish/rollback are atomic multi-writes in an **explicit transaction** (no Unit of Work).
8. Student-facing reads filter to the **latest published version**; preview/media references served via `Shared.Kernel.Storage.IStorageService`.
9. All publish/preview/rollback admin-only (`AdminOnly`); non-admin → 403.

## Affected modules & data (new vs existing)
**Module:** `Learning` only. Schema: `learning`.

**Existing (verified):**
- The curriculum entities to be versioned all live in `Learning`: `Subject`, `Unit`, `Lesson`, `ContentBlock` (from P7-02), `QuizQuestion`/quiz (from P7-04). All carry `SubjectCode`/`Language` via the Subject root (`SubjectLanguageResolver`).
- `SubjectLanguageResolver` for resolving a tree's language. `IStorageService` (`Shared.Kernel.Abstractions.Storage`) for media. `AppControllerBase` (note: it has **no current-user accessor** — `publishedBy` must come from a JWT-claims accessor; see handoff).

**Net-new (this story — the entire lifecycle layer):**
- **`LifecycleState` (Draft/Published)** on the versionable entities (subject/unit/lesson/quiz). → EF config + migration. Decide granularity (per-entity column vs per-tree state — see open question).
- **`ContentVersion` entity** — entity ref (type + id), version no., `PublishedAt`, `PublishedBy`, **snapshot payload** (jsonb), and a **language tag** for traceability (BE-7). → table + EF config + migration.
- **Publish command** — snapshot current draft → new `ContentVersion`, flip the live version, atomic (explicit transaction), AdminOnly.
- **Rollback command** — restore the previous published `ContentVersion`, atomic, AdminOnly.
- **Preview query** — render a draft as a student would, without publishing, AdminOnly.
- **Read-side version filter** — student reads → latest published only; admin reads → live + pending draft.
- **Publication-coverage query** — publish state per `(SubjectCode, Language)` tree for a grade (complements P7-01-BE-8's *existence* coverage with *publish-state* coverage). AdminOnly.
- **Per-language scoping** — publish/version/preview/rollback each operate on a single `(SubjectCode, Language)` tree; `ContentVersion` records the resolved language.

## Handoff → db-migration
- New Npgsql migration(s), schema `learning`:
  - Add `LifecycleState int NOT NULL DEFAULT <Published or Draft>` to the versionable entities (decide default — likely existing seeded content = Published; new edits = Draft). Mind backfill so existing student-served content stays visible.
  - Create `ContentVersions` table — `Id` PK, `EntityType` (enum/int), `EntityId` (int), `VersionNumber` (int), `PublishedAtUtc` (timestamptz), `PublishedBy` (string/Guid — admin user id), `Snapshot` (jsonb), `Language` (`ContentLanguage` int, for traceability), audit columns; index `(EntityType, EntityId, VersionNumber)`.
- **timestamptz note (HANDOFF P4-11):** under `Npgsql.EnableLegacyTimestampBehavior=true`, call `.ToUniversalTime()` at the mapping boundary for any datetime read back.
- Non-destructive. No re-seed wipe.

## Handoff → backend-feature
- **Commands:** `PublishCommand(entityType, entityId)`, `RollbackCommand(entityType, entityId)` — both atomic via an **explicit transaction** (platform rule: no Unit of Work). AdminOnly.
- **Queries:** `GetPreviewQuery(entityType, entityId)` (student-rendered draft, AdminOnly); admin read variants returning live + pending draft (`?view=admin`); `GetPublicationCoverageQuery(gradeId)` (publish state per `(code, language)` tree, AdminOnly).
- **Read filters:** student-facing reads (the P2-* browse/lesson/skill-tree queries) must filter to `LifecycleState == Published` / latest published `ContentVersion`. **This touches existing student read handlers** — change carefully and regression-test P2-02/04/05/09.
- **`publishedBy`:** `AppControllerBase` has no user accessor. Read the admin user id from the JWT (mirror the existing `LearningLanguageClaimAccessor` / `IHttpContextAccessor` claim-reading pattern already in `Learning.Application/Helpers`). Do not trust a client-supplied id.
- **Per-language scoping:** resolve the tree's language via `SubjectLanguageResolver` from the Subject root; publish/rollback/preview never touch the sibling-language tree; `ContentVersion.Language` records it.
- **Storage:** preview/media references stay behind `IStorageService` (no module-local MinIO).
- **Event seam:** publish `AdminActionPerformedEvent` on publish/rollback for P7-12 audit. **⚠️ Contract not yet in `Shared.Contracts`** — depends on the P7-01 decision.
- **Conventions:** `BaseResponse<T>`, `NewResult(...)`, `Successed`, `ILoggerManager`, `AdminOnly`. Mirror Learning shapes; no design pattern.

## Handoff → frontend
Out of scope this run. FE contract (`P7-05-FE`) per task file: `GET /api/Learning/{type}/{id}?view=admin|student`, `POST .../Publish`, `GET .../Preview`, `POST .../Rollback`, `GET /api/Learning/Publish/Coverage?gradeId=`. `{type}` ∈ subject/unit/lesson/quiz, all under `Learning`. Admin-only.

## Open questions / assumptions / risks
- **Q1 (lifecycle granularity — load-bearing):** is `LifecycleState`/versioning **per individual entity** (each lesson/quiz publishes independently) or **per `(SubjectCode, Language)` tree** (publish the whole tree as a unit)? The AC mixes both ("publish acts on one tree" vs "publish a curriculum item"). This drives the entire `ContentVersion` shape and the publish command granularity. **Recommend the lead decide before db-migration.** Do not guess.
- **Q2 (snapshot scope):** does a `ContentVersion` snapshot a single entity's payload, or the whole sub-tree (e.g. a lesson + its content blocks + its quiz)? Atomic rollback fidelity depends on this. Assumption: per-entity snapshot in jsonb; tree publish = a batch of per-entity versions in one transaction. Flag for lead.
- **Q3 (default LifecycleState on migration):** existing seeded content must remain student-visible → backfill as `Published`. New edits → `Draft`. Confirm. (Getting this wrong hides all live curriculum from students.)
- **Q4 (AdminActionPerformedEvent):** same cross-wave contract dependency as P7-01.
- **Risk (student-read regression):** adding the published-version filter modifies existing P2-* student read paths. High regression risk — `api-tester` must re-run the P2-02/04/05/09 suites. Mind the existing `P2_09`/`P2_04` seeder-ordering flakiness noted in HANDOFF.
- **Risk (preview fidelity):** preview must render the *draft* (not the live version) exactly as a student read would, including language resolution — easy to accidentally read the published row.
- **Dependency:** hard-depends on **P7-01..P7-04** (the content + the language-tree + the Quiz model from P7-04 Q1). This is the **last** story in the wave — sequence after the other four merge.

## Recommended pipeline order (first cut — planner finalizes)
1. **(decision gate)** — lead resolves Q1 (granularity) + Q3 (default state) before any code; depends on P7-01..P7-04 being merged.
2. **db-migration** — `LifecycleState` columns + `ContentVersions` table per Q1/Q2.
3. **backend-feature** — publish/rollback (atomic), preview, admin/student read variants + published-version filter, per-language scoping, coverage query, JWT `publishedBy`, (optional) `AdminActionPerformedEvent`.
4. **api-tester** — integration tests (draft not served to students; publish creates versioned snapshot + flips live; admin sees live+draft; preview renders draft without publishing; rollback restores prior version; per-language scoping — `ar` publish doesn't touch `en`; coverage; AdminOnly 403) **+ regression of P2-02/04/05/09 student reads**.
5. **security-auditor** — admin-write governance surface (publish/rollback/preview affect what students see) + `publishedBy` from JWT not client + media via IStorageService → required; confirm AdminOnly, no IDOR, no draft leakage to students.
6. **reviewer** — gate against AC + CONVENTIONS.md; confirm explicit-transaction atomicity (no UoW), no `assessment` module, student-read regression green.
