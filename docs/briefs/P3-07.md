# Pipeline Brief — P3-07: Retrieve curriculum context via vector search (RAG retrieval)

> **AI Helper MVP context:** See `docs/briefs/ai-helper-mvp.md`. P3-07 provides the **`RagContextProvider`** — the second implementation of `ILearningContextProvider` (Section 3.1 of `ai-helper-mvp.md`). The first implementation, `SeededCorpusContextProvider`, ships with the AI Helper (P3-04/05/06) at MVP using the P2-11 skill graph and hand-seeded verified skill content. P3-07 delivers the full pgvector RAG path that swaps in via config (DI registration) when ready — no code changes required in the Helper. The Helper does NOT gate on P3-07; P3-07 enhances it later. Do NOT redefine `chunk_embeddings` schema from BL-04 — reference it via `IChunkRetrievalContract` only.

## Summary & traceability
- **Task (1 line):** Stand up a **curriculum/RAG retrieval** capability — embed a **seeded, pre-chunked** curriculum corpus into a **pgvector** column and expose a top-k similarity query filtered by **grade + subject + (optional) weak-area** — implementing the **`RagContextProvider`** variant of `ILearningContextProvider` so that the AI Helper's grounding upgrades from seeded corpus to full pgvector RAG via a config swap, with no code changes in the Helper itself.
- **User story:** [user-stories/Phase-4-AI-Tutor/P3-07-rag-retrieval.md](../../user-stories/Phase-4-AI-Tutor/P3-07-rag-retrieval.md) — *"As the AI tutor, I want to retrieve the most relevant curriculum chunks for a student's grade, subject, and weak areas…"*

- **FR-IDs:** **FR-AI-3** (questions grounded in retrieved curriculum context), **FR-CI-4** (store chunk embeddings in a vector store for retrieval). Indirectly enables FR-AI-1/2 (grounded explanations/hints).

## Business context & value
- **Who benefits:** indirectly the **student** (curriculum-faithful tutoring) and the **parent** (trust — the AI talks about the real syllabus, not the open internet); directly the AI tutor pipeline. Pure enabler.
- **Value:** retrieval is the "R" in RAG — without it, every AI feature either hallucinates or talks generically. Grounding in retrieved chunks is what makes the Safety Layer's hallucination check tractable and what lets P3-06 *decline rather than fabricate*. It is also the cost lever (NFR-9: RAG over fine-tuning).
- **Success measure:** given a student's grade + subject (+ optional weak-area skill), a top-k query returns the most semantically-relevant seeded chunks within the latency budget that keeps the **total** AI response < 4 s (NFR-1); given no relevant chunks, it returns **empty** and the caller (P3-06/04) handles emptiness without fabricating.

## Acceptance criteria (testable)
1. **AC-1 (schema + extension):** A `CurriculumChunk` entity exists with an `Embedding` property mapped to a **pgvector** `vector(N)` column; a migration enables `CREATE EXTENSION IF NOT EXISTS vector` and creates the table; it applies cleanly against `pgvector/pgvector:pg17` (the compose image already ships the extension). `N` (embedding dimension) is fixed by the chosen model (OQ-1).
2. **AC-2 (corpus seeded):** A **seeded, pre-chunked** corpus exists for the MVP subjects/grades (4 subjects: Math, Science, Arabic, English — no Social Studies) with embeddings populated. No OCR / upload / Azure-Document-Intelligence dependency (those are BL-01..05).
3. **AC-3 (top-k filtered retrieval):** A retrieval query/service returns the **top-k** chunks ordered by vector distance (cosine / L2 — OQ-2), **filtered by grade + subject and (when supplied) weak-area** (a skill/concept id), via the embedded query vector for the input text. Filtering happens in SQL (`WHERE grade = … AND subject = …`) before/with the `ORDER BY embedding <=> @q LIMIT k`.
4. **AC-4 (empty handling):** When no chunks match the filters / similarity floor, retrieval returns an **empty** result (not an error, not a fabricated chunk). Callers (P3-06/04/05) are contractually responsible for declining — this story guarantees the empty signal is clean and distinguishable.
5. **AC-5 (latency):** Retrieval latency is small enough that the **total** AI response stays < 4 s (NFR-1) for typical queries. A pgvector index (HNSW or IVFFlat — OQ-4) is created so retrieval does not full-scan at corpus scale.
6. **AC-6 (conventions):** If exposed as an HTTP endpoint, the handler returns `BaseResponse<T>` (`Successed` spelling), no UoW assumption, `ILoggerManager` injected, module isolation respected (no cross-module project ref / FK). If consumed only in-process by P3-06/04, it is an internal service/contract — confirm the seam (OQ-5).

## Handoff → backend-feature

Handler: embed `Text` → run the pgvector top-k filtered query via EF (`OrderBy(c => c.Embedding.CosineDistance(q)).Take(k)` with the Pgvector EF extension, plus `Where` on grade/subject/skill) → map to DTO (return `Content` + `Metadata` + a `Score`/distance; **never** return the raw embedding). Apply a **similarity floor** so weakly-related chunks don't pass as "relevant" (this is what makes AC-4 meaningful — OQ-7).
- **Emptiness contract:** the DTO list is empty when nothing clears the floor. Document this in the response so P3-06 can branch on it deterministically (e.g. `BaseResponse<RetrievalResult>` where `RetrievalResult.Chunks` may be empty and `Successed=true`). Do **not** model empty as a failure.

## Open questions / assumptions / risks
- **OQ-1 (embedding model + dimension N):** BGE-M3 (1024-d) vs OpenAI `text-embedding-3-small` (1536-d)? `N` is baked into the schema — **must be decided before db-migration** (a model swap = a migration + re-embed). Recommend pinning one in settings; default to whatever P3-01 (AI Gateway) standardizes on.
- **OQ-2 (distance metric):** cosine vs L2/inner-product — drives the index ops class and the `OrderBy` operator. Recommend **cosine** (`vector_cosine_ops`, `<=>`), standard for normalized embeddings.
- **OQ-3 (embedding via Gateway vs direct):** does .NET embed query text by calling the **AI Gateway (P3-01)**, or a direct provider `HttpClient`? CLAUDE.md infra cluster says ".NET calls AI only through the gateway, never an LLM directly" — embeddings should likely also go through the gateway. **Cross-cluster dependency on P3-01.** Confirm.
- **OQ-4 (vector index type):** HNSW (better recall/latency, more memory) vs IVFFlat (cheaper build). Recommend **HNSW** for a small seeded corpus; flag tuning for when BL-05 grows the corpus.
- **OQ-5 (seam — internal service vs HTTP endpoint):** is retrieval consumed only in-process by the AI pipeline (P3-06/04), or also a standalone endpoint? Recommend **internal service** (cleaner, no public RAG endpoint to secure), with an optional dev-only endpoint behind `[Authorize]` for api-tester. Affects whether api-tester runs.
- **OQ-6 (NEW MODULE — needs explicit lead approval, CLAUDE.md ask-before-new-modules):** create a new `Curriculum` module, OR fold `CurriculumChunk` into the existing `Learning` module (where `KnowledgeNode`/`Concept` already live)? SRS/architecture/BL-04 all say **new `curriculum` module**; the project memory says "ask before new modules" and prefers folding. **Recommend new module** but **do not scaffold until the lead confirms.** This is the single biggest gate on this story.
- **OQ-7 (similarity floor / threshold):** what distance cutoff counts as "no relevant context" for AC-4? Without a floor, top-k always returns *something*, which would defeat P3-06's "decline rather than hallucinate" criterion. Recommend an empirically-tuned cosine-distance threshold; flag that it needs the seeded corpus to calibrate.
- **OQ-8 (corpus source for seed):** where does the seeded chunk text come from (hand-authored demo text mirroring P2-10, or extracted from real curriculum samples in `info/`)? MVP only needs a thin, representative slice per subject/grade. Confirm scope.
- **Risk — Pgvector EF translation:** the `CosineDistance`/`<=>` operator must translate to SQL through `Pgvector.EntityFrameworkCore`; verify EF doesn't client-evaluate (which would full-scan). Mitigation: integration-test the generated SQL.
- **Risk — `EnableLegacyTimestampBehavior`** (Program.cs) and seed `DateTime.Now` carryover — mirror existing modules; not P3-07 scope but note for the seeder.
