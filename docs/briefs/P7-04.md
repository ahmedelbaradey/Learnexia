## Summary & traceability
- **Task (one line):** Add the admin **quiz/question authoring path** in `Learning` — Question CRUD over the existing `QuizQuestion` entity with the 4 per-type validators (wiring up the orphaned `QuizQuestionTypeValidation` helper), question ordering, a quiz-grouping/attach-to-lesson-or-skill association, and same-language-tree attach enforcement.
- **User story:** `user-stories/Phase-7-Admin-Console/P7-04-manage-quizzes-and-questions.md` (SP 8).
- **BE task file:** `tasks/Backend/Phase-7-Admin-Console/P7-04-BE.md` (BE-1..BE-6).
- **FR / SRS:** FR-ADM-3 (quiz/question management), SRS §3. BRD goal: **G3** (curated assessments instead of seeded).
- **Phase/epic:** Phase 7 · Epic *Admin — Curriculum Management*. Post-MVP.
- **Module:** `Learning`. **Depends on P2-06** (`QuizQuestion` + `QuestionType` + per-type validator helper — all present) and **P7-01** (language-tree model).

## Business context & value
- **Who benefits:** **admin** authors assessment content; **students** get curated, type-valid, language-pure quizzes (consumed by the existing student attempt flow — `QuizzesController` Start/Submit/Complete/Abandon).
- **Value:** today questions are seeded; the student attempt path reads them. This story adds the admin **authoring** path (the gap explicitly called out in HANDOFF: "the admin authoring path is the P7-04 gap").
- **Success measure:** an admin creates/edits questions of the 4 types with enforced shapes, orders them, groups them into a quiz, attaches the quiz to a lesson/skill only within the same language tree, and is blocked on invalid per-type shapes and cross-language attaches.

## Acceptance criteria (testable)
1. Create/edit a quiz persists title, description, and an **ordered** list of questions.
2. Add a question → pick one of **4 types** (MCQ, True/False, Matching, Fill-in-the-blank); the editor/API enforces that type's shape (options + correct answer).
3. A question with an invalid shape for its type (e.g. MCQ with no valid correct option) is rejected with a clear **per-type** validation error (`Successed=false`).
4. Quiz/question `Language` is **inherited from the owning Subject tree** (no independent language column).
5. Attach a quiz to a lesson or skill is saved **only if both stay in the same `(SubjectCode, Language)` tree**; cross-language attach (e.g. `ar` quiz → `en` lesson) is rejected with a clear error. (All intra-`Learning` — direct FK fine.)
6. Edit/remove a question updates the quiz's question order accordingly.
7. All mutations admin-only (`AdminOnly`); non-admin → 403.

## Affected modules & data (new vs existing)
**Module:** `Learning` only. Schema: `learning`.

**Existing (verified — do NOT re-create or move):**
- `QuizQuestion` entity (`Domain/Entities/QuizQuestion.cs`): `LessonId` (loose int reference), `SkillId?`, `QuestionType`, `QuestionText`, `Options` (jsonb string), `CorrectAnswer` (jsonb string, excluded from client DTO), `Difficulty`, `GeneratedBy`, `StudentAnswers`. `QuizQuestionConfig` + `AddQuizTables` migration exist.
- `QuestionType` enum (MCQ/TrueFalse/Matching/FillInBlank), `QuizQuestionService`, `QuizProfile` mapping, `QuizQuestionDto` (student-facing, no correct answer).
- **`QuizQuestionTypeValidation.Validate(...)`** (`Application/Features/Questions/Validation/`) — the **orphaned static helper** with the 4 per-type shape checks, **zero callers today**. P7-04 wires it into the authoring validators. Explicitly NOT a Strategy/Factory (per its own doc + CLAUDE.md rule 8).
- `QuizzesController` — **student attempt endpoints only** (Start/Submit/Complete/Abandon, `[Authorize(Roles=Student)]`). **No admin authoring endpoints.**
- `SubjectLanguageResolver` for language derivation.

**Net-new (this story):**
- **Question authoring CRUD** (`Application/Questions/*` Add/Edit/Delete/Reorder + queries) over `QuizQuestion`, AdminOnly, wiring the per-type validator helper into `AddQuestionCommandValidator`/`EditQuestionCommandValidator`.
- **Quiz grouping + attach.** **⚠️ There is NO `Quiz` aggregate entity today** — `QuizQuestion` references a Lesson/Skill directly via loose int. The story/AC talk about a "quiz" with a title/description and an ordered question list and an "attach to lesson/skill." Decide the model (see open question): either (a) a net-new lightweight `Quiz` entity (title, description, FK questions, attach target) + migration, or (b) treat "quiz" as the existing implicit per-lesson question set (no new entity; ordering + a `SequenceOrder` on `QuizQuestion`). This is the biggest modeling decision in the story.
- **Question ordering** — `QuizQuestion` has no `SequenceOrder` today → net-new column + reorder command (batch, explicit transaction) if ordering is required.
- **Same-language-tree attach validator** (resolve quiz's tree vs target lesson/skill tree via `SubjectLanguageResolver`; reject mismatch → `Successed=false`).
- Admin authoring endpoints on `QuizzesController` (or a new admin sub-route) — net-new alongside the existing student attempt routes.

## Handoff → db-migration
- **Conditional on the Quiz-model decision (Q1):**
  - If a `Quiz` entity is introduced: new `Quizzes` table (title, description, attach target lesson/skill, audit) + FK from `QuizQuestion` (`QuizId`) + migration.
  - If "quiz" stays implicit (per-lesson question set): likely just add `QuizQuestion.SequenceOrder int` (+ index `(LessonId, SequenceOrder)`) for ordering.
- Reuse `LearningSchema.Name`; Npgsql; non-destructive (defaults backfill). Keep `Options`/`CorrectAnswer` as jsonb.

## Handoff → backend-feature
- **Validators:** wire `QuizQuestionTypeValidation.Validate(type, options, correctAnswer, localizer)` into `AddQuestionCommandValidator` + `EditQuestionCommandValidator` (it returns null when valid / a localized message when invalid → map to a FluentValidation failure). Reuse the P2-06 type discriminator.
- **Commands:** `AddQuestionCommand`, `EditQuestionCommand`, `DeleteQuestionCommand`, `ReorderQuestionsCommand` (batch, explicit transaction). Plus quiz CRUD + `AttachQuizCommand(lessonId | skillId)` per the chosen model.
- **Attach guard:** resolve the quiz's `(SubjectCode, Language)` tree and the target lesson/skill's tree; reject cross-language attach → `Successed=false`. Intra-`Learning` FK is allowed (no `Shared.Contracts` seam needed).
- **DTOs:** admin `QuizDto`/`QuestionDto` that **include** type/text/options/correctAnswer for authoring (note: the student-facing `QuizQuestionDto` deliberately excludes `CorrectAnswer` — keep that separation; the admin DTO is a distinct authoring shape).
- **Event seam:** publish `AdminActionPerformedEvent` per mutation for P7-12 audit. **⚠️ Contract not yet in `Shared.Contracts`** — depends on the P7-01 decision.
- **Conventions:** `BaseResponse<T>`, `NewResult(...)`, `Successed`, `ILoggerManager`, `AdminOnly`. Mirror existing Learning shapes; no design pattern.

## Open questions / assumptions / risks
- **Q1 (Quiz model — the load-bearing decision):** there is **no `Quiz` aggregate** today; `QuizQuestion` is per-lesson via loose int. The story assumes a quiz object with title/description/ordered-questions/attach-target. **Options:** (a) introduce a lightweight `Quiz` entity + FK questions + attach target (cleaner, more migration), or (b) keep "quiz" as the implicit per-lesson question set and just add ordering + treat the lesson/skill as the attach target. **Recommend the lead choose before db-migration runs** — the whole story's surface (entity, migration, attach semantics) hinges on this. Do not guess.
- **Q2 (AdminActionPerformedEvent):** same cross-wave contract dependency as P7-01.
- **Q3 (admin DTO exposing CorrectAnswer):** confirm the admin authoring DTO may return `CorrectAnswer` (it must, to edit it) while the student DTO continues to exclude it. Assumption: yes, distinct admin DTO, AdminOnly-gated. Flag to security-auditor.
- **Risk:** the `LessonId`/`SkillId` are **loose ints (no FK)** by design (quiz lifecycle decoupled from lesson deletes) — the attach validator must check existence + language tree in the handler, not rely on a DB FK.
- **Dependency:** depends on **P7-01** (language-tree model) and **P2-06** (entities). Sequence after P7-01; can run parallel to P7-02/P7-03 if the Quiz-model decision is made.

## Recommended pipeline order (first cut — planner finalizes)
1. **(decision gate)** — lead resolves Q1 (Quiz model) before any code.
2. **db-migration** — per Q1 (new `Quiz` table + FK, or just `QuizQuestion.SequenceOrder`).
3. **backend-feature** — question CRUD + wire the 4 per-type validators, ordering, quiz grouping + attach + same-language guard, admin DTOs/endpoints, (optional) `AdminActionPerformedEvent`.
4. **api-tester** — integration tests (each of the 4 types valid + invalid → per-type `Successed=false`; ordering persists; attach within-tree succeeds, cross-language attach → `Successed=false`; AdminOnly 403; correct-answer never leaks on student DTO).
5. **security-auditor** — admin-write + the CorrectAnswer-exposure surface → required; confirm AdminOnly, no leak of correct answers to student-facing reads, no IDOR.
6. **reviewer** — gate against AC + CONVENTIONS.md; confirm the orphan validator was wired (not re-implemented) and no `assessment` module was created.
