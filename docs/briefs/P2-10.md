# Pipeline Brief — P2-10 Seed demo subjects & skill trees

## Summary & traceability
- **One-line task:** Author idempotent seed content for the 4 MVP subjects (Math, Science, Arabic, English) — units → lessons → concepts → skills forming navigable trees — and run it at startup in **Development** on the existing Learning module, with Math given the deepest tree.
- **User story (source of truth):** `user-stories/Phase-2-Learning-Core/P2-10-seed-demo-data.md`
- **Task file:** `tasks/Backend/Phase-2-Learning-Core/P2-10-BE.md` (BE-1 author content, BE-2 idempotent startup invoke, BE-3 Math deepest tree)
- **FR / spec:** SRS §6 (data model). Covers backlog item **D2.5**.
- **BRD goal:** G2 (adaptive learning / mastery) — a realistic curriculum dataset is the prerequisite for adaptivity demos (BRD §4). Math is the deepest adaptivity target.
- **Epic / phase:** Data / DB Foundation · Phase 2 — Learning Core (Week 3–4).
- **Type:** Technical enabler · SP 2 · **Backend/infra only, no Frontend.**
- **Dependencies:** Blocked by **P2-01** (Learning module + entities — DONE; module exists at `backend/src/Modules/Learning/`). Unblocks **P2-02 / P2-03** demos. **P2-11** (skill dependency graph) will later EXTEND this seeder with prerequisite edges — the seeder must be built extensibly.
- **Product-decision override applied:** MVP is **4 subjects** — Social Studies removed (overrides BRD §4).

## Business context & value
- **Who benefits:** the dev team and demo/stakeholder audiences (internal). No end-user-facing feature.
- **Value:** P2-02/P2-03 (skill-tree navigation, lesson flow) and later adaptive-engine work need a realistic, navigable dataset to build and demo against. Without seed data those stories start against an empty DB. Math's deeper tree exercises the adaptivity/branching paths most heavily.
- **Success measure:** after a fresh Development startup the DB holds 4 fully-linked subject trees; a second startup adds nothing (idempotent); navigating Grade → Subject → Unit → Lesson → Concept → Skill yields no dead ends.

## Acceptance criteria (testable)
1. On Development startup the seed runs and populates exactly the **4 subjects** Math, Science, Arabic, English (no Social Studies, no extras).
2. Each subject has **at least one grade's** worth of content: ≥1 Unit, each Unit ≥1 Lesson, the Subject ≥1 Concept, each Concept ≥1 Skill — forming a fully linked, navigable tree (no orphan Units/Lessons/Concepts/Skills; every Lesson belongs to a Unit; every Skill to a Concept; every Subject to a Grade).
3. Lessons link to Skills where intended (`Lesson.SkillId` set for taught lessons; nullable elsewhere) so the Concept↔Skill↔Lesson relationships are demonstrable.
4. **Idempotent:** running the seed twice (restart) does not duplicate any row — counts are identical after the second run.
5. **Math has the deepest tree** — strictly more units/lessons/concepts/skills and greater depth than each of the other three subjects.
6. Seed runs **only in Development** (not staging/production), consistent with how Identity gates its dev-only convenience seeds.
7. Seeding does not break the existing startup migrate hook (`LearningModule.InitializeAsync`) and respects module isolation (Host never touches Learning Infrastructure directly).
8. Solution builds; existing tests stay green; a unit/integration test covers the idempotency invariant.

## Affected modules & data
- **Module:** Learning only (`backend/src/Modules/Learning/...`). No other module touched. No cross-module references.
- **Entities — all EXISTING from P2-01, no schema change expected:**
  - `Grade` (Number, DisplayName) — `Grade 1—* Subject`
  - `Subject` (Name, Country?, GradeId) — `Subject 1—* Unit`, `Subject 1—* Concept`
  - `Unit` (Name, SequenceOrder, SubjectId) — `Unit 1—* Lesson`
  - `Lesson` (Name, Difficulty `DifficultyLevel`, SequenceOrder, IsLocked, UnitId, **SkillId nullable**) — `Lesson *—o1 Skill`
  - `Concept` (Name, Description?, DifficultyLevel, SubjectId) — `Concept 1—* Skill`
  - `Skill` (Name, MasteryThreshold, EstimatedTimeMinutes, ConceptId) — `Skill 1—* Lesson` (a skill may be taught by many lessons)
  - Enum `DifficultyLevel { Easy=1, Medium=2, Hard=3 }` — reference by member, never magic int.
- **Note on Subject↔Grade:** `Subject` is scoped to a single `Grade` (GradeId is non-null). So "4 subjects per grade" — if seeding one grade, that is 4 Subject rows; if multiple grades are seeded, it is 4 × (number of grades). See Open Questions.
- **DbContext:** `LearningDbContext` (schema `"learning"`), DbSets for all six entities. Entities derive from `AggregateRoot`/`FullAuditedEntity` (audit fields stamped via `SaveChangesAsync(int userId)`).
- **No migration expected** — this is data, not schema. (If the implementer finds a missing field, that is an Open Question, not a silent schema change.)

## Handoff → db-migration
- **None expected.** P2-10 is pure seed data over existing P2-01 tables; no new entities, fields, or relationships. If the implementer determines a column is genuinely missing to satisfy a tree relationship, stop and raise it — do not add a migration unilaterally under a seed-data story.

## Handoff → backend-feature
This is the whole story. Implementation shape (mirror the Identity seed pattern, not the CQRS feature pattern):

- **New artifact:** a `LearningSeeder` static class in `Learnexia.Modules.Learning.Infrastructure/Persistence/Seed/` (mirror `Identity/.../Persistence/Seed/`). Keep the DbContext inside Infrastructure — module isolation.
- **Invocation:** extend `LearningModule.InitializeAsync(IServiceProvider)` (`backend/src/Modules/Learning/Learnexia.Modules.Learning.Api/LearningModule.cs`) — it already calls `dbContext.Database.MigrateAsync()`. After migrate, **if `IHostEnvironment.IsDevelopment()`**, call `LearningSeeder.SeedAsync(serviceProvider)`. Resolve `IHostEnvironment` from the provider (mirror `IdentitySeeder` which resolves `IHostEnvironment` and gates dev-only seeds). The Host already calls `LearningModule.InitializeAsync(scope.ServiceProvider)` in `Program.cs` (~line 153) inside a scope after `app.Build()` — no Host edit needed beyond what exists.
- **Idempotency strategy:** guard each insert by a stable natural key (e.g. check `Subjects.Any(s => s.Name == ... && s.GradeId == ...)` before adding; same for Grade by Number, Unit by (SubjectId, Name/SequenceOrder), etc.). Do **not** rely on auto-Id. Top-level guard (e.g. "if any Grade/Subject already seeded, skip") is acceptable if it keeps the whole tree consistent, but prefer per-node guards so partial seeds self-heal. Decide and document in the seeder.
- **Save semantics:** the Learning module uses deferred commit via `UnitOfWorkBehavior` for `ICommand<>` handlers only — that behavior does **not** wrap a startup seeder. The seeder runs outside MediatR, so it must call `LearningDbContext.SaveChangesAsync(userId)` (the int-userId override that stamps audit) itself. Use a system/seed user id constant (e.g. `0` or `1` — confirm the convention used by Catalog/Identity seeds; CreatedBy is a plain int, not an FK). Consider a single SaveChanges at the end (EF resolves FK graph by navigation) or staged saves if you need generated parent Ids before children — mirror whichever keeps the graph correct.
- **Content authoring (BE-1 / BE-3):** author realistic Arabic-curriculum-flavored content for Math, Science, Arabic, English. Keep content data in a clearly separated, **extensible** structure (e.g. an in-memory object graph or per-subject builder method) rather than a flat hardcoded block — **P2-11 will add KnowledgeNode/Edge prerequisite seed on top of this**, so the seeder should expose seam(s) (e.g. partial/extension method, or skills addressable by a stable key) that P2-11 can hook prerequisite edges onto without rewriting P2-10. Do not introduce a design pattern (Strategy/Factory/etc.) to achieve this without asking the lead first — a plain per-subject builder method is the default.
- **Depth (BE-3):** Math must be strictly the deepest — more units, lessons per unit, concepts, and skills per concept than the other three. Give the other three subjects a smaller but still navigable tree.
- **Set `DifficultyLevel`** by enum member; vary it across lessons/concepts so demos show a range. Set sensible `MasteryThreshold` (cf. FR-AD-3) and `EstimatedTimeMinutes`, `SequenceOrder`, and `IsLocked` (e.g. first lesson unlocked, later ones locked) to make the tree look real.
- **Logging:** inject/resolve `ILoggerManager` (not `ILogger<T>`) if logging seed progress; do not add a second logger registration.
- **Tests:** add/extend the Learning unit/integration test project — assert 4 subjects seeded, tree linkage, Math-is-deepest, and **idempotency** (run seed twice → equal row counts). Mirror `tests/Modules.Catalog.UnitTests` shape.

## Handoff → frontend
- **None.** Backend/infra-only story — no UI surface, no Design Spec, no `frontend` agent. (P2-02/P2-03 consume this dataset later.)

## Open questions / assumptions / risks
1. **How many grades to seed?** AC says "at least one grade's worth." `Subject` is grade-scoped, so seeding 4 subjects implies one grade unless we seed several. **Assumption:** seed a single grade (e.g. Grade 1) with all 4 subjects for MVP demos, keeping the seeder extensible to add more grades later. *Confirm with lead if multi-grade seed is wanted now (affects P2-02/P2-03 grade-transition demos).*
2. **Seed user id / audit stamping:** which int does `CreatedBy` take for system-seeded rows? **Assumption:** a fixed seed/system id (0 or the seeded admin's id). Implementer should match whatever Catalog/Identity seeds use; flag if there is no established convention.
3. **Idempotency granularity:** top-level "already seeded → skip" vs per-node natural-key guards. **Assumption:** per-node guards preferred for self-healing; acceptable to do a coarse guard if it keeps the tree consistent. Non-blocking — implementer's call, documented in the seeder.
4. **Content language/locale:** subject/unit/lesson names — Arabic, English, or bilingual? `Subject.Country` is nullable. **Assumption:** readable English (or Arabic transliteration) names are fine for a dev seed; this is internal demo data, not user-facing copy. Confirm if Arabic display names are required for the demo.
5. **Environment gate location:** AC says "Development." **Assumption:** gate inside `InitializeAsync`/`LearningSeeder` via `IHostEnvironment.IsDevelopment()` (mirrors Identity), since the Host calls `InitializeAsync` in all environments. Low risk.
6. **P2-11 extension seam:** must not hardcode the tree in a way that blocks adding KnowledgeNode/Edge prerequisite seed later. Risk if skills aren't addressable by a stable key. **Mitigation:** author skills with stable natural keys/names and a builder structure P2-11 can extend. (No KnowledgeNode/Edge entity exists yet — that arrives with P2-11; do not create it here.)
7. **No migration:** confirmed expectation is zero schema change. Risk only if a relationship can't be expressed with current fields — raise rather than migrate silently.
