## Business context & value
**Who benefits:** the **parent**. Today the Settings shell is live but four of six tabs render a "coming soon" panel — parents cannot self-serve notification preferences, manage their linked children, change their password / kill sessions, or see their plan. The P2-12 backend (already on `main`) provides all the endpoints; FE work in W10 lights them up.

**Per-tab parent intent:**
- **Notifications** — pick which categories (Weekly Report, Streak At-Risk, Product Announcement, Achievement) ping me by Email and/or Push. Controls alert fatigue, drives engagement.
- **Linked children** — see who is linked, edit a child's basic profile (full name / grade / language / country), unlink a child (with a last-parent guard), and jump to Add Child. Reduces support load (parent-driven).
- **Security** — rotate password and kick stray sessions. On password change the BE invalidates all *other* sessions and revokes the refresh-token cache; the active session keeps working. Tied to G1 trust.
- **Plan & billing** — read-only "what plan am I on?" surface. No payments BE yet (BE returns `{planName: "Free", status: "Active"}`); a Manage CTA is a stub linking to a future payments story.

**Success measures (FE-scoped):**
- Each tab matches `web/07-settings.png` and reuses the existing P1-11 shell (header / left rail / panel surface) — pixel-perfect per the designer rule.
- All four tabs render in both EN (LTR) and Arabic (RTL), light + dark, with no raw hex / px and no new design pattern unilaterally introduced (mirror existing primitives).
- Reads and writes use the typed `@learnexia/api-client` (regenerated) — no manual `fetch`.
