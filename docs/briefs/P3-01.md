## ⚠️ Read this first — two blocking decisions before any code

1. **The story text says "Python FastAPI gateway"; the resolved stack says .NET 10 modular monolith.** The story (written early, mirrors BRD §6 system diagram) describes "a Python FastAPI gateway sitting between the .NET backend and the LLM providers." But the **resolved, authoritative stack** is **.NET 10 modular monolith + PostgreSQL (+ pgvector)** — BRD §90 ("backend is .NET 10 (modular monolith, reusing `backend` patterns)") and the CLAUDE.md hard facts. **A separate Python service is a new deployable, a new CI target, a new auth boundary, and a new ops surface — none of which exist today.** The analyzer's recommendation is to implement the gateway **in-process as a .NET seam** (an `IAiGateway` abstraction + provider adapters) unless the lead/PO explicitly wants the polyglot service. **This is Q1 — a hard blocker.** Do not let an implementer assume one or the other.

2. **A provider abstraction is a design pattern (Strategy / adapter registry) AND likely a new module.** CLAUDE.md rule 8 ("design patterns — ask first") and the `ask-before-new-modules` memory both fire here. The gateway is, by definition, "GPT and Gemini behind one interface with task-based routing" = a Strategy + Factory shape, and it most naturally lives in a **new `Ai` module** (or `Shared`). **Both require explicit lead approval before the implementer writes them.** Flagged as Q2 (module location) and Q3 (pattern approval).

## Summary & traceability

## Business context & value

- **Who benefits:** indirectly the **student** (every tutor explanation/hint/question rides this rail and must be fast + available), and directly the **business/operator** — the gateway is the single point of **cost control** (model routing keeps spend down per NFR-9) and **vendor-risk mitigation** (BRD §103: single-provider dependency is a named risk; the abstraction lets Learnexia swap GPT↔Gemini↔Claude without touching feature code).
- **Why it matters now:** it is the **first brick of the entire AI phase**. Hint generation (P3-05), concept explanation (P3-04), grounded question generation (P3-06), and RAG-backed answers (P3-07) all hard-depend on it. Building any of those before the gateway would scatter provider SDK calls + secrets across feature handlers — exactly the anti-pattern this story prevents.
- **Success measurement (from AC):**
  - A feature handler asks for an explanation → it calls `IAiGateway`, never an SDK directly. (Grep test: no provider SDK type appears outside the gateway adapter assembly.)
  - The gateway routes a "hint" task to the cheap/fast model and a "hard reasoning" task to the premium model, purely from a task-kind on the request.
  - A simulated provider 500 / timeout → caller receives a **typed, graceful error** (`AiUnavailable` / `AiTimeout`), not an exception with a stack trace, and the host stays healthy.
  - Switching the default provider/model in config (appsettings/env) changes behavior **without recompiling**.
  - Per-call usage (tokens in/out, model, latency, estimated cost) is captured for the cost dashboard (P7-11 / FR-ADM-10 consume it later).
- **Deterministic-vs-AI boundary (BRD §97 / NFR-8 / FR-AI-6):** the gateway is the membrane. Deterministic engines (Adaptivity, Mastery, Gamification) **never** depend on it. Only the AI content generators do. The gateway returns *content*, never *decisions*.

## Acceptance criteria (verbatim from story + testable backend gates)

From `P3-01-ai-gateway.md`:

1. **AC1 — The .NET backend calls AI features only through the gateway, never an LLM directly.**
   - Backend gate: a single `IAiGateway` abstraction is the only public entry point. Provider SDK packages are referenced **only** by the gateway's adapter assembly — no other module/project references them. (Architecture test / grep gate: provider SDK namespace must not appear in any feature handler.)
2. **AC2 — The gateway abstracts GPT and Gemini behind one interface and routes by task (cheap model for hints/simple explanations, premium for hard reasoning).**
   - Backend gate: the request carries a **task kind** (e.g. `Hint`, `SimpleExplanation`, `HardReasoning`, `QuestionGeneration`) and/or an explicit **model-tier** hint; a routing component maps task→provider+model from config. At least two providers are pluggable behind the same interface; Claude is the default (Q4). Routing is unit-testable in isolation (pure mapping, no I/O).
3. **AC3 — A provider outage or error returns a graceful, typed error to the backend (no raw stack traces).**
   - Backend gate: provider exceptions/timeouts are caught at the adapter boundary and translated to a typed `BaseResponse<T>` failure (or a typed `AiResult` discriminated outcome) — `Successed = false` with a safe, non-leaking message. **No `ex.Message` / stack trace is echoed.** Retries with backoff on transient failures (configurable count); a hard timeout caps the call at the NFR-1 budget.
4. **AC4 — Model/provider choice is configurable without code changes.**
   - Backend gate: provider, default model, per-task model overrides, timeout, and retry policy all bind from an options class (`AiGatewayOptions`, section e.g. `Ai:Gateway`) → settable via appsettings/env. Changing them requires **no recompile**. API keys come from configuration/secret store, never literals.

## Handoff → backend-feature

Mirror an existing module's four-layer shape (Learning/Gamification reference). `BaseResponse<T>` via `BaseResponseHandler` where a handler is involved; `Successed` flag (rule 2); inject `ILoggerManager` not `ILogger<T>` (rule 5); no `ValidationBehavior` on queries (rule 4). **Do not introduce the Strategy/registry pattern until Q3 is approved** (rule 8) — but note this story is *the* case where a pattern is genuinely warranted; name it explicitly to the lead.

- **Seam contract (`Shared.Contracts/Ai/`):** `IAiGateway`, `AiRequest`, `AiResult`, `AiError`, `AiUsage`, `AiTaskKind`, `AiModelTier`. Keep this provider-neutral — no provider SDK types leak into the contract.
- **Gateway facade (`Ai.Infrastructure`):** implements `IAiGateway`; resolves provider via `AiModelRouter`; applies timeout + retry/backoff; translates provider exceptions → typed `AiError`; records `AiUsage`; **never throws to the caller** (returns `Successed = false` with a safe message).
- **Provider adapters (`Ai.Infrastructure`):** `ClaudeProvider` (default — see Q4), plus at least one of `OpenAiProvider`/`GeminiProvider` to prove the abstraction. Each adapter owns its SDK + key handling. Keys read from secret config (`IConfiguration` secret section / env), **never literals, never logged**.
- **Router (`Ai.Application` or `Ai.Domain`):** pure `AiTaskKind + tier → (provider, modelId)` from `AiGatewayOptions`. Unit-test the mapping table.
- **Options + DI:** `AiGatewayOptions` bound from `Ai:Gateway`; `AddAiModule` registers gateway + adapters + router; provider SDK clients pooled (HttpClient via `IHttpClientFactory`, not per-call `new`).
- **Resilience:** configurable retry count + exponential backoff on transient (429/5xx/timeout); hard timeout per `TimeoutSeconds` honoring NFR-1; cancellation token threaded end-to-end.
- **Hardening:** no key in logs; no raw provider error echoed; gateway returns typed failure; usage capture does not store prompt/response text (no PII) unless Q5 approves.

## Handoff → security-auditor

**Mandatory run — this is a security-sensitive batch (LLM provider secrets + outbound calls handling child-adjacent prompts).** Per CLAUDE.md, Critical/High findings block the gate.

- **Provider API keys (NFR-4 "encrypted secrets"):** keys must come from a secret store / env, **never** committed literals, never in appsettings checked into git, never logged. Verify no key appears in logs, error messages, or usage records.
- **Outbound trust boundary:** the gateway makes outbound calls to third-party LLMs. Confirm prompts sent out do **not** yet contain unscrubbed child PII (P3-03 prompt builder owns scrubbing, but P3-01 must not log prompt bodies that may carry PII; flag if it does).
- **Error leakage:** provider stack traces / internal error bodies must not reach the client (AC3) or logs in raw form.
- **DoS / cost-exhaustion:** retry policy must be bounded (no unbounded retry storm amplifying a provider outage into a cost/latency incident); timeout must cap the call. Confirm retries are capped and backed off.
- **Usage log (if Q5 = persist):** confirm no prompt/response text or student PII is persisted; aggregate-only.

## Handoff → api-tester

Runs **only if P3-01 exposes an HTTP endpoint this cycle.** As scoped, P3-01 is an **internal seam with no public endpoint** (the first endpoint is P3-04 explain-concept). **Recommendation: P3-01 ships no controller** → api-tester is **not required for P3-01**; coverage is unit/architecture tests instead. **Confirm Q6** (if a debug/health endpoint like `POST /api/Ai/Complete` is wanted for early integration, then api-tester runs).

- **Architecture test:** no provider SDK namespace referenced outside `Ai.Infrastructure` (enforces AC1).

## Cost & model routing

> **See the authoritative strategy:** [docs/briefs/ai-cost-routing.md](ai-cost-routing.md). This section summarises P3-01's specific responsibilities within that strategy.
> **Eval Gate:** The tier-mix split (routing `Explain`/`Hint` to Haiku instead of Sonnet) must not be promoted to production until the AI evaluation dataset gate passes. See **[docs/briefs/ai-eval-gate.md](ai-eval-gate.md)** — do not trust the 80% Haiku target for Arabic pedagogy until measured. The routing table floor for `Explain` and `Hint` remains Sonnet until Gate A is validated.

### Two cost lanes

**OFFLINE lane** — content generation that runs once and is amortized across all students (concept explanations, hint pre-generation, question generation). Use Batch API; Sonnet for bulk generation, Opus for QA pass. Spend freely; cost per student → near zero with scale.

**RUNTIME lane** — per-student daily AI calls. Every call multiplies by active-student count. Cost discipline is non-negotiable. Cheap by default; escalate only on failure.

### ModelRouter (P3-01 owns this seam)

`AiModelRouter` is a **deterministic, FREE mapping** — it never calls an LLM. It resolves `(AiTaskKind, AiModelTier?, AiGatewayOptions) → (providerName, modelId)`. The full routing table is in [ai-cost-routing.md §3](ai-cost-routing.md):

| Task kind | Default runtime model |
|---|---|
| `CheckAnswer`, `Classify`, `ShortTask` | `claude-haiku-4-5` |
| `Explain`, `Hint`, `Simplify`, `QuestionGeneration` (runtime) | `claude-sonnet-4-6` |
| `AnalyzeDiagram`, `HardReasoning`, `ContentQA` | `claude-opus-4-8` (offline/rare) |

**Escalate-on-failure:** if the cheap-tier response is low-confidence or the student signals continued confusion, the gateway bumps one tier (Haiku → Sonnet; Sonnet → Opus). Maximum one escalation per call chain; never escalate to Opus at runtime without explicit config override.

**IMPORTANT:** The prior Q4 wording that listed `claude-opus-4-8` as the default is superseded. **Runtime default is cheap; Opus is the exception.** Always verify current Anthropic model IDs before launch.

### Prompt caching (`cache_control`)

The gateway facade (`AiGateway`) is responsible for marking the static portions of every system prompt with `cache_control` breakpoints:
- Child-safe system prompt prefix (100-200 tokens, reused across all requests for a given module).
- Curriculum chunk context for a given lesson (identical for all students on that lesson).
- Safety/guardrail prefix.

Estimated input-token reduction on cached portions: ~90% on repeated calls (verify with Anthropic caching docs at launch). The `ClaudeProvider` adapter must support sending `cache_control` metadata; wire it from the `AiRequest` (add a `CacheableSystemPrompt` field or a `CacheHints` collection to the DTO).

### Batch API submission path (offline lane)

The gateway must expose an offline-batch path for pre-generation jobs:
- Either a separate `IAiBatchGateway.SubmitBatchAsync(IReadOnlyList<AiRequest>) → BatchJobId` (recommended) or a method on `IAiGateway` (confirm with lead — see [ai-cost-routing.md OQ-C](ai-cost-routing.md)).
- The `ClaudeProvider` adapter must support the Anthropic Batch API endpoint in addition to the synchronous completion endpoint.
- Batch API cost saving: ~50% vs synchronous (verify at launch).

### Per-plan daily request cap (MVP cost-safety guardrail)

The gateway facade is the enforcement point for a **minimal daily request cap** — this is NOT a full credit economy:

1. Before every runtime LLM call, check the student's remaining **daily request count** (via an `IAiUsageBudget` seam — reads from a plan/subscription DB counter or a Redis counter; confirm store with lead — see [ai-cost-routing.md OQ-D and OQ-E](ai-cost-routing.md)).
2. If cap exhausted → skip the LLM call and return a `QuotaExhausted` `AiError` (a new typed error variant). The caller (P3-04/P3-05/P3-06 handler) degrades gracefully to the best available cached response — never returns a hard error to the student.
3. On successful LLM call completion → increment the student's daily request counter (fire-and-forget; never blocks the stream).

**Scope boundary — what this IS and IS NOT:**
- IS: a simple per-plan daily request count cap with graceful degrade-to-cache. Tracks requests, not credits. No per-action pricing, no money, no billing.
- IS NOT: a credit economy. There are no credit ledgers, no credit transactions, no purchasable packs, no monthly credit grants, no per-action pricing tiers, no billing integration.
- The full credit economy (ledger `ai.AiUsageLedger`, `ai.AiCreditTransaction`, purchasable credit packs, billing, monthly grants/reset, "⚡ طاقة المساعد" UI) is deferred to **Phase 9 (`P9-*` — Payment, Billing & Credits)**, which supersedes this MVP guardrail and promotes the ledger concept to a full first-class system.

Budget tracking for analytics feeds `AiUsageLogs` (P7-11). For MVP, an interim daily counter on the plan/subscription record suffices.

### Graceful degradation to cache on cap exhaustion

When `QuotaExhausted` is returned (daily request cap hit — not a billing event):
- P3-04 explain handler → serve the `ConceptExplanationCache` row if it exists (pre-generated offline).
- P3-05 hint handler → serve the `HintCache` row if it exists.
- P3-06 question generation → return a "quota exhausted" result (not a student-facing error; admin/content trigger context).
- If no cached row exists AND quota is exhausted → return a friendly "AI tutor busy" response (never a raw error).
