### Strategic framing — barrier-to-entry BE2 (read this first)
This story **closes gap 3a-2 and 3a-3** from `docs/briefs/barrier-to-entry-gap-analysis.md` and is one of the **two highest-impact** recommendations in that analysis (alongside P4-09 re-engagement). The barrier-to-entry doc calls **Student Modeling (BE2)** a core moat: log *how* a child learns, not just whether they got answers right — building an *"Adaptive Learning Profile"* like *"visual learner, weak in fractions, bored after 8 minutes, improves with short quizzes."* Today the platform captures only correctness/time/mastery (P2-08, P3-09); the SRS already has a **`StudentProfile.PreferredExplanationStyle` column (§6) that no story populates** — this story turns that dormant field into a live signal and builds the behavioral layer that feeds the **BE7 data network effect** (the more a child uses the platform, the better it models them — *"hard for a newcomer to replicate"*). It is the moat layer that differentiates Learnexia from an AI chatbot wrapper. **Treat it as a strategic moat investment, not a nice-to-have** — but scope it to the rule-based MVP (no ML, AC out-of-scope) so it ships.

- **Product-decision context:** 4 subjects, no Social Studies, no teacher role. **Grade transition preserves history** — the behavioral profile is a per-child accumulation; a grade change must NOT reset it (BE7 network effect depends on accumulation). **Child-privacy is load-bearing** (see security section) — this profiles a minor.

## Business context & value
- **Who benefits:** the **student** (explanations/pacing/recommendations fit *them* — the AI tutor explains in their preferred style, sessions shorten before fatigue sets in); the **AI tutor** (P3-03 prompt builder consumes `PreferredExplanationStyle` + weak areas → pedagogically personalized prompts); the **adaptivity engine** (P3-08 can shorten sessions / switch explanation style for fatigue-prone or struggling students); the **parent** (richer weak-area reporting, P5-02); the **business** (the BE2/BE7 moat — accumulated behavioral data competitors can't replicate).
- **Why it matters:** see the strategic framing. This is the difference between "adaptive difficulty" (P3-08) and "knows *how* you learn." It is the richest unbuilt moat layer (SP 8).
- **Why rule-based / explainable:** FR-AD-5 + AC2 + BRD "habit loops, not the strongest model." Every derived attribute must be inspectable and reproducible (a parent/child can see *why* the system thinks "you're a visual learner" or "you fade after 8 minutes"). **No ML training** (AC out-of-scope) — derivations are deterministic rules over aggregates.
- **Success measure (testable):** for a student with seeded answer/session history, the profile derives the four attributes deterministically; `PreferredExplanationStyle` is populated (no longer null); the profile is queryable per student; a new student gets safe defaults that fill in as data accumulates; attributes are inspectable for the child and never expose another child's data; P3-03/P3-08 can read it in-process.

4. **AC4 — Cold-start.** A new student gets safe defaults; the profile fills in as data accumulates (feeds the BE7 network effect). *(verbatim.)*
5. **AC5 — Transparency & isolation.** All derived attributes are inspectable for a child (transparency) and **never expose another child's data**. *(verbatim — child-privacy + IDOR.)*

## Open questions for the lead — recommended defaults
> "Approve all defaults" ships a coherent v1. P3-13 has the most genuinely open design — flag liberally.

### Q1 — Derivation rules for each of the four attributes (THE core design — flag explicitly)
Recommended deterministic, explainable rules (all isolated in a pure `StudentProfileEngine`):
- **Question-type affinity:** per `QuestionType` (MCQ/TrueFalse/Matching/FillInBlank), success rate = correct/total for that type; "affinity" = the type(s) where success rate is meaningfully above the student's overall rate (with a min-sample guard, e.g. ≥N answers per type). Output: ranked types + rates.
- **Recurring-error clusters:** skills/concepts where the student has repeated wrong answers (e.g. ≥K incorrect on a skill, or wrong-after-wrong patterns); reuse P3-09 `needs_review` + raw `StudentAnswer.IsCorrect` streaks per `SkillId`. Output: list of weak skill/concept ids with an error-density score.
- **Attention-span / fatigue:** bucket a session's answers by elapsed minutes; detect the minute-bucket where accuracy drops below the student's session-start accuracy by a threshold ("accuracy drops after N minutes"). v1 proxy from `Attempt`/`StudentAnswer` timing (Q3); enrich from P5-03 later. Output: `AttentionSpanMinutes` estimate + confidence.
- **`PreferredExplanationStyle`:** **the hardest to derive deterministically** — there's no direct signal for "visual vs verbal." Recommend a **conservative mapping**: derive from question-type affinity + hint behavior (e.g. strong on Matching/visual formats + high hint usage on text → lean "visual/simpler"; strong on FillInBlank/text → "verbal/standard"). **This is a heuristic, not a measurement** — flag it as the weakest/most speculative attribute and ship a small, defensible enum (e.g. `Standard`/`Simplified`/`Visual`/`StepByStep`) with a clear default. Confirm the enum values with the lead (they must match what P3-03's prompt builder can actually consume).
- **All thresholds (N, K, min-sample, drop-%) are tunables** → `StudentProfileOptions` (config-bound). Flag — product hasn't specified them; ship defensible defaults.
- **Do NOT** train/infer with ML (AC out-of-scope, FR-AI-6). Flag any temptation.

### Q2 — Recompute trigger (AC2 "on a schedule and/or after each session")
- **Recommended default: both, lightweight** — (a) a **Hangfire recurring job** (`StudentProfileRecomputeJob`, mirror Gamification jobs) recomputes profiles periodically (e.g. nightly) for students with new activity; (b) an **on-session-end / on-attempt-completion hook** marks the profile stale or does an incremental recompute. v1 can be simpler: **recompute on attempt completion** (piggyback P3-09's completion hook) + a nightly safety-net job. Idempotent (pure recompute over all signals).

### Q3 — Attention-span without P5-03 (the dependency gap)
- **Recommended default: derive a proxy from existing `Attempt`/`StudentAnswer` timestamps** for v1 — within an attempt, order answers by time, bucket by cumulative `TimeSpentSeconds`, find the accuracy-drop point. This satisfies AC1's fatigue signal using only built data. **When P5-03 (sessions) lands**, enrich with cross-attempt session boundaries for a truer "bored after 8 minutes" signal. **Flag:** the story lists P5-03 as a dependency; confirm with the lead that a P2-08-only proxy is acceptable for v1 so P3-13 isn't hard-blocked on unbuilt P5-03. **Recommend yes** — the proxy is honest and upgradeable.

### Q4 — Cold-start defaults (AC4)
- **Recommended default:** a new/low-data student (`DataPointCount < threshold`) gets a **neutral default profile**: `PreferredExplanationStyle = Standard`, no affinity/clusters, default attention span (or null/unknown). The `DataPointCount` + per-attribute confidence let consumers (P3-03/P3-08) know when to trust vs. ignore an attribute. Profile fills in as data accumulates (BE7). Never block on insufficient data.

### Q5 — Engine shape (pattern caution, rule 8)
- **Recommended default:** pure static `StudentProfileEngine.Derive(StudentSignals signals, StudentProfileOptions options) → DerivedProfile` (mirror `LearningPathEngine`). `StudentSignals` = pre-fetched answer/attempt/mastery aggregates. A thin `StudentProfileService` fetches signals + persists the result. Job + completion-hook orchestrate. No DB/DI in the engine.
- **Pattern caution (high risk here):** four distinct derivations invite a **Strategy/Visitor/Pipeline** ("one rule class per attribute") abstraction, and `PreferredExplanationStyle` invites a **State/Rules-engine**. **Do NOT introduce any of these without asking the lead** (rule 8) — even though "a derivation per attribute" *feels* like it wants Strategy. Default = four private methods in one pure engine + a config options object. If the lead wants pluggable derivations later, that's a deliberate, approved refactor.

### Q6 — Exposure to P3-03 / P3-08 (AC3)
- **Recommended default: an in-process read seam** `IStudentProfileService.GetProfile(studentId) → DerivedProfile` consumed by P3-08 (this cluster, same module — direct call). **P3-03 prompt builder lives in the unbuilt AI module** — when it lands it reads the same seam (or a `Shared.Contracts` read contract if cross-module). For now, expose the seam + a query endpoint; P3-03 wiring is a flagged follow-up. Plus the **inspection endpoint** for AC5 (`GET /api/Learning/Profile`, Student JWT, IDOR-guarded).

## Risks & assumptions
1. **P5-03 (sessions) is unbuilt** — the fatigue signal's ideal source. Mitigate with a P2-08-only proxy (Q3); don't hard-block. **Flag to lead.**
2. **P3-03 (prompt builder) is unbuilt** (AI module absent) — AC3's "exposed to P3-03" is satisfied by the read seam; actual prompt consumption is deferred. Note, don't block.
3. **`PreferredExplanationStyle` derivation is speculative** (Q1) — no direct signal. The heuristic must be honest + low-confidence-flagged; the enum values must match what P3-03 can consume (coordinate when P3-03 is built). The biggest "soft" risk in the story.
4. **Child-privacy is load-bearing** (security section) — this profiles a minor. Data minimization, purpose limitation, transparency (AC5), strict IDOR. **security-auditor is mandatory** (story Notes say so).
5. **Module-isolation ownership split** (Affected modules) — must NOT FK to or duplicate gamification's `StudentProfile` XP/streak fields. Own only behavioral attributes in `StudentLearningProfile`.
6. **Grade transition must preserve the profile** (BE7) — no reset on grade change. Coordinate with the grade-transition story owner.
7. **Tunables unspecified** (Q1) — many thresholds; isolate in `StudentProfileOptions` config.
8. **Depends on P3-09 mastery** for weak-area input — merge after P3-09. Otherwise reads built P2-08 data.
