## Business context & value

- **Why this, not P10-11's `BillingConfigVersion`?** P10-11 introduced an effective-dated `BillingConfigVersion` store with an `IBillingConfigReader` seam — the right shape for billing-specific config. P10-12 generalises that pattern into a **platform-wide Global Settings store** covering the AI-economy values AND the AI cache/review thresholds (auto-approval confidence, WhyWrong variant cap, practice pool size). The P3-04/05/06 AI cache stories already have placeholders for a settings contract; P10-12 is the DB-backed implementation of what those stories coded against. A single generalised store is simpler than two parallel config mechanisms.
- **Cross-phase seam:** the `IGlobalSettingsProvider` **contract + a bootstrap-default implementation** ship earlier with the AI Helper (Phase 4) so Phase 3 cache thresholds (P3-04/05/06) are coded against the interface from day one. P10-12 upgrades it to the DB-backed + Redis-cached + audited + admin-editable implementation — mirroring the `ILearningContextProvider` Seeded→RAG pattern.
- **Managed keys (no tutor-session key — flagged to lead):** see the managed-keys table below. A "tutor session" cost key was requested but the Tutor-Session action was previously removed (AI-Helper-not-Teacher MVP) — key omitted pending lead confirmation.
- **Success measure:** consumers read every economy value through `IGlobalSettingsProvider` typed getters (no hardcoded constants, no per-module `*Options` for economy values); values cached in Redis/memory and invalidated when an admin writes a new value; every write audited who/when/old→new; safe code defaults bootstrap the system when a key is absent.

## `GlobalSetting` entity shape

```csharp
// Shared.Kernel — schema "platform", table "GlobalSettings"
public sealed class GlobalSetting
{
    public string Key { get; private set; }           // e.g. "credits.free_monthly"
    public string Value { get; private set; }         // always stored as string; cast by typed getters
    public GlobalSettingType Type { get; private set; } // Int, Decimal, String, Bool
    public string UpdatedBy { get; private set; }     // admin user id / name (non-FK — no cross-module FK)
    public DateTimeOffset UpdatedAt { get; private set; }

    // Update method (no public setters — enforces audit discipline)
    public void Update(string newValue, string updatedBy, DateTimeOffset now) { ... }
}

public enum GlobalSettingType { Int, Decimal, String, Bool }
```

No `FullAuditedEntity` base (those have CreatedBy/UpdatedBy split — here `UpdatedBy`/`UpdatedAt` are sufficient for a settings row that is updated in-place). The audit trail (old→new) is written separately to `Moderation.AuditLog` via the existing P7 `IAuditLogWriter` seam on every write.

## `IGlobalSettingsProvider` shape

```csharp
// Shared.Contracts — the cross-module contract
public interface IGlobalSettingsProvider
{
    // Typed getters — return bootstrap default if key absent from DB
    int GetInt(string key, int defaultValue);
    decimal GetDecimal(string key, decimal defaultValue);
    string GetString(string key, string defaultValue);
    bool GetBool(string key, bool defaultValue);

    // Convenience / named getters (delegates to GetInt with the key constant + default)
    int FreeMonthlyCredits { get; }
    int PremiumMonthlyCredits { get; }
    int FreeDailyCap { get; }
    int PremiumDailyCap { get; }
    int PackPriceEgp { get; }
    int PackSize { get; }
    int HintCost { get; }
    int ExplainMistakeCost { get; }
    int DeepExplanationCost { get; }
    int PracticeGenerationCost { get; }
    decimal AutoApprovalConfidenceThreshold { get; }
    int WhyWrongVariantCap { get; }
    int PracticePoolSize { get; }

    // Invalidate the local cache (called by the write path after a DB update)

}
```

## Caching strategy

- **Primary:** `IDistributedCache` (Redis) — reuse existing infrastructure from the Gamification module (no new Redis setup). Cache key: `global_settings:{key}`. TTL: long (e.g. 24 h) — invalidation is explicit, not TTL-based.
- **Fallback:** if Redis is unavailable, fall back to `IMemoryCache` (in-process; per-instance, not shared — acceptable for config reads).
- **Invalidation:** the `UpdateGlobalSettingCommand` handler calls `InvalidateCacheAsync(key)` after every successful DB write. The next read reloads from DB and re-caches.
- **Startup warm-up:** pre-load all managed keys into cache on application startup (via `IHostedService` or `InitializeAsync`) so the first user request does not incur a DB round-trip.

## Audit strategy

- Every `GlobalSetting` update writes an audit record (old-value, new-value, key, `UpdatedBy`, timestamp) to `Moderation.AuditLog` via the existing `IAuditLogWriter` seam in `Shared.Contracts/Moderation/` (the P7 pattern). No cross-module FK to `Moderation.*` projects — the seam only.
- Read operations are never audited.

## P10-11 reconciliation (bespoke mechanism superseded)

P10-11 introduced `BillingConfigVersion` / `IBillingConfigReader` as a dedicated billing-config store. P10-12 supersedes this mechanism:

| Aspect | P10-11 original | P10-12 reconciliation |
|---|---|---|
| Store | Effective-dated `BillingConfigVersion` rows | `GlobalSetting` key/value rows (mutable + audited) |
| Versioning | Full effective-dated version rows | Write audit (old→new) in `Moderation.AuditLog`; no version rows |
| Read seam | `IBillingConfigReader` in `Shared.Contracts` | `IGlobalSettingsProvider` in `Shared.Contracts` |
| Admin write | `UpdateBillingConfigCommand` | `UpdateGlobalSettingCommand` (generic) |
| Effective-dating | Explicit `EffectiveFromUtc` column | Immediate (next read after invalidation) |
| Caching | Optional in-memory cache | Required: `IDistributedCache` (Redis) + invalidation |

**Migration path:** the P10-11 task file is updated in this pass to replace `IBillingConfigReader` references with `IGlobalSettingsProvider`, remove `BillingConfigVersion` entity/migration, and replace `UpdateBillingConfigCommand` with calls to `UpdateGlobalSettingCommand` (or direct `IGlobalSettingsProvider` writes). The admin UI (P10-11-FE) still renders/edits the same values — only the backend mechanism changes.

**Never-retroactive invariant is preserved:** `GlobalSetting` rows are updated in place (not appended), but the `CreditTransaction.Amount` ledger rows remain immutable. A config update changes what value future reads return; it never rewrites past ledger rows. This satisfies the P10-11 never-retroactive AC (ledger immutability is in P10-01, not in the config mechanism).

**Effective-dated versioning trade-off (flagged to lead):** P10-11 originally specified effective-dated version rows for a clean "schedule a future change" path. P10-12 uses immediate-on-write (no scheduling). If the lead wants to retain scheduled future changes, either: (a) keep effective-dated rows in a `GlobalSettingVersion` table (adds complexity); or (b) accept immediate-only for MVP. **Recommend immediate-only; flag to lead.**

## Handoff — security-auditor

- **Admin-only writes (CRITICAL):** `UpdateGlobalSettingCommand` must be behind the admin policy; no parent/student/child can write a setting.
- **Key allowlist enforcement:** the command must reject any key not in the managed-keys allowlist (no arbitrary key injection by a malicious admin payload).
- **Value type/range validation:** every managed key has a known type and a sensible range (e.g. costs ≥ 0, monthly credits > 0, confidence threshold 0–1). The validator must enforce these server-side.
- **Audit completeness:** every write records old→new, who, when.
- **No payment secrets:** `GlobalSetting` must not store API keys / payment-gateway secrets — those belong in the secret store. The key allowlist is the enforcement mechanism.
- **Cache-poisoning resistance:** the cache is keyed by the managed-key string; confirm no user-supplied key can bypass the allowlist and pollute the cache.
- **Never-retroactive:** a setting update must not trigger a rewrite of any `CreditTransaction` rows; confirm the handler has no path to the ledger.

## Handoff — api-tester

- Read `FreeMonthlyCredits` via `IGlobalSettingsProvider` → returns 100 (seeded default).
- Write `credits.free_monthly` = 150 via `UpdateGlobalSettingCommand` → cache invalidated; next read returns 150; `Moderation.AuditLog` has a record (key, old=100, new=150, updatedBy, timestamp).
- Write with invalid key → rejected (key not in allowlist).
- Write with invalid value type (string for int key) → rejected.
- Write with out-of-range value (cost = -1) → rejected.
- Non-admin write attempt → 403.
- Unauthenticated → 401.
- Cache warm-up: after restart, first read does not error (pre-loaded from DB).
- `GetGlobalSettingsQuery` returns all 17 managed keys with current values.
