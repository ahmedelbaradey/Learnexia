# Pipeline Brief — P7-05 (admin-dashboard) Publish, version & preview curriculum content

> Scope: **Frontend only.** Backend is built + merged in the `Learning` module (`ContentLifecycleController` + Lifecycle feature handlers). This brief documents the **actual merged contract** (which differs from the task-file contract — see §"Affected modules & data" and §"Open questions"), and the FE surface to build on the Wave 1 admin foundation.
> Wave 2 of the admin-dashboard frontend (Next.js 15, `apps/admin-dashboard`, port 3001).

## Summary & traceability
- **Task (one line):** Build the admin-dashboard curriculum lifecycle UI — a **shared publish/unpublish/archive control** (reused by P7-01/02/03/04 surfaces), **version history + rollback** (confirm + reason), **preview** of a curriculum entity, an **admin live-vs-draft state** indicator, and a **per-language publication-coverage** view — all on the Wave 1 admin foundation.
- **User story:** `user-stories/Phase-7-Admin-Console/P7-05-publish-version-preview-curriculum.md`
- **FE tasks:** `tasks/Frontend/admin-dashboard/Phase-7-Admin-Console/P7-05-FE.md` (FE-1..FE-6)
- **BE tasks (done):** `tasks/Backend/Phase-7-Admin-Console/P7-05-BE.md` (BE-1..BE-8)
- **Requirements:** SRS §3 (Admin role), **FR-ADM-4**. Epic: Admin — Curriculum Management. SP 8.
- **BRD goal:** G5 (operational excellence / safe content governance) — admins edit safely and only expose vetted content to students.
- **Product-decision alignment:** 4 subjects only (`SubjectCode` enum = MATH/SCIENCE/ARABIC/ENGLISH — no Social Studies); no teacher role (AdminOnly). Bilingual parallel trees per `(SubjectCode, Language)` (Phase 8 merged).
- **Phase/sprint:** Phase 7 Admin Console, FE Wave 2 (Wave 1 = P7-06/07/08, merged).

## Business context & value
- **Who benefits:** Admins (content editors) directly; students indirectly (they only ever see published, vetted content). No parent/teacher surface.
- **Value:** A draft→published lifecycle with versioning + rollback lets admins edit curriculum safely without exposing half-finished content. Preview lets them verify before publishing. Per-language coverage prevents the classic bilingual gap (e.g. `ar` Math live but `en` Math still draft) where one language cohort silently gets nothing.
- **Success measures (from story ACs):** edits stay draft until published; publish records a versioned snapshot with timestamp+author; live vs pending-draft is distinguishable; preview renders without publishing; rollback restores a prior version; one-sided language coverage is flagged; non-admin is blocked.
- **Cross-cutting note:** P7-05 is the **lifecycle/publish backbone** the other four curriculum stories (P7-01..04) depend on. The shared lifecycle control + lifecycle badge + lifecycle hooks this story owns are consumed by those surfaces. The planner will likely sequence the shared control + hooks **first**.

## Acceptance criteria (testable)
Lifecycle control & state (FE-1, FE-2, FE-5):
- A `LifecycleBadge` renders Draft / Published / Archived for a curriculum entity, color + non-color signal (icon/shape), EN+AR labels, never raw ints. (AC: live vs pending-draft distinguishable.)
- A shared lifecycle control exposes **Publish** (Draft→Published), **Unpublish** (Published→Draft), **Archive** (Published→Archived), and **Restore** (Archived→Draft) — only the transitions legal for the current state are offered (see transition table in §Handoff→frontend).
- Publish requires a confirmation dialog; on success the UI reflects the new Published state and surfaces a success message; caches for that entity are invalidated.
- Illegal transitions (e.g. Archived→Published direct) are not offered in the UI, and if attempted the 400 envelope is surfaced as an error, not a crash.
- Admin can distinguish current state (Draft vs Published vs Archived) on list/detail surfaces via the badge.

Version history & rollback (FE-4):
- A `VersionHistory` panel lists published versions newest-first, showing version number, publish timestamp (localized from `PublishedAtUtc`), and the publishing admin (id; resolve to name if a lookup is available, else show id — see OQ).
- Rollback to a selected version requires a confirmation dialog **with a required reason** (mirrors the Wave 1 destructive-dialog + `ReasonField` pattern). On success the entity is re-published and version history refetches (a new version row appears).
- Empty history (entity never published) shows an empty state, not an error.

Preview (FE-3):
- From a curriculum entity, admin can open a Preview that shows the entity's **current (possibly Draft)** state without publishing it, rendered in the **tree's language** (RTL for `ar`, LTR for `en`) using `PreviewDto.Language`.
- Preview never mutates state and is reachable only by admins.

Publication coverage (FE-6):
- A `PublicationCoverage` view, given a grade, shows for each `SubjectCode` the `ar` and `en` trees side-by-side with publish state (Published / Draft / Archived / not-existing), and **visibly flags one-sided coverage** (one language published while its sibling is not).

Security & access (all):
- All endpoints are AdminOnly. Anonymous → 401, non-admin → 403/redirect (enforced by `useAdminGuard` + middleware, same as Wave 1).
- Publish, Unpublish, Archive, and Rollback all go through an explicit confirm step (no one-click destructive/high-impact publish).

### Actual merged backend contract (AUTHORITATIVE — supersedes the task-file contract)
Controller: `backend/src/Modules/Learning/Learnexia.Modules.Learning.Api/Controllers/ContentLifecycleController.cs`. Route base: **`/api/learning/ContentLifecycle`**. Entire controller is `[Authorize(Policy = AuthorizationPolicies.AdminOnly)]`. All responses are `BaseResponse<T>` (success flag spelled `Successed`; FE unwraps via the api-client envelope layer).

Enums (from `Learning.Domain.Enums`):
- `VersionedEntityType`: **Subject=1, Unit=2, Lesson=3, QuizQuestion=4** (NOT 0-based; bind by these ints).
- `LifecycleState`: **Draft=1, Published=2, Archived=3**.
- `ContentLanguage`: **Ar=0, En=1**.
- `SubjectCode`: **MATH=0, SCIENCE=1, ARABIC=2, ENGLISH=3**.

Endpoints:
1. **`POST /api/learning/ContentLifecycle/Transition`** — body `{ entityType: number, entityId: number, targetState: number }` → `BaseResponse<string>` (success message). One endpoint covers **publish (→2), unpublish (→1), archive (→3), restore (Archived→Draft)**. On →Published the backend creates a `ContentVersion` snapshot and stamps `PublishedByUserId` from the JWT. Legal transitions only (see table in §Handoff→frontend); illegal → 400 `Successed=false`. 404 if entity missing/soft-deleted.
2. **`POST /api/learning/ContentLifecycle/Rollback`** — body `{ entityType: number, entityId: number, versionNumber: number }` → `BaseResponse<string>`. Restores the snapshot's editorial fields, re-publishes the entity, and appends a NEW version row. 404 if the version row or entity is missing. **Note:** the backend does NOT require a reason field (no reason in the command) — the required-reason gate is a **FE-only UX guardrail**; the reason is not persisted server-side (flag — see OQ2).
3. **`GET /api/learning/ContentLifecycle/VersionHistory?entityType={int}&entityId={int}`** → `BaseResponse<List<ContentVersionDto>>`, newest-first. `ContentVersionDto`: `{ id, entityType, entityId, versionNumber, publishedAtUtc (ISO), publishedByUserId (int), language (ContentLanguage), snapshot (JSON string) }`.
4. **`GET /api/learning/ContentLifecycle/Preview?entityType={int}&entityId={int}`** → `BaseResponse<PreviewDto>`. `PreviewDto`: `{ entityType, entityId, currentState (LifecycleState), language (ContentLanguage), snapshot (JSON string) }`. **The snapshot is raw serialized JSON of the live entity**, not pre-rendered content. Preview reflects the *current* state (Draft or Published), not a historical version.
5. **`GET /api/learning/ContentLifecycle/PublicationCoverage?gradeId={int}`** → `BaseResponse<PublicationCoverageReportDto>`. `PublicationCoverageReportDto`: `{ gradeId, gradeNumber, coverage: PublicationCoverageSlotDto[] }`. Each slot: `{ subjectCode (SubjectCode), language (ContentLanguage), exists (bool), subjectId (int?), name (string?), isActive (bool?), lifecycleState (LifecycleState?), isPublished (bool) }`. Slot is emitted per `(SubjectCode, Language)` whether or not the subject exists.

**Snapshot field shapes** (for any client-side rendering of the JSON snapshot — from the rollback handler's `Apply*Snapshot`):
- Subject: `Name, Country, SubjectCode, Language, SequenceOrder, IsActive`.
- Unit: `Name, SequenceOrder, IsActive`.
- Lesson: `Name, Difficulty, SequenceOrder, IsLocked, IsActive, EstimatedMinutes, Explanation, Visual, IsBoss`.
- QuizQuestion: `QuestionText, QuestionType, Options (JSON string), CorrectAnswer (string), Difficulty, GeneratedBy, SequenceOrder, IsActive`.

### Contract gaps vs the task file (do NOT follow the task-file contract blindly)
- Task file says `GET /api/Learning/{type}/{id}?view=admin|student` returning `liveVersion` + `draft` distinguished. **This endpoint does not exist.** There is no single read returning both live and pending-draft. The live vs pending-draft distinction in the merged backend is **per-entity LifecycleState** (an entity is Draft OR Published — there is no separate "pending draft of a published entity" record). FE-5's "live vs pending draft toggle" must be re-scoped to: show the entity's current `LifecycleState` (via badge) + offer Preview of current state + show last-published version via VersionHistory. (See OQ1.)
- Task file says separate `POST .../Publish`. **Actual:** single `Transition` endpoint with `targetState`.
- Task file route casing `/api/Learning/...`; **actual** base is `/api/learning/ContentLifecycle/...`.

## Handoff → frontend
**App routes (proposed, under the `(admin)` group):**
- `app/(admin)/curriculum/page.tsx` — curriculum landing (likely the per-language **PublicationCoverage** view with a grade selector; FE-6). Wire `AdminSideNav` "Curriculum" placeholder → `/curriculum`.
- `app/(admin)/curriculum/preview/[type]/[id]/page.tsx` — **Preview** (FE-3). `[type]` ∈ subject|unit|lesson|quiz (map to `VersionedEntityType` int), `[id]` numeric.
- The lifecycle control + version history are **components** embedded into P7-01..04 entity detail/list surfaces (which do not exist yet) AND/OR a self-contained per-entity panel under `/curriculum`. Because P7-01..04 surfaces aren't built, build the shared pieces as standalone, composable components with a small demo/host so they can be reviewed and E2E-tested in isolation. (See OQ4 for where they mount.)

**Components to build:**
- `components/LifecycleBadge.tsx` (FE-1) — pill for `LifecycleState` (Draft/Published/Archived). **Mirror `StatusBadge.tsx`** (dot + uppercase label, color + non-color signal). Suggested palette: Draft = amber/neutral, Published = green, Archived = grey/red-muted. Keyed off a new `LIFECYCLE_STATE` const in `@learnexia/shared` (mirror `ACCOUNT_STATUS`), never raw ints. EN+AR labels via `strings`.
- `components/CurriculumLifecycleControl.tsx` (FE-2, FE-5 — **the shared cross-cutting piece this story owns**) — given `{ entityType, entityId, currentState, language }`, renders the legal action buttons + opens the relevant confirm dialog. This is the control P7-01..04 reuse.
- Confirm dialogs (mirror `SuspendUserDialog`): `PublishCurriculumDialog`, `UnpublishCurriculumDialog`, `ArchiveCurriculumDialog`, `RollbackVersionDialog`. Publish/Unpublish/Archive: confirm + optional notice (publish is high-impact → make the impact explicit: "students will immediately see this"). Rollback: confirm **+ required `ReasonField`** (FE guardrail).
- `components/VersionHistory.tsx` (FE-4) — list `ContentVersionDto[]` newest-first (version #, localized timestamp, publisher id/name), each row offering "Roll back to this version" → `RollbackVersionDialog`.
- `components/PublicationCoverage.tsx` (FE-6) — grade selector + a per-`SubjectCode` table with `ar`/`en` columns; each cell a `LifecycleBadge` (or "not created"); flag one-sided coverage (e.g. warning chip when one language `isPublished` and the sibling is not).
- `components/CurriculumPreview.tsx` (FE-3) — renders `PreviewDto`. **Rendering approach (decision needed):** the snapshot is raw JSON and the student renderers live in the Expo app (`@learnexia/ui`, react-native) and are **not directly usable** in Next.js. Recommended pragmatic v1: render a **structured, read-only preview of the snapshot fields** (per the snapshot field shapes above) in the correct direction/locale, clearly labeled "Preview — not published", rather than attempting to reuse the Expo lesson player. (See OQ5.)

**Legal transition table (drive the available actions from current state):**
- Draft → Published (Publish) ✓ ; Draft → Archived ✗ (must publish first).
- Published → Draft (Unpublish) ✓ ; Published → Archived (Archive) ✓.
- Archived → Draft (Restore) ✓ ; Archived → Published ✗ (must go via Draft).
- Same→same: no-op success.

**New hooks (`packages/api-client/src/hooks/`, mirror Wave 1 admin hooks; export from `hooks/index.ts`; add `adminLifecycle.*` keys):**
- `useContentVersionHistory(entityType, entityId)` — GET VersionHistory; `enabled: entityId>0`; key `adminLifecycle.versions(entityType, entityId)`.
- `usePreviewContent(entityType, entityId)` — GET Preview; `enabled: entityId>0`; key `adminLifecycle.preview(entityType, entityId)`.
- `usePublicationCoverage(gradeId)` — GET PublicationCoverage; `enabled: gradeId>0`; key `adminLifecycle.coverage(gradeId)`.
- `useTransitionLifecycle()` — POST Transition `{ entityType, entityId, targetState }`; on success invalidate `adminLifecycle.versions(...)`, `adminLifecycle.preview(...)`, `adminLifecycle.coverage` (by grade if known), and any P7-01..04 entity lists. Returns `BaseResponse<string>` message.
- `useRollbackToVersion()` — POST Rollback `{ entityType, entityId, versionNumber }`; same invalidations.

**States to handle on every surface:** loading (skeleton — reuse `AdminLoadingSkeleton`/shimmer pattern), empty (no versions; coverage with no subjects), error (`AdminErrorBanner` + retry; keep dialogs open on error so admin can retry/cancel), pending (spinner + disabled confirm), success (banner + cache invalidation). 401→ guard redirect; 403 surfaced; 404 → "not found" state.

**RTL/i18n + a11y:** EN-first but bilingual copy (follow `lib/strings.ts`). Preview direction is driven by the entity's `language` (Ar→rtl, En→ltr), independent of the admin UI locale. Dialogs: focus trap, ESC cancels, `aria-modal`, required-field `aria-required`/`aria-invalid`, `role="alert"` on errors, color never the only signal (badge dots/icons). Confirm buttons disabled until valid; pending state announced.

## Open questions / assumptions / risks
1. **(OQ1 — contract mismatch, BLOCKER-ish for FE-5)** The task file's `?view=admin` returning `liveVersion`+`draft` does not exist; the merged backend is **per-entity single state** (no concurrent "published + pending draft" record). Recommend the lead confirm FE-5 is re-scoped to "show current `LifecycleState` + Preview + last published version", and that the story AC "both the live version and the pending draft are distinguishable" is interpreted as state-badge + version-history (since there is no pending-draft-of-a-published-entity in the model). Designer/frontend should NOT build a dual live/draft toggle.
2. **(OQ2)** Rollback has **no reason field server-side**. The story/task imply a reason on rollback. Confirm: keep the required-reason as a FE-only guardrail (not persisted), OR request a backend follow-up to persist it (audit). Default assumption: FE-only guardrail, clearly not persisted.
3. **(OQ3)** `ContentVersionDto.publishedByUserId` is an int with no name in the lifecycle endpoints. Confirm whether the UI shows the raw id, or whether we may call an admin user-lookup (e.g. `GET /api/Admin/Users/{id}`) to resolve a name. Default assumption: show id with a tooltip/label; resolve to name only if a cheap lookup is approved.
4. **(OQ4 — sequencing/host)** P7-01..04 curriculum entity surfaces (subject/unit/lesson/quiz lists + detail) **do not exist yet** (HANDOFF confirms only P7-06/07/08 FE shipped). The shared lifecycle control/badge/version-history are meant to embed there. Confirm whether P7-05 ships them as standalone, composable components (with a minimal `/curriculum` host for review + E2E) now, with P7-01..04 wiring them later — or whether the planner pulls a slice of P7-01 forward to give the control a real host. Default assumption: build standalone + a `/curriculum` coverage landing + preview route; expose the control/badge for later reuse.
5. **(OQ5 — Preview rendering, design decision)** "Render as a student would" is hard: student renderers are Expo/react-native in `@learnexia/ui` (not usable in Next.js), and the Preview payload is raw JSON. Confirm the v1 approach: (a) structured read-only field preview of the snapshot in the correct direction/locale (recommended, low-risk), or (b) invest in a web-rendering path. Designer should decide the visual treatment; frontend should not attempt to import the Expo lesson player.
6. **(Assumption)** `LIFECYCLE_STATE` const will be added to `@learnexia/shared/constants` (mirroring `ACCOUNT_STATUS`) so the badge keys off a typed const, not raw ints. Flag if shared-package edits must be serialized with other in-flight work (Directory.Packages.props-style serialization rule does not apply to TS, but shared edits still touch a common file).
7. **(Risk)** This is a **high-impact, security-sensitive** batch (publishing flips content live to students). Requires: AdminOnly verified end-to-end (anonymous/non-admin blocked), explicit confirm on publish/unpublish/archive/rollback, and audit awareness (the backend already raises `AdminActionPerformedDomainEvent` → P7-12 audit on every transition/rollback; the FE must not bypass the dialogs). `security-auditor` should run before the reviewer gate.
8. **(Risk)** Quiz entity type is `QuizQuestion` (per-question), not "quiz" — the task file says "quiz". Lifecycle is per question. Confirm the route slug mapping (`quiz` → `QuizQuestion=4`) and whether admins lifecycle whole quizzes or individual questions. Default: per `QuizQuestion`, matching the backend.

## Recommended pipeline order (first cut — the `planner` finalizes)
1. **Resolve OQ1, OQ4, OQ5 with the lead/user first** (contract mismatch + host + preview approach materially change the design). Do not start the designer until OQ1/OQ5 are answered.
2. **designer** — Design Spec for: LifecycleBadge variants (Draft/Published/Archived), the shared CurriculumLifecycleControl + its four confirm dialogs (publish/unpublish/archive/rollback, with the rollback reason), VersionHistory panel, PublicationCoverage grid (ar/en side-by-side + one-sided flag), CurriculumPreview treatment (per OQ5), all states + RTL/ar+en + a11y. Reuse the `design-system/` kit + Wave 1 patterns.
3. **frontend — Batch 1 (foundation, sequence first):** `LIFECYCLE_STATE` in `@learnexia/shared`; the five hooks + `adminLifecycle` query keys + barrel exports; `LifecycleBadge`. These are what P7-01..04 will reuse.
4. **frontend — Batch 2 (parallel where independent):** CurriculumLifecycleControl + the 4 dialogs; VersionHistory; PublicationCoverage + `/curriculum` landing; CurriculumPreview + preview route; wire AdminSideNav "Curriculum" link; strings (EN+AR).
5. **security-auditor** — audit the publish/rollback flows (AdminOnly enforcement, confirm gates, no bypass, no PII leakage from snapshots).
6. **frontend-e2e-tester** — Playwright over the running admin PWA: publish→state change, unpublish, archive, rollback (with reason), preview (ar RTL + en LTR), coverage one-sided flag, auth/role routing (anonymous→login, non-admin→403), EN+AR.
7. **reviewer** — gate against these ACs + CONVENTIONS, including security-auditor + e2e results. Then **committer** (per-story branch `feat/P7-05-…`, PR).
