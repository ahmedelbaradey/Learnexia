# Pipeline Brief — P2-08 Record granular per-question answers

## Summary & traceability
- **Task (1 line):** Persist per-question detail (correctness, time-spent, hint-used), aggregate it onto the `Attempt` (accuracy %, duration, hints-used, status), capture partial attempts on abandon, and make the data queryable per student and per skill.
- **User story (source of truth):** `user-stories/Phase-2-Learning-Core/P2-08-record-granular-answers.md`
- **Task file:** `tasks/Backend/Phase-2-Learning-Core/P2-08-BE.md` (BE-1..BE-4; **backend/infra only — no Frontend tasks**)
- **FR-IDs:** FR-QZ-4 (granular answer recording). Feeds FR-AD (adaptivity, Phase 3 — P3-08/P3-09) and FR-PA (analytics, Phase 5).
- **BRD goal / epic:** Assessment Module; supports the engagement + adaptive-mastery goals (the "data backbone").
- **Phase / sprint:** Phase 2 — Learning Core (Week 3–4). Story Points: 3.
- **Module:** **Learning** (schema `learning`). Quiz/assessment lives in Learning, NOT a separate Assessment module (lead decision, HANDOFF). The task file's `Assessment` route strings are stale — use `api/Learning/...` (the P2-06 `QuizzesController` already does).

## Business context & value
- **Who benefits:** indirectly the **student** (better adaptive sequencing later), the **parent** (analytics/reports in Phase 5), the **platform/adaptivity engine** (Phase 3). No new UI in this story.
- **Why it matters:** P2-08 is the **signal-capture backbone**. Adaptivity (P3) decides what to show next from accuracy/time/hint patterns; analytics (P5 parent reports) aggregate the same rows. If signals aren't captured cleanly and reliably now, both later phases inherit corrupt or missing data.
- **Why partial capture on abandon matters:** students abandon quizzes (close tab, lose connection, run out of time). An abandoned attempt with 3 of 5 questions answered still carries real signal — those 3 answers and their correctness/timing must survive. Discarding partials biases the dataset toward only-finished attempts (survivorship bias) and undercounts struggle, which is exactly the signal adaptivity needs.
- **Success measure:** every submitted answer produces a durable `StudentAnswer` row with correctness/time/hint; every terminal attempt (Completed or Abandoned) carries correct aggregates; the per-student and per-skill queries return accurate counts/accuracy. Validated by `api-tester` integration tests.

## Acceptance criteria (testable)
1. **Per-answer detail persisted** — each `StudentAnswer` row stores `IsCorrect` (bool), `TimeSpentSeconds` (int ≥ 0), and `HintUsed` (bool), tied to its `AttemptId` and `QuestionId`. (→ BE-1)
2. **Attempt aggregates** — on attempt completion (and on abandon), `Attempt` carries `AccuracyPercentage` (correct/answered × 100), `DurationSeconds`, `HintsUsedCount` (sum of `HintUsed` answers), and `Status` (`Completed`/`Abandoned`). (→ BE-2, BE-3)
3. **Reliable on abandon** — abandoning mid-quiz transitions the attempt to `Abandoned`, sets `CompletedAt`, and recomputes aggregates over the answers captured so far; previously-submitted answers are not lost. (→ BE-3)
4. **Queryable per student** — a query returns a student's attempts (with aggregates + status) — `GET /api/Learning/Students/{studentId}/Attempts`. (→ BE-4)
5. **Queryable per skill** — a query returns stats for a skill aggregated across answers whose question maps to that skill — `GET /api/Learning/Skills/{skillId}/Stats`. (→ BE-4)
6. **Auth/ownership** — answer/abandon writes resolve `StudentId` from the JWT (never the client); a student may only write to their own in-progress attempt (403/404 otherwise). Per-student/per-skill read endpoints must be access-scoped (see Open Questions).

## Affected modules & data
**Module:** Learning only. No cross-module FKs. `StudentId` stays a loose `int` (Identity reference, module isolation).

### Entities — ALL FIELDS ALREADY EXIST (built forward-compatible in P2-06)
This is the critical finding: **the schema gap is effectively zero.** P2-06 already shipped every P2-08 field with EF config and a migration (`AddQuizTables`).

- **`StudentAnswer`** (`...Domain/Entities/StudentAnswer.cs`) — `FullAuditedEntity`, child of the `Attempt` aggregate. Already has: `AttemptId` (FK Cascade), `QuestionId` (FK Restrict), `AnswerPayload` (string), **`IsCorrect`** (bool), **`TimeSpentSeconds`** (int, default 0), **`HintUsed`** (bool, default false). Indexes on `AttemptId`, `QuestionId` (`StudentAnswerConfig.cs`).
- **`Attempt`** (`...Domain/Entities/Attempt.cs`) — `AggregateRoot`. Already has: `StudentId` (int, indexed), `LessonId` (int, indexed), `Status` (`AttemptStatus` enum: NotStarted/InProgress/Completed/Abandoned), **`AccuracyPercentage`** (double, default 0), **`DurationSeconds`** (int, default 0), **`HintsUsedCount`** (int, default 0), `StartedAt`, **`CompletedAt`** (nullable). (`AttemptConfig.cs`)
- **`QuizQuestion`** (`...Domain/Entities/QuizQuestion.cs`) — `LessonId` (int, indexed), **`SkillId`** (int?, indexed), `QuestionType`, `QuestionText`, `Options` (jsonb), `CorrectAnswer` (jsonb), `Difficulty`, `GeneratedBy`. The `SkillId` index is what makes the per-skill query feasible.

**Per-skill linkage:** `StudentAnswer → QuizQuestion.SkillId → Skill`. `QuizQuestion.SkillId` is **nullable** — questions without a skill cannot contribute to per-skill stats (see Risks). Note `Lesson` also has a `SkillId`; the per-skill stat path should use `QuizQuestion.SkillId` directly (it's the indexed, question-level link), not go through Lesson.

### What needs to be ADDED (behavior, not schema)
- **No new entities. No new columns.** A migration is likely **unnecessary** unless the implementer adds composite indexes (see db-migration handoff).
- **New Application features** under `Features/Attempts/`: `SubmitAnswerCommand`, `AbandonAttemptCommand`, `GetStudentAttemptsQuery`, `GetSkillStatsQuery` (+ DTOs/validators/mapping).
- **New controller actions** on `QuizzesController` (or new `StudentsController`/`SkillStats` actions — see Open Questions on routing).

## Handoff → db-migration
- **Expectation: likely NO migration.** All P2-08 columns + FKs + single-column indexes already exist (shipped by P2-06's `AddQuizTables`). Confirm the model is unchanged before generating anything — a `dotnet ef migrations add` on an unchanged model produces an empty migration; do **not** commit an empty migration.
- **Optional performance migration (recommend, decide with planner):** the per-student and per-skill read paths benefit from composite/covering indexes that don't exist yet:
  - `Attempt`: composite index on `(StudentId, Status)` — the per-student query filters/sorts by student and likely status.
  - `StudentAnswer`: the existing `IX_StudentAnswers_QuestionId` supports the join to `QuizQuestion`, but the per-skill aggregation joins `StudentAnswer → QuizQuestion(SkillId)`; consider an index on `QuizQuestion(SkillId)` (already exists) is sufficient — measure before adding more.
  - If added, name a migration e.g. `AddAttemptQueryIndexes`, schema `learning`, mirror existing `*Config.cs` index naming (`IX_<Table>_<Cols>`). Apply to the remote dev DB per HANDOFF run instructions.
- **Do not** change FK delete behavior (Cascade on AttemptId, Restrict on QuestionId are deliberate).

## Handoff → backend-feature
Mirror the **Catalog** reference patterns + the existing `StartAttempt` feature shape. Return `BaseResponse<T>` via `BaseResponseHandler`; controllers use `NewResult(...)`; success flag is `Successed`. Inject `ILoggerManager`. Commands are auto-validated (`ValidationBehavior`); **queries are NOT** — validate query inputs inline if needed. No Unit of Work — `GenericRepository` commits per call; for the multi-write aggregate updates open an explicit transaction OR follow the `StartNewAsync` precedent (explicit `SaveChangesAsync`).

**Cross-story dependency — coordinate with P2-07:** P2-07-BE-1 defines the **SubmitAnswer endpoint** (returns `{ isCorrect, correctAnswer?, hintAvailable }` synchronously) and P2-07-BE-2 explicitly says "reuse P2-08-BE-1" for persistence. **There is one SubmitAnswer command, shared.** Recommendation for the planner: build **`SubmitAnswerCommand` once** as the union of P2-07 (correctness check + feedback response + `AnswerSubmitted` event stub) and P2-08 (persist `IsCorrect`/`TimeSpentSeconds`/`HintUsed`). Do not build two competing submit handlers. If P2-07 and P2-08 are sequenced, the one that runs first owns the command and the second extends it. Flag to lead which story owns the file.

### New commands
1. **`SubmitAnswerCommand`** (`Features/Attempts/Commands/SubmitAnswer/`)
   - Input: `AttemptId` (route), `QuestionId`, `AnswerPayload` (string), `TimeSpentSeconds` (int), `HintUsed` (bool). `StudentId` from JWT.
   - Behavior: verify attempt exists, belongs to the JWT student, and is `InProgress` (else 404/403/409). Load the `QuizQuestion`, compare `AnswerPayload` to `CorrectAnswer` server-side (reuse/extend the P2-06 `QuizQuestionContentValidator` correctness logic per `QuestionType`), set `IsCorrect`. Persist the `StudentAnswer`. Idempotency: decide whether re-answering the same question updates the existing row or rejects (Open Question).
   - Output: `BaseResponse<SubmitAnswerResponse>` with `{ isCorrect, correctAnswer?, hintAvailable }` (P2-07 contract).
   - Plants `AnswerSubmitted` integration-event stub in `Shared.Contracts` (P2-07-BE-3) for Phase-4 XP/hearts.
   - Validator: `AttemptId > 0`, `QuestionId > 0`, `AnswerPayload` not empty, `TimeSpentSeconds >= 0`.

2. **`CompleteAttemptCommand`** (optional but recommended — see Open Questions)
   - Transitions `InProgress → Completed`, sets `CompletedAt`, recomputes aggregates. If P2-06's StartAttempt has no completion path, the aggregates in AC-2 need a trigger. The planner must decide whether completion is its own endpoint or folded into the last SubmitAnswer.

3. **`AbandonAttemptCommand`** (`Features/Attempts/Commands/AbandonAttempt/`)
   - Input: `AttemptId` (route); `StudentId` from JWT.
   - Behavior: verify ownership + `InProgress`. Transition to `Abandoned`, set `CompletedAt = UtcNow`, recompute aggregates over answers captured so far (`AccuracyPercentage` = correct/answered×100, guard divide-by-zero when zero answers → 0; `DurationSeconds`; `HintsUsedCount`). Idempotent on already-terminal attempts (return current state, don't error-hard).
   - Output: `BaseResponse<AttemptSummaryDto>`.

**Aggregate computation (shared helper):** accuracy/duration/hints recompute is needed by both Complete and Abandon. Factor it into one place (a method on a service or a domain method on `Attempt`). `DurationSeconds`: prefer **server-side** `UtcNow - StartedAt` as the source of truth for total attempt duration; per-question `TimeSpentSeconds` is client-reported (see Risks). Decide whether attempt duration = server elapsed or sum of per-question times (Open Question).

### New queries (NOT auto-validated)
4. **`GetStudentAttemptsQuery`** → `GET /api/Learning/Students/{studentId}/Attempts`
   - Returns the student's attempts with aggregates + status. Consider paging/filtering by status. Project to a DTO (do not leak `CorrectAnswer`). Access scope: see Open Questions (a student should only read their own; parents/admin later).

5. **`GetSkillStatsQuery`** → `GET /api/Learning/Skills/{skillId}/Stats`
   - Aggregates `StudentAnswer` joined to `QuizQuestion` where `QuizQuestion.SkillId == skillId`. Returns e.g. `{ skillId, totalAnswers, correctAnswers, accuracyPercentage, distinctStudents, avgTimeSpentSeconds, hintUsageRate }`. Scope is ambiguous (this-student vs all-students) — see Open Questions.

### Plumbing
- New DTOs under `Features/Attempts/Dtos/` + AutoMapper profile entries (mirror `QuizQuestionDto`'s exclusion of `CorrectAnswer`).
- Controller actions: add to existing `QuizzesController` for `{attemptId}/Answers` + `{attemptId}/Abandon`; the per-student/per-skill reads may warrant their own controllers (`StudentsController`, or actions on `SkillsController`) — keep route base `api/Learning/...`.
- `[Authorize(Roles="Student")]` on write endpoints (mirror StartAttempt). Read endpoints' policy is an Open Question.
- No new module — extend Learning's existing `ILearningServiceManager`/repository seams if a service method is added (e.g. extend `IAttemptService`).

## Handoff → frontend
**None.** P2-08 is backend/infra only (task file: "no Frontend tasks"). The synchronous SubmitAnswer feedback contract that the FE consumes is owned by **P2-07-FE**, not this story. Do not dispatch the `designer` or `frontend` agents for P2-08.

## Handoff → api-tester
Validate against the running API (integration tests, real Postgres):
- SubmitAnswer: correct answer → `isCorrect=true` + persisted row with correct fields; wrong answer → `isCorrect=false` + `hintAvailable`; `TimeSpentSeconds`/`HintUsed` round-trip.
- Auth: submit/abandon on another student's attempt → 403; non-existent attempt → 404; submit to a non-`InProgress` attempt → 409 (or defined behavior).
- Abandon: partial attempt (e.g. 2 of 5 answered) → status `Abandoned`, `CompletedAt` set, aggregates computed over the 2 answers; previously-submitted answers still present.
- Aggregates: accuracy %, duration, hints-used correct after completion/abandon; zero-answer abandon → accuracy 0 (no divide-by-zero).
- `GET .../Students/{id}/Attempts` returns the seeded attempts with aggregates; `CorrectAnswer` never leaked.
- `GET .../Skills/{id}/Stats` aggregates correctly across questions mapped to the skill; a skill with no answers → zeroed stats (not 500).

## Security-auditor (flag to planner)
This batch touches **child/student data** and ownership-scoped reads → **security-sensitive**; recommend `security-auditor` before the review gate. Focus: JWT-derived `StudentId` (never client-supplied), per-student/per-skill read authorization (no IDOR — a student reading `Students/{otherId}/Attempts`), and no `CorrectAnswer` / `ex.Message` leakage.

## Open questions / assumptions / risks
**Open questions (recommend the lead confirm before/early in the pipeline):**
1. **Attempt-completion trigger (highest priority).** AC-2 ("Attempt aggregates accuracy/duration/hints/status") needs a moment when the attempt becomes `Completed`. P2-06 only Starts/Resumes; no completion path exists. Is there a `CompleteAttempt` endpoint (new here), or are aggregates only finalized on Abandon, or computed lazily on read? **This determines whether BE-2 adds a `CompleteAttemptCommand`.**
2. **SubmitAnswer ownership — P2-07 vs P2-08.** Both stories describe the same submit/persist. Confirm which story owns `SubmitAnswerCommand` so two handlers aren't built. Recommend: one command, built once, sequenced.
3. **Per-skill stats scope.** Is `GET /Skills/{id}/Stats` per-the-current-student (a student's own mastery signal) or platform-wide aggregate (analytics)? They imply different auth + different DTO. The story says "queryable per skill" without specifying audience.
4. **Read-endpoint authorization.** Who can call `Students/{studentId}/Attempts`? Student-self-only? Parents (P5)? Admin (P7)? Phase 5/7 consume this but this story exposes it now — define the policy to avoid IDOR.
5. **Re-answer idempotency.** May a student submit the same `QuestionId` twice in one attempt? Update-in-place, reject, or append? Affects accuracy denominator.

**Assumptions:**
- No migration is required for the core feature (entities/columns/FKs already exist from P2-06). Optional perf indexes only.
- `StudentId` is always resolved from the JWT; writes are Student-role-only, mirroring StartAttempt.
- Aggregate accuracy = correct answers / answered questions (not / total lesson questions), unless the lead says otherwise — relevant for partial abandons.

**Risks:**
- **Concurrency.** Multiple SubmitAnswer calls for the same attempt could race (two answers written, or simultaneous submit + abandon). No Unit of Work — each repo call commits independently. Aggregate recompute must read a consistent snapshot; an abandon racing with a submit could drop a just-written answer from the aggregate. Mitigate with an explicit transaction around read-answers + write-aggregate on terminal transitions, and/or compute aggregates from a fresh query at terminal time rather than from in-memory state.
- **Client-reported timing.** `TimeSpentSeconds` and `HintUsed` are client-supplied and trivially spoofable/clock-skewed. Treat per-question time as advisory; use server-side `UtcNow - StartedAt` as the authoritative attempt `DurationSeconds`. Validate `TimeSpentSeconds >= 0` and consider a sane upper bound.
- **"Queryable per skill" indirection.** The path is `StudentAnswer → QuizQuestion.SkillId`, and `QuizQuestion.SkillId` is **nullable** — questions never assigned a skill are invisible to per-skill stats (acceptable but document it). Do **not** route through `Lesson.SkillId` (also nullable, different grain). The seeded demo data (P2-10) may or may not populate `QuizQuestion.SkillId` — verify the seeder sets it, else per-skill stats return empty in dev.
- **Empty/no migration trap.** Running `ef migrations add` on the unchanged model yields an empty migration; committing it is noise. Verify the model diff is empty (or only the optional indexes) before generating.
