# Pipeline Brief — P2-06 Take a quiz (4 question types)

## Summary & traceability
- **Task (1 line):** Scaffold a new `Assessment` module and model the quiz primitives — `QuizQuestion` (4 types), `Attempt`, `StudentAnswer` — plus a start-quiz endpoint that creates an `Attempt`.
- **User story:** [user-stories/Phase-2-Learning-Core/P2-06-take-a-quiz.md](../../user-stories/Phase-2-Learning-Core/P2-06-take-a-quiz.md) — *"As a student, I want to take a quiz with multiple question types…"*
- **BE tasks:** [tasks/Backend/Phase-2-Learning-Core/P2-06-BE.md](../../tasks/Backend/Phase-2-Learning-Core/P2-06-BE.md) — BE-1 scaffold, BE-2 entities+migration, BE-3 four types, BE-4 start-attempt endpoint.
- **FR-IDs:** **FR-QZ-1** (support MCQ / True-False / Matching / Fill-in-the-blank). *Out of scope this story:* FR-QZ-2 (instant feedback → P2-07), FR-QZ-4 (granular answer recording + aggregation → P2-08), FR-QZ-3 (adaptive selection → P3-11), AI generation (P3-06).
- **BRD goal:** **G2 (Learning outcomes)** — varied, engaging assessment.
- **Phase / Epic:** Phase 2 — Learning Core · Epic: Assessment Module · SP 5 · Backend-only slice (FE is P2-06-FE, separate stack).
- **Module status:** `Assessment` is **NEW** (architecture.md §16 / SRS §6 list it as not-yet-built). This story creates the 4-project module from scratch.

## Business context & value
- **Who benefits:** the **student (child)** — takes quizzes to test knowledge; downstream the **parent** (progress visibility) and **adaptivity/gamification** engines (which consume Attempt/StudentAnswer signals).
- **Value:** the quiz engine is the central interaction loop of the product. Varied question types keep engagement high (G2) and produce the granular signal that later powers feedback (P2-07), mastery tracking, adaptive difficulty (P3-11) and the behavioral model (FR-AD-5).
- **Success measure (this slice):** a student can start a quiz → an `Attempt` row is created and returned; the three entities persist a quiz session; all four question types are representable and validated. Per-type rendering and instant feedback are measured in other stories.

## Acceptance criteria (testable, this backend slice)
1. The `Assessment` module exists as 4 projects (`Domain`/`Application`/`Infrastructure`/`Api`), added to `Learnexia.Modular.sln`, referenced by the Host, registered via `AddAssessmentModule(configuration)` + `AssessmentModule.InitializeAsync(...)`, mirroring the **Learning** module shape exactly.
2. EF schema is **`assessment`**; a migration creates `QuizQuestion`, `Attempt`, `StudentAnswer` tables in that schema with `MigrationsHistoryTable("__EFMigrationsHistory", "assessment")`.
3. `QuizQuestion` persists: question type, text, options, correct answer, difficulty, generatedBy. All four types (MCQ, True/False, Matching, Fill-in-the-blank) are representable and have per-type validation.
4. `POST /api/Assessment/Quizzes/{id}/Attempt` creates an `Attempt` and returns its identifier (the FE contract: response carries `attemptId`).
5. `Attempt` and `StudentAnswer` are shaped to support P2-07 (correctness, hint used) and P2-08 (time spent, accuracy %, status, completedAt) **without a schema rewrite** — those fields exist now even though they are not yet populated by logic.
6. Question type and difficulty are modeled as **enums stored as int** (`HasConversion<int>`), per the project no-free-text rule (mirror `DifficultyLevel`).
7. Solution builds (`dotnet build backend/Learnexia.Modular.sln`); handler returns the `BaseResponse<T>` envelope; `"Assessment"` is added to `Claims.GenerateModules()`.
8. No cross-module project reference and **no cross-module FK** — `SkillId` / `LessonId` / `StudentId` are plain `int` loose references (mirror how `CreatedBy` is a plain int).

## Affected modules & data
- **New module:** `Assessment` (schema `assessment`). Mirror **Learning** (the freshly-built canonical new-module: `AggregateRoot`, per-module `UnitOfWorkBehavior`, `ApplyConfigurationsFromAssembly`, design-time factory, `InitializeAsync` migrate hook).
- **New entities (all `assessment` schema):**
  - **`QuizQuestion : AggregateRoot`** — `QuestionType` (enum int), `QuestionText` (string), `Options` (serialized — see Open Q), `CorrectAnswer` (serialized/string), `Difficulty` (enum int, reuse a local `DifficultyLevel`), `GeneratedBy` (enum int: e.g. `Curated`/`AI`), `SkillId` (int, loose ref to Learning.Skill).
  - **`Attempt : AggregateRoot`** — `StudentId` (int loose ref), `LessonId` (int loose ref), `Status` (enum int: `InProgress`/`Completed`/`Abandoned`), `AccuracyPercentage` (int, P2-08), `DurationSeconds` (int, P2-08), `HintsUsedCount` (int, P2-08), `CompletedAt` (DateTime?, P2-08), `StartedAt`. One Attempt → many StudentAnswers.
  - **`StudentAnswer : FullAuditedEntity`** (child of the Attempt aggregate — likely not its own AggregateRoot) — `AttemptId` (int, **same-module FK** to Attempt → real FK is fine), `QuestionId` (int, FK to QuizQuestion same-module), `StudentAnswerValue` (string/serialized), `IsCorrect` (bool, P2-07), `TimeSpentSeconds` (int, P2-08), `HintUsed` (bool, P2-07/08).
- **Existing entities touched:** none directly. `Skill`/`Lesson` (Learning) and the student user (Identity) are referenced **by Id only**.
- **Reconciliation:** field set above matches the SRS §6 / architecture proposed ERD (`QuizQuestion{SkillId,QuestionType,QuestionText,Options,CorrectAnswer,Difficulty,GeneratedBy}`, `Attempt{StudentId,LessonId,AccuracyPercentage,DurationSeconds,HintsUsedCount,Status,CompletedAt}`, `StudentAnswer{AttemptId,QuestionId,StudentAnswer,IsCorrect,TimeSpentSeconds,HintUsed}`).

## Handoff → db-migration
- **Schema:** `assessment`. Create `AssessmentDbContext` mirroring [LearningDbContext.cs](../../backend/src/Modules/Learning/Learnexia.Modules.Learning.Infrastructure/Persistence/LearningDbContext.cs): `public const string Schema = "assessment"`, `HasDefaultSchema(Schema)`, `ApplyConfigurationsFromAssembly`, the audit-stamping `SaveChangesAsync(int userId)` override, the `PendingModelChangesWarning` ignore. Add `AssessmentDbContextFactory` (design-time, `UseNpgsql`) and `AssessmentSchema.Name`.
- **DbSets:** `QuizQuestions`, `Attempts`, `StudentAnswers`.
- **Configurations** (`Persistence/Configurations/*`, mirror `SkillConfig`):
  - `QuizQuestionConfig` — `QuestionType`/`Difficulty`/`GeneratedBy` as `.HasConversion<int>()`, required; `Options`/`CorrectAnswer` columns; index on `SkillId` (plain int, **no FK**).
  - `AttemptConfig` — enum `Status` as int; `StudentId`/`LessonId` plain int + index (**no FK**); nullable `CompletedAt`.
  - `StudentAnswerConfig` — `HasOne(Attempt).WithMany().HasForeignKey(AttemptId)` (intra-module FK OK, `DeleteBehavior.Cascade` or `Restrict` — decide with lead); FK to `QuizQuestion` via `QuestionId`.
- **Migration:** name `InitialAssessment`, output to `Infrastructure/Migrations/`, `MigrationsHistoryTable("__EFMigrationsHistory", AssessmentDbContext.Schema)`. Wire `AssessmentModule.InitializeAsync` (MigrateAsync) into Host `Program.cs` startup block. No startup auto-migrate exists for non-Identity modules other than the explicit `InitializeAsync` call — add it next to `LearningModule.InitializeAsync`.
- **DI:** `AddDbContext<AssessmentDbContext>` with `UseNpgsql(GetConnectionString("default"))` + `MigrationsHistoryTable`/`MigrationsAssembly`, mirroring Learning `DependencyInjection.AddDbContext`.

## Handoff → backend-feature
- **Commands/queries (this slice = start-attempt only):**
  - `StartAttemptCommand : ICommand<BaseResponse<string>>` carrying `QuizId` (route `{id}`) and resolving `StudentId` from `ICurrentUserService` (do **not** trust a client-supplied StudentId — see Open Q on auth). Handler mirrors `AddSkillCommandHandler`: inject `IAssessmentServiceManager`, `ILoggerManager`, `IStringLocalizer<SharedResources>`; `try/catch`; return envelope; create the `Attempt` (Status=InProgress, StartedAt=now) and return its Id.
  - Validator `StartAttemptValidation : AbstractValidator<StartAttemptCommand>` (commands are validated by `ValidationBehavior`; queries are not).
- **Endpoint:** `QuizzesController : AppControllerBase`, route `api/Assessment/[controller]`, `POST {id}/Attempt` → `=> NewResult(await Mediator.Send(new StartAttemptCommand{ QuizId = id }));`. Mirror `SkillsController`.
- **Service/repo:** copy Learning Infrastructure `GenericRepository`/`RepositoryManager`/`BaseService`/`ServiceManager`/`CurrentUserService`; define `IAssessmentRepositoryManager`, `IAssessmentServiceManager`, and a typed `IAttemptService : IBaseService<Attempt>` (+ `IQuizQuestionService` if needed).
- **Mapping:** AutoMapper profile `CreateMap<StartAttemptCommand, Attempt>()` and an `AttemptDto`/`StartAttemptResponse` if returning more than the id.
- **DI:** `AddAssessmentApplication` (validators + AutoMapper + `ValidationBehavior`; **do NOT** call `AddMediatR` — Host registers it once) and `AddAssessmentInfrastructure` (DbContext + repos/services + `ICurrentUserService` + `ILoggerManager` + register `UnitOfWorkBehavior<,>` **after** ValidationBehavior). Mirror Learning's two `DependencyInjection.cs`.
- **`AssessmentModule.cs`:** `AddAssessmentModule` → `AddAssessmentApplication()` + `AddAssessmentInfrastructure(config)` + `AddControllers().AddApplicationPart(typeof(QuizzesController).Assembly)`; `MapAssessmentModule` passthrough; `InitializeAsync` migrate hook. Mirror `LearningModule.cs`.
- **Per-type validation (BE-3):** validate the answer/options shape per `QuestionType` (e.g. MCQ needs ≥2 options + a correct index; True/False has fixed 2 options; Matching needs paired left/right; Fill-in-the-blank needs expected token(s)). Recommend a small per-type validation helper invoked from the QuizQuestion validator — **not** a Strategy/Factory pattern unless the lead approves (CLAUDE.md rule 8: ask first).
- **Contract for FE (P2-06-FE):** question payload includes `type` + type-specific `options`; start-attempt returns `attemptId`.

## Handoff → frontend

## Open questions / assumptions / risks
1. **(KEY — needs lead decision) How to model the 4 question types?**
   - *Option A (recommended):* a **single `QuizQuestion` entity** with a `QuestionType` enum discriminator + `Options` and `CorrectAnswer` stored as **serialized JSON strings** (Npgsql `jsonb` or plain text). This matches the SRS/architecture ERD verbatim (`string Options`, `string CorrectAnswer`), is the simplest, keeps one table, and is consistent with Catalog/Learning (no inheritance used anywhere yet). Per-type shape is enforced in the validator, not the schema.
   - *Option B:* TPH inheritance (`McqQuestion`/`TrueFalseQuestion`/… : `QuizQuestion`) with EF discriminator. More type-safe but introduces an inheritance hierarchy + per-type configs — a design-pattern-ish choice the codebase has not used. **Per CLAUDE.md rule 8, do not introduce this without lead approval.**
   - **Recommendation:** go with **Option A** (single entity + enum + serialized options) unless the lead wants strong typing now. Decision affects the migration and validators, so resolve before db-migration runs.
2. **Is there a Quiz aggregate, or are questions grouped by Lesson/Skill id?** The endpoint is `Quizzes/{id}/Attempt` but no `Quiz` entity is in scope (BE-2 lists only QuizQuestion/Attempt/StudentAnswer). The ERD ties `QuizQuestion → SkillId` and `Attempt → LessonId`. **Question for lead:** does `{id}` mean a **LessonId** (a "quiz" = the question set for a lesson) or a **SkillId**, or do we need a thin `Quiz` entity? Recommend treating `{id}` as **LessonId** and persisting it on `Attempt.LessonId` (no Quiz table yet) — but confirm, because the route noun "Quizzes" implies a quiz resource the model doesn't have.
3. **How is `StudentId` resolved?** Assumption: from the authenticated child's JWT via `ICurrentUserService.UserId` (parent-driven onboarding means the child has their own identity/session). Confirm the child auth model is in place by P2-06 and that the endpoint should be `[Authorize]`. Do not accept a client-supplied StudentId.
4. **`Options`/`CorrectAnswer` storage type:** plain `text` vs Npgsql `jsonb`. Recommend `jsonb` for queryability later, but plain string matches the ERD and is simpler. Lead to confirm.
5. **`StudentAnswer` ownership:** modeled as a child of the `Attempt` aggregate (not its own AggregateRoot) — created/written via the Attempt in P2-08. Confirm; affects whether it raises its own domain events.
6. **Fetching questions for a quiz** (read endpoint) is not in BE-2..BE-4. The FE will need a list-questions endpoint eventually — flag whether it belongs here or in P2-07. Assumption: out of scope for P2-06 backend.
7. **`GeneratedBy` enum values:** assume `{ Curated = 1, AI = 2 }` (AI generation lands in P3-06). Confirm naming.
8. **Risk — shared-file edits:** this story edits `Program.cs`, `Learnexia.Modular.sln`, `Claims.cs`, and the Host csproj. Per PARALLELISM.md these are serialized — coordinate if other Phase-2 stories run concurrently.
