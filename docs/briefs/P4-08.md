## Business context & value

- **Who benefits:** the **student** directly. The Phase-3 engines (P4-02..P4-07) all silently update DB rows when the player wins; with P4-08 the player *sees* the win — a Reward overlay pops with confetti, the XP bar fills with a satisfying animation, a fresh badge slides into the collection, the league promotion shows a tier badge upgrade. Without P4-08, every Phase-3 system is invisible — engines exist but the dopamine loop is muted. This is the story that *sells* Phase 3.
- **Why it matters now:** P4-02..P4-07 each landed minimal "one-row dashboard wire" frontend slips — XP value flips from `0` to a real number, hearts pill shows up, streak flame shows the count, league row shows tier + rank. None of those changes celebrate anything. The story explicitly says *"satisfying reward, badge, league, and mission screens with delightful motion, so that earning progress feels exciting and keeps me coming back"* — this is the engagement payoff for the whole phase. P4-09 (re-engagement notifications) and P4-10 (Redis realtime) downstream both rely on the celebration surface existing.
- **Success measurement (per AC):**
  - **AC1 — Screens exist:** Five dedicated screens / overlays render with real BE data (Reward overlay, Badges screen, League screen, Missions screen, Hearts/Practice-Mode screen or overlay) and pass an EN + AR visual review.
  - **AC2 — Motion specs implemented:** XP bar fills smoothly on diff, Badge disc pops in on first-earn, confetti fires on level-up + badge unlock + mission complete, QuestionCard shakes on a wrong answer, StreakFlame pulses continuously + ignites on streak-advance.
  - **AC3 — Kid-accessibility / mobile-smooth:** Every animation runs on the UI thread (Reanimated worklets or Skia canvas — never JS-thread layout) and respects `AccessibilityInfo.isReduceMotionEnabled()`. Touch targets ≥ 44 px. No flash > 3 Hz. Live-region announces on reward events.
  - **AC4 — RTL + EN/AR:** Every new screen renders correctly in `dir=rtl` with logical positioning (`borderStartWidth`, `flexDirection: row-reverse`) and every new copy slot is keyed in both `en` and `ar` resources.
- **Deterministic principle:** all transitions are client-side diff-driven (cached dashboard snapshot vs new value). No randomness in the celebration logic itself; the *content* of celebration (which badge, which mission, which tier) is the BE's authoritative state.

1. **AC1 — Screens exist for: Reward, Badge collection, League, Missions, and Hearts/Practice mode.**
   - FE gate per task ID:
     - **FE-1 Reward screen** — overlay route at `apps/student-app/app/(child)/reward.tsx` OR a screen-level `RewardOverlay` mounted on the dashboard / lesson player. Consumes XP delta + level delta from prior cached dashboard. Mounts `RewardPopup` (already in `@learnexia/ui`). Closes on CTA tap. Auto-dismiss after 5 s if user idle.
     - **FE-2 Badge collection screen** — route at `apps/student-app/app/(child)/badges.tsx`. Grid of 10 badge discs (3 cols × 3-4 rows on phone). Each badge: `Badge` variant (mapped from `BadgeDefinition.Rarity` → bronze/silver/gold/legendary, locked → `locked`), label = localized title, sub-label = AwardedAtUtc date or "Locked". Tap a badge → detail bottom-sheet with description + criteria. **First-render**: a "Newly Earned" disc (`isNewlyEarned` prop) fires pop-in for the most recent badge from `recentBadges`.
     - **FE-3 League screen** — route at `apps/student-app/app/(child)/league.tsx`. Top: tier medal + week-ends-at countdown. List: top-30 rows with `Rank`, `Student #N` display, weekly XP, current-student row highlighted (`$primarySoft` background). Promotion cutline (rank 7) and demotion cutline (rank 26) shown as inline divider rows with copy ("Promotion zone" / "Stay zone" / "Demotion zone"). Tier-tier transitions shown as `Bronze → Silver → Gold → Diamond` ladder pill.
     - **FE-4 Missions screen** — route at `apps/student-app/app/(child)/missions.tsx`. Two sections: Daily (5 mission cards) + Weekly (1 mission card). Each card is `MissionBanner` reused (or a new `MissionCard` if the design diverges — see Open Q1.4). Progress bar per mission. Completed missions render `Completed ✓` pill + dimmed.
     - **FE-5 Hearts / Practice-Mode screen** — recommend an **overlay banner**, not a dedicated route (Practice Mode is a *modal state*, not a destination). When `dashboardQuery.data.inPracticeMode === true`, the dashboard renders a full-width `PracticeModeBanner` between header + ContinueCard. When the user enters a lesson in Practice Mode, the lesson player renders a top banner reminding them "Practice Mode — no XP, no streak; lessons still attemptable." **Hearts depletion modal** (the moment hearts hit 0) is a one-time bottom-sheet on the dashboard mount after diff detects the 1→0 transition.

2. **AC2 — Motion specs are implemented: XP fill, badge pop-in, confetti, shake on wrong answer, animated flame.**
   - FE gate per motion:
     - **XP fill** — `XPBar animated` prop driven by mount + value diff. Spec: Moti timing `duration: durations.slow (640ms)`, fill grows from `0%` to target on mount; on subsequent value change, animate from prior cached pct → new pct.
     - **Badge pop-in** — `Badge isNewlyEarned` prop. Spec: Moti spring `springs.pop (damping 10, stiffness 200)` `from={{ scale: 0, opacity: 0 }} animate={{ scale: 1, opacity: 1 }}`.
     - **Confetti** — `ConfettiLayer` real Skia particle system: 40–60 particles, gravity-driven, ~2 s lifetime. Token-derived `CONFETTI_COLORS` palette already defined.
     - **Shake on wrong answer** — `QuestionCard` host. Spec: Reanimated `withSequence(withTiming(-8, 60), withTiming(8, 60), withTiming(-4, 60), withTiming(0, 60))` on `translateX`. Triggered when `submitAnswer.data.isCorrect === false`.
     - **Animated flame** — `StreakFlame` continuous pulse + a one-shot "ignite" scale-bump on streak-advance detection (current pct vs cached pct in dashboard).
     - **Heart shatter** — added implicitly under "shake" + as the FE-5 task spec. Reanimated `withSequence(withSpring(1.3), withTiming(0, 200))` + opacity fade on the just-lost heart.
   - All animations respect `AccessibilityInfo.isReduceMotionEnabled()` — when true: fades only, no translates, no scale, no confetti.

3. **AC3 — Animations respect kid-accessibility (clear visual feedback on every action) and perform smoothly on mobile.**
   - FE gate:
     - Every motion runs on the **UI thread** — Reanimated `useSharedValue` + `useAnimatedStyle`, or Moti (which wraps Reanimated), or Skia canvas. Zero `setState`-driven animation loops.
     - Reduce-motion: `useReducedMotion()` hook (Reanimated already exports one) returns true → all animations collapse to instantaneous state changes with fade-only.
     - Live regions: RewardPopup is `accessibilityRole="alert" + accessibilityLiveRegion="assertive"`. Mission complete + level up announce via the same.
     - Touch targets: all interactive surfaces ≥ 44 px (existing `Button`, `MissionBanner`, `Badge` already comply).
     - No flashing > 3 Hz (StreakFlame pulse is `durations.slow = 640 ms` = 0.78 Hz; well below; confetti particles have no global flash).
     - **Performance smoke** — mount the Missions screen + 8 mission cards + scroll on a mid-tier Android (Pixel 4a or equivalent) and verify 60 fps (or the reviewer accepts a 50+ fps degradation; flag if any animation drops to 30 fps).

4. **AC4 — Screens render in Arabic (RTL) and English.**
   - FE gate:
     - Every new screen sets `dir = directionForLocale(locale)`, uses `flexDirection: row-reverse` for row layouts in RTL, uses `borderStartWidth` / `paddingStart` / `marginEnd` instead of physical L/R props.
     - Every new copy slot keyed in both `en` and `ar` under `child.gamification.*` namespace.
     - Numerals: Arabic locale renders Eastern-Arabic numerals where the W13 dashboard does (per `@learnexia/shared/i18n` precedent). Verify on rank, XP, mission progress.
     - Sign-direction of progress bars: per W13 design spec §3.3 (MissionBanner), progress bars are ALWAYS wrapped in `dir="ltr"` (brand law — progress reads L→R) even in RTL. P4-08 must inherit this.
     - Visual review against `design-system/screenshots/mobile-ar/13-reward.png`, `14-mission-completed.png`, `15-daily-mission.png`, `16-league.png`, `17-badges.png`, `18-hearts.png`.
