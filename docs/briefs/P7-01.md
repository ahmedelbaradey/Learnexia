# Pipeline Brief — P7-01 Manage subjects & units (Backend)

> Analyzer brief, 2026-06-08. Backend-only slice of the Phase-7 Admin Console **Curriculum wave**. Grounded in `docs/briefs/phase-7-admin-gap-analysis.md` (PR #85), the `docs/dev/HANDOFF.md` "P7 — gap analysis + modular spec refit" + Phase-8 localization sections, and a fresh read of the live `Learning` source tree. **Do not re-open the locked decisions** (module placement, AdminOnly policy, bilingual `(SubjectCode, Language)` model, separate auth hotfix) — they are settled.

## Summary & traceability
- **Task (one line):** Add admin curation of the top two curriculum levels — **subject + unit reorder, activate/deactivate (soft state), the missing `SequenceOrder`/`IsActive` columns, the "unit not empty" delete guard, graceful duplicate-tree rejection, and a per-grade language-coverage report** — on top of the existing (already AdminOnly-gated) Subjects/Units CRUD in the `Learning` module, honoring the bilingual `(SubjectCode, Language)` parallel-tree model.
- **User story:** `user-stories/Phase-7-Admin-Console/P7-01-manage-subjects-and-units.md` (SP 5).
- **BE task file:** `tasks/Backend/Phase-7-Admin-Console/P7-01-BE.md` (BE-1..BE-8).
- **FR / SRS:** FR-ADM-1 (admin curriculum management), SRS §3 (Admin role). BRD goal: **G3 — curriculum quality / operational scalability** (admins curate without dev seed scripts).
- **Phase/epic:** Phase 7 — Admin Console · Epic *Admin — Curriculum Management*. Post-MVP.
- **Module:** `Learning` (locked — no new module). Mirror existing Learning command/query/controller shapes.

## Business context & value
- **Who benefits:** the **admin** (curriculum operator) directly; **students** indirectly (correctly ordered, vetted, language-correct trees; inactive items hidden but not lost).
- **Value:** removes the developer-in-the-loop for top-of-tree curation. Today subjects/units are seeded by `LearningSeeder` (6 language-tagged roots per grade, P8-02). FR-ADM-1 makes that an admin self-service surface.
- **Success measure:** an admin can list all 6 roots per grade distinguishably (code + language), reorder within one language tree, soft-deactivate, see coverage gaps, and is blocked from creating a duplicate/5th tree or deleting a non-empty unit — all admin-only.

## Acceptance criteria (testable)
1. `GET` subjects returns each root with **`SubjectCode` (MATH/SCIENCE/ARABIC/ENGLISH)**, **`Language` (Ar/En)**, grade, `SequenceOrder`, `IsActive` — all 6 roots per grade visible and distinguishable. *(Today `SubjectDto` exposes only Name/Country/GradeId — code/language/order/active are net-new on the DTO.)*
2. Per-grade **language-coverage** read reports which `(SubjectCode, Language)` trees exist vs the expected 6 and flags gaps (e.g. `ar` Science present, `en` Science missing).
3. Create/edit a unit persists title + `SequenceOrder` **scoped to its `(SubjectCode, Language)` tree** (ordering not shared across the two language trees of one code).
4. Reorder subject or unit saves the new `SequenceOrder` **within that language tree only**; reflected on reload. Batch reorder is atomic (explicit transaction).
5. Toggle active/inactive sets soft `IsActive`; inactive rows are **hidden from student-facing reads but preserved**; scoped to the language tree. Delete on Subject/Unit performs deactivate-instead-of-delete per the story.
6. Create/Update that would duplicate an existing `(GradeId, SubjectCode, Language)` tree, or introduce a 5th `SubjectCode`, is **rejected gracefully** with `Successed=false` + clear message (catch the existing unique-index violation; validate code against the 4 fixed values).
7. Delete of a unit that still has lessons → rejected with a clear **"unit not empty"** `Successed=false` error.
8. All mutations admin-only (`AuthorizationPolicies.AdminOnly`); non-admin → 403.

## Affected modules & data (new vs existing)
**Module:** `Learning` only. Schema: `learning`.

**Existing (verified in source — do NOT re-create):**
- `Subject` entity (`Domain/Entities/Subject.cs`): `Name`, `Country`, `SubjectCode`, `Language`, `GradeId`, `Units`, `Concepts`. **Has the P8-02 unique index `(GradeId, SubjectCode, Language)`** (`SubjectConfig.cs`).
- `Unit` entity: `Name`, **`SequenceOrder` (already present)**, `SubjectId`, `Lessons`.
- `SubjectsController` + `UnitsController` Create/Update/Delete — **already `[Authorize(Policy = AdminOnly)]`** (the "live auth hole" hotfix has effectively landed for these; read endpoints `[Authorize]` for students). So the task file's BE-1/BE-2 "apply AdminOnly" is largely **already done** — verify and keep, don't duplicate.
- Full Add/Edit/Delete command+handler+validator stacks for Subjects and Units; `SubjectLanguageResolver`, `ContentLanguage`/`SubjectCode` enums (Domain).

**Net-new (this story):**
- **Columns:** `Subject.SequenceOrder` (int), `Subject.IsActive` (bool, default true), `Unit.IsActive` (bool, default true). `Unit.SequenceOrder` already exists. → **one EF migration.**
- **DTO fields:** expose `SubjectCode`, `Language`, `SequenceOrder`, `IsActive` on `SubjectDto`/`UnitDto` (currently absent).
- **Reorder** command/handler for Subjects and Units (batch `SequenceOrder`, explicit transaction).
- **Activate/deactivate** command/handler; read-side filter to exclude inactive rows from student reads; redefine Delete as soft-deactivate.
- **"Unit not empty" guard** in the Unit delete handler/validator.
- **Language-coverage** query `GetSubjectLanguageCoverage(gradeId)` (AdminOnly, read-only).
- Graceful duplicate-`(GradeId,SubjectCode,Language)` handling on Create/Update (catch unique violation → `Successed=false`), and validator rejecting unknown/5th `SubjectCode`.

## Handoff → db-migration
- New Npgsql migration (mirror `20260523190052_InitialLearning` shape; schema `learning`): add `Subject.SequenceOrder int NOT NULL DEFAULT 0`, `Subject.IsActive boolean NOT NULL DEFAULT true`, `Unit.IsActive boolean NOT NULL DEFAULT true`.
- Update EF configs: `SubjectConfig` (add the two props; optional index `(GradeId, SequenceOrder)` mirroring Unit's `(SubjectId, SequenceOrder)`), and the Unit config (`IsActive`). Do **not** touch the existing unique `(GradeId, SubjectCode, Language)` index.
- Non-destructive (defaults backfill existing rows). No data wipe (unlike the P8-02 re-seed).

## Handoff → backend-feature
- **Commands (new):** `ReorderSubjectsCommand`, `ReorderUnitsCommand` (ordered id list → batch `SequenceOrder` in an explicit transaction — the platform rule is **no Unit of Work**, open a transaction for multi-write); `SetSubjectActiveCommand`, `SetUnitActiveCommand` (toggle `IsActive`). Redefine `DeleteSubjectCommand`/`DeleteUnitCommand` handlers to soft-deactivate per story (confirm with lead — see open question).
- **Validators:** Unit delete guard ("has lessons" → `Successed=false`); Add/Edit Subject validator rejects unknown `SubjectCode` and surfaces a clean duplicate-tree error (wrap the unique-index `DbUpdateException`). Validation runs for `ICommand<>` only.
- **Queries (new):** `GetSubjectLanguageCoverageQuery(gradeId)` → which `(SubjectCode, Language)` of the 6 exist/missing, AdminOnly.
- **DTOs:** extend `SubjectDto`/`UnitDto` with `subjectCode`, `language`, `sequenceOrder`, `isActive`. Reuse `SubjectLanguageResolver` rather than re-deriving language.
- **Read-side filter:** student-facing subject/unit reads exclude `IsActive == false`. Admin reads include inactive.
- **Conventions:** `BaseResponse<T>` via `BaseResponseHandler`; controller `NewResult(...)`; success flag spelled `Successed`; inject `ILoggerManager`.
- **Cross-module/event seam:** each admin mutation handler should publish a `Shared.Contracts` **`AdminActionPerformedEvent`** so the future P7-12 audit log can consume it. **⚠️ This event type does NOT yet exist in `Shared.Contracts`** (verified — PR #86 was a docs-only spec refit; no contract was added to source). The wave's **first** story to need it (P7-01) should introduce the contract type, or the lead should decide to defer event-emission until the P7-12/Moderation wave. **See open question.**
- **Policy:** `AuthorizationPolicies.AdminOnly` (single existing policy; granular per-area policies deferred).

## Open questions / assumptions / risks
- **Q1 (delete semantics):** The story says "delete = deactivate (soft state, not deleted)" but the existing `DeleteSubjectCommand`/`DeleteUnitCommand` hard-delete. Confirm: should `DELETE` map to soft-deactivate (story's intent), or keep hard-delete for empty items and only block non-empty units? **Assumption:** Unit delete = hard-delete only when empty (BE-6 guard) + a separate soft `IsActive` toggle; Subject delete = soft-deactivate. Flag for lead.
- **Q2 (AdminActionPerformedEvent ownership):** the contract is not in source. Either P7-01 introduces `Shared.Contracts.Admin.AdminActionPerformedEvent` (a shared-file edit → serialize per PARALLELISM.md) and emits it, or event-emission is deferred to the P7-12 wave and P7-01 ships without it. **Recommendation:** introduce the contract now (small, additive) so P7-02..P7-05 can emit consistently; lead to confirm.
- **Assumption:** BE-1/BE-2 "apply AdminOnly" is already satisfied on `SubjectsController`/`UnitsController` (verified in source) — the real work is BE-3..BE-8. No re-gating needed; just confirm during review.
- **Risk:** the reorder/active/coverage handlers must respect the language-tree scope (filter by the owning Subject's `Language`) — getting this wrong leaks ordering/active state across the Ar/En sibling trees. Cover with tests asserting Ar-tree reorder doesn't touch the En tree.

## Recommended pipeline order (first cut — planner finalizes)
1. **db-migration** (Subject `SequenceOrder`/`IsActive`, Unit `IsActive`) — gating; everything else depends on the columns.
2. **backend-feature** — DTO extensions, reorder/active commands, coverage query, unit-not-empty guard, duplicate-tree handling, read-side active filter, (optionally) `AdminActionPerformedEvent` emission. Single batch (cohesive).
3. **api-tester** — integration tests over the running API (reorder scoping per language tree, soft-deactivate hides from student reads, duplicate-tree → `Successed=false`, unit-not-empty → `Successed=false`, AdminOnly 403 for non-admin).
4. **security-auditor** — authz surface (admin-write curriculum); confirm AdminOnly on all new mutations, no IDOR on reorder/coverage. Required because this is an admin-write/role-gated surface.
5. **reviewer** — gate against the AC above + CONVENTIONS.md.
