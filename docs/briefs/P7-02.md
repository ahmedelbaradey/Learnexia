## Business context & value
- **Who benefits:** **admin** authors structured lesson material directly; **students** receive curated, ordered, language-correct lesson content rather than hand-seeded `Explanation`/`Visual` strings.
- **Value:** the lesson is the unit of student consumption (P2-05 lesson player). Today lessons carry only seeded `Explanation` (Markdown) + `Visual` (single asset key). This story makes a lesson an **ordered list of typed content blocks** (text/image/video/callout) editable in the console.
- **Success measure:** an admin creates/edits a lesson with metadata, adds/reorders/removes content blocks, deletes a lesson (blocks handled atomically), and never sets language on a lesson (it is inherited from the owning Subject tree).

## Acceptance criteria (testable)
1. Create/edit a lesson persists title, difficulty, estimated time, `SequenceOrder`, lock state, scoped to its unit.
2. A lesson's `Language` is **inherited from the owning Subject tree** (Unit → Subject) and is **not editable on the lesson** — read DTOs surface the *resolved* language; there is **no language column** on Lesson/ContentBlock.
3. Add content blocks with a type (text/image/video/callout), payload, and ordering within the lesson; payload validated **per type**.
4. Reorder or remove a content block saves the new order/removal; reflected on reload. Batch reorder is atomic (explicit transaction).
5. Reorder lessons within a unit updates each lesson's `SequenceOrder` (atomic).
6. Delete a lesson removes/soft-deactivates it and **handles its content blocks atomically** (explicit transaction); no longer served to students.
7. Create/Update validators reject placing a lesson under a unit/subject tree that doesn't resolve to a single valid language (orphan/cross-tree placement → `Successed=false`).
8. Media payloads (image/video/file) are stored via `Shared.Kernel.Storage.IStorageService` — **no module-local MinIO**.
9. All mutations admin-only (`AdminOnly`); non-admin → 403.

## Affected modules & data (new vs existing)
**Module:** `Learning` only. Schema: `learning`.

**Existing (verified — do NOT re-create):**
- `Lesson` entity: `Name`, `Difficulty` (`DifficultyLevel`), `SequenceOrder`, `IsLocked`, `UnitId`, `SkillId?`, `Explanation?` (Markdown), `Visual?` (asset key/url), `IsBoss`. Index `(UnitId, SequenceOrder)` exists.
- `LessonsController` Create/Update/Delete — **already `[Authorize(AdminOnly)]`** (verified); reads `[Authorize]`. So BE-1's "apply AdminOnly" is already satisfied — verify, don't duplicate.
- Full Add/Edit/Delete + list/get stacks for Lessons; `SubjectLanguageResolver`.

**Net-new (this story):**
- **`ContentBlock` entity** — FK→Lesson (within-module, real FK fine), `Type` (enum: Text/Image/Video/Callout), `Payload` (**jsonb**, Npgsql), `SequenceOrder`; derive from `FullAuditedEntity` (match how other Learning entities derive from `AggregateRoot`). Net-new table + EF config + migration.
- **Lesson metadata extension** — `EstimatedMinutes` (int) is net-new; `Difficulty`/`SequenceOrder`/`IsLocked` already exist (map "lockState" → existing `IsLocked`). Add `IsActive`/soft-delete if delete = soft-deactivate (mirror the P7-01 decision). → migration.
- **ContentBlock CRUD** (`Application/ContentBlocks/*`) with per-type payload validators (text/image/video/callout shape) — analogous to the `QuizQuestionTypeValidation` static-helper pattern (no design pattern).
- **Reorder** content blocks within a lesson + lessons within a unit (batch `SequenceOrder`, explicit transaction).
- **Atomic delete** lesson + its content blocks (explicit transaction).
- **Language-inheritance validators** on lesson/content placement (resolve via `SubjectLanguageResolver`); read DTOs surface resolved language (read-only, not stored).

## Handoff → db-migration
- New Npgsql migration (schema `learning`): create `ContentBlocks` table — `Id` PK, `LessonId` FK (`DeleteBehavior.Cascade` or handled-in-handler per the atomic-delete decision), `Type int NOT NULL`, `Payload jsonb NOT NULL`, `SequenceOrder int NOT NULL`, audit columns; index `(LessonId, SequenceOrder)` mirroring the Lesson/Unit ordering index.
- Add `Lesson.EstimatedMinutes int NOT NULL DEFAULT 0` (and `Lesson.IsActive boolean NOT NULL DEFAULT true` if soft-delete is chosen).
- Reuse `LearningSchema.Name`. Non-destructive.

## Handoff → backend-feature
- **Entity:** `ContentBlock` + `ContentBlockType` enum (Domain), EF config (Infrastructure/Persistence/Configurations), jsonb mapping for `Payload`.
- **Commands:** `AddContentBlockCommand`, `EditContentBlockCommand`, `DeleteContentBlockCommand`, `ReorderContentBlocksCommand` (batch, explicit transaction), `ReorderLessonsCommand` (batch, explicit transaction). Extend `AddLessonCommand`/`EditLessonCommand` with `EstimatedMinutes`.
- **Validators:** per-type payload shape (text/image/video/callout); lesson/content placement resolves to a single valid Subject language tree (`SubjectLanguageResolver`) else `Successed=false`.
- **Delete:** lesson delete handler removes/deactivates lesson and its blocks in **one explicit transaction** (no Unit of Work).
- **Storage:** inject `Shared.Kernel.Abstractions.Storage.IStorageService` for media payloads; store the returned key/url in the block payload. **Do not register MinIO at module level** (registered once at Host per P1-12 BE-4).
- **DTOs:** `ContentBlockDto` (id, type, payload, sequenceOrder); extend `LessonDto` with `difficulty`, `estimatedMinutes`, `sequenceOrder`, `isLocked`, resolved `language`.
- **Event seam:** publish `AdminActionPerformedEvent` from each mutation handler for the future P7-12 audit log. **⚠️ The contract is not yet in `Shared.Contracts`** — depends on the P7-01 decision (introduce it in P7-01, reuse here). If P7-01 defers, P7-02 also defers.
- **Conventions:** `BaseResponse<T>`, `NewResult(...)`, `Successed`, `ILoggerManager`. `AdminOnly` policy.

## Handoff → frontend
Out of scope this run. FE contract (`P7-02-FE`) per task file: `GET /api/Learning/Units/{unitId}/Lessons`, `GET /api/Learning/Lessons/{id}/ContentBlocks`, `POST/PUT/DELETE` Lessons + ContentBlocks, `PUT .../ContentBlocks/Reorder`, `PUT .../Lessons/Reorder`. Admin-only.

## Open questions / assumptions / risks
- **Q1 (block type set):** the gap analysis (§2 P7-02) flags that `text/image/video/callout` was never reconciled against the P2-05 Lesson Renderer. **Risk:** admin-authorable block types diverge from what the student lesson player can render. **Recommend** the lead confirm the canonical block-type set against P2-05 before validators are frozen. Assumption for now: the 4 types in the story.
- **Q2 (delete semantics):** same soft-delete vs hard-delete question as P7-01 — keep consistent. Assumption: hard-delete lesson + cascade/handle blocks atomically, with an optional `IsActive` toggle for "hidden but preserved."
- **Q3 (legacy `Explanation`/`Visual`):** the existing `Lesson.Explanation`/`Visual` fields and the new `ContentBlock` model overlap. Confirm whether ContentBlocks **replace** or **coexist** with `Explanation`/`Visual` (and whether P2-05 reads which). Assumption: coexist for now; ContentBlocks are additive. Flag for lead.
- **Risk:** jsonb payload is unvalidated at the DB layer (per-type shape enforced only in FluentValidation, matching the `QuizQuestion` precedent) — ensure validators are thorough and unit-tested.
- **Dependency:** depends on **P7-01** (unit/subject reorder + active patterns + language-tree scoping). Sequence after P7-01.
