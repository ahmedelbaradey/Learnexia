## ⚠️ Load-bearing finding — shipped backend ≠ task-file contract

The task file (`P7-12-FE.md` §"Contract from Backend") was written against the **planned** BE contract, which the shipped backend does **not** match. **Trust the merged controller/query/DTO, not the task file.** Three divergences the planner/frontend must absorb:

1. **Route.** Shipped controller is `[Route("api/Admin/Audit")]` → `GET api/Admin/Audit/Log` (the task says `/api/Audit/Log`). Use **`/api/Admin/Audit/Log`** — consistent with the other admin hooks (`/api/Admin/Users`).
   - Source: `backend/src/Modules/Moderation/Learnexia.Modules.Moderation.Api/Controllers/AuditController.cs`.
2. **No export endpoint.** The shipped `AuditController` exposes **only** `GET Log`. There is **no `GET Log/Export`** (CSV/JSON) endpoint. **FE-4 (export button) is NOT buildable** against the current backend → see Open Question OQ1. Story AC "Admins can export the filtered log (CSV/JSON)" is currently **unsatisfiable on the FE without a backend addition** — flag, do not fake it with a client-side CSV dump of one page (that would silently export only the visible page and leak the impression of a full export).
3. **DTO shape — single `details`, not `before`/`after`.** The shipped `AuditLogDto` (`…/Features/AuditLog/Dtos/AuditLogDto.cs`) is:
   ```
   AuditLogDto(int Id, Guid EventId, int AdminUserId, string Action,
               string TargetEntityType, int TargetEntityId, string? Details,
               DateTime OccurredAtUtc, DateTime CreatedAt)
   ```
   There are **no `before`/`after`/`beforeJson`/`afterJson` fields** — accountability detail is the single PII-safe `Details` string (ids + enum/state values). The "before/after snapshot" of the story is satisfied by `Details`. FE-3's "diff/JSON viewer" must degrade to a **read-only `Details` panel** (it may pretty-print if `Details` happens to be JSON, but must not assume a two-sided diff).

## Business context & value

- **Who benefits:** Admins (accountability + compliance review of who-did-what-when), the platform owner (G2 governance/regulatory defensibility for a child-data product), indirectly parents/children (privileged actions on their accounts are now visibly traceable).
- **Value:** A queryable, view-only window onto the immutable system-of-record for every admin mutation across modules — moderation decisions, curriculum publishing, account lifecycle, child grade/learning-language overrides, and gamification overrides (P7-13). Required for investigating misuse of admin power and for compliance evidence (NFR-4).
- **Success measure:** An admin can land on `/audit`, filter by acting admin / action type / target entity type / date range, page through results, open any entry to read its PII-safe details, and never see (or be able to invoke) an edit/delete affordance. Non-admins cannot reach the page.

## Acceptance criteria (testable, FE)

1. `/audit` renders inside `AdminShell` (self-wrap per page, like `users/page.tsx`) behind `useAdminGuard`; an unauthenticated/non-admin user is redirected/blocked (no flash of audit data). [story AC5; FE-5]
2. A new **active-aware nav item** ("Audit log") appears in `AdminSideNav` and highlights for `/audit` and `/audit/*`. [FE-5]
3. The page shows a **paginated, read-only table** with columns: acting admin (admin user id), action type, target (entity type + id), and timestamp (`OccurredAtUtc`). Newest-first (backend already orders this way). [story AC3; FE-2]
4. **Filters** map exactly to the shipped query params: acting admin id (`AdminUserId`, int), action type (`ActionType`, string — surfaced as a dropdown from the known `AdminActions` vocabulary), target entity type (`TargetEntityType`, string/dropdown), and a date range (`DateFrom`/`DateTo`). Changing any filter resets to page 1. All filtering is server-side. [story AC3; FE-2]
5. The four canonical list states are implemented exactly like the Wave-1 pattern: **loading skeleton / empty / error+retry / results**, with `placeholderData: keepPreviousData` so rows stay visible during refetch, plus `aria-live` announcements. [FE-2; CONVENTIONS reuse]
6. Each row can be **expanded / opened to a detail view** showing the full entry: `EventId`, `AdminUserId`, `Action`, `TargetEntityType`, `TargetEntityId`, `OccurredAtUtc`, `CreatedAt`, and the PII-safe **`Details`** panel (pretty-printed if JSON, plain text otherwise). **Read-only** — no edit/save/delete controls anywhere. [story AC2, AC6; FE-3]
7. The **action-type filter/legend includes the newer admin actions** with localized labels — child **learning-language change** (`Child.LearningLanguageChanged`), **child grade override** (`Child.GradeOverridden`), and the P7-13 **gamification overrides** (`Gamification.LeagueTierOverridden`, `Gamification.StreakFreezeGranted`, badge/mission/timed-event create/update/activate/deactivate). [story AC1; FE-2/FE-6]
8. **No write affordances exist anywhere** on the surface (no edit/delete/restore buttons, no mutating hook). The viewer is strictly read-only. [story AC2; FE-3/FE-5]
9. Full **EN + AR** copy via `lib/strings.ts` for columns, action-type labels, target-type labels, filter labels, states, and the detail panel; **RTL-correct** layout (logical props, `dir="ltr"` islands for ids/timestamps/`EventId`). [story AC7; FE-6]
10. **A11y:** table has `<caption>`/`scope="col"` headers, the result region is `aria-live`, the detail open/close is keyboard-operable, filters have labels. (Mirror `users/page.tsx`.)
11. **PII safety:** the UI renders only what the API returns (ids + enum/state values) and never enriches rows with names/emails by joining to user data. (Covered free by reusing the read-only DTO.) [story AC7]
12. **Export (FE-4):** blocked pending a backend export endpoint — see OQ1. If the lead adds the endpoint, wire an `ExportLogButton` to it; otherwise omit the control and record the story-AC gap. **Do not** ship a client-side single-page CSV pretending to be a full export.

## Exact backend contract (authoritative — from merged source)

- **Endpoint:** `GET /api/Admin/Audit/Log` — `[Authorize(Policy = AdminOnly)]`, read-only, DB-side filter+page, newest-first.
- **Query params** (PascalCase binding on `GetAuditLogQuery`):
  | Param | Type | Notes |
  |---|---|---|
  | `AdminUserId` | int? | filter by acting admin |
  | `ActionType` | string? | e.g. `"Subject.Created"` — match `AdminActions.*` constants |
  | `TargetEntityType` | string? | e.g. `"Subject"`, `"User"`, `"Child"` |
  | `DateFrom` | DateTime? (ISO) | inclusive lower bound on `OccurredAtUtc` |
  | `DateTo` | DateTime? (ISO) | inclusive upper bound on `OccurredAtUtc` |
  | `PageNumber` | int (default 1) | 1-based |
  | `PageSize` | int (default 20) | backend clamps **1–100** — enforce ≤100 on FE like `useSearchUsers` |
- **Response:** `BaseResponse<PaginatedResult<AuditLogDto>>`. `getPaginated<AuditLogDto>(...)` unwraps to `PaginatedResult<AuditLogDto>` (`{ data, totalCount, totalPages, pageNumber, pageSize }`) — same shape `useSearchUsers` consumes. Empty result returns a **success** envelope with empty `data` → render the empty state, not an error.
- **`AuditLogDto`** (hand-write the FE type from this — there is no NSwag DTO for it):
  ```ts
  export interface AuditLogDto {
    id: number;
    eventId: string;          // Guid
    adminUserId: number;
    action: string;           // AdminActions.* constant
    targetEntityType: string;
    targetEntityId: number;   // 0 for batch/multi-row actions
    details: string | null;   // PII-safe summary (ids + enum states); may be JSON
    occurredAtUtc: string;    // ISO; the action time (display this as "When")
    createdAt: string;        // ISO; row-insert time
  }
  ```
- **Action vocabulary** (for the `ActionType` dropdown + legend) lives in `backend/src/Shared/Learnexia.Shared.Contracts/Admin/AdminActions.cs` (~50 constants across Subject/Unit/Lesson/ContentBlock/Skill/KnowledgeEdge/QuizQuestion/Content lifecycle/User/Account/Child/Gamification/Badge/Mission/TimedEvent/GlobalSetting/ModerationItem). The FE should mirror a curated subset (or all) as a const map with EN+AR labels — **do not hardcode raw strings inline**; centralize in `shared` or `strings.ts`. Note `User.Searched`/`User.Viewed` are high-volume read actions — consider whether they belong in the default view (OQ5).

## Handoff → security-auditor (WARRANTED — run before the reviewer gate)

This surface is security-sensitive even though it's read-only: the audit feed **references user/child entity ids and admin identities** (PII-adjacent) and is **AdminOnly**. Audit for:
- **Authorization:** `/audit` is fully behind `useAdminGuard`; the hook hits an `[Authorize(AdminOnly)]` endpoint; a non-admin/anonymous user gets 401/403 and is redirected with no data leak (no SWR/cache flash of a prior admin's data on logout/role-switch).
- **PII exposure:** the UI renders only the DTO's ids + enum/state `Details` and never joins in or displays names/emails/raw content. `Details` is displayed verbatim — confirm no `dangerouslySetInnerHTML` / unsanitized HTML sink if it's rendered as rich text (render as **plain text / escaped JSON**, never HTML — unlike the curriculum markdown sink, audit `Details` must NOT be passed through `marked`/HTML).
- **No write path:** confirm zero mutation hooks/affordances on the surface (immutability invariant must hold in the UI, not just the API).
- **Export (if built):** the export must respect AdminOnly and must not include PII beyond the DTO ids; a client-side export must not over-fetch unbounded pages.

Critical/High findings block the gate.
