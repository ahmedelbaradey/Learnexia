## 2. Business intent (one screen, one flow)

Student is in `(child)/subjects/[subjectId]` → taps an **Available** lesson card → lands on `/(child)/lessons/[lessonId]`. The current file at that route is a stub that renders "Lesson player coming soon" — W12 **replaces** it entirely.

The replacement is a single Expo Router screen that walks a three-stage view-state machine:

1. **Intro** — title + explanation (markdown-safe text) + visual placeholder + hearts (static 3, Phase-3 wires the live count) + streak + start CTA. Calls `GET /api/Learning/Lessons/{id}` on mount to fetch `{ name, explanation, visual, quickCheck }`. Optionally previews the quick-check inline.
2. **Quiz** — on Start, posts `POST /api/Learning/Quizzes/{lessonId}/Attempt`, captures `{ attemptId, questions[] }`, walks questions one at a time with a progress indicator (`Question n/N`). Per question:
   - Render the matching renderer for `questionType` (MCQ / TrueFalse / FillInBlank / Matching — Matching is a "Coming soon" stub this wave per Q9).
   - Locked-after-submit: once `Submit` is tapped, the answer controls disable.
   - Posts `POST /api/Learning/Quizzes/{attemptId}/Answers` with `{ questionId, answerPayload, timeSpentSeconds, hintUsed:false }`.
   - On `{ isCorrect:true }`: green confirmation strip → **auto-advance after 800ms**.
   - On `{ isCorrect:false, correctAnswer:"…" }`: red strip + reveal `correctAnswer` + explicit **Next** CTA. (No heart decrement this wave — visual stays static; Phase-3 P4-04 owns hearts logic.)
   - Hint button slot is **rendered but disabled** with helper text "Hint coming in v2" (P3-05 wires it).
3. **Summary** — on the last question's advance, posts `POST /api/Learning/Quizzes/{attemptId}/Complete`, captures `AttemptSummaryDto`, renders score + accuracy + duration + two CTAs:
   - **"Back to subject"** → `/(child)/subjects/[subjectId]`.
   - **"Try again"** → resets state, re-triggers Start (creates a new attempt; existing Attempt is server-side terminal).

If the student navigates away mid-quiz (Android back, web close-tab, Expo Router `useFocusEffect` cleanup), we fire `POST /api/Learning/Quizzes/{attemptId}/Abandon` (idempotent on terminal — safe to call from cleanup).

## 3. Acceptance criteria (testable, FE-scoped)

### P2-05-FE — Open and complete a lesson
- **A1.** Tapping an Available `LessonCard` in `/(child)/subjects/[subjectId]` navigates to `/(child)/lessons/[lessonId]` and renders the **Intro** stage within one render of the lesson GET resolving.
- **A2.** The Intro stage shows: lesson **title** (from `name`), **explanation** (markdown rendered safely — no raw HTML injection), **visual** (or placeholder when `visual` is null), **hearts** (static 3 — `Hearts={3}`), **streak** placeholder. AI Tutor bubble slot rendered with the explanation text (no live AI until P3-04).
- **A3.** When the lesson GET returns `explanation:null` / `visual:null` / `quickCheck:null`, the screen still renders without crashing and shows graceful fallbacks (placeholder visual, "Quick check coming soon" if `quickCheck:null`).
- **A4.** Tapping **Start** transitions to the Quiz stage and triggers `StartAttempt` once. While the request is in flight, a button-level spinner shows; tapping again is a no-op (mutation is `isPending`).
- **A5.** Completing the attempt transitions to the Summary stage with score + accuracy + duration. Tapping **Back to subject** routes to `/(child)/subjects/[subjectId]`. The Subject Lessons tab re-renders this lesson as **Completed** on next focus (TanStack Query invalidates `queryKeys.learning.subjectLessons(subjectId)` on summary mount).
- **A6.** Loading: a single shimmer skeleton for the lesson card on Intro. Error: retry button. 404 lesson: "Lesson not found" + Back CTA.
- **A7.** Lesson screen is RTL/LTR aware via `useLocale().direction` (mirror Wave 11 pattern). All text uses i18n keys (EN + AR). All colors via design tokens (no raw hex).
- **A8.** Back gesture / hardware back from Quiz stage fires `Abandon` for the in-flight `attemptId` (idempotent — safe if BE already terminal). Back gesture from Summary stage does NOT fire Abandon (attempt is already Completed).

### P2-06-FE — Take a quiz (4 question types)
- **Q1.** The Quiz stage shows a progress indicator labeled "Question n/N" (or AR equivalent). N is the length of `attempt.questions`.
- **Q2.** **MCQ:** renders the 4 options (parsed from `question.options` JSON array of strings) as large, tappable cards; selecting one highlights it; **Submit** is disabled until one is selected. Tap target ≥ 48×48.
- **Q3.** **TrueFalse:** renders two large buttons (True / False, localized). One-tap-to-submit OR select-then-submit (designer decides — recommend select-then-submit for consistency with MCQ).
- **Q4.** **FillInBlank:** renders the question prompt above a `TextField` and a Submit CTA. Submit disabled while the input is empty/whitespace.
- **Q5.** **Matching:** **OUT OF SCOPE this wave** (Q9 below). Renders a "Coming soon — try another question type" placeholder if a Matching question is ever received (BE has zero matching questions seeded today — verified in P2-07 brief R4).
- **Q6.** Answer controls are **locked** after the first Submit on the same question (user cannot re-select).
- **Q7.** Submitting an answer calls `SubmitAnswer` exactly once per question. Network failure surfaces an inline retry (does NOT advance, does NOT lock — user can retry).
- **Q8.** Responsive: 1-column on phones (<768px), centered with max-width 720px on tablet/desktop (Tamagui media queries — mirror existing Wave 11 cards).
- **Q9.** RTL/LTR aware. Option labels render with `writingDirection={direction}`. Logical positions only (start/end), no left/right.

### P2-07-FE — Instant feedback
- **F1.** On `{ isCorrect:true }`: a **green** `AnswerFeedbackStrip` slides in with positive confirmation copy. After **800 ms** the strip slides out and the next question loads (or, if last, Summary stage).
- **F2.** On `{ isCorrect:false, correctAnswer:"…" }`: a **red** `AnswerFeedbackStrip` slides in with "Not quite — the correct answer was: <correctAnswer>". The student-selected option (MCQ/TrueFalse) is highlighted red; the correct option is highlighted green. An explicit **Next** CTA appears; auto-advance does NOT fire on wrong.
- **F3.** Feedback shows on the same screen with no full reload (state-machine transition only).
- **F4.** Hint affordance is rendered as a disabled secondary button labeled "Hint" with helper text "Hint coming in v2". The button MUST exist (per story F2/AC) but MUST NOT call any endpoint this wave.
- **F5.** When `correctAnswer` is `null` (i.e. on correct), the FE does NOT attempt to render it (defensive — BE strips it).
- **F6.** No XP toast / heart decrement / streak update is fired by the FE — those are P4 stories. The Summary screen MAY show a placeholder "+10 XP" string that is hardcoded with a `// TODO P4-02` comment and MUST NOT call any XP/gamification endpoint.

### 4.4 NSwag gap — must be resolved before FE can type the hooks

The four quiz endpoints + the lesson GET all return `Promise<void>` from the generated client because no `[ProducesResponseType]` attribute is on the controller actions. This is the **same gap Wave 11 fixed for SubjectsController** (see HANDOFF.md Wave 11). Two options:

- **(A) [RECOMMENDED]** **Add `[ProducesResponseType(typeof(BaseResponse<…>), 200)]` to the 5 controller actions, regenerate NSwag.** Tiny BE diff (5 attributes), unblocks fully-typed FE hooks, mirrors the W11 pattern. **Adds a small BE-side touch to a "FE-only" wave** — flag for planner / lead.
- **(B)** **Hand-roll TS interfaces in `@learnexia/api-client`** and call the NSwag method, manually deserialize via a thin wrapper. Avoids touching BE; FE-only wave preserved. Trade-off: hand-rolled types drift from BE — every Phase-3/4 change to these DTOs silently breaks the FE.

**Recommend (A)** — it's a 30-minute BE change and unblocks W12 + every future wave that touches these endpoints. **Lead must pick before the FE batch starts** (the designer doesn't need this resolved; the frontend agent does).

## 5. Routes & navigation

**Decision: single route, view-state machine.** Reasoning:

- Cleaner back-stack: Android back from anywhere in the lesson exits to the subject (one pop), not three.
- Easier to share state (the `attemptId`, questions cache, hearts header) without context-prop drilling across screens.
- Easier to fire `Abandon` on unmount — a single `useEffect` cleanup hook.
- Trade-off: deep-linking into "the Summary of an attempt I just completed" doesn't work — acceptable for v1.

**Route:** `app/(child)/lessons/[lessonId].tsx` (replaces the stub at the same path — verified file exists today, 115 LOC).

**View-state:**
```ts
type Stage =
  | { kind: 'intro' }                                                                    // Lesson GET + Start CTA
  | { kind: 'quiz'; attemptId: number; questions: QuizQuestionDto[]; currentIndex: number; answerState: AnswerState }
  | { kind: 'summary'; summary: AttemptSummaryDto };

type AnswerState =
  | { phase: 'answering'; selectedValue: string | null }                                  // user picking
  | { phase: 'submitting' }                                                               // POST in flight
  | { phase: 'feedback'; isCorrect: boolean; correctAnswer: string | null; selectedValue: string };  // locked, showing strip
```

On stage transition `quiz → summary`, invalidate `queryKeys.learning.subjectLessons(subjectId)` so the Lessons tab re-renders the now-Completed lesson. **`subjectId` is NOT in the URL** — derive it from the loaded `Lesson.unitId → Unit → Subject` chain (the lesson GET response carries `unitId`; we need to either pass `subjectId` as a query param in the navigation from the Lessons tab, OR look it up from the cache). **Recommend: add `?subjectId=…` to the navigation URL in `subjects/[subjectId]/index.tsx`** (one line change, line 274). Cleanest.

## 8. State machine — full transition table

```
Stage         Event                           Next stage / action
────────────────────────────────────────────────────────────────────────────
intro         lessonGet succeeds              intro (renders content)
intro         lessonGet 404                   intro (renders "Lesson not found" + Back CTA)
intro         tap Start                       intro → quiz: call useStartAttempt; on success set
                                              attemptId + questions + currentIndex=0 +
                                              answerState={phase:'answering', selectedValue:null}
intro         hardware back                   exit screen → subject (no Abandon — no attempt yet)

quiz          select option (MCQ/TF)          quiz: answerState.selectedValue = X (still 'answering')
quiz          type into FillInBlank           quiz: answerState.selectedValue = text
quiz          tap Submit                      quiz: answerState.phase = 'submitting';
                                              call useSubmitAnswer({ questionId, answerPayload:selectedValue,
                                              timeSpentSeconds: msSinceQuestionRender / 1000, hintUsed:false })
quiz          submit succeeds isCorrect=true  quiz: answerState = {phase:'feedback', isCorrect:true, ...};
                                              start 800ms timer → on timer fire → advanceOrComplete()
quiz          submit succeeds isCorrect=false quiz: answerState = {phase:'feedback', isCorrect:false,
                                              correctAnswer:X, selectedValue}; show Next CTA
quiz          tap Next (on wrong feedback)    advanceOrComplete()
quiz          submit fails (network)          quiz: answerState.phase back to 'answering' with inline error;
                                              user can retry
quiz          hardware back                   exit screen → subject; fire useAbandonAttempt(attemptId) on
                                              unmount cleanup (don't await — fire-and-forget)

advanceOrComplete() helper:
  if currentIndex + 1 < questions.length:
    currentIndex++; answerState = {phase:'answering', selectedValue:null}
  else:
    call useCompleteAttempt(attemptId); on success → stage = {kind:'summary', summary}
    invalidate queryKeys.learning.subjectLessons(subjectId)
    invalidate queryKeys.learning.dashboard()  // if exists, so Home reflects completion

summary       tap Back to subject             router.replace('/(child)/subjects/' + subjectId)
summary       tap Try again                   reset all state; call useStartAttempt again
summary       hardware back                   exit to subject (no Abandon — already Completed)
```

**Edge cases for designer + frontend:**
- BE empty-questions guard: if `StartAttemptResponse.questions.length === 0`, render a friendly "This lesson has no questions yet" + Back CTA. Don't crash.
- Timer cleanup: the 800 ms auto-advance timer MUST be cleared on unmount and on hardware back to avoid a setState-after-unmount warning.
- Re-rendering with a new `lessonId` (router back-stack edge): reset all state on `lessonId` change.

## 13. Risks

- **R1 (HIGH) — NSwag gap (§4.4).** Without typed responses, the FE either hand-rolls TS (drift risk) or the BE gets a touch (small wave-creep). **Resolve OQ1 before the frontend batch starts.**
- **R2 (MED) — `subjectId` derivation.** The lesson route does not carry `subjectId` today. Without the OQ6 URL-param fix, navigating back to the subject requires a `unitId → subjectId` lookup which is not in any cached DTO. Easy fix; flag for the frontend agent.
- **R3 (MED) — Hardware back on Android during quiz.** The Abandon-on-cleanup must be debounced/once-only to avoid double-firing. The `useEffect` return function in React only fires once per unmount, so a plain ref-guard is sufficient.
- **R4 (LOW) — TanStack Query mutation race.** If the user double-taps Submit, two `useMutation` calls could fire. Use the `isPending` flag to disable the button (mirror the W11 pattern).
- **R5 (LOW) — Markdown rendering of `explanation`.** BE returns markdown. The FE must render it safely (no `dangerouslySetInnerHTML` on web, no raw HTML on native). **Recommend:** render as plain text for now; markdown rendering is a follow-up. Flag for designer.
- **R6 (LOW) — `Options` JSON parsing per type.** BE stores `Options` as jsonb string. FE must `JSON.parse` per `questionType`. Wrap in try/catch; on parse failure, render "Question content error" + advance CTA.
- **R7 (LOW) — `correctAnswer` is a string (per BE DTO).** For MCQ, the BE stores it as one of the option strings; the FE compares against the selected option string. For TrueFalse, it'll be `"true"` / `"false"`. For FillInBlank, a free-form trimmed string. All three work with simple `===` after trim. Matching is undefined (deferred).
- **R8 (LOW) — Lesson 404 from old subject cache.** If a parent grade-transitions a child and the subjectsLessons cache is stale, tapping a now-deleted lesson 404s. Handled by §3 AC A6; flag for QA.
