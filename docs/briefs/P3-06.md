# Pipeline Brief — P3-06: Generate curriculum-grounded questions (RAG) / Similar Example

> **AI Helper MVP context:** See `docs/briefs/ai-helper-mvp.md`. P3-06 now serves two distinct purposes: (1) the existing **offline Batch API question generation** (admin/content-triggered, unchanged), and (2) a new **runtime "similar example" helper** implementing **intent #4 — "اديني مثال مشابه" (give me a similar example)**. The similar-example intent is runtime-grounded (via `ILearningContextProvider`), scoped to the active skill context, and follows the same refuse-and-redirect rule (no context = redirect). The offline batch question generation is not a student-facing helper intent and is unaffected by the Helper scope constraint. Build order is parallel with Gamification-FE / Parent work — NOT gated on BL-* or the full BL pipeline.

## Summary & traceability
- **Task (1 line):** (1) Generate practice/quiz questions **grounded in retrieved curriculum context**, validate them, map them to the existing 4-type quiz schema (`QuizQuestion`, `GeneratedBy.AI`), pass them through the Safety Layer — and **decline rather than hallucinate when retrieval returns nothing**. (2) Expose a **runtime "give me a similar example"** endpoint (intent #4: "اديني مثال مشابه") that returns a similar worked example grounded in the active skill context via `ILearningContextProvider`, refuses with a redirect when no context is available, and emits instrumentation events.
- **User story:** [user-stories/Phase-4-AI-Tutor/P3-06-generate-grounded-questions.md](../../user-stories/Phase-4-AI-Tutor/P3-06-generate-grounded-questions.md) — *"As a student, I want practice and quiz questions generated from my actual curriculum…"*
- **Task file:** **MISSING** — no `tasks/Backend/Phase-4-AI-Tutor/P3-06-BE.md`. Flag to lead (all five P3-0x in this cluster lack task files).
- **FR-IDs:** **FR-AI-3** (RAG-grounded question generation). Also exercises **FR-AI-4** (Safety Layer, mandatory) and **FR-AI-6** (AI generates content only — does not decide progression/difficulty selection).
- **BRD goal:** **G2 (Learning outcomes)** — "what I'm tested on matches what I'm meant to be learning."
- **Phase / Epic / SP:** Phase 4 — AI Tutor (Week 6–7) · Epic **Prompt Builder & Tutor** · 5 SP · `ai` / `quiz` / `backend`.
- **UI:** None directly. Generated questions feed the existing quiz UI (P2-06-FE) and adaptive quizzes (P3-11). **No designer stage.**
- **Build position:** **Second in the cluster.** Hard-blocked by **P3-07 (RAG retrieval)**. Also depends on the infra cluster **P3-01 (Gateway)**, **P3-02 (Safety)**, **P3-03 (Prompt Builder)** for generation + filtering. Feeds **P3-11** (adaptive quizzes) and reuses the **P2-06** quiz engine.

## Business context & value
- **Who benefits:** the **student** (assessed on their real curriculum, not generic items) and the **content/admin** side (scales question authoring without manual curation per skill); downstream the **adaptivity engine** (P3-11) gets a larger item pool.
- **Value:** grounded generation is the bridge from "tutor that explains" to "tutor that assesses" — and it is the cheapest path to broad question coverage. The **decline-on-empty** rule is the trust guarantee: the product never tests a child on a fabricated, off-syllabus item.
- **Success measure:** for a target skill/grade with curriculum coverage, generation returns ≥1 **valid** question of a supported type with a correct answer, tagged `GeneratedBy.AI`, having passed the Safety Layer; for a skill/grade with **no** retrieved context, generation **declines** (returns an explicit "no grounding" result) and writes **no** `QuizQuestion`.

## Current-state findings (reality in code)
1. **The quiz schema already exists and is AI-ready.** `QuizQuestion` lives in the **Learning** module (`backend/.../Learning.Domain/Entities/QuizQuestion.cs`), supports all four types via `QuestionType { MCQ=1, TrueFalse=2, Matching=3, FillInBlank=4 }`, stores `Options`/`CorrectAnswer` as serialized jsonb, and **already has `GeneratedBy { Curated=1, AI=2 }`** with a comment "AI generation lands in P3-06." So the persistence target is built — this story populates it via AI.
2. **Per-type validation already exists:** `QuizQuestionTypeValidation` (`Learning.Application/Features/Questions/Validation/`) enforces the per-type Options/CorrectAnswer shape. **Reuse it** to validate AI output — do not re-invent.
3. **`AnswerComparator`** (Learning.Domain/Services) defines correct-answer equality per type. Generated `CorrectAnswer` must be in the shape `AnswerComparator` expects, else grading breaks.
4. **Matching-type is a known gap:** the comparator's Matching equality + payload shape is **unresolved** (CARRYOVER decision #1, CO-BE-1/2). Recommend P3-06 generates **MCQ / TrueFalse / FillInBlank only** at MVP and **skips Matching** until CO-BE-1 lands (OQ-4).
5. **None of the AI infra exists yet:** no Gateway (P3-01), no Safety Layer (P3-02), no Prompt Builder (P3-03), no RAG (P3-07). **This story cannot start until that stack is built** — it is purely an orchestration over them.
6. **Module isolation:** if generation/orchestration lives in the new `Curriculum` module (P3-07) but writes `QuizQuestion` (Learning), that's a **cross-module write** — forbidden as a direct project/FK reference. Resolve the seam (OQ-1): either generation lives **in Learning** (it owns `QuizQuestion`) and calls Curriculum's retrieval via `Shared.Contracts`, or it returns a DTO that Learning persists.

## Acceptance criteria (testable)

### Part A — Offline question generation (admin/content-triggered, unchanged)
1. **AC-1 (grounded):** Generation calls `ILearningContextProvider` (or `IChunkRetrievalContract` for the batch path) for the target skill/grade and includes retrieved chunks in the generation prompt. Output is grounded in those chunks, not free-form.
2. **AC-2 (valid + typed):** Each generated question maps to a supported `QuestionType` (**MCQ / True-False / Fill-in-the-blank**; Matching deferred per OQ-4) with a **valid `CorrectAnswer`** that passes the existing `QuizQuestionTypeValidation` and is gradeable by `AnswerComparator`. Malformed AI output is rejected/regenerated, never persisted.
3. **AC-3 (safety + traceability):** Every generated question passes the **Safety Layer (P3-02)** before being returned/persisted; persisted rows are tagged `GeneratedBy.AI`. A safety failure blocks the item and the event is logged.
4. **AC-4 (DECLINE ON EMPTY — hard criterion for offline path):** When retrieval returns empty (no relevant context for the skill/grade), generation **declines**: returns an explicit "no grounding available" result, does NOT call the LLM, and does NOT write any `QuizQuestion`.
5. **AC-5 (conventions):** Handler returns `BaseResponse<T>` (`Successed`), `ICommand<>` validated by `ValidationBehavior`, `ILoggerManager` injected, no UoW (explicit transaction for multi-write), module isolation respected.

### Part B — Runtime "similar example" helper (intent #4 — new)
6. **AC-6 (similar example grounded in active skill — intent #4):** Given an active skill context, calling `SimilarExampleCommand` returns a similar worked example **grounded in the active skill content** from `ILearningContextProvider`. The example is scoped to the current skill — the prompt does not invite the model to produce examples from outside the skill context.
7. **AC-7 (refuse-and-redirect — hard criterion for intent #4):** When `ILearningContextProvider` returns no approved context for the active skill, the handler returns the redirect response ("خلينا نكمل تحدي [skill] الحالي...") and does NOT call the LLM. Test: request a similar example for a skill with no seeded content → redirect response, zero LLM calls.
8. **AC-8 (instrumentation for intent #4):** `HelpRequested { Intent=SimilarExample }`, `HelpDelivered { Intent=SimilarExample, ContextSource }`, or `HelpDeclined { Reason=NoContext }` events are emitted for every similar-example request. These feed P5-03 analytics and P6-02 eval.
9. **AC-9 (safety for intent #4):** Similar example output passes P3-02 Safety Layer before streaming to the student. No bypass path.

## Handoff → backend-feature
- **Command:** `GenerateGroundedQuestionsCommand : ICommand<BaseResponse<GeneratedQuestionsResult>>` carrying `{ SkillId | LessonId, GradeId, Count, Types[] }`. Validated by `ValidationBehavior`.
- **Handler orchestration (sequential, fail-soft at each AI boundary):**
  1. **Retrieve** (P3-07): get top-k chunks for skill/grade. **If empty → return immediately with `Declined` result (AC-4); no LLM call, no write.**
  2. **Build prompt** (P3-03): inject grade/age/language/curriculum-context (the chunks)/child-safe tone + a per-subject question-generation template; instruct strict JSON output for the chosen `QuestionType`(s).
  3. **Generate** (P3-01 Gateway): route to a model (cheap for simple items, premium for harder — NFR-9). Parse the structured JSON.
  4. **Validate** (reuse `QuizQuestionTypeValidation` + `AnswerComparator` shape check). Invalid → regenerate up to a bounded retry count, else drop the item.
  5. **Safety** (P3-02): every surviving item passes the Safety Layer; failures are blocked/regenerated and logged (AC-3).
  6. **Persist** valid+safe items as `QuizQuestion` (`GeneratedBy.AI`). If persisting >1 atomically, **open an explicit transaction** (no UoW).
- **Decline contract:** model the "no grounding" outcome explicitly in `GeneratedQuestionsResult` (e.g. `Status: Generated | Declined_NoContext | Declined_AllFailedSafety`) so callers (P3-11, tests) branch deterministically. `Successed=true` with a `Declined` status is preferable to a thrown error (AC-4 is a *valid* business outcome, not a failure).
- **Seam decision (OQ-1):** if the command lives in **Learning** (owns `QuizQuestion`), it consumes Curriculum retrieval through `Shared.Contracts` (an `IChunkRetrievalContract` integration seam) — **not** a project reference. Confirm with lead.
- **DI:** register the gateway client, safety client, prompt-builder service, and retrieval contract in the owning module's Infrastructure; mirror the typed-HttpClient pattern (`ExpoPushSender`).

## Handoff → security-auditor (AI-safety — HARD GATE)
- This story **generates AI content shown to children** → **security-auditor is a hard gate** (Critical/High block). Audit:
  - **No Safety-Layer bypass** (AC-3): there is literally no code path that persists/returns a generated question without passing P3-02.
  - **Prompt-injection resistance:** retrieved chunks + any student-supplied skill context can't smuggle instructions that subvert the generation/safety prompt.
  - **Decline-on-empty is enforced** (AC-4) — confirm no fallback that silently free-generates when retrieval is empty.
  - **No secret/key leakage** in logs from the gateway/safety adapters.
  - **Cost/abuse:** bound the retry/regenerate loop and `Count` to prevent a generation amplification / cost-bomb.

## Handoff → api-tester
- If exposed as an endpoint (admin/content tooling or an internal trigger): test (a) grounded generation for a seeded skill returns valid typed questions tagged `AI`; (b) **empty-retrieval skill → `Declined_NoContext`, zero rows written** (the headline test); (c) a deliberately unsafe generation is blocked and logged; (d) malformed LLM output is rejected, not persisted; (e) envelope/`Successed`/validation paths. Use a **stubbed/faked gateway + safety** so tests are deterministic (don't hit live LLMs in CI).

## Open questions / assumptions / risks
- **OQ-1 (orchestration location + cross-module seam — KEY):** does `GenerateGroundedQuestions` live in **Learning** (owns `QuizQuestion`, consumes Curriculum retrieval via `Shared.Contracts`) or in **Curriculum** (owns RAG, returns DTOs Learning persists)? Recommend **Learning owns the write**, Curriculum exposes retrieval via a contract. Resolve before backend-feature — drives module boundaries.
- **OQ-2 (when does generation run?):** on-demand (admin/content trigger to pre-author an item bank) vs live per-quiz (P3-11 adaptive selection requests fresh items)? Recommend **batch/pre-author into an item bank** at MVP (latency + safety review headroom) rather than live-in-the-quiz-loop. Confirm — affects endpoint shape + whether it's student-triggered.
- **OQ-3 (structured-output strategy):** strict JSON schema / function-calling vs free-text-then-parse? Recommend the Gateway (P3-01) expose a structured-output mode; parse defensively. Drives the prompt template (P3-03).
- **OQ-4 (Matching deferral):** generate MCQ/TrueFalse/FillInBlank only and **skip Matching** until CO-BE-1/2 define the Matching payload + comparator? Recommend **yes** — Matching grading is unresolved per CARRYOVER decision #1.
- **OQ-5 (Draft vs Published + moderation):** do AI-generated questions land as `LifecycleState.Draft` and route to the moderation queue (P7-09) before students see them, or go straight to `Published`? Recommend **Draft → moderation** (human-in-the-loop on AI content, FR-ADM-8) — but P7-09 is itself blocked, so MVP may auto-Publish post-safety. Confirm the risk appetite.
- **OQ-6 (generation audit):** persist a generation-audit record (prompt, chunks used, model, safety verdict) for traceability/debugging? Recommend a lightweight log via `ILoggerManager` at MVP; a dedicated table only if P7-11 (AI-quality dashboard) needs it.
- **Risk — hard blockers:** P3-06 cannot start until **P3-07, P3-01, P3-02, P3-03 all exist**. It is the most-blocked story in the cluster. Sequence accordingly.
- **Risk — grading shape drift:** generated `CorrectAnswer` must exactly match `AnswerComparator`'s expected per-type shape, or correct answers grade as wrong. Validate against the comparator, not just the type validator.

## Cost & model routing (Batch API primary)

> **See the authoritative strategy:** [docs/briefs/ai-cost-routing.md](ai-cost-routing.md). This section captures P3-06's specific responsibilities.

### Offline batch generation is the PRIMARY path

Question generation is an OFFLINE, admin/content-triggered operation. It is NOT called live in the student quiz loop (that is P3-11 scope, which pulls from the pre-authored item bank).

**Model routing for P3-06:**

| Task | Model | API mode |
|---|---|---|
| Bulk question generation | Sonnet `claude-sonnet-4-6` | Anthropic Batch API |
| QA validation pass | Opus `claude-opus-4-8` | Anthropic Batch API |
| Runtime question generation (exceptional path only) | Sonnet `claude-sonnet-4-6` | Synchronous (via `AiModelRouter`) |

**There is no persistent "question cache" in P3-06** — the output is persisted directly into `QuizQuestion` rows tagged `GeneratedBy.AI`. The `QuizQuestion` table itself is the item bank.

### Revised handler orchestration — Batch API first

For the primary (batch/admin-trigger) path:

1. Receive `GenerateGroundedQuestionsCommand` (admin-triggered; not student-triggered at MVP per OQ-2).
2. Call `IChunkRetrievalContract.RetrieveAsync`. **If chunks empty → `Declined_NoContext` immediately; no LLM call, no write** (AC-4 hard criterion).
3. Build generation prompt(s) via P3-03 Prompt Builder for each `(SkillId, QuestionType)` combination in the request.
4. **Submit to Anthropic Batch API** via `IAiBatchGateway.SubmitBatchAsync(...)`. Record `BatchJobId`. Return `BatchSubmitted` status to the caller — do not block waiting for results.
5. A **Batch completion handler** (background job polling or webhook): on job completion, for each result: parse JSON, validate against `QuizQuestionTypeValidation` + `AnswerComparator`, run P3-02 Safety Layer, persist valid+safe items as `QuizQuestion` (`GeneratedBy.AI`, `LifecycleState` per OQ-5). Open explicit transaction for batch persist (no UoW).
6. **Opus QA pass (optional, async):** after batch completion, submit surviving items to Opus via Batch API for a QA review pass. Set a `QaPassedAt` / `QaScore` field on the `QuizQuestion`. Flag low-QA items for human review.

For the exceptional runtime path (live generation, e.g. adaptive quiz running low on items): synchronous Sonnet call via `IAiGateway`, same decline-on-empty rule applies, quota checked.

Apply prompt-caching `cache_control` on the repeated system-prompt + curriculum-context portions for any synchronous calls.

Always verify current Anthropic pricing/model IDs before launch.
