- **User story:** `user-stories/Phase-7-Admin-Console/P7-02-manage-lessons-and-content.md` (SP 8 — the richest editing surface in the area).
- **FE task file:** `tasks/Frontend/admin-dashboard/Phase-7-Admin-Console/P7-02-FE.md` (FE-1..FE-6).
- **BE task file (done):** `tasks/Backend/Phase-7-Admin-Console/P7-02-BE.md` (BE-1..BE-6, merged).
- **FR / SRS:** FR-ADM-1 (admin curriculum management), SRS §3 (Admin role). **BRD goal: G3** — curriculum quality / operational scalability (admins author lesson content without dev seed scripts).
- **Phase/epic:** Phase 7 — Admin Console · Epic *Admin — Curriculum Management* · post-MVP.
- **App / packages:** `apps/admin-dashboard` (routes/components/strings); new hooks in `packages/api-client`; block renderers may live in `packages/ui` for later student-app reuse (per FE notes).

## Business context & value
- **Who benefits:** the **admin** (curriculum author) directly; **students** indirectly (structured, vetted, language-correct lesson material rendered from ordered blocks rather than the legacy flat `Lesson.Explanation`/`Lesson.Visual` seed fields).
- **Value:** P7-01-FE gives admins the top of the tree (subjects/units); P7-02-FE adds the **leaf authoring surface** — the only place lesson narrative/media is created through the dashboard. Removes the developer-in-the-loop for lesson content.
- **Success measure:** an admin can open a unit, create a lesson with metadata, add/edit/reorder/delete typed content blocks, reorder lessons within the unit, deactivate or delete a lesson (blocks handled), and see (never edit) the lesson's inherited language — all without leaving the dashboard and without a non-admin ever reaching the surface.

## Acceptance criteria (testable — FE)
1. **Lessons list under a unit.** Given a unit (arrived at from the P7-01 curriculum tree), the lessons list shows each lesson's title, difficulty, estimated minutes, sequence order, and lock state, ordered by `SequenceOrder`. (Story AC1; FE-1.)
2. **Create/edit lesson.** Creating/editing a lesson persists title, difficulty, estimated time, sequence order, and lock state scoped to the unit; on success the list reflects it (cache invalidation). Validation errors from the API render inline (e.g. empty name, negative minutes). (Story AC1; FE-1.)
3. **Inherited language (read-only).** The lessons list and the lesson/content editor header show the **language of the owning Subject tree** as a read-only badge; there is **no language field/picker** anywhere in the lesson or content editor. The block preview honors that language's direction. (Story AC2; FE-6.)
4. **Add content blocks by type.** In the content-block editor the admin can add a block of each supported type — **Text / Image / Video / Callout** — with a per-type input form; on save the block persists with type + payload and is appended at the end. (Story AC3; FE-2.)
5. **Edit / reorder / delete blocks persist.** Editing a block's payload/type, drag-reordering blocks, and removing a block all persist and survive reload (verified by refetch). Reorder is a single batch call. (Story AC4; FE-2/FE-3/FE-4.)
6. **Reorder lessons within a unit.** Drag-reordering lessons updates each lesson's `SequenceOrder` via one batch call and reflects on reload. (Story AC5; FE-3.)
7. **Delete lesson (blocks handled atomically).** Deleting a lesson removes/deactivates it (backend soft-delete) and is no longer served to students; the UI confirms via a typed/confirm dialog and invalidates caches. (Story AC6; FE-4.)
8. **Inline block preview.** Each block renders an inline author-facing preview approximating student rendering (Markdown for Text/Callout, image/video for media), in the inherited language direction. (FE-5.)
9. **Loading / empty / error states.** Lessons list and content editor each render the four states: loading skeleton, empty ("no lessons / no blocks yet" with a primary add CTA), error + retry, and results. Empty-list is a success-with-empty-data state, **not** an error banner (mirror `useSearchUsers` contract).
10. **Admin-only access.** Non-admin → redirect/403 (client `useAdminGuard` via `AdminShell`, mirrored by `middleware.ts`). All writes go to AdminOnly endpoints; a 401 triggers the silent-refresh path, a 403 surfaces the forbidden state. (Story AC7.)
11. **Lifecycle visible & gated.** Lesson active/inactive and block active state are visible (badge) and toggleable where the backend exposes it (lesson `Active` endpoint exists; block-level toggle does **not** — see open question Q4). Inactive items remain visible to the admin (admin reads include inactive).

## Exact endpoints (verified against the live controllers — note the routes differ from the task-file "Contract" stubs)
> ⚠️ The task files describe `GET /Units/{unitId}/Lessons` and `/Lessons/{id}/ContentBlocks` with Guid IDs. **The actual controllers use `int` IDs and different routes.** Use the real shapes below. All routes are `[Authorize(Policy = AdminOnly)]` unless noted. All responses are `BaseResponse<T>` with the success flag spelled **`Successed`**; the api-client unwraps `data` (or throws on `Successed=false`).

**Lessons (`LessonsController`, base `api/learning/Lessons`):**
- **List lessons under a unit:** `GET /api/learning/Lessons/List?UnitId={unitId}&PageNumber=&PageSize=&OrderBy=` → `BaseResponse<PaginatedResult<SingleLessonResponse>>`. `UnitId` is an optional filter on the paginated admin list; admin list includes **inactive** lessons. (Mirror `useSearchUsers` → `client.getPaginated`, PascalCase params.)
- **Admin lesson detail (incl. content blocks):** `GET /api/learning/Lessons/{id}/Admin` → `BaseResponse<AdminLessonDetailDto>` (lesson + all non-deleted blocks incl. inactive, ordered by `SequenceOrder`). **This is the editor's primary read** — it returns the blocks too, so a separate blocks fetch is optional.
- **Create lesson:** `POST /api/learning/Lessons/Create` — body = `AddLessonCommand` (`AddLessonDto` = LessonDto fields: `name`, `difficulty`, `sequenceOrder`, `isLocked`, `unitId`, `skillId?`, `estimatedMinutes`). → `BaseResponse<string>` (message).
- **Update lesson:** `PUT /api/learning/Lessons/Update` — body = `EditLessonCommand` (LessonDto incl. `id`). → `BaseResponse<string>`.
- **Delete lesson:** `DELETE /api/learning/Lessons?id={id}` → `BaseResponse<string>` (backend soft-delete; blocks handled atomically).
- **Activate/deactivate lesson:** `PUT /api/learning/Lessons/{id}/Active` — body `{ lessonId, isActive }` → `BaseResponse<string>`.
- **Reorder lessons within a unit:** `PUT /api/learning/Lessons/Reorder` — body `{ lessonIds: [int,...] }` (position = new `SequenceOrder`; all must belong to one unit) → `BaseResponse<string>`.

**Content blocks (`ContentBlocksController`, base `api/learning/ContentBlocks`):**
- **List blocks for a lesson:** `GET /api/learning/ContentBlocks/ByLesson/{lessonId}` → `BaseResponse<List<AdminContentBlockDto>>` (non-deleted incl. inactive, ordered). *(Redundant with `/Lessons/{id}/Admin`; pick one as the editor's source of truth — prefer the lesson-detail read so lesson + blocks stay consistent.)*
- **Add block:** `POST /api/learning/ContentBlocks` — body `{ lessonId, blockType, payload }` (appended at end). → `BaseResponse<string>`.
- **Edit block:** `PUT /api/learning/ContentBlocks` — body `{ id, blockType, payload }` (only type+payload editable). → `BaseResponse<string>`.
- **Delete block:** `DELETE /api/learning/ContentBlocks/{id}` (soft-delete `IsDeleted=true`). → `BaseResponse<string>`.
- **Reorder blocks within a lesson:** `PUT /api/learning/ContentBlocks/Reorder` — body `{ contentBlockIds: [int,...] }` (all must belong to one lesson). → `BaseResponse<string>`.

**Inherited-language source (for FE-6 badge):** there is **no** language field on any Lesson/ContentBlock DTO. Language lives only on `SubjectDto` (`subjectCode` + `language` = `ContentLanguage` enum, int on the wire). The unit's `subjectId` (`UnitDto.subjectId`) → subject → `language`. Resolve the badge by carrying the subject's language down from the P7-01 tree context (Subject → Units → Lessons navigation). See **Open question Q1** — recommend the FE pass language via route/props rather than a new endpoint.

**Per-type `payload` JSON shapes (must match backend `ContentBlockPayloadValidator` exactly):**
- **Text** (`blockType: 1`): `{ "markdown": "<non-empty, ≤32768>" }`
- **Image** (`blockType: 2`): `{ "url": "<absolute HTTPS, ≤2048>", "altText": "<optional, ≤1024>" }`
- **Video** (`blockType: 3`): `{ "url": "<absolute HTTPS, ≤2048>", "caption": "<optional, ≤1024>" }`
- **Callout** (`blockType: 4`): `{ "variant": "info"|"warning"|"tip", "markdown": "<non-empty, ≤32768>" }`
- Overall payload capped at **65536** chars (P7-SEC-2). **URL rules (P7-SEC-3):** must be absolute **https**, host may not be `localhost`/loopback/private/link-local/bare-IP — the FE should mirror these as client-side validation hints so authors get fast feedback, but the **backend is authoritative** (render its `Successed=false` message on rejection).

## Security / audit (admin curriculum content writes)
- **Authorization:** every write hits an **AdminOnly** endpoint (verified on both controllers). The FE relies on `useAdminGuard` + `middleware.ts`; surface 403 as a forbidden state, 401 flows through silent-refresh. No client-side trust — the server is the gate.
- **Audit (P7-12) is automatic on the backend:** Lesson + ContentBlock writes raise `AdminActionPerformedDomainEvent` (`AdminActions.LessonCreated/Updated/Deleted/Reordered/Activated/Deactivated`, `ContentBlock.Added/Updated/Deleted/Reordered`) dispatched post-commit. The FE needs to do **nothing** to emit audit — but should not assume it can bypass it.
- **Lifecycle / soft-delete:** delete is **soft** (backend `IsDeleted`), lesson/block have `IsActive`; admin reads include inactive, student reads exclude them. The FE must show active/inactive clearly and never present a destructive "permanent delete" claim (mirror the Wave-1 suspend copy caution).
- **⚠️ Content-rendering risk — the load-bearing security item:** Text/Callout payloads are author-supplied **Markdown** stored verbatim (the backend validates *shape/length/url-safety*, **not** HTML safety). The inline `BlockPreview` (FE-5) — and later the student renderer — render this Markdown. **Markdown→HTML MUST be sanitized** (e.g. a vetted sanitizer / safe renderer; strip raw HTML, `javascript:`/`data:` URLs, event handlers) before injection. Image/Video URLs are backend-restricted to absolute https + non-private hosts, but the preview must still not execute arbitrary embeds. This is a **children's platform** — treat the preview as an untrusted-content sink. **→ This makes the batch security-sensitive (content rendering); run `security-auditor` after `frontend` (XSS via Markdown/HTML injection, URL scheme handling, no `dangerouslySetInnerHTML` without sanitization).**
- No secrets/PII on this surface beyond admin auth (already handled by the api-client; tokens never logged).

## Open questions / assumptions / risks
- **Q1 (inherited-language source — recommend FE-side, not backend):** No Lesson/ContentBlock DTO carries a resolved `language`/`subjectCode`; `GetAdminLessonQueryHandler` explicitly applies "no language guard." The badge (Story AC2, FE-6) must derive language from the owning **Subject** (`SubjectDto.language`, walked via `Unit.subjectId`). **Recommendation:** carry `language` (+ subject/unit names) down through the P7-01 tree navigation context (route params/props) so no backend change is needed. **Decision needed:** is FE-side resolution acceptable, or should BE add a resolved `language` field to `AdminLessonDetailDto`/`SingleLessonResponse`? (Small additive BE change if preferred — flag to lead; do not assume.)
- **Q2 (hard dependency on P7-01-FE — BLOCKER for navigation):** P7-02 lessons live **under a unit**, but **P7-01-FE is not built** (Curriculum is still an `aria-disabled` placeholder; no `/curriculum` routes, no subjects/units hooks, no tree). Without it there is no in-app way to reach a unit, and the lessons route's `unitId`/`subjectId`/`language` context has no upstream provider. **Options:** (a) sequence P7-01-FE first (recommended — it owns the tree + Subject/Unit hooks + the language source); (b) build P7-02 with a temporary unit-picker entry point and stub navigation. **Recommend the lead confirm P7-01-FE ordering before this batch starts.**
- **Q3 (route shape):** task file names a flat `app/(admin)/curriculum/lessons/page.tsx`; a nested `subjects/[id]/units/[id]/lessons` reads cleaner and carries context. Designer + planner to settle once P7-01-FE's tree shape is known. Assumption: flat route + `?unitId=`/context props for v1.
- **Q4 (block-level active toggle):** `ContentBlock.IsActive` exists and `AdminContentBlockDto` exposes it, but **no endpoint sets it** (Edit only changes type/payload; Delete is soft-delete). So the FE can *display* block active state but cannot *toggle* it. **Assumption:** FE shows block active state read-only and uses delete (soft) for removal; AC11 block-toggle is **out of scope** unless BE adds a block `SetActive` endpoint. Flag to lead.
- **Q5 (lesson `sequenceOrder` on create):** `AddLessonCommand` accepts `sequenceOrder`, but ordering is normally managed by the Reorder endpoint. **Assumption:** create appends (FE sends a sensible next value or 0 and relies on reorder), and the form does not expose a free sequence field. Confirm with designer.
- **Q6 (media upload vs URL):** BE-3 mentions `IStorageService` for media, but the shipped content-block payloads take a **URL** string (no upload endpoint on `ContentBlocksController`). **Assumption:** v1 is URL-only (paste an https URL); a file-upload affordance is a later enhancement. Flag if the product expects in-dashboard upload.
- **Risk (route contract drift):** the task-file "Contract from Backend" stubs (Guid IDs, `/Units/{id}/Lessons`, `/Lessons/{id}/ContentBlocks`) **do not match the live controllers** (int IDs, `/Lessons/List?UnitId=`, `/ContentBlocks/ByLesson/{id}`). The brief's "Exact endpoints" section is authoritative — build to it, not the stubs.
- **Risk (XSS):** unsanitized Markdown/HTML in `BlockPreview`/renderer is the top risk on a children's platform — must be closed before the security gate (see Security section).
