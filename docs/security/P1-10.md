## Targeted verification against the audit brief

- **No public admin registration:** CONFIRMED. The full `app/` route tree contains only `/login`, `/` (redirects to `/dashboard`), and `/(admin)/dashboard`. No `/register`, `/signup`, `/admin/register`, `/create-account`, or `/forgot` route or UI exists anywhere. `signInSchema` has only `userName` + `password` — no registration fields. No "Register"/"Forgot password" link on the login page (Design Spec §3f honored).
- **Admin role gate correctness:** CONFIRMED fail-closed. `getRolesFromToken` returns `[]` on null/missing/malformed token, and `isAdminRoleList([])` is `false` → not admin. `base64UrlDecode` and `decodeJwtPayload` catch all errors and return `null`. Role comparison is case-insensitive (`r.toLowerCase()` vs lowercase `ROLES` constants), covering PascalCase `Admin`/`SuperAdmin` from the token. The gate fires in two places (login-time in `page.tsx:91-98`, and continuously in `useAdminGuard` via `tokenGrantsAdmin`). A non-admin with valid credentials is signed out and shown the forbidden banner — never enters the shell.
- **Hydration / re-entry gap closed:** `authStore.hydrate()` flips status to `signed-in` purely on token presence, but `useAdminGuard` re-decodes the token (`tokenGrantsAdmin(accessToken)`) on every render — so a hydrated non-admin token is still redirected. No path lets a parent/student token reach the shell.
- **Token storage / XSS:** sessionStorage only (no `localStorage`). See findings #2 and #4.
- **No token logging:** CONFIRMED. No `console.*` calls in `apps/admin-dashboard` or `packages/api-client/src`. No token value placed in URLs, error messages, or banner copy. Sign-in errors map to generic user-facing strings.
- **Sign-out completeness:** CONFIRMED. `useSignOut` calls the server Sign-Out (best-effort), then `authStore.signOut()` which `storage.clear()`s sessionStorage and nulls in-memory `accessToken`/`refreshToken`/`user` and sets status `signed-out`, then `router.replace('/login')`. A subsequent protected visit is redirected by the guard (token gone). No residual session.
- **Secrets / config:** CONFIRMED no hardcoded secrets/API keys/credentials in the app. API base URL is from `NEXT_PUBLIC_API_URL` (`lib/apiClient.ts` throws early if unset). `.env.local.example` contains only the base URL placeholder. Seed password is backend-only (finding #3).
- **`skipAuth` scope:** the sign-in mutation is the only `skipAuth` caller (in `@learnexia/api-client`'s `useSignIn`); no other endpoint bypasses auth. Sign-out is an authenticated call.
- **`robots: { index: false, follow: false }`** set in the root layout metadata — the admin portal is not indexed.

## Verdict: PASS-with-notes

No Critical or High findings. All findings are Low/Info and are accepted/deferred debt explicitly documented in the brief, plan, and code comments. Nothing blocks the reviewer gate.

## Notes / accepted risks

1. **Client-only route guard** (finding #1) and **sessionStorage token storage** (finding #2) are accepted for this story; both are remediated by the same follow-up: HttpOnly-cookie auth (requires a backend cookie path — out of scope). Recommend tracking as Phase-2 hardening debt.
2. **CSP / security headers** (finding #4) — recommend adding before the admin dashboard is exposed beyond local dev; it is the highest-value cheap mitigation given JS-readable tokens. Not blocking for this auth/shell story.
3. **Seed password** (finding #3) — ops/backlog item; rotate before any production deploy. Backend `GuardJwtSecret` already prevents the default JWT secret in prod (finding #6).
4. Dependency scan: this is an FE-only story consuming existing workspace packages with no `package.json` dependency additions reviewed here beyond Next/Tamagui/react-hook-form/zod; `pnpm audit` is intentionally deferred to wave integration (the plan defers `pnpm-lock.yaml` regeneration to the lead at merge). No vulnerable package was introduced by the audited source. Recommend the lead run `pnpm audit` at wave-4 lockfile integration.

Security: PASS
