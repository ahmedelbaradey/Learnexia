### Verified-correct (no finding)

- **AC-1/AC-3 (wrong role → 403):** `AuthorzationController` now class-level `AdminOnly` with no per-action `[AllowAnonymous]` override. Catalog write actions carry `AdminOnly`. A non-admin authenticated caller resolves to 403.
- **AC-2 (unauthenticated → 401):** `UseAuthentication()` precedes `UseAuthorization()` (`Program.cs:163-164`); JWT bearer challenge yields 401 for missing/invalid token, 403 for authenticated-but-forbidden. No global filter coerces one into the other.
- **401 vs 403 consistency:** `ErrorHandlerMiddleWare` only maps thrown `UnauthorizedAccessException`→401; framework policy denials short-circuit with the correct status and never throw, so the paths do not collide. `AuthorizationLoggingMiddleware` is pass-through (logs policy name + path; **no token/PII/secret logged**) and mutates no status.
- **AC-4/AC-5 (family-scope fail-closed):** `FamilyScopeAuthorizationHandler` calls `context.Succeed(...)` only on explicit match (admin/superadmin OR self-id OR existing `ParentStudent` link row). Missing/unparsable `Id` claim → returns without succeeding. No `else Succeed`, no `try/catch` swallow, no success-on-exception. DB check fully awaited before any Succeed. Deny-by-default confirmed. The `Id` claim it depends on is emitted in the JWT (`AuthenticationIdentityService.GetClaims:200`). Parent role holds no learner permission claim (no learning module / no `Catalog.*` claim seeded to Parent).
- **Over-/under-permissioning:** `AdminOnly` resolves to `RequireRole(Admin, SuperAdmin)` (PascalCase, matching the JWT's `ClaimTypes.Role` values). Catalog reads use the default `[Authorize]` (require-authenticated) policy — a real registered policy, not a dangling string. No endpoint references a permission-claim policy (`Catalog.Create` etc.) that no role holds, so there is **no "403-everyone" trap**. No Learnexia policy depends on legacy fund-management roles (`FundManager`/`LegalCouncil`/`BoardSecretary`); those appear only in dead `UserManagementController` lookup actions already behind `AdminOnly`. No `RoleHelper` lower-case constant is used in any policy or handler.
- **AC-6 (claims scoped to real modules):** `GenerateModules()` returns only `"Catalog"`; no policies registered for non-existent modules.
- **AC-7 (secret out of source):** `appsettings.json` `JwtSettings.Secret` is the `CHANGE_ME…` placeholder, not a real key. `GuardJwtSecret` fail-fasts in Production/Staging on empty or placeholder value, defaults unknown env to Production (fail-closed). `.env`, `.env.*`, `appsettings.*.local.json` are git-ignored. No other committed provider keys found (Redis connection string is empty; DB password is the local-dev `postgres/admin` only).
- **AC-8 (authn stays anonymous):** Register-Parent, Sign-In, Validate-Token, Refresh-Token remain `[AllowAnonymous]`; Sign-Out is `[Authorize]`; health probes anonymous. No regression.

## Verdict: PASS-with-notes

No Critical or High findings. **Nothing in P1-05 blocks the reviewer gate.** The P1-05 change set (gating `AuthorzationController` + Catalog controllers, verifying Identity/Notifications gating, fail-closed family-scope, hardened JWT secret, correct 401/403 wiring) is sound and meets AC-1 through AC-8.

F2–F5 are pre-existing Low/Info backlog items.
