## Execution batches

### Batch 1 — SEQUENTIAL — `backend-feature` — BE-1 then BE-2

**BE-1 (`ISafetyLayer` + `SafeAiResult`):**
- `ISafetyLayer` in `Shared.Contracts/Ai/`:
  ```csharp
  Task<SafeAiResult> GenerateSafeAsync(AiRequest request, CancellationToken ct = default);
  ```
- `SafeAiResult(bool Allowed, string? Content, SafetyVerdict Verdict, IReadOnlyList<CheckResult> Results)` — the **only** type feature handlers consume for AI content.
- `SafetyVerdict { Allowed, Blocked, Fallback }`.
- `CheckResult(string CheckName, CheckOutcome Outcome, string ReasonCode, double? Score)`.
- `CheckOutcome { Pass, Block, NeedsRegeneration }`.

**BE-2 (check interfaces):**
- `IToxicityCheck`, `IAgeAppropriatenessCheck`, `IHallucinationCheck` each: `Task<CheckVerdict> CheckAsync(string content, Language language, CancellationToken ct)`. `IHallucinationCheck` adds an overload accepting `IReadOnlyList<CurriculumChunk>? ragContext`.
- `CheckVerdict(CheckOutcome Outcome, string ReasonCode, double? Score)`.
- `ReasonCode` — stable enum/string set (e.g. `"TOXICITY_HIGH"`, `"AGE_INAPPROPRIATE"`, `"POTENTIAL_HALLUCINATION"`, `"PASS"`) — P7-09 categorizes by these codes.

**Gate after Batch 1:** Build green. `Shared.Contracts/Ai/ISafetyLayer.cs` and domain check interfaces compile.

### Batch 2 — PARALLEL — `backend-feature` (three threads) + `backend-feature` (SafetyOptions) — BE-3, BE-4, BE-5 in parallel; BE-8 also independent

**BE-3 (ToxicityCheck):**
- Named `HttpClient` to moderation endpoint.
- Reads `SafetyOptions.ModerationApiKey` from secret config (never logged).
- Handles ar + en content (verify the chosen provider's Arabic coverage — flag as a quality risk if weak).
- **Fail-closed:** on HTTP error, timeout, or unexpected exception → return `CheckVerdict(Block, "TOXICITY_CHECK_ERROR", null)`. Never return `Pass` when the check cannot complete.

**BE-4 (AgeAppropriatenessCheck):**
- Same moderation-API pattern as BE-3 but checking for adult content / violence / age-inappropriate themes.
- Fail-closed.

**BE-5 (HallucinationCheck):**
- Heuristic-based: uncertainty language cues, ungrounded factual claims, inconsistency signals.
- Accepts `IReadOnlyList<CurriculumChunk>? ragContext` — when non-null, compare AI output against context chunks (simple token/claim overlap). When null (until P3-07), use heuristics only.
- Fail-closed.

**BE-8 (SafetyOptions — can run in parallel with BE-3/4/5):**
- `SafetyOptions` bound from `Ai:Safety`:
  - `EnableToxicityCheck` (bool, default true)
  - `EnableAgeCheck` (bool, default true)
  - `EnableHallucinationCheck` (bool, default true)
  - `MaxRegenerationAttempts` (int, default 2)
  - `ModerationProvider` (string)
  - Fallback copy keys (ar/en string — resolved from existing localization mechanism)
- Moderation API keys sourced from `IConfiguration` secret section, not from this options class.

**Gate after Batch 2:** Build green; check impls compile; `SafetyOptions` binds from test configuration.

### Batch 3 — SEQUENTIAL — `backend-feature` — BE-6

**BE-6 (SafetyLayer pipeline):**
- `GenerateSafeAsync` flow:
  1. Optional light **input screen** (flag overtly unsafe student input using `ToxicityCheck` — Q4 decision). If input is blocked → return `SafeAiResult(Allowed: false, Verdict: Blocked)` + log a `SafetyEvent`.
  2. Call `IAiGateway.CompleteAsync(request, ct)` to get raw `AiResult`.
  3. Run all three output checks **concurrently** (`Task.WhenAll(toxCheck, ageCheck, hallCheck)`).
  4. Collect all `CheckVerdict` results. If any `Block` → skip regeneration, go to step 6.
  5. If any `NeedsRegeneration` (and no `Block`) → re-call gateway (bounded by `SafetyOptions.MaxRegenerationAttempts`), re-run checks. If still failing after max attempts → go to step 6.
  6. Block path: write `SafetyEvent`, return `SafeAiResult(Allowed: false, Content: localizedFallback, Verdict: Blocked/Fallback)`. **Never return the unsafe content.**
  7. Pass path: return `SafeAiResult(Allowed: true, Content: rawResult.Content, Verdict: Allowed)`.
  8. **Fail-closed:** if any check throws / gateway throws / `CancellationToken` fired → block + fallback. Never return unscreened content on error.

**Gate after Batch 3:** `SafetyLayer` compiles. Unit tests: (a) toxic input → blocked, `SafetyEvent` written, fallback returned; (b) safe input → allowed; (c) check throws → blocked (fail-closed); (d) regeneration path — first response blocked, regenerated response safe → safe returned.

### Batch 4 — PARALLEL — `db-migration` (BE-7) and `backend-feature` (BE-9) — run concurrently

**BE-7 (SafetyEvent migration):**
- Entity:
  ```
  ai.SafetyEvents
  Id (int, PK)
  StudentId (int — plain int, NO FK, no cross-module navigation)
  TaskKind (string/enum)
  FailedChecks (string[] / json — the check names that failed)
  ReasonCodes (string[] / json — all reason codes collected)
  ActionTaken (string enum: "Blocked" | "Regenerated" | "FallbackReturned")
  ModelId (string)
  OccurredAtUtc (datetime, UTC, indexed)
  ```
- No `PromptText`, no `ResponseText`, no `StudentName`, no `Email` — PII-light by design.
- `AiDbContext` (new or extension of existing context in `Ai.Infrastructure`): `DbSet<SafetyEvent> SafetyEvents`.
- Migration: `AddSafetyEventsTable`. Schema: `ai`. Apply manually per CONVENTIONS §13.

**BE-9 (eval-set harness — parallel with BE-7):**
- JSON file `safety-eval-set.json` with curated samples:
  - Arabic + English safe sentences (expected: all checks `Pass`).
  - Arabic + English toxic sentences (expected: `ToxicityCheck` → `Block`).
  - Age-inappropriate content in ar + en (expected: `AgeAppropriatenessCheck` → `Block`).
  - Hallucination-suspect text (ungrounded factual claim) (expected: `HallucinationCheck` → `Block` or `NeedsRegeneration`).
- xUnit `Theory` test reading each sample, running the relevant `ICheck` impl, asserting the expected `CheckOutcome`.
- Tagged with `[Trait("Category", "Eval")]` so it can be run separately in CI.
- This is the regression harness P6-02 expands. The eval-set JSON is the acceptance artifact the reviewer checks.

**Gate after Batch 4:** `AddSafetyEventsTable` migration applies cleanly. Eval-set harness runs in CI and passes (all samples assert expected verdict).

### Batch 6 — SEQUENTIAL — `security-auditor` (MANDATORY gate — highest priority in the cluster)

**Focus areas (per brief handoff — each is a potential Critical finding):**

1. **No-bypass (AC1 — Critical if violated):** verify there is genuinely no code path to obtain AI content (`AiResult`) without passing through `ISafetyLayer`. Check every handler and service in the codebase — no direct `IAiGateway` call from outside the safety layer.
2. **Fail-closed (Critical if violated):** if any check throws, times out, or returns an unexpected result, the pipeline must block + fallback. Verify the error path for each check. A fail-open path (returning unscreened content on error) is an automatic Critical.
3. **Child-safety completeness:** all three checks are wired and **enabled by default** (`SafetyOptions` defaults). No flag that silently disables checks in prod without explicit config change.
4. **Unsafe-content handling:** unsafe content is never returned to the client AND never written to general logs in raw form. Only reason codes / hashes in `SafetyEvent`. Verify the block path in `SafetyLayer.GenerateSafeAsync`.
5. **Moderation provider secrets:** keys sourced from secret store, never literals, never in `SafetyOptions` class fields that end up in logs.
6. **Regeneration bound:** `MaxRegenerationAttempts` is finite; no infinite loop possible.
7. **Log PII:** `SafetyEvents` carries `StudentId` (plain int), no name/email, no prompt/response body. Verify the entity definition.
8. **Arabic-language safety quality:** if the moderation provider has weak Arabic coverage, flag as a High finding (quality risk for the child-safety mandate).

**Critical/High findings block the reviewer gate.**
