### Batch 3 — PARALLEL — `backend-feature` agent — BE-4 ‖ BE-7

**Depends on:** Batch 2 complete.
**Mode:** BE-4 and BE-7 are independent; run in parallel (two agent threads or two sequential tasks in one agent pass — both read from BE-1 entity and BE-2 constants).

**BE-4 — `GlobalSettingsProvider` (DB + Redis-cached):**

- Implements `IGlobalSettingsProvider`.
- On startup (`IHostedService.StartAsync`): load all `GlobalSetting` rows from DB; store each as `IDistributedCache.SetString("global_settings:{key}", value, new DistributedCacheEntryOptions { AbsoluteExpirationRelativeToNow = TimeSpan.FromHours(24) })`.
- `GetInt(key, defaultValue)`: `var raw = await cache.GetStringAsync("global_settings:{key}")`; if null, load from DB and re-cache; if still null, return `defaultValue`; parse and return.
- `InvalidateCacheAsync(key)`: `await cache.RemoveAsync("global_settings:{key}")`.
- `IMemoryCache` fallback: wrap the `IDistributedCache` call in try/catch; on exception, fall back to `IMemoryCache` lookup; log the Redis failure via `ILoggerManager`.
- Registered as Singleton (confirm: `IDistributedCache` is Singleton by default; `GlobalSettingsProvider` holds no scoped dependencies — Singleton is appropriate).

**BE-7 — `GetGlobalSettingsQuery` (admin read):**

Returns `BaseResponse<GlobalSettingsDto>` where `GlobalSettingsDto` contains `IReadOnlyList<GlobalSettingDto>` sorted by key. `GlobalSettingDto`: `Key`, `Value`, `Type`, `UpdatedBy`, `UpdatedAt`. `[Authorize("Admin")]`. No `ValidationBehavior` (query). `ILoggerManager`.

**Gate after Batch 3:** `dotnet build` green; `GlobalSettingsProvider` resolves; a DB-round-trip is observable (or cache hit after warm-up); `GetGlobalSettingsQuery` returns all 13 seeded keys.

### Batch 4 — SEQUENTIAL — `backend-feature` agent — BE-5 + BE-6 + BE-8 + BE-9

**Depends on:** Batch 3 complete.
**Agent:** `backend-feature`

**BE-5 — `UpdateGlobalSettingCommand`:**

```csharp
public record UpdateGlobalSettingCommand(
    string Key,
    string NewValue
) : ICommand<BaseResponse<bool>>;
```

Handler steps:
1. `ValidationBehavior` runs `UpdateGlobalSettingValidator` (BE-6) automatically.
2. Load `GlobalSetting` row by `Key`; if absent, return `Successed=false` + "Key not found" (should not occur for managed keys; belt-and-braces guard).
3. Capture `oldValue = row.Value`.
4. Call `row.Update(NewValue, currentUserId, UtcNow)`.
5. Begin explicit transaction.
6. `SaveChangesAsync`.
7. `IAuditLogWriter.WriteAsync(entityType: "GlobalSetting", entityKey: Key, action: "Update", oldValues: { Value: oldValue }, newValues: { Value: NewValue }, performedBy: currentUserId, performedAt: UtcNow)`.
8. Commit transaction.
9. `await provider.InvalidateCacheAsync(Key)`.
10. Return `BaseResponse<bool> { Successed = true }`.

`[Authorize("Admin")]`. `ILoggerManager`. `currentUserId` from `ICurrentUserService`.

**BE-6 — `UpdateGlobalSettingValidator`:**

FluentValidation rules (auto-run via `ValidationBehavior`):
- `Key` must be in `GlobalSettingKeys.ManagedKeys` (`.Must(k => GlobalSettingKeys.ManagedKeys.Contains(k)).WithMessage("Unknown or unmanaged key.")`).
- `NewValue` not null/empty.
- For Int-typed keys: `NewValue` parseable as `int`.
- For Decimal-typed keys: `NewValue` parseable as `decimal`.
- Per-key range rules:
  - `ai_cost.*` keys and `credits.*_cap` / `credits.*_monthly` / `credits.pack_size`: parsed value `>= 0`.
  - `credits.free_monthly`, `credits.premium_monthly`, `credits.pack_size`, `credits.pack_price_egp`: `> 0`.
  - `ai_cache.auto_approval_confidence`: `>= 0.0` and `<= 1.0`.
  - `credits.free_daily_cap`: cross-key check — load `credits.free_monthly` current value from DB; parsed new daily cap must be `<= current free_monthly`.
  - `credits.premium_daily_cap`: cross-key check — load `credits.premium_monthly` current value from DB; parsed new daily cap must be `<= current premium_monthly`.

Cross-key reads in the validator use a direct DB query (not from cache — to avoid stale read during concurrent updates).

### Batch 5 — SEQUENTIAL — `security-auditor` agent (authz + safety gate)

**Depends on:** Batch 4 complete.

**Audit focus (security-sensitive: economy config + admin-authz):**

- **Admin-only writes (CRITICAL):** every `GlobalSettingsController` endpoint — especially `PUT` — is behind the admin policy. A parent/student/child caller must not be able to write a setting. Grep for `[Authorize` on the controller and confirm the policy name matches the P7 admin policy.
- **Key allowlist enforcement (CRITICAL):** `UpdateGlobalSettingValidator` must reject any key not in `GlobalSettingKeys.ManagedKeys`. Confirm the validator runs via `ValidationBehavior` and cannot be bypassed by passing an allowlisted-looking key with injected characters.
- **Value type/range validation (HIGH):** every managed key has a declared type and range. Confirm the validator enforces types server-side (not only in admin UI); confirm negative-cost and out-of-range values are rejected before the DB write.
- **Audit completeness (HIGH):** every successful `UpdateGlobalSettingCommand` execution writes old→new, key, performer, timestamp to `Moderation.AuditLog`. Confirm the audit write is inside the explicit transaction so a DB failure rolls back both the setting update and the audit.
- **No payment secrets in `GlobalSetting` (HIGH):** confirm `GlobalSettingKeys.ManagedKeys` contains no API key / secret field names, and that the entity schema has no secret-typed field. Payment-gateway keys belong in the secret store (P9-06), not here.
- **Cache-poisoning resistance:** confirm the Redis cache key `"global_settings:{key}"` is built from the validated managed-key only (never from raw user input that bypasses the allowlist). A key like `"global_settings:../../../admin"` must be impossible.
- **Never-retroactive (MEDIUM):** confirm `UpdateGlobalSettingCommand` has no code path that writes to `CreditTransaction` rows. The command updates only `GlobalSetting` rows and writes an audit record. Grep for `CreditTransaction` in the command handler.
- **Cross-key validator DB read (MEDIUM):** the validator loads related keys from DB directly for cross-key checks. Confirm this read is not injectable (uses parameterised EF query by `GlobalSettingKeys.*` constants — not user-supplied key values).
