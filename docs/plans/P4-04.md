## Acceptance criteria (verbatim from story)

1. **AC1** — A student starts a session with a set number of hearts; a wrong answer deducts one.
2. **AC2** — When hearts reach zero, the student enters Practice Mode rather than being hard-blocked.
3. **AC3** — Hearts-remaining is stored on the profile and shown in the lesson/quiz UI.
4. **AC4** — Heart loss is triggered by the `AnswerSubmitted` event (P4-01), consistent with instant feedback (P2-07).

**`LazyHeartRefiller.cs`** at `Gamification.Domain/Services/` — pure static:

```csharp
/// <summary>
/// Pure helper — computes how many hearts have regenerated since the last refill tick.
/// Zero side-effects. All arguments are value types. Unit-tested at boundaries.
/// </summary>
public static (int NewHearts, DateTime? NewLastRefillAtUtc, int Regenerated) Compute(
    int currentHearts,
    int cap,
    DateTime? lastRefillAtUtc,
    DateTime nowUtc,
    int intervalMinutes)
```

Logic:
- If `currentHearts >= cap` — return `(currentHearts, null, 0)` (clock idle; null clears the timestamp).
- If `lastRefillAtUtc is null` — return `(currentHearts, null, 0)` (clock not running).
- `elapsed = (nowUtc - lastRefillAtUtc.Value).TotalMinutes`.
- `heartsToAdd = (int)(elapsed / intervalMinutes)`. If 0 → `(currentHearts, lastRefillAtUtc, 0)` (no change).
- `newHearts = Math.Min(cap, currentHearts + heartsToAdd)`.
- `actualAdded = newHearts - currentHearts`.
- `newLastRefillAt = (newHearts >= cap) ? null : lastRefillAtUtc.Value + TimeSpan.FromMinutes(actualAdded * intervalMinutes)`.
- Return `(newHearts, newLastRefillAt, actualAdded)`.

The `null` returned for `newLastRefillAt` when at-cap is the sentinel that means "clock idle." This prevents the "at cap with a stale timestamp" state.

### B2a-3 — Extend `StudentXpProfile` with heart mutation methods

Add to `StudentXpProfile.cs` (the properties were added in B1-1):

```csharp
/// <summary>
/// Derived — true when Hearts == 0. Reward paths use this to short-circuit.
/// [NotMapped] — not a stored column; EF must not attempt to map it.
/// </summary>
[NotMapped]
public bool InPracticeMode => Hearts == 0;

/// <summary>
/// Applies lazy refill via <see cref="LazyHeartRefiller.Compute"/> then decrements Hearts by 1
/// (min 0). Updates <see cref="LastHeartRefillAtUtc"/> = occurredAtUtc (clock resets on loss —
/// Duolingo semantics: next heart refills 30 min from THIS loss). Raises
/// <see cref="HeartsDepletedDomainEvent"/> when Hearts transitions to 0.
/// Hearts == 0 already → decrement is a no-op (clamped by Math.Max); audit row is still written
/// by the handler (D7 / A9 — wrong answer happened, audit reflects it).
/// </summary>
public void LoseHeart(DateTime occurredAtUtc, int cap, int intervalMinutes)
{
    var (refilled, newLastRefill, _) = LazyHeartRefiller.Compute(
        Hearts, cap, LastHeartRefillAtUtc, occurredAtUtc, intervalMinutes);
    Hearts = refilled;
    LastHeartRefillAtUtc = newLastRefill;

    var wasInPracticeMode = InPracticeMode;
    Hearts = Math.Max(0, Hearts - 1);
    LastHeartRefillAtUtc = occurredAtUtc;  // reset refill clock to time of loss

    if (!wasInPracticeMode && InPracticeMode)
        RaiseDomainEvent(new HeartsDepletedDomainEvent(StudentId, occurredAtUtc));
}

/// <summary>
/// Adds +1 heart (capped). Called on a correct answer while in Practice Mode
/// (RegenOnCorrectAnswerInPracticeMode = true). Raises <see cref="HeartsRefilledDomainEvent"/>
/// when Hearts transitions out of 0.
/// </summary>
public void RegainHeartFromPractice(DateTime occurredAtUtc, int cap)
{
    var before = Hearts;
    Hearts = Math.Min(cap, Hearts + 1);
    LastHeartRefillAtUtc = occurredAtUtc;
    if (before == 0 && Hearts > 0)
        RaiseDomainEvent(new HeartsRefilledDomainEvent(StudentId, before, Hearts, occurredAtUtc));
}

/// <summary>
/// Applies lazy refill bookkeeping without raising domain events. Used by reward command handlers
/// to ensure Practice Mode check uses a fresh hearts value.
/// </summary>
public void RefreshHeartsAgainst(DateTime nowUtc, int cap, int intervalMinutes)
{
    var (newHearts, newLastRefill, _) = LazyHeartRefiller.Compute(
        Hearts, cap, LastHeartRefillAtUtc, nowUtc, intervalMinutes);
    Hearts = newHearts;
    LastHeartRefillAtUtc = newLastRefill;
}
```

## Top 3 risks

**R1 (HIGH) — Forgetting the Practice-Mode gate in one of the 3 reward handlers.**
Silent AC2 failure: XP or streak awards while Hearts == 0. Mitigation: test cases T6 / T8 / T9 each target a different handler independently. Reviewer must verify all 3 handlers carry the gate before approving.

**R2 (HIGH) — Ghost heart-loss on Learning transaction rollback (ADR 0002 §3 acknowledged risk).**
Producer (P2-07) publishes `AnswerSubmittedIntegrationEvent` inside Learning's UoW. If Learning rolls back AFTER the event was published, a `HeartLoss` row is written for an answer that never persisted. The `OriginEventId` unique index prevents double-loss on replay but the single ghost loss remains and can unfairly put a student in Practice Mode. Mitigation: accepted per ADR 0002; document in HANDOFF as P4-12 outbox follow-up. Test suite cannot easily reproduce this (cross-transaction scenario).

**R3 (MED) — Lazy refill persist-on-read race condition in `StudentHeartsQuery`.**
Two simultaneous dashboard fetches for the same student both compute `+1 heart` and race to `ExecuteUpdateAsync`. Without a `WHERE LastHeartRefillAtUtc = @oldValue` guard clause, the second update clobbers the first (idempotent in outcome — same target value — but the second write is redundant). Mitigation: include the WHERE-guard in the `ExecuteUpdateAsync` call to make it conditional + safe; document the acceptable marginal race; verify outcome is idempotent in test T11.
