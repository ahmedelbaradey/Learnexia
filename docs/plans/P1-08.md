### Key ordering rationale

1. FE-1 before everything: Tamagui config object is the foundation; `packages/ui` cannot import tokens until the config exists and is built.
2. FE-2 before FE-3: fonts must be registered in the Tamagui config before the RTL provider can select font families by locale.
3. FE-3 before FE-4: the RTL provider/hook is used by every component; its API must be stable before components are written.
4. FE-4 before FE-5 and FE-6: `Button` and `Card` establish the component authoring patterns (token usage, touch-target enforcement, press feedback, package structure) that FE-5 gamification components follow; `packages/ui` scaffold lives in FE-4.
5. FE-5 and FE-6 can run in parallel because they target different component files with no shared writes (FE-6 applies a11y rules to components already created by FE-4/FE-5 — the implementer should apply FE-6 rules as FE-5 components are written, treating them as one merged sub-task if done by a single agent).
6. FE-7 last: the catalog can only demonstrate what is already implemented.

### Batch 1 — Frontend: design-system foundation (sequential)

**Agent:** `frontend`
**Mode:** sequential (FE-1 → FE-2 → FE-3; each step depends on the previous)
**Consumes:** Design Spec from Batch 0 + `design-system/colors_and_type.css`
**Target package:** `packages/design-system` (currently empty stub — scaffold from scratch)

#### Step 1a — FE-1: Package scaffold + Tamagui token config

Files to create:
- `packages/design-system/package.json` — mirror `packages/shared` conventions: `type: module`, `main/types: ./src/index.ts`, subpath exports (`.` and `./config`), scripts (`build: tsc --build`, `lint`, `type-check`); add deps: `tamagui`, `@tamagui/config`, `@tamagui/core`; devDeps: `@learnexia/eslint-config`, `@learnexia/tsconfig`, `typescript`, `eslint`
- `packages/design-system/tsconfig.json` — extends `@learnexia/tsconfig/react-library.json`, add `composite: true`, `outDir: ./dist`, `rootDir: ./src`
- `packages/design-system/src/tokens/index.ts` — define all token objects from `colors_and_type.css` (colors, gamification accents, surfaces, gradients as string constants, spacing scale as numeric, radii, shadows, motion durations/easings)
- `packages/design-system/src/tamagui.config.ts` — `createTamagui({ tokens, themes: {}, fonts: {}, media: {} })` using the token objects; export as named `tamaguiConfig`
- `packages/design-system/src/index.ts` — barrel export of config + tokens
- `packages/design-system/eslint.config.js` — mirror `packages/shared/eslint.config.js`

Token encoding rules (from `colors_and_type.css`):
- Colors: 5-step primary (`#4F46E5` base + hover/press/soft/glow), secondary/success, accent/reward, danger, purple/badge; gamification: xp `#FACC15`, streak `#FB923C`, heart `#FB7185`, gold `#FBBF24`, gem `#38BDF8`; surfaces: bg `#0F172A`, bg-elevated `#111B33`, card `#1E293B`, card-soft `#334155`; text: fg1/fg2/fg3; borders; overlay
- Gradients: xp `linear-gradient(90deg,#22C55E,#4F46E5)`, reward, levelup — stored as string constants (Tamagui does not model gradients natively; expose as a `gradients` export consumed by components directly)
- Spacing: 4/8/12/16/20/24/32/40/48/64 (keys `$1`…`$16` or semantic names — pick one scheme and document it)
- Radii: sm `8`, button `16`, card `20`, modal `24`, pill `9999`
- Shadows: soft, float, popup, glow variants — stored as string constants (Tamagui `createTokens` accepts shadow tokens as strings)
- Motion: ease-out, ease-spring (as CSS cubic-bezier strings for web; document RN equivalents), durations: fast `120`, base `240`, slow `400`, celebrate `700` (ms)

#### Step 1b — FE-2: Fonts + themes + media queries

Files to create/extend:
- `packages/design-system/src/fonts/index.ts` — `createFont()` calls for Poppins (face: Regular/Medium/SemiBold/Bold/ExtraBold/Black), Cairo (face: Regular/Medium/SemiBold/Bold/ExtraBold — Arabic display), Tajawal (face: Regular/Medium/Bold/ExtraBold — Arabic body). Use `require()` / `Platform.select` pattern for native `.ttf` paths from `design-system/fonts/`; use font-family name string for web (fonts loaded via CSS on web). Note: Cairo `.ttf` files ARE present locally in `design-system/fonts/` — use them for native (Cairo-Regular.ttf, Cairo-Bold.ttf, etc.). No Google Fonts fallback needed for native.
- `packages/design-system/src/themes/index.ts` — `createTheme()` for `dark` (default game-world palette mapping tokens → semantic slots: `background`, `backgroundStrong`, `color`, `colorHover`, `borderColor`, etc.) and `light` (parent/print palette with `--lx-bg-light` surface). Dark is the default.
- `packages/design-system/src/media.ts` — media query breakpoints: `sm: { maxWidth: 767 }`, `tablet: { minWidth: 768 }`, `laptop: { minWidth: 1024 }`
- Update `src/tamagui.config.ts` to include fonts, themes, media queries
- Update `src/index.ts` exports

#### Step 1c — FE-3: RTL wiring

Files to create:
- `packages/design-system/src/rtl/index.ts` — a `LearnexiaProvider` component that wraps `TamaguiProvider` from Tamagui; accepts a `locale` prop; on locale change: (a) selects the correct font family (Poppins for LTR, Cairo for AR display / Tajawal for AR body) and passes it as the active font override, (b) calls `applyWebDirection(locale)` on web, (c) exposes `applyNativeRtl` from `@learnexia/shared/i18n` as a re-export with the native-reload caveat documented in JSDoc. Do NOT re-implement RTL detection — call `isRtlLocale` / `directionForLocale` from `@learnexia/shared/i18n`. Do NOT import RN-specific modules (`I18nManager`, `react-native-restart`) in this package — the app injects them via `applyNativeRtl`.
- `packages/design-system/src/rtl/useDirection.ts` — `useDirection(locale: string): Direction` hook calling `directionForLocale` from shared.
- Update `src/index.ts` to export `LearnexiaProvider` and `useDirection`.

**Batch 1 review gate:** `reviewer` checks that `packages/design-system` compiles cleanly (`tsc --build`), tokens match `colors_and_type.css` values (spot check 10 vars), RTL provider API is correct and does not duplicate `packages/shared` logic, and package.json conventions mirror `packages/shared`. Reviewer PASS unlocks Batch 2.

## Parallelism notes

Within this story, all batches are **sequential** (each depends on the previous). There is no cross-story parallelism concern here because P1-08 touches only `packages/design-system` and `packages/ui` — both of which are new, stub files only. No shared-file edits to `pnpm-workspace.yaml` / `turbo.json` / `apps/` are required (the scaffold already exists from PKG-FOUNDATION-FE).

The one internal parallelism opportunity is FE-5 + FE-6: the `frontend` agent may implement gamification components and apply accessibility rules in a single combined pass, treating them as one merged task, since they target the same component files and a single agent working top-to-bottom is more efficient than two separate agents writing to the same files.
