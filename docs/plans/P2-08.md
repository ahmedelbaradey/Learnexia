### Optional performance migration (Batch 1 decision)
The per-student query (`GET /Students/{id}/Attempts`) filters on both `StudentId` and potentially `Status`. The existing `IX_Attempts_StudentId` single-column index covers the lookup; a composite `(StudentId, Status)` index would benefit queries that filter by both. This is **recommended but not blocking**.

- If accepted: migration named `AddAttemptQueryIndexes`, schema `learning`, adds composite index `IX_Attempts_StudentId_Status` on `(StudentId, Status)`.
- If deferred: single-column index is sufficient for correctness; add the composite index in a follow-on perf pass.
- **Decision for the db-migration agent:** run `dotnet ef migrations add` only if the planner accepts the perf index. If adding no indexes, produce NO migration (an empty migration must not be committed).

**Command shape:**
```csharp
public record SubmitAnswerCommand : SubmitAnswerDto, ICommand<BaseResponse<SubmitAnswerResponse>> { }

public record SubmitAnswerDto
{
    // AttemptId from route — injected by controller, not in DTO body
    public int AttemptId { get; set; }
    public int QuestionId { get; set; }
    public string AnswerPayload { get; set; } = null!;
    public int TimeSpentSeconds { get; set; }
    public bool HintUsed { get; set; }
}
```

**Response shape:**
```csharp
public class SubmitAnswerResponse
{
    public bool IsCorrect { get; set; }
    // CorrectAnswer is conditionally included only when wrong (P2-07 contract).
    // Null when IsCorrect=true so client never gets it for free.
    public string? CorrectAnswer { get; set; }
    public bool HintAvailable { get; set; }  // stub = false; P2-07 will wire this to hint logic
}
```

**Handler logic (in order):**
1. Resolve `studentId` from `_currentUser.UserId`; if null → `Unauthorized`.
2. Load `Attempt` by `AttemptId` with tracking (needs update later in Complete/Abandon, but SubmitAnswer only adds a child row — no Attempt field update here). If not found → `NotFound`.
3. Check `attempt.StudentId == studentId` → else `Unauthorized` (ownership).
4. Check `attempt.Status == AttemptStatus.InProgress` → else `BusinessValidation` (HTTP 424, attempt not in progress — 409-equivalent).
5. Load `QuizQuestion` by `request.QuestionId` where `question.LessonId == attempt.LessonId` (guard cross-lesson answer injection). If not found → `NotFound`.
6. Compare `request.AnswerPayload` to `question.CorrectAnswer` server-side. Correctness logic: for this story, case-insensitive string equality on the raw JSON values is sufficient (P2-07 will refine per `QuestionType`). Set `isCorrect`.
7. Stage a new `StudentAnswer` via `_repository.Learning.AddAsync(...)`. Do NOT call SaveChanges — `UnitOfWorkBehavior` commits.
8. Return `BaseResponse<SubmitAnswerResponse>` with `IsCorrect`, `CorrectAnswer` (null if correct, the value if wrong), `HintAvailable = false` (stub).
9. Do NOT publish `AnswerSubmittedIntegrationEvent` yet — that is P2-07-BE-3. Leave a `// TODO P2-07: publish AnswerSubmittedIntegrationEvent here` comment.
10. Wrap in `try/catch` → `_logger.LogError` + `ServerError`.

**Re-answer idempotency (resolved decision):** if a `StudentAnswer` already exists for this `AttemptId + QuestionId`, **reject** with `BusinessValidation` ("question already answered in this attempt"). This keeps the accuracy denominator clean and avoids ambiguous updates.

**Validator rules:**
- `AttemptId > 0`
- `QuestionId > 0`
- `AnswerPayload` not empty / not null
- `TimeSpentSeconds >= 0`

**Controller action (add to `QuizzesController`):**
```csharp
[HttpPost("{attemptId}/Answers")]
[Authorize(Roles = "Student")]
public async Task<IActionResult> SubmitAnswer([FromRoute] int attemptId, [FromBody] SubmitAnswerCommand command)
{
    command = command with { AttemptId = attemptId };
    return NewResult(await Mediator.Send(command));
}
```

**Mapping additions to `QuizProfile`:** add `CreateMap<SubmitAnswerCommand, StudentAnswer>()` (field mapping: `AnswerPayload`, `TimeSpentSeconds`, `HintUsed`, `IsCorrect` — `IsCorrect` is computed in the handler, not from the command, so `ForMember(dest => dest.IsCorrect, opt => opt.Ignore())`).

**UoW note:** this handler only stages one `StudentAnswer.AddAsync`. No explicit `SaveChangesAsync`. `UnitOfWorkBehavior` commits the entire command atomically.

**Completion gate:** `dotnet build` passes; `POST /api/Learning/Quizzes/{attemptId}/Answers` exists in Swagger; validator rejects invalid input.

**Shared aggregate computation logic (private static helper, usable by both handlers):**

```
static void RecomputeAggregates(Attempt attempt, IList<StudentAnswer> answers)
{
    var answered = answers.Count;
    var correct  = answers.Count(a => a.IsCorrect);

    attempt.AccuracyPercentage = answered == 0 ? 0.0
                                               : Math.Round((double)correct / answered * 100, 2);
    attempt.DurationSeconds    = (int)(DateTime.UtcNow - attempt.StartedAt).TotalSeconds;
                                // Server-side elapsed time is authoritative for total duration.
                                // Per-question TimeSpentSeconds is advisory (client-reported).
    attempt.HintsUsedCount     = answers.Count(a => a.HintUsed);
    attempt.CompletedAt        = DateTime.UtcNow;
}
```

Do not introduce a new design pattern (Strategy, service class, etc.) for this helper without asking the lead first. Implement as a `private static void` method called from both handlers, or duplicate the ~6 lines if the static helper creates any cross-handler coupling concern. Either approach is acceptable; keep it simple.

**CompleteAttemptCommandHandler logic:**
1. Resolve `studentId` from JWT; if null → `Unauthorized`.
2. Load `Attempt` with tracking (needs update). If not found → `NotFound`.
3. Ownership check: `attempt.StudentId == studentId` → else `Unauthorized`.
4. Status check: if `attempt.Status == Completed` → idempotent return of current state (do not error). If `attempt.Status == Abandoned` → `BusinessValidation` ("attempt already abandoned").
5. Load all `StudentAnswer` rows for this `AttemptId` (fresh query — not cached in-memory — to guard against concurrent submits).
6. Call `RecomputeAggregates(attempt, answers)`.
7. Set `attempt.Status = AttemptStatus.Completed`.
8. Stage update via `_repository.Learning.UpdateAsync(attempt)`.
9. Publish `LessonCompletedIntegrationEvent` (stub) — leave a `// TODO P2-07: publish LessonCompletedIntegrationEvent` comment. The event record already exists in `Shared.Contracts.Learning`.
10. Return `BaseResponse<AttemptSummaryDto>`.

**AbandonAttemptCommandHandler logic:**
1–4. Same ownership/status guards.
4a. If `attempt.Status == Abandoned` → idempotent return of current state.
4b. If `attempt.Status == Completed` → `BusinessValidation` ("attempt already completed").
5. Load all `StudentAnswer` rows (fresh query). Zero answers is valid (accuracy = 0).
6. Call `RecomputeAggregates(attempt, answers)`.
7. Set `attempt.Status = AttemptStatus.Abandoned`.
8. Stage update.
9. Return `BaseResponse<AttemptSummaryDto>`.

**Validators (commands only):**
- `CompleteAttemptValidation`: `AttemptId > 0`.
- `AbandonAttemptValidation`: `AttemptId > 0`.

**Controller actions (add to `QuizzesController`):**
```csharp
[HttpPost("{attemptId}/Complete")]
[Authorize(Roles = "Student")]
public async Task<IActionResult> CompleteAttempt([FromRoute] int attemptId)
    => NewResult(await Mediator.Send(new CompleteAttemptCommand { AttemptId = attemptId }));

[HttpPost("{attemptId}/Abandon")]
[Authorize(Roles = "Student")]
public async Task<IActionResult> AbandonAttempt([FromRoute] int attemptId)
    => NewResult(await Mediator.Send(new AbandonAttemptCommand { AttemptId = attemptId }));
```

**UoW note:** both handlers stage Attempt update via `UpdateAsync`. `UnitOfWorkBehavior` commits atomically. The fresh query for `StudentAnswer` rows happens inside the same EF DbContext scope (same request), so the read is consistent with in-flight staged changes.

**Concurrency risk note:** a race between a final `SubmitAnswer` and `CompleteAttempt` arriving simultaneously could produce inconsistent aggregates. The `UnitOfWorkBehavior` transaction wraps each command independently, so a `SubmitAnswer` that commits just after `CompleteAttempt` reads its snapshot will not be included. This is acceptable for Phase 2 — document it in the handler comment. Pessimistic locking is a Phase 3+ concern.

**Completion gate:** `dotnet build` passes; both endpoints in Swagger; partial-answer test case (manually) shows non-zero aggregates and `Abandoned` status.

**GetStudentAttemptsQueryHandler logic:**
1. Inline validation: `studentId > 0` → else `BadRequest`.
2. Authorization scope: check `studentId == _currentUser.UserId` → else `Unauthorized`. (A student may only read their own attempts. Parent/admin scoping is Phase 5/7.)
3. Query `Attempts` where `StudentId == studentId` ordered by `StartedAt` descending (most recent first). No paging required for Phase 2 (add `BaseListDto` paging parameter if the lead requests it — default to no paging for now).
4. Project to `AttemptListItemDto` via AutoMapper `ProjectTo`.
5. Never expose `CorrectAnswer` — it is not in `AttemptListItemDto`.
6. Return `BaseResponse<List<AttemptListItemDto>>`. If empty → `EmptyCollection(...)`.

**GetSkillStatsQueryHandler logic:**
1. Inline validation: `skillId > 0`, `studentId > 0` (query string param) → else `BadRequest`.
2. Authorization: check `studentId == _currentUser.UserId` → else `Unauthorized`. Scope is per-student (a student's own mastery signal), not platform-wide.
3. Query:
   ```
   StudentAnswers
     .Include(sa => sa.Question)
     .Where(sa => sa.Question.SkillId == skillId
               && sa.Attempt.StudentId == studentId)
   ```
   Note: `QuizQuestion.SkillId` is nullable — the `WHERE` clause only picks up questions with that skill assigned. Questions without a skill are silently excluded (correct behavior, documented in brief).
4. If no matching answers → return zeroed `SkillStatsDto` (do not 404 or 500).
5. Aggregate in memory (or via LINQ grouping):
   - `TotalAnswers = count`
   - `CorrectAnswers = count where IsCorrect`
   - `AccuracyPercentage = TotalAnswers == 0 ? 0 : Math.Round(CorrectAnswers / TotalAnswers * 100.0, 2)`
   - `AvgTimeSpentSeconds = TotalAnswers == 0 ? 0 : answers.Average(a => a.TimeSpentSeconds)`
   - `HintUsageRate = TotalAnswers == 0 ? 0 : Math.Round(answers.Count(a => a.HintUsed) / (double)TotalAnswers * 100, 2)`
6. Return `BaseResponse<SkillStatsDto>`.

4. **SubmitAnswer — ownership violation:** JWT for student A, `attemptId` belonging to student B → 401 (Unauthorized).
5. **SubmitAnswer — non-existent attempt:** `attemptId` that does not exist → 404.
6. **SubmitAnswer — non-InProgress attempt:** attempt in `Completed` or `Abandoned` state → 424 (BusinessValidation).
7. **CompleteAttempt — happy path:** start attempt, submit 3 answers (mix of correct/wrong), POST Complete → `Status=Completed`, `AccuracyPercentage = correct/3 * 100`, `CompletedAt` not null, `DurationSeconds > 0`.
8. **CompleteAttempt — zero answers:** start attempt, immediately Complete → `AccuracyPercentage=0`, no divide-by-zero.
9. **CompleteAttempt — idempotent:** call Complete twice → second call returns 200 with existing completed state (not 500 or error).
10. **AbandonAttempt — partial (BE-3 signal capture):** start attempt, submit 2 of 5 answers, POST Abandon → `Status=Abandoned`, `CompletedAt` set, aggregates computed over those 2 answers (not 5), previously-submitted answers rows still present in DB.
11. **AbandonAttempt — zero answers:** start attempt, immediately Abandon → `AccuracyPercentage=0`, `HintsUsedCount=0`, `DurationSeconds > 0` (server elapsed), no error.
12. **AbandonAttempt — already abandoned (idempotent):** call Abandon twice → second returns current state, no error.
13. **GetStudentAttempts — self:** seed 2 attempts for student, `GET /Students/{id}/Attempts` with that student's JWT → returns 2 items with correct aggregates; no `CorrectAnswer` field in any response item.
14. **GetStudentAttempts — other student IDOR:** student A calls `GET /Students/{studentB_id}/Attempts` → 401.
15. **GetSkillStats — with data:** seed answers for skill → `GET /Skills/{id}/Stats?studentId=X` returns correct `TotalAnswers`, `CorrectAnswers`, `AccuracyPercentage`, `AvgTimeSpentSeconds`, `HintUsageRate`.
16. **GetSkillStats — no data:** skill with no answers → returns zeroed stats (not 404, not 500).
17. **GetSkillStats — questions without SkillId:** verify answers to questions with null `SkillId` are not counted in any skill's stats.

### Batch 6 — security-auditor (sequential after Batch 5)

**Agent:** `security-auditor`

This story is security-sensitive: child/student data, ownership-scoped reads, server-side correctness check.

**Focus areas:**

1. **JWT-derived StudentId — never client-supplied:** confirm `SubmitAnswerCommandHandler`, `CompleteAttemptCommandHandler`, `AbandonAttemptCommandHandler` all resolve `StudentId` from `_currentUser.UserId`, not from the request body or route.
2. **Ownership enforcement on writes:** all three write commands verify `attempt.StudentId == studentId` before any state change. Confirm the check happens before any DB write is staged.
3. **IDOR on read endpoints:** `GetStudentAttemptsQueryHandler` must verify `studentId == _currentUser.UserId`. `GetSkillStatsQueryHandler` must verify `studentId == _currentUser.UserId`. No route parameter can override the JWT-scoped identity without authorization.
4. **CorrectAnswer not leaked:** confirm `AttemptListItemDto` and `SkillStatsDto` contain no `CorrectAnswer` field. Confirm `QuizProfile` mapping ignores/excludes `CorrectAnswer` for any new maps. The existing `QuizQuestionDto` mapping already guards this; the new DTOs must not regress it.
5. **ex.Message not leaked to client:** confirm all handlers follow the `// Log server-side, return ServerError<T>()` pattern (no `ex.Message` passed to `ServerError`). The brief calls this out explicitly.
6. **TimeSpentSeconds upper bound:** client-supplied int with no upper bound is exploitable for stats inflation. Confirm validator enforces a reasonable maximum (e.g., `<= 3600` seconds — 1 hour per question is a generous but sane ceiling). If the validator does not include this bound, flag as a finding (High).
7. **Attempt cross-lesson answer injection:** `SubmitAnswerCommandHandler` should verify `question.LessonId == attempt.LessonId` when loading the question, preventing a student from submitting an answer from a different lesson into the current attempt. Confirm this check is present.

**Blocking threshold:** Critical or High findings block Batch 7. Medium/Low findings are documented but do not block.
