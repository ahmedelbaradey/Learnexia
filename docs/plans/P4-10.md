## Plan summary

P4-10 adds a Redis read-model layer over the six existing Gamification query seams (XP / streak / hearts / badges / missions / leagues) using the **decorator pattern** registered at DI composition root — so no handler or controller changes — with **read-through caching** per-seam TTL and **write-around invalidation** (DEL on the eight verified domain events). A **Redis sorted-set leaderboard** (`league:{leagueId}:standings`, scored `WeeklyXp * 16777216 + (16777215 - JoinOrder)`) is added to back P4-07's `GetMyLeagueQueryHandler` for O(log n) rank reads. A `GamificationCacheRebuilder` service plus a nightly Hangfire job at 03:00 UTC provides idempotent reconciliation. Postgres remains the sole source of truth; Redis is a derived mirror. No new endpoint, no new entity, no new migration, no FE work.

**Sub-task B1-A: BE-6 — 6 cache decorators + DI re-wire**

For each of the 6 query seams, ship a `Cached*Query` decorator class. The pattern (applied identically to all 6, with seam-specific notes below):

- Rename the existing Postgres impl from `StudentXpQuery` → `PostgresStudentXpQuery` (and similarly for the other 5). Register the concrete Postgres class directly. Register the interface via a factory delegate.
- Decorator constructor: `IStudentXpQuery inner, IGamificationCache cache, IOptions<GamificationCacheOptions> opts, ILoggerManager logger`.
- On `GetByStudentIdAsync`: (1) if `!_opts.Enabled` → delegate straight to inner; (2) attempt `_cache.TryGetAsync<StudentXpSnapshot?>(key, ct)`; (3) on hit → log `cache.gamification.xp.hit student={id}` and return; (4) on miss → delegate to inner; (5) `await _cache.SetAsync(key, result, ttl, ct)`; (6) return result.
- Null caching: `null` snapshots (brand-new students) are cached under a short TTL (15 seconds hardcoded in the decorator — prevents stampede before profile is created; not a configurable option to reduce surface area).

**Seam-specific notes:**

| Seam | Key | TTL config field | Lazy-write note |
|---|---|---|---|
| `IStudentXpQuery` | `{prefix}student:{id}:xp` | `XpTtlSeconds` | None — pure read |
| `IStudentStreakQuery` | `{prefix}student:{id}:streak` | `StreakTtlSeconds` | None — pure read |
| `IStudentHeartsQuery` | `{prefix}student:{id}:hearts` | `HeartsTtlSeconds` | Lazy-refill side-effect runs inside inner; decorator caches the post-refill snapshot on miss; cache hit skips inner entirely (no double-refill) |
| `IStudentBadgesQuery` | `{prefix}student:{id}:badges:3` | `BadgesTtlSeconds` | Only cache when `recentTake == 3`; other values pass through to inner |
| `IStudentMissionsQuery` | `{prefix}student:{id}:missions:{dailyKey}` | `MissionsTtlSeconds` | Lazy-instantiation runs inside inner; decorator caches post-instantiation snapshot; cache key rotation at period boundary forces a miss + re-run of the side-effect |
| `IStudentLeagueQuery` | `{prefix}student:{id}:league:{weeklyKey}` | `LeagueSnapshotTtlSeconds` | Lazy-placement runs inside inner; decorator caches (Tier, WeeklyXp, GroupSize) only — **`CurrentRank` is always re-derived via `ZREVRANK` on every read** (Q13 — always correct, cheap O(log n)); cached snapshot TTL is short (30s) |

Eight `INotificationHandler<TDomainEvent>` classes, all at `Gamification.Application/Features/Cache/Invalidators/`.

**Pattern for all 8:**
```csharp
public sealed class XpAwardedCacheInvalidator : INotificationHandler<XpAwardedDomainEvent>
{
    // ctor injects IGamificationCache, RedisLeagueLeaderboard, IGamificationRepository,
    //             IOptions<GamificationCacheOptions>, ILoggerManager
    public async Task Handle(XpAwardedDomainEvent ev, CancellationToken ct)
    {
        try { /* ... DEL + ZADD CH ... */ }
        catch (Exception ex)
        {
            _logger.LogWarn("P4-10: cache invalidation failed — Postgres is authoritative, nightly rebuild will reconcile.");
            _ = ex; // do NOT log ex.Message (F-09)
        }
    }
}
```

**Key invalidation map (all write-around — DEL then let next read repopulate):**

| Invalidator | Event | Keys removed | Extra sorted-set update |
|---|---|---|---|
| `XpAwardedCacheInvalidator` | `XpAwardedDomainEvent` | `{prefix}student:{id}:xp` | Yes — re-reads `WeeklyXp` + `JoinOrder` from Postgres via `IGamificationRepository.GetMembershipForStudentAsync(...)`, calls `_leaderboard.UpdateScoreAsync(...)` (ZADD CH) |
| `StudentLeveledUpCacheInvalidator` | `StudentLeveledUpDomainEvent` | `{prefix}student:{id}:xp` (idempotent — level is in the XP snapshot) | None |
| `StreakAdvancedCacheInvalidator` | `StreakAdvancedDomainEvent` | `{prefix}student:{id}:streak` | None |
| `StreakBrokenCacheInvalidator` | `StreakBrokenDomainEvent` | `{prefix}student:{id}:streak` | None |
| `HeartsDepletedCacheInvalidator` | `HeartsDepletedDomainEvent` | `{prefix}student:{id}:hearts` | None |
| `HeartsRefilledCacheInvalidator` | `HeartsRefilledDomainEvent` | `{prefix}student:{id}:hearts` | None |
| `BadgeEarnedCacheInvalidator` | `BadgeEarnedDomainEvent` | `{prefix}student:{id}:badges:3` | None |
| `MissionCompletedCacheInvalidator` | `MissionCompletedDomainEvent` | `{prefix}student:{id}:missions:{dailyKey}` AND `{prefix}student:{id}:missions:{weeklyKey}` (both cleared — Q16 recommendation) | None |

**XpAwardedCacheInvalidator** is the most complex:
- After DEL on the XP key, fetch current membership: `_repo.GetMembershipForStudentAsync(profileId, currentWeeklyKey, ct)`. If null (no lazy placement yet) → skip sorted-set update (logged as INFO).
- Call `_leaderboard.UpdateScoreAsync(membership.LeagueId, membership.Id, membership.WeeklyXp, membership.JoinOrder, ct)`.
- Two concurrent `XpAwardedDomainEvent` handlers racing the same student: each reads the post-commit `WeeklyXp` and calls `ZADD CH` — last-writer-wins equals correct-final-value (Q9 guarantee).

**Auto-registration:** all 8 handlers are in `Gamification.Application` assembly — scanned by the host `AddCrossModuleMediatR()` already. No DI change needed.
