# Execution Plan — P10-13..17 Family Energy Wallet, Child Seats, Grace/Enforcement, Redistribution & Refund Reconciliation

> **BACKEND-ONLY wave.** The 6-story "family-energy-model" cluster: P10-13..17 locked 2026-06-16; **FINAL mid-cycle seat model + P10-18 (pause/unpause) added 2026-06-17**. Re-homes energy ownership from the live per-child `CreditAccount` to a parent/family `FamilyEnergyAccount` with two non-convertible buckets, adds paid child seats (with mid-cycle money proration + no energy mint on add), payment-failure-only grace/enforcement (no mid-cycle forfeit; voluntary cancels are cycle-end events), sibling redistribution (also the mid-cycle energy mechanism), purchased-refund reconciliation, parent-control pause/unpause, and migrates off the old model via a **clean cutover** (system is pre-launch).
>
> **ALL lead gates / open questions are RESOLVED** — baked in below (see brief §6, updated 2026-06-16). This plan does NOT re-raise OQ-A..OQ-L. It encodes them.
>
> **`security-auditor` is MANDATORY on every story** in this wave (money-derived entitlement + child data). No story ships without a clean (no Critical/High) audit.
>
> **All six `*-FE` tasks (P10-13-FE..P10-18-FE) are OUT OF SCOPE** — owned by a different (frontend) lead. They are listed once under "Out of scope" and never planned, designed, or e2e-tested here.
>
> **Canonical ID mapping (user stories = source of truth): 13 wallet · 14 seats (mid-cycle money proration + no energy mint) · 15 lifecycle (payment-failure grace only + renewal-boundary enforcement — no mid-cycle forfeit) · 16 redistribution (also mid-cycle energy mechanism) · 17 refunds · 18 pause/unpause — this plan WINS over any stale task-file cross-ref.** Some BE task files carry stale internal pointers; defer to this mapping.

### Verified facts that shape this plan (from live code on `feat/phase4-ai-runtime`)
- The **`Billing` module is fully built** (P10-01..P10-12 merged) — `BillingDbContext` / schema `billing`, `CreditAccount`+`CreditTransaction` ledger (`IdempotencyKey` unique `UX_CreditTransactions_IdempotencyKey`, `RelatedPaymentId`), `Subscription` (incl. dunning `FailedAttemptCount`/`NextRetryAt`/`GraceEndsAt`), `Plan`, `Payment`/`WebhookEvent`, `IPaymentProvider`+`FakePaymentProvider`, `RefundService`, `DbBackedGlobalSettingsProvider`, `BillingGrantJob` (per-child), Hangfire jobs. **This wave EXTENDS it — no re-scaffold.**
- `ICreditSpendService.TryDebitAsync(int childId, int amount, string reasonCode, string idempotencyKey, ct)` + `GetBalanceAsync(int childId, ct)` is the frozen AI-consumed seam. **The 4 Ai handlers are NOT edited** — only the `CreditSpendService` impl behind the seam changes (allocation-row-first → shared-purchased-fallback). `DebitResult` is extended **additively via init-only properties** (`FromAllocation`/`FromPurchasedFallback`) — **NOT** new positional ctor params — leaving the existing 5-arg positional record ctor intact so the AI module + its unit tests (reading `.FromGranted`/`.FromPurchased`) compile unchanged.
- `BillingGrantJob` today is **per-child** (`ApplyGrant`/`ExpireGrant` per `CreditAccount`, reads `credits.free_monthly`/`credits.premium_monthly`). This wave **rewrites it per-family**: grant = `PlanEnergyPerSeat × ActivePaidSeats`, deposited once per family then equal-split-allocated. **No per-child grant path remains** after cutover.
- `IParentChildQuery.GetChildIdsForParentAsync(parentUserId)` and `IsParentOfChildAsync` **already exist** in `Shared.Contracts/Parent` — this is the OQ-B parent↔child seam. No new contract.
- `Subscription` already carries `GraceEndsAt` (set by P10-09 dunning, currently `= CurrentCycleEnd` after 3×24h retries). **OQ-E reconciliation:** the 7-day seat grace maps onto this same `GraceEndsAt` — one clock, not two.
- `HandleProviderWebhookCommand` already branches on `PaymentKind` (`Subscription`, `Pack`) with `WebhookEvent` dedup. This wave adds a `Seat` branch (P10-14) and refines the `refund.succeeded` branch (P10-17).
- Persistence = **Option C service-only** (CONVENTIONS §7): `Billing.Application` is EF-free; logic in `Infrastructure` services; explicit transactions (no UoW — ADR 0001). `BaseResponse<T>`/`Successed`; `ILoggerManager`; localized `SharedResourcesKey` (EN+AR), no free-text literals.

### Risks / things to watch (none block start; mitigations baked into the batches)
- **R-CUTOVER — migration cutover window.** The clean cutover retires the live per-child `CreditAccount` grant/spend/pack/refund write-paths. *Mitigation:* sequence `MigrateCreditAccountsToFamilyWallet` (Batch 1b) **after** both the `AddFamilyEnergyWallet` schema (BE-4) and the spend re-impl behind the seam (BE-7) are in; retire old paths **only after** the orphan-guard passes; idempotent + rerun-safe; security-auditor reviews the cutover. - **R-HOTROW — shared-purchased concurrency + HARDEN-01 backoff.** The single shared `PurchasedBalance` row is the only contention point when siblings hit the purchased fallback concurrently; a hot row under load risks lost updates / retry storms. *Mitigation:* keep the shared row **cold** (touched only on allocation shortfall — allocation-row-first); reuse the existing `xmin` + bounded exponential-backoff-with-jitter retry already in `CreditSpendService` (the **HARDEN-01 backoff** — clamp the shift exponent, long arithmetic, jitter, `ChangeTracker.Clear()` between attempts); api-tester must include a concurrent-sibling-fallback stress case.
