### Batch 1a — PARALLEL — `designer` agent + `frontend` agent (FE-2)

These two can start in parallel once the wire format (OQ-2) is pinned:

**1a-Designer — `designer` agent:**
- Output: `design-system/ui_kits/student-mobile/P3-12-ai-tutor.md`
- Cover (per the brief's Handoff → designer):
  - **Ask-AI / explanation surface** — where it lives (designer recommends per OQ-1); streaming typing state; progressive text; `AITutorBubble variant='ai'`.
  - **Hint flow** — contextual bubble on wrong answer (`variant='hint'`), hint-level escalation affordance ("Hint 2 of N"), "simpler explanation" chip/button; where it attaches to the `AnswerFeedbackStrip`.
  - **Loading / streaming / error / retry / declined-explanation** states — typing indicator, partial-stream, gateway-error gentle-retry copy, empty/declined copy.
  - **RTL + LTR** mirrors; **EN + AR copy** for all slots (i18n inventory).
  - **Tokens only — no raw hex/px.** Kid-a11y baseline (≥48dp targets, contrast, `accessibilityLiveRegion`).
  - Reference the existing `AITutorBubble` component API — design *to* it, do not redesign it.

**1a-FE-2 — `frontend` agent (can start in parallel with designer if wire format is pinned):**
- `useStreamingText(url, options)` hook in `packages/shared/src/hooks/useStreamingText.ts`.
- Platform-adaptive: `EventSource` on web, `fetch`+`ReadableStream`+`TextDecoder` on native (one abstraction, no library — rule 8).
- Consumes P3-04/05 SSE wire format: parse `data:` lines, detect `[DONE]` sentinel, parse `event: error` payload, emit typed `TutorError`.
- Exposed state: `{ text: string, isStreaming: boolean, error: TutorError | null, retry: () => void }`.
- Note on native (OQ-4): the native path is the trickiest risk item — budget extra time if native streaming must work for this story.

**Gate after Batch 1a:** Design Spec file exists and is reviewed; `useStreamingText` compiles and unit-tested with a mock SSE server (Node.js `http.createServer` or MSW).

### Batch 1b — PARALLEL — `frontend` agent — FE-3 and FE-4 (independent)

**Depends on:** FE-2 complete + P3-04/P3-05 merged.
**Agent:** `frontend`
**Mode:** Parallel — different files.

FE-3 — `useExplainStream`:
- Calls `POST /api/AiTutor/Explain` with child JWT (via `apiClient` base URL + auth header pattern).
- Body: `{ lessonId?, conceptId?, skillId?, question? }`.
- Wires through `useStreamingText`. Exposes `{ text, isStreaming, error, retry, start }`.
- Hand-rolled (no NSwag). Note NSwag skip annotation in the controller if applicable.

FE-4 — `useHintStream` + `useSimplifyStream`:
- `useHintStream(params: { questionId, attemptId, hintLevel? })`: calls `POST /api/AiTutor/Hint`; parses preamble `event: meta` for `hintLevel`/`nextHintLevel`; exposes `{ text, isStreaming, error, retry, currentHintLevel, nextHintLevel }`.
- `useSimplifyStream(params: { lessonId?, conceptId? })`: calls `POST /api/AiTutor/Simplify`; same as `useExplainStream` without level metadata.

**Gate after Batch 1b:** Hooks compile; unit-tested with MSW/stubbed SSE.

### Batch 3 — SEQUENTIAL — `frontend` agent — FE-7, FE-8, FE-10, FE-11

**Depends on:** Batch 2 complete.
**Agent:** `frontend`
**Mode:** Sequential (FE-7/FE-8/FE-10 are all integration finishes; FE-11 is the final cleanup pass).

FE-7 — `hintUsed` recording:
- If P3-05 records server-side via `HintUsedIntegrationEvent`: verify no FE change needed (document this explicitly in the PR description).
- If FE must set `hintUsed: true` on the next `SubmitAnswer`: update W12's `useSubmitAnswer` to carry the flag when a hint was delivered in the current session.

FE-8 — Loading/error/empty states (integrated into FE-5/FE-6 components):
- Typing indicator: `AITutorBubble message={null}` while `isStreaming`.
- Gentle retry affordance: a "Tap to try again" button when `error !== null` — calls `retry()` from the stream hook. No crash, no modal.
- Stream-interruption recovery: if `EventSource` / `ReadableStream` closes early, set `error` + expose `retry`.
- Declined/empty copy: when the backend returns an empty stream or a specific "no context" hint in the SSE metadata, show the friendly "I don't have enough on that yet" slot (EN+AR per Design Spec OQ-7).

FE-10 — RTL + i18n:
- Add EN+AR keys to `packages/shared/src/i18n/resources.ts`:
  - `tutor.typing`: "Lexi is thinking…" / "ليكسي تفكر…"
  - `tutor.hintLevel`: "Hint {{n}} of {{max}}" / "تلميح {{n}} من {{max}}"
  - `tutor.simplify`: "Explain more simply" / "شرح بطريقة أبسط"
  - `tutor.retry`: "Tap to try again" / "اضغط للمحاولة مجددًا"
  - `tutor.noContext`: "I don't have enough on that yet — try asking about your current lesson" / "لم أجد معلومات كافية — جرب السؤال عن درسك الحالي"
- Apply `useLocale().direction` for logical RTL positioning in all tutor surfaces (bubble tail, chip placement).
- Add `accessibilityLiveRegion='polite'` to the streaming `AITutorBubble` for a11y (screen reader announces new text).

FE-11 — Final cleanup:
- Barrel re-exports for all new hooks and primitives.
- TypeScript strict-mode pass (no `any` that can be avoided, no missing return types).
- NSwag skip annotations on streaming controllers if NSwag is configured to auto-generate.

**Gate after Batch 3:** `pnpm build` green; i18n keys present in both locales; RTL layout visually verified.

### Batch 4 — SEQUENTIAL — `frontend-e2e-tester` agent

**Depends on:** Batch 3 complete + student-app web PWA running.
**Agent:** `frontend-e2e-tester`

Drive the web PWA with Playwright (child JWT under `(child)/` routes). Required flows:

1. **Explain stream + typing animation:** navigate to a lesson → trigger "Ask the tutor" → observe typing indicator → text streams in and completes → assert `AITutorBubble` contains non-empty text (EN).
2. **Explain stream (Arabic/RTL):** switch locale to AR → same flow → assert text is AR; assert bubble tail and layout are RTL-mirrored.
3. **Wrong-answer hint flow:** complete a quiz question incorrectly → hint bubble appears → assert `variant='hint'` bubble; assert hint text is non-empty; assert "Hint 1 of N" label shown.
4. **Simplify action:** click "Explain more simply" chip → assert a new stream starts and returns different (simpler) text; assert "Hint 2 of N" reflects escalation.
5. **Provider-error graceful degradation:** stub/force a gateway error → assert gentle retry affordance shown (no crash, no raw error text shown to student).
6. **Stream interruption recovery:** simulate network drop mid-stream → assert recovery (retry button) appears.
7. **Auth/role routing:** non-child JWT (or no JWT) → tutor surface is unreachable (redirected to login or 403 page); tutor endpoints not callable.
8. **Debounce:** rapidly clicking "Ask the tutor" multiple times does not fire multiple concurrent streams.

### Batch 5 — `security-auditor` (light FE pass)

**Depends on:** Batch 3 complete.
**Agent:** `security-auditor`

FE-side audit (not a hard gate — the hard AI-safety gate is on BE stories P3-04/P3-05):
- **Safe rendering:** streamed text rendered via React's safe text rendering — no `dangerouslySetInnerHTML` on web, no raw HTML injection. Verify `AITutorBubble` does not render markdown as HTML.
- **Child-JWT only:** tutor entry points are only reachable under `(child)/` routes; no parent or admin JWT can reach them.
- **Debounce/abuse:** the FE does not allow trivial spam (debounce on ask/hint trigger) — noted in FE code; BE rate-limit is the primary guard.
- **No AI request outside `(child)/` routes:** verify routing guards.
