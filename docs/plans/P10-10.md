## Execution batches

### Batch 1 — PARALLEL — `designer` (FE-1) + `frontend` (FE-2, FE-3)

FE-1 (designer) and FE-2/FE-3 (hook setup, potentially including a mini BE read) are independent of each other and can start simultaneously.

**FE-1 (designer):** deliver `design-system/ui_kits/student-mobile/P10-10-energy-meter.md`. Must cover: `EnergyMeter` (⚡, distinct colour token, distinct placement from hearts); `EnergyCostPill` (⚡N before confirm); spend animation (on success only); `LowEnergyState` + `OutOfEnergyState` ("ask a parent," no purchase action); EN+AR copy, RTL mirrors, tokens only. Explicitly must NOT look like `design-system/screenshots/mobile/18-hearts.png`.

**FE-2 (frontend):** if the balance endpoint exists from P10-01/P10-03 — add typed hook `useEnergyBalance()` + NSwag regen. If missing — implement mini BE read `GET /api/Credits/Balance/Me` (in Billing/Credit module, child JWT only, returns `{ spendable, refillDate }`) + hook. **D1 gate.**

**FE-3 (frontend):** add `useActionCosts()` hook reading per-action costs from the agreed source (P10-03/P10-11). **D5 gate.**

**DoD for Batch 1:** design spec delivered; `useEnergyBalance` hook wired to a confirmed endpoint; `useActionCosts` hook returning `{ hint: 1, explainMistake: 3, deepExplanation: 5, similarExample: 5 }`.

### Batch 2 — SEQUENTIAL — `frontend` — FE-4 + FE-6

After Batch 1 design spec and hooks are ready. Build `EnergyMeter`, `EnergyCostPill`, `OutOfEnergyState` in `packages/ui/src/energy/`. FE-6 (i18n) runs alongside — add the `energy` namespace, ensure "Credits" never appears in either language.

**DoD:** primitives build + render with tokens; "Credits" absent from all i18n keys; RTL correct.

### Batch 3 — SEQUENTIAL — `frontend` — FE-5

After Batch 2. Wire `EnergyMeter` into the lesson/quiz header (alongside but distinct from hearts slot per design spec). Wire `EnergyCostPill` onto each AI Helper action button (P3-12). Wire `OutOfEnergyState` on zero/low balance. Spend animation fires only on successful P10-03 charge response. Requires P3-12 AI Helper UI to be present — **confirm P3-12 is deployed or mocked before dispatching this batch.**

**DoD:** energy meter renders in lesson/quiz header; cost pills show on AI Helper buttons; spend animation fires on success only; out-of-energy state shows correctly; no "Credits" text anywhere in child UI.

### Batch 4 — SEQUENTIAL — `frontend-e2e-tester` — FE-7

After Batch 3. Drive web PWA with a child JWT. Assert:
- Energy meter is visually distinct from hearts (different CSS class / component hierarchy / icon).
- Each Helper action shows its cost (⚡1/⚡3/⚡5) before confirm.
- Successful AI Helper action decrements energy + spend animation visible.
- Refusal/error does NOT decrement.
- Out-of-energy shows "refills monthly" + "ask a parent" — zero purchase/checkout/plan controls anywhere on child routes.
- RTL (ar) + LTR (en) correct.
- The word "Credits" never appears in the child UI in either language.

### Batch 5 — SEQUENTIAL — `reviewer` then `committer`

Reviewer gates all ACs + CONVENTIONS (no design pattern introduced, tokens only, i18n only, no payment UI on child routes). PASS → `committer` → branch `feat/P10-10-kid-energy-ui`, PR to `main`, HANDOFF.md update (balance endpoint confirmed, cost source confirmed, "ask a parent" v1 behaviour, visual-distinction approach). Never merge.

**No security-auditor stage** — read-only child surface; no payment/secret/file-upload. Reviewer confirms the no-purchase-UI + read-scope boundary. The balance endpoint (FE-2) must be scoped to the authenticated child (child can only read their own energy) — reviewer verifies this claim.
