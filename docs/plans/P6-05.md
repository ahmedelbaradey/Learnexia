> Scope: **Host + one read-only AI seam (`Shared.Contracts`).** No new module, no DB migration, no new NuGet (OTel + health-check packages already centrally versioned), no Unit of Work. Branch: `feat/P6-05-observability`.

## Locked decisions (lead, 2026-06-21) — resolving the brief's open questions
- **OTel export:** OTLP exporter, **config-gated** — registered only when `OpenTelemetry:Otlp:Endpoint` is set; otherwise OTel is wired but exports nowhere (no-op). Local dev + integration suite run unchanged with no collector.
- **Sampling:** configurable ratio, **default 1.0** (always-on); devops lowers via `OpenTelemetry:SamplingRatio`.
- **NLog:** **create `nlog.config` from scratch** (none exists today — CONVENTIONS §13). Console + rolling file targets; enrich every line with `traceId`/`spanId` (+ path/status) for trace↔log correlation. **No second/third `ILoggerManager` registration** (there's already a known duplicate — do not add another).
- **AI-Gateway health check:** new `IAiReadinessProbe` seam in `Shared.Contracts/Ai/` (booleans/enum only — **never key values**), implemented in `Ai.Infrastructure` (Scoped, mirrors `IAiSafetyEvalResultsQuery`). Host's `AiGatewayHealthCheck` injects the seam only. **Config-inspection only — no paid model call, no real key.** Degraded-tolerant.
- **MinIO check:** **yes** — add a Degraded-tolerant MinIO readiness check in the same pass (completes "dependency monitoring").
- **Npgsql/EF DB tracing:** **deferred** (no centrally-versioned OTel Npgsql package + no-new-NuGet rule). v1 instruments ASP.NET Core + HttpClient + Runtime.
- **OTLP log exporter target:** **deferred** (NLog file/console + trace correlation this pass; OTLP logs when the collector exists).
- **Health JSON writer:** add a **minimal status-only** `ResponseWriter` to `/health` (`{status, entries:{name:status}}`) — **no exception/stack detail** (security).

## Batches (backend-feature)
- **Batch 1 — BE-1 + BE-2 (one sequential pass; both edit `Program.cs`).** OTel tracing+metrics (ASP.NET/HttpClient/Runtime instrumentation, Resource = service name/version/env, OTLP exporter config-gated, sampling ratio) + `OpenTelemetrySettings`; AI-Gateway + MinIO health checks via the new `IAiReadinessProbe` seam; minimal status-only health JSON writer; add the OTel `PackageReference`s to `Host.csproj`.
- **Batch 2 — BE-3.** Create `nlog.config` (console + rolling file) with `traceId`/`spanId` correlation; no new logger registration.
- **Batch 3 — BE-4 (docs, parallel).** HANDOFF: dashboard/alerts = devops on the OTLP stream + the existing `api/Admin/Analytics/kpis` (DAU/WAU, accuracy, retention) endpoints; OTLP env vars; `/health` = the 99.5%-uptime probe.
- **Batch 4 — gates (sequential):** api-tester (BE-5) → **security-auditor** (telemetry must not leak child PII / AI prompts / secrets — analyzer flagged this) → reviewer → committer (PR; HANDOFF in same PR).

## Review gates
- App **starts cleanly with OTel wired but no OTLP endpoint** (no-op path) — integration suite unaffected.
- `/health` reports `database` / `redis` / `ai-gateway` (+ `minio`) entries; `/health/live` always 200; AI-gateway-misconfigured → Degraded (not hard 503).
- **security-auditor:** no secret/PII in spans or logs; readiness probe exposes booleans only (no key material).
