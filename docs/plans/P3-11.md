## Execution batches

### Batch 1 — PARALLEL with Batch 2a — `db-migration` agent — BE-1

**Depends on:** P3-08 (and transitively P3-09) merged.

**Migration:** `AddAttemptServedDifficultyMix` (schema `learning`):
- Add `Attempt.ServedDifficultyMix jsonb NULL` — stores the difficulty distribution served + metadata: `{"Easy":n,"Medium":n,"Hard":n,"Target":"Medium","WasDefault":true}`.
- Add `Attempt.TargetDifficulty int NULL` — stores `DifficultyLevel` enum as int; nullable (existing rows null).
- Mirror `AttemptConfig` EF conventions: `HasColumnType("jsonb")` for the jsonb column; `HasColumnType("int")` + nullable for `TargetDifficulty`.
- Backfill-safe: all existing `Attempt` rows keep null values.

Run `dotnet ef migrations add AddAttemptServedDifficultyMix` and review generated SQL before committing. Confirm `dotnet build` green.

**Completion gate:** Build green; migration SQL reviewed (two nullable columns, no existing-data modification).

### Batch 2 — PARALLEL — `backend-feature` agent (two threads)

#### Batch 2a — BE-2 (QuizSelectionOptions) — PARALLEL with Batch 1

**Files (NEW):**
- `Learning.Application/Options/QuizSelectionOptions.cs` — POCO bound from `QuizSelection:Engine` config section: `double HardRatio = 0.7`, `double MediumRatio = 0.6`, `double EasyRatio = 0.7` (fraction from target difficulty), `double BlendRatio = 0.3` (adjacent-difficulty blend).
- `appsettings.json` — add `QuizSelection:Engine` section.

**Completion gate:** Compile.

#### Batch 2b — BE-3 (QuizSelectionEngine + unit tests) — SEQUENTIAL after Batch 2a

**Files (NEW):**
- `Learning.Domain/Services/QuizSelectionEngine.cs` — pure static class: `Select(IReadOnlyList<QuizQuestion> candidates, DifficultyLevel target, QuizSelectionOptions options) → IReadOnlyList<QuizQuestion>`. Implementation:
  - Sort `candidates` by `Id` (deterministic stable ordering for resume reproducibility — AC4).
  - Partition by `Difficulty` into Easy/Medium/Hard buckets.
  - Given `target`, build a weighted pick: ~70% from target bucket, ~30% from adjacent. Use ratio config from `QuizSelectionOptions`.
  - Graceful degradation: if target bucket is empty, serve available; if total pool is empty, return empty (never throw). Log a content-gap warning (via caller — engine is pure, so caller logs).
  - Returns ordered list deterministically for the same inputs.
- `tests/Modules.Learning.UnitTests/QuizSelectionEngineTests.cs` — 6+ cases: all-Hard pool + target Hard → all Hard; mixed pool + target Hard → skewed toward Hard; mixed pool + target Easy → skewed toward Easy; cold-start (Medium target) → balanced; thin pool (only Easy) → returns Easy without error; determinism (same inputs, same output); empty pool → empty result, no exception.

**Completion gate:** Build green; 6+ engine tests pass; plain static class.

### Batch 3 — SEQUENTIAL — `backend-feature` agent — BE-4

**Depends on:** Batch 1 (migration) AND Batch 2b (engine) complete AND P3-08's `IAdaptivityService` available.

**File (EDIT):** `Application/Features/Attempts/Commands/StartAttempt/StartAttemptCommandHandler.cs`

Changes (additive — must not break existing guards):
1. After loading `Published+Active` lesson questions (the existing candidate list), BEFORE building the response:
   - Call `IAdaptivityService.GetTargetDifficulty(studentId, lesson.SkillId)` — `studentId` from `ICurrentUserService.UserId`.
   - Call `QuizSelectionEngine.Select(candidates, decision.Difficulty, options)` — returns the selected subset.
   - If the selected list is empty (edge case — empty pool), fall back to the full candidate list (never return empty if candidates exist).
   - Log a content-gap warning (server-side only, not in response) if the pool had no questions at target difficulty.
2. Build the response question list from the **selected** set (not the full set).
3. On new-attempt start: persist `Attempt.ServedDifficultyMix` (jsonb, serialize `{Easy:n, Medium:n, Hard:n, Target:"X", WasDefault:decision.IsDefault}`) + `Attempt.TargetDifficulty` (int) on the `Attempt` entity before the save.
4. On resume: re-run `QuizSelectionEngine.Select` with the same deterministic seed inputs (candidates + target recomputed fresh; stable ordering by Id ensures same output → AC4 resume determinism). Do NOT persist the mix again on resume (it was persisted at first start).
5. Existing guards unchanged: lifecycle filter (`LifecycleState == Published`), `IsActive` filter, language guard, resume branch — all preserved as-is.

**Completion gate:** Build green; `StartAttempt` endpoint functional with selection step; existing tests still pass.

### Batch 4 — SEQUENTIAL — `api-tester` agent

**Depends on:** Batch 3 complete.

**File to create:** `backend/tests/Learnexia.IntegrationTests/P3_11_AdaptiveQuizSelection_Tests.cs`

**Prerequisite seed:** A lesson must have questions at all three difficulty levels (Easy, Medium, Hard) — at least 3 per level — so the selection is observable. Flag if the seed doesn't have this; the test file must create its own test data or use a seeder extension.

**Minimum 8 integration test cases:**

| # | Test | Assertion |
|---|---|---|
| 1 | New student starts quiz → mix skews Medium/balanced; `attempt.ServedDifficultyMix.WasDefault == true` | AC3 cold-start |
| 2 | Student with seeded strong history on skill → mix skews Hard (`hardCount > easyCount` in the recorded mix) | AC2 direction + AC4 recorded |
| 3 | Student with seeded struggle history → mix skews Easy | AC2 direction |
| 4 | Resume same attempt → identical question list (determinism) | AC4 resume reproducibility |
| 5 | Lesson with null `SkillId` → starts without error; mix is default/balanced | AC3 null-skill |
| 6 | Thin pool (only Easy questions) → quiz starts successfully; mix contains only Easy | AC-resilience |
| 7 | Existing `StartAttempt` regression: lifecycle/language guard still rejects unpublished questions | Existing guard preserved |
| 8 | `Attempt.ServedDifficultyMix` is non-null and parseable JSON after start | AC4 persistence |

**Completion gate:** All 8 cases pass; api-tester reports PASS.
