### Batch 1 — PARALLEL — `backend-feature` agent — BE-1 and BE-2 (independent)

**Agent:** `backend-feature`
**Mode:** Parallel — different files, no overlap.
**Shared-file warning:** BE-2 touches `Shared.Contracts` — serialize against any concurrent story editing that package.

BE-1 — `ExplainConceptCommand` + validator:
- `record ExplainConceptCommand(int? LessonId, int? ConceptId, int? SkillId, string? Question) : ICommand<void>` (void for streaming — or `ICommand<ExplainResult>` if the handler returns the stream; confirm based on OQ-1 SSE pattern).
- Grade/age/language resolved from `ICurrentUserService` in the handler — NOT in the command body (AC-6).
- Validator: at least one of LessonId/ConceptId/SkillId required; `Question` max 500 chars if present.

BE-2 — `ILessonContextContract` in `Shared.Contracts/Learning/`:

- `LessonContextDto { int LessonId, string Title, int SubjectId, int GradeId }`.
- Learning.Infrastructure adapter: queries `LearningDbContext.Lessons` by id, maps to DTO. Registered as `ILessonContextContract → LessonContextContractAdapter` in `AddLearningInfrastructure`.

**Gate after Batch 1:** `dotnet build` green; `ILessonContextContract` visible from the AiTutor module (via `Shared.Contracts`).

### Batch 2 — SEQUENTIAL — `backend-feature` agent — BE-3

**Depends on:** Batch 1 complete. Cross-cluster deps (P3-01/02/03/07) merged or stubbed for compilation.
**Agent:** `backend-feature`
**Task:** BE-3

`ExplainConceptCommandHandler` — orchestration steps:
1. Resolve grade/age/language from `ICurrentUserService` (`StudentGrade`, `StudentAge`, `PreferredLanguage` claims).
2. If LessonId present, call `ILessonContextContract.GetLessonContextAsync` to get title + subjectId + gradeId (enriches retrieval query and prompt).
3. Call `IChunkRetrievalContract.RetrieveAsync(text = lesson title or concept name, gradeId, subjectId, skillId = null, topK = 5)`.
   - If empty: proceed with reduced grounding (OQ-5). Do not decline — explain is contextual, not generation. Note in the prompt "no specific curriculum context retrieved."
4. Call P3-03 Prompt Builder — explain template: inject grade, age, language, curriculum chunks (or "no context" note), child-safe tone, lesson title. Returns a structured prompt.
5. Call P3-01 Gateway — request a streaming completion (model routing: cheap model for simple explains per NFR-9).
6. **Buffer full response** (OQ-2a). Safety is non-negotiable — buffer prevents any token reaching the student before the full response is checked.
7. Call P3-02 Safety Layer on the buffered text. If safety fails → do NOT stream; return a typed gentle error (no stack trace, AC-5). Log the safety failure via `ILoggerManager`.
8. Stream the pre-checked text to the calling controller (return the buffered string; controller handles SSE emission — see BE-4).
9. Fire-and-forget interaction log: log concept/lesson, grade, model, safety verdict, latency via `ILoggerManager` (OQ-4). Never blocks the response.
10. No writes to mastery/XP/unlock (AC-4).

Inject: `ICurrentUserService`, `ILessonContextContract`, `IChunkRetrievalContract`, P3-03 prompt builder, P3-01 gateway client, P3-02 safety client, `ILoggerManager`.

**Gate after Batch 2:** Handler compiles (with stubbed cross-cluster deps); unit-testable orchestration flow.

### Batch 3 — SEQUENTIAL — `backend-feature` agent — BE-4

**Depends on:** Batch 2 complete + OQ-1 (SSE) confirmed by lead.
**Agent:** `backend-feature`
**Task:** BE-4

**SSE streaming endpoint — new backend pattern (CLAUDE.md rule 8: lead has confirmed SSE before this batch is dispatched):**

`POST /api/AiTutor/Explain` — `[Authorize(Roles="Student")]`

Controller implementation pattern:
- Does NOT use `NewResult(...)` — SSE is a streaming response that bypasses the buffered `BaseResponse<T>` envelope for the happy path.
- On success: set `Response.ContentType = "text/event-stream"`, `Response.Headers["Cache-Control"] = "no-cache"`, `Response.Headers["X-Accel-Buffering"] = "no"`. Write `data: {chunk}\n\n` for each chunk of the pre-checked text (or the full pre-checked text as one chunk since we buffered). Write `data: [DONE]\n\n` sentinel.
- On handler error / safety failure: write `event: error\ndata: {typed error JSON}\n\n` and complete. The typed error shape mirrors `BaseResponse<T>` but is an SSE event. Document this pattern divergence in a code comment.
- Add a code comment: "SSE response bypasses BaseResponse<T> by design — see OQ-1 decision in HANDOFF.md."
- `[ProducesResponseType(200)]` + `[Produces("text/event-stream")]`.

**Gate after Batch 3:** Controller action visible in Swagger; SSE response confirmed with a curl test.

### Batch 5 — SEQUENTIAL — `api-tester` agent

**Depends on:** Batch 4 complete. Use **stubbed gateway + safety** (do not hit live LLMs in CI).
**Agent:** `api-tester`

Required test cases:
1. **Happy path (English):** authenticated child JWT, valid LessonId with seeded P3-07 chunks → SSE stream returns text, `[DONE]` sentinel; text is non-empty; no raw stack trace.
2. **Happy path (Arabic):** same with Arabic-language child JWT → response text is in Arabic (or verify prompt injection language preference).
3. **Safety-block path:** stub safety layer to block → no text tokens streamed; SSE `event: error` with typed error payload; no stack trace.
4. **Empty-retrieval path:** skill/grade with no seeded chunks → explain still returns (reduced grounding per OQ-5); does NOT return an error or decline.
5. **Provider-error path:** stub gateway to throw → SSE `event: error` with gentle typed error; no stack trace.
6. **Auth:** non-Student JWT → 403; no bearer → 401. Camelcase error envelope.
7. **Wire format:** verify `data:` line format, `[DONE]` sentinel, `event: error` event name — these are the contract P3-12 consumes.
8. **Rate limit:** exceed the per-student limit → 429.

### Batch 6 — `security-auditor` (HARD GATE)

**Depends on:** Batch 4 complete.
**Agent:** `security-auditor`

AI text shown to children — **security-auditor is a hard gate; Critical/High findings block.**

Audit:
- **No Safety-Layer bypass under buffered-stream (AC-2):** trace all code paths in BE-3. Confirm the buffer → safety → emit sequence has no shortcut.
- **Prompt-injection:** `Question` free-text parameter + retrieved chunks cannot subvert the child-safe system prompt or exfiltrate the prompt structure. Verify prompt builder (P3-03) wraps user content safely.
- **Child-data minimization (AC-6):** grade/age/language come from JWT claims — not from the request body. Interaction log (OQ-4) doesn't capture more child PII than needed.
- **No secret leakage:** gateway/safety adapter logs don't include API keys. Mirror the `ExpoPushSender` header-not-mutated pattern.
- **Rate limit enforced (AC-6):** a child cannot spam expensive premium-model calls (verify BE-5 policy is wired).
- **`[Authorize(Roles="Student")]` applied** — not just `[Authorize]`.
