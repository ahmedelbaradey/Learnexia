#### BE-3 — Acyclic validator + unit tests

**`backend/src/Modules/Learning/Learnexia.Modules.Learning.Domain/Services/SkillGraphValidator.cs`**

This is a plain domain-layer service (static helper or instantiable — mirror the existing `QuizQuestionContentValidator` helper shape; no design pattern needed). Signature:

```csharp
/// <summary>
/// Validates that a set of KnowledgeEdge records form an acyclic directed graph over
/// Prerequisite-typed edges. Related edges are excluded from the acyclic constraint.
/// Throw <see cref="InvalidOperationException"/> (or a domain-specific error type if one exists)
/// with a clear message when a cycle is detected.
/// </summary>
public static class SkillGraphValidator
{
    /// <summary>
    /// Checks all existing + proposed edges for cycles.
    /// Call before persisting any new edge.
    /// </summary>
    /// <param name="allEdges">All edges (existing + new) to validate.</param>
    /// <exception cref="InvalidOperationException">Thrown when a cycle is detected.</exception>
    public static void AssertAcyclic(IEnumerable<KnowledgeEdge> allEdges) { ... }
}
```

Implementation notes:
- Filter to `RelationshipType == EdgeRelationshipType.Prerequisite` only before running DFS.
- Build an adjacency list from `SourceNodeId → TargetNodeId`.
- Standard DFS with three-color marking (White/Gray/Black) or a visited + recursion-stack approach.
- Self-loop (`SourceNodeId == TargetNodeId`) is caught naturally by DFS (visiting a Gray node).
- On cycle detection throw: `new InvalidOperationException("Cycle detected in prerequisite graph. Edge {sourceId} → {targetId} creates a cycle.")` — include the offending node IDs in the message for debuggability. This surfaces as a `ServerError` in the seeder / command handler, NOT a raw 500 through the global handler.
- If a future domain error type is introduced, mirror it — do not invent one here.

**Unit tests:** `backend/tests/Modules.Learning.UnitTests/SkillGraphValidatorTests.cs`

Mirror `QuizQuestionTypeValidationTests.cs` (xUnit + FluentAssertions). Three required cases:
1. Acyclic graph (chain A→B→C): `AssertAcyclic` must not throw.
2. Single cycle (A→B→C→A): must throw `InvalidOperationException`.
3. Self-loop (A→A): must throw `InvalidOperationException`.
4. Related edges do not trigger cycle check (a Related "cycle" R-A→R-B→R-A must be ignored): no throw.

#### BE-5 — Query CQRS + `KnowledgeGraphController`

**Two queries under `Application/Features/KnowledgeGraph/Queries/`:**

Folder structure:
```

  Queries/
```

**`GetPrerequisitesQuery`** — `record GetPrerequisitesQuery(int NodeId) : IQuery<BaseResponse<List<KnowledgeNodeDto>>>`

**`GetPrerequisitesQueryHandler`** — returns the set of nodes that are sources of `Prerequisite` edges whose `TargetNodeId == NodeId` (i.e. "what must be mastered before NodeId"). Uses `ILearningRepositoryManager` for the custom graph traversal (not `BaseService` — BaseService only handles single-entity CRUD). Inject `ILearningRepositoryManager`, `IMapper`, `ILoggerManager`. If NodeId is not found return `NotFound<List<KnowledgeNodeDto>>("Node not found.")`. If found but no prereqs return `EmptyCollection(new List<KnowledgeNodeDto>())`.

**`GetUnlockedByQuery`** — `record GetUnlockedByQuery(int NodeId) : IQuery<BaseResponse<List<KnowledgeNodeDto>>>`

**`GetUnlockedByQueryHandler`** — returns the set of nodes that are targets of `Prerequisite` edges whose `SourceNodeId == NodeId` (i.e. "what does mastering NodeId unlock"). Same pattern as above; same NotFound/Empty handling.

**`KnowledgeNodeDto`** (read model):

### Batch 3 — SEQUENTIAL — `backend-feature` agent — BE-4 (Seeder extension)

**Depends on:** Batch 2 complete (schema from BE-2 applied; validator from BE-3 passing tests).
**Agent:** `backend-feature`
**Task:** BE-4

**What to build:** Extend `LearningSeeder.cs` in `backend/src/Modules/Learning/Learnexia.Modules.Learning.Infrastructure/Persistence/Seed/LearningSeeder.cs`.

Add a new static method `SeedSkillGraphAsync` and call it at the end of `SeedAsync`:

```csharp
public static async Task SeedAsync(IServiceProvider serviceProvider)
{
    var db = serviceProvider.GetRequiredService<LearningDbContext>();
    // ... existing grade/subject loops ...
    await SeedSkillGraphAsync(db);  // NEW — called after all skills are seeded
}
```

**`SeedSkillGraphAsync` specification:**

Step 1 — Map Skills to KnowledgeNodes (idempotent by `SkillId`):
- Load all `Skill` rows from the DB (with their `Concept` + `Subject` chain to resolve `SubjectId` and `Grade`).
- For each `Skill`, check `db.KnowledgeNodes.Any(n => n.SkillId == skill.Id)` — if not present, create a `KnowledgeNode`:
  - `Name` = `skill.Name`
  - `NodeType` = `KnowledgeNodeType.Skill`
  - `SubjectId` = resolved from `skill.Concept.Subject.Id`
  - `GradeId` = resolved from the subject's `Grade.Id` (the seeded Subjects carry a `GradeId`)
  - `Difficulty` = 3 (default mid-range; can be refined per skill in future)
  - `SkillId` = `skill.Id`
- Save after creating nodes: `await db.SaveChangesAsync(SystemUserId)`

Step 2 — Author Prerequisite edges for Math (within-subject, within-grade, per AC):
- Build a local dictionary `skillName → knowledgeNodeId` by querying the newly-created `KnowledgeNode` rows where `SkillId IS NOT NULL`.
- Define prerequisite chains for Math, Grade 1 through Grade 6 (at minimum). Use skill names exactly as seeded by P2-10 (do NOT rename). Examples (the seeder agent must verify exact names match P2-10's seed strings):
  - G1: `"Counting"` → `"Place Value"` (counting is prereq for place value)
  - G1: `"Place Value"` → `"Addition"`
  - G2: `"Addition"` → `"Subtraction"`
  - G3: `"Subtraction"` → `"Multiplication"`
  - G4: `"Multiplication"` → `"Division"`
  - G5: `"Division"` → `"Fractions"`
  - G6: `"Fractions"` → `"Decimals"` (if present in P2-10 seed; verify exact name)
  - Additional same-grade intra-subject chains as appropriate.
- For each proposed `(sourceNodeId, targetNodeId, Prerequisite)` edge: check `db.KnowledgeEdges.Any(e => e.SourceNodeId == src && e.TargetNodeId == tgt && e.RelationshipType == EdgeRelationshipType.Prerequisite)` — idempotent skip if present.
- Collect all new edges into a list (do not save yet).
- Run `SkillGraphValidator.AssertAcyclic(existingEdges.Concat(newEdges))` — if a cycle is detected, log the error and skip saving the edges (do not throw and crash the seeder; log as a warning/error so it is visible without aborting startup).
- Save: `await db.SaveChangesAsync(SystemUserId)`

**Critical constraint:** `LearningSeeder` calls `SaveChangesAsync` directly (outside UoW — it runs at startup, not via MediatR). This is the established P2-10 pattern. Continue that pattern.

**Critical constraint:** Do NOT rename any skill name string from P2-10. The seeder must look up nodes by `SkillId` (not by name) to build edges — look up the `SkillId` first from the `Skill` table by name, then use `SkillId` to find the `KnowledgeNode`. This makes the lookup robust to future renames.

**Gate after Batch 3:** `dotnet run` in Development mode seeds the graph without cycle errors; re-running adds zero new rows.
