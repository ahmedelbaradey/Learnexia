### Batch 6 — PARALLEL — `api-tester` + `security-auditor`

**Agent:** `api-tester` + `security-auditor` (parallel)
**Depends on:** Batch 5 complete (.NET) + Python service running or mocked.

**`api-tester` validations (against mocked ingestion client):**
1. A parsed document → ingest → hierarchy rows + `CurriculumChunk` rows created; `IngestionStatus = Done`.
2. Re-ingest is idempotent: no duplicate Subject/Unit/Lesson/Concept/Skill/Chunk rows on second run.
3. Low-confidence stub → `IngestionReviewItem` created; hierarchy node withheld.
4. Admin approves review item → hierarchy node created; item `ReviewStatus = Approved`.
5. Admin rejects review item → item `ReviewStatus = Rejected`; no hierarchy node.
6. Re-ingest command resets status; prior review items for the doc are cleared.
7. Admin-only on all write endpoints → 403 for non-admin.
8. `Successed` key in response envelope.

**`security-auditor` checklist (REQUIRED — LLM/AI + admin + data writes):**
- LLM / ingestion-service credentials in secret manager (env var / key vault), NOT in source.
- Prompt-injection surface: curriculum content fed to LLM → assert ingestion output is structured data, not executed. Confirm confidence scoring does not expose raw LLM output in `SuggestedClassification` (log only, not in API response).
- Admin-only on all ingest/reingest/approve/reject triggers.
- **Idempotent writes must NOT corrupt P2-10 hand-seeded demo data** — confirm natural-key upsert logic does not clobber existing rows (assert in api-tester test #2).
- `IngestionDiagnostics` field does not expose stack traces / secrets in production response.
- Cross-module write seam (if option A) uses `Shared.Contracts` only — verify no direct cross-module DbContext reference exists in code.

Critical/High findings block the gate.
