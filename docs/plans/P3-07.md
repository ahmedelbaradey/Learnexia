### Batch 2 — PARALLEL — `backend-feature` agent — BE-6 and BE-9 (independent)

**Agent:** `backend-feature` (two parallel threads or one agent doing both)
**Mode:** Parallel — BE-6 and BE-9 touch different files, no overlap
**Tasks:** BE-6 (embedding adapter) || BE-9 (seeder)

**File isolation check:**
- BE-6 creates `Curriculum.Application/Abstractions/IEmbeddingProvider.cs` + `Curriculum.Infrastructure/Services/EmbeddingService.cs` + settings. No overlap with BE-9.
- BE-9 creates `Curriculum.Infrastructure/Persistence/Seed/CurriculumChunkSeeder.cs`. No overlap with BE-6.

BE-6 details:
- Interface `IEmbeddingProvider { Task<Pgvector.Vector> EmbedAsync(string text, CancellationToken ct); }`.
- Adapter: typed `HttpClient` (mirror `ExpoPushSender`) — if OQ-3 = gateway, points to P3-01 AI Gateway embedding endpoint; else direct provider. `IOptions<EmbeddingSettings>`, `ILoggerManager`, fail-soft (never throw, return null/empty + log on failure). Never logs secrets/API keys.
- Cross-cluster dep: if gateway path, P3-01 must be merged before this runs in a live environment (but can be coded + unit-tested with a stubbed HttpClient).

BE-9 details:
- `CurriculumChunkSeeder` — idempotent; skips if chunks already present for a subject/grade pair. Inserts pre-chunked text for Math/Science/Arabic/English × MVP grades. Ships pre-computed vectors (OQ-8b — deterministic, no network at seed). Called from `InitializeAsync`.

**Gate after Batch 2:** `dotnet build` green; seeder inserts data on first run, zero rows on second run.

### Batch 3 — SEQUENTIAL — `backend-feature` agent — BE-7, BE-8, BE-10

**Depends on:** Batch 2 complete.
**Agent:** `backend-feature`
**Mode:** BE-7 first, then BE-8 (optional) and BE-10 in parallel (independent files).

BE-7 — `RetrieveChunksQuery` handler:
- Record `RetrieveChunksQuery { Text, GradeId, SubjectId, WeakAreaSkillId?, TopK }`.
- Handler: guard inputs (queries not auto-validated); embed `Text` via `IEmbeddingProvider`; EF query: `WHERE grade = ... AND subject = ... ORDER BY embedding <=> @q LIMIT k` (verify translates to SQL, not client-evaluated); apply similarity floor (distance > threshold → exclude); map to `CurriculumChunkDto { Content, Metadata, Score }` (never expose raw embedding); return `RetrievalResult { Chunks }` (`Successed=true`, empty list if nothing clears floor). Inject `ILoggerManager`.
- `RetrievalResult` type: `{ IReadOnlyList<CurriculumChunkDto> Chunks }` — `Chunks.Count == 0` is the unambiguous empty signal.

BE-8 (optional per OQ-5) — dev-only `RetrievalController`:
- `GET /api/Curriculum/Retrieve?text=...&gradeId=...&subjectId=...&topK=5`
- `[Authorize]`, `NewResult(await Mediator.Send(new RetrieveChunksQuery(...)))`.

BE-10 — DI wiring:
- `AddCurriculumApplication`: AutoMapper profile (`CurriculumChunk → CurriculumChunkDto`), MediatR handler scans (no `AddMediatR`).
- `AddCurriculumInfrastructure`: `CurriculumDbContext` with `UseNpgsql(cs, o => o.UseVector())`, `IEmbeddingProvider` typed `HttpClient` registration, `CurriculumChunkSeeder`.
- `Host/Program.cs`: `AddCurriculumModule()` + `InitializeAsync` call.

**Gate after Batch 3:** `dotnet run` in Development starts; `CurriculumChunkSeeder` logs seed success; `RetrieveChunksQuery` can be exercised (via BE-8 controller or integration test) and returns results with score.

### Batch 4 — SEQUENTIAL — `api-tester` agent (if HTTP seam chosen — OQ-5)

**Depends on:** Batch 3 complete.
**Agent:** `api-tester`

Required validations (against running API + real PostgreSQL with seeded corpus):
1. `GET /api/Curriculum/Retrieve?text=Algebra&gradeId=3&subjectId=1&topK=3` → HTTP 200, `Successed=true`, `Chunks` non-empty (Math-G3 content), all chunks are Math-G3 (filter correctness).
2. Filter isolation: a Math-G1 query returns Math-G1 chunks, not Science-G3 chunks.
3. **Empty-result path:** query with a grade/subject combo that has no seeded chunks → `Successed=true`, `Chunks: []` (not HTTP 500, not a fabricated chunk). This is AC-4.
4. Similarity floor: query with a completely unrelated term → empty list (floor working).
5. Unauthenticated request → HTTP 401; camelCase error envelope.
6. Latency sanity: retrieval well under the 4 s budget on the seeded corpus (log query time).

If retrieval is in-process only (OQ-5 = no HTTP endpoint), skip this batch and cover retrieval via P3-06/P3-04's integration tests instead.

### Batch 5 — `security-auditor` (light pass)

**Depends on:** Batch 3 or 4 complete.
**Agent:** `security-auditor`

This story's security surface is low (read-only, seeded curated curriculum) but it is the grounding source for AI output. Audit:
- Embedding adapter never logs secrets / API keys (mirror the `ExpoPushSender` header-not-mutated pattern).
- `EmbeddingSettings` (model endpoint, API key) — verify not logged at any log level.
- Prompt-injection content in chunks: at MVP chunks are hand-authored/seeded (low risk), but note for when BL-05 ingestion lands.
- PII: chunks are curriculum text, not student data — no child-data exposure.
- Empty retrieval signal is clean (AC-4): no code path fabricates a chunk when retrieval is empty.

**This is NOT a hard gate** — light findings are advisory; Critical/High would block, but none are expected here. Hard AI-safety gates are on P3-02, P3-04, P3-05, P3-06.
