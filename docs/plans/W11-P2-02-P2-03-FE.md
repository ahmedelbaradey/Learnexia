    subjectLessons: (subjectId: number) => [...queryKeys.learning.all, 'subject-lessons', subjectId] as const,

## Risks / known unknowns

1. **Grade null path.** If `useMe().data?.grade` is null (non-student account, or identity server does not return grade for a legacy seeded user), `useSubjectsForGrade` is disabled and the Subjects screen renders no rows. This is graceful degradation. The Subjects header must silently omit the grade caption — not crash.
2. **Boss derivation cross-reference cost.** The FE makes two queries (Lessons + Tree) for the subject detail screen. The boss-derivation is a free in-memory join. However, if a student navigates to the Tree tab without first visiting the Lessons tab, `useSubjectLessons` may not be in the TanStack Query cache. The Tree screen must call `useSubjectLessons` independently (same query key → single HTTP request if already cached, one extra request if cold). This is the accepted design; no additional network penalty in the common flow.
3. **NSwag method name casing.** The exact generated names for `subjectsForGrade`, `subjectsLessons`, `subjectsSkillTree` must be confirmed post-regen (NSwag camelCase convention mirrors controller + action names). If the generated names differ, the hook files must use the actual generated names, not the assumed names.
4. **Expo Router file-system routing for nested dynamic segments.** `(child)/subjects/[subjectId]/_layout.tsx` introduces a dynamic tab layout nested under a dynamic segment. Verify Expo Router SDK 52 handles this without requiring additional `unstable_settings` or `HrefObject` workarounds. If routing is anomalous, the agent must flag before implementing screens.
5. **Mascot greeting removed from `(child)/index.tsx`.** The P1-09 placeholder content (welcome mascot greeting) is replaced by the Subjects list. The mascot greeting moves to Wave 13 (P2-09-FE home dashboard). The sign-out action and `childName` derivation from `authStore` must be preserved — only the body content changes.
6. **Navigation guard when student has no grade.** If a student account has `Grade = null` (e.g., legacy seed user or incomplete onboarding), the Subjects list will be empty (enabled: false). This is not an error — the screen shows a neutral empty state. A separate onboarding guard (routing the student to a grade-selection step) is out of scope for Wave 11.
7. **Skill tree edge layout is linear (V1).** The plain vertical list of nodes grouped by concept matches the `09-skill-tree.png` screenshot but does not render actual DAG edges between skills across concepts. This is an accepted V1 simplification. Wave 11 does not render `KnowledgeEdge` data at all — the tree is a visual affordance, not a true DAG render.
8. **`SkillNodeDto.LessonIds` ordering.** Per HANDOFF, `SkillNodeDto.LessonIds` is returned in insertion order (`sk.Lessons.Select(l => l.Id)`). Wave 11 picks `lessonIds[0]` for navigation. If multiple lessons per skill become UX-important, the tab-scroll-to-skill pattern is deferred.
9. **.NET 9 runtime for NSwag.** Regen requires .NET 9 runtime installed side-by-side (HANDOFF load-bearing config). The B0b agent must check before running `refresh:swagger` and install if absent.
10. **`WhyLockedSheet` on web.** The brief says "bottom sheet on mobile, dialog on web." For Wave 11 a single component can detect platform via `Platform.OS === 'web'` and swap between a modal overlay and a bottom-sheet layout. If this increases complexity beyond 1h, fall back to a modal dialog on both platforms for Wave 11 and mark a Wave 12 polish note.
