## Execution batches

### Batch 1 — Author + wire the seeder (sequential, single `backend-feature` agent)

**Agent:** `backend-feature`

**Tasks:** P2-10-BE-1, P2-10-BE-3, P2-10-BE-2 (in that order within the batch)

**Rationale:** BE-1 and BE-3 share the same output file; BE-2 is a small follow-on edit to a different file but depends on the seeder type existing. All three are content-only changes with no schema impact. Running them as one batch avoids a mid-implementation reviewer gate on a partial state.

**Files to create / modify:**

- CREATE `backend/src/Modules/Learning/Learnexia.Modules.Learning.Infrastructure/Persistence/Seed/LearningSeeder.cs`
- MODIFY `backend/src/Modules/Learning/Learnexia.Modules.Learning.Api/LearningModule.cs` (add `IHostEnvironment` resolve + dev-only seeder call after `MigrateAsync`)

**Implementation constraints for the agent (bake into the code, not negotiable):**

1. **Location:** `Learnexia.Modules.Learning.Infrastructure/Persistence/Seed/LearningSeeder.cs` — mirrors `IdentitySeeder.cs` path exactly.

2. **Signature:** `public static class LearningSeeder` with `public static async Task SeedAsync(IServiceProvider serviceProvider)`. Resolve `LearningDbContext` and `IHostEnvironment` from the provider; the environment gate is already in `InitializeAsync` (see item 6 below), but the seeder itself should not re-gate — keep it pure data logic so tests can call it directly without needing a host environment.

3. **System user id:** `CreatedBy` is a plain `int` on `CreationAuditedEntity` (no FK). The Identity and Catalog seeders use no `CreatedBy` convention since they use ASP.NET Identity's `UserManager` (which handles its own audit). For `LearningDbContext.SaveChangesAsync(userId)`, use `userId = 0` as the system/seed constant. Document this constant in the seeder with a comment. (There is no established Catalog seeder to mirror for this — `0` is the safe default for a system-originated row with no real user.)

4. **Idempotency strategy:** per-node natural-key guards at each level:
   - Grade: `Grades.AnyAsync(g => g.Number == number)` — if exists, fetch it, do not add.
   - Subject: `Subjects.AnyAsync(s => s.Name == name && s.GradeId == gradeId)`.
   - Unit: `Units.AnyAsync(u => u.Name == name && u.SubjectId == subjectId)`.
   - Concept: `Concepts.AnyAsync(c => c.Name == name && c.SubjectId == subjectId)`.
   - Skill: `Skills.AnyAsync(sk => sk.Name == name && sk.ConceptId == conceptId)`.
   - Lesson: `Lessons.AnyAsync(l => l.Name == name && l.UnitId == unitId)`.
   - Use `AsNoTracking` for the existence checks; add only when missing.

5. **Save semantics:** stage all new entities via `dbContext.Add(...)`, then call `await dbContext.SaveChangesAsync(SystemUserId)` once at the end (EF resolves the FK graph). If the grade/subject already exists, fetch the existing Id by querying (not by navigation) before building children — generated Ids are needed for FK columns.

6. **LearningModule.InitializeAsync wiring:** add `using Microsoft.Extensions.Hosting;` to LearningModule.cs. After `await dbContext.Database.MigrateAsync();`, add:
   ```csharp
   var env = serviceProvider.GetRequiredService<IHostEnvironment>();
   if (env.IsDevelopment())
       await LearningSeeder.SeedAsync(serviceProvider);
   ```
   No Host edit needed — `Program.cs` already calls `LearningModule.InitializeAsync(scope.ServiceProvider)`.

7. **Content structure — per-subject builder methods** (no design patterns): one private static method per subject — `SeedMathAsync`, `SeedScienceAsync`, `SeedArabicAsync`, `SeedEnglishAsync` — called from a loop over grades. Each method receives `(LearningDbContext db, int gradeId, int subjectId)` and is responsible for its own Units/Lessons/Concepts/Skills. This is the P2-11 extension seam: P2-11 can call an equivalent `SeedMathKnowledgeEdgesAsync(db, subjectId, existingSkillIds)` without modifying P2-10 content.

8. **Grades seeded:** all 6 (Grade 1–6), each with the 4 subjects. `Grade.Number` is the natural key (`Number = 1` through `6`). `Grade.DisplayName` = `"Grade 1"` through `"Grade 6"` (English, consistent with dev/demo context). This satisfies the lead decision to seed all 6 grades with extensible structure.

9. **Math depth requirement (BE-3):** Math per grade must have strictly more than the other three subjects:
   - Math: ≥ 5 Units, each Unit ≥ 3 Lessons (at least one with `SkillId` set), ≥ 5 Concepts, each Concept ≥ 3 Skills.
   - Science, Arabic, English: ≥ 2 Units, each Unit ≥ 2 Lessons, ≥ 2 Concepts, each Concept ≥ 2 Skills.
   - Vary `DifficultyLevel` (Easy/Medium/Hard) across lessons and concepts. Set `MasteryThreshold` (e.g. 70–90), `EstimatedTimeMinutes` (10–45), `SequenceOrder` (1-based, ascending), and `IsLocked` (first lesson false, subsequent true).

10. **Skill natural keys for P2-11:** skill Names must be stable and unique within their Concept (e.g. `"Add Single-Digit Numbers"` not `"Skill 1"`). These names are the stable keys P2-11 will use to look up skills and attach prerequisite edges.

11. **No design patterns** introduced without lead approval — plain per-subject private static methods are the default and sufficient.

12. **No logging required** in the seeder unless it aids diagnostics — if added, resolve `ILoggerManager`, not `ILogger<T>`.

13. **No migration** — zero schema changes; if a missing column is discovered, stop and raise it.

**Test project spec:**
- Mirror `backend/tests/Modules.Catalog.UnitTests/Modules.Catalog.UnitTests.csproj` structure.

**Test cases required (all assertions via FluentAssertions):**

| Test | What it asserts | Maps to AC |
|---|---|---|
| `SeedAsync_Creates_ExactlyFourSubjects_PerGrade` | After seeding, `db.Subjects.Count(s => s.GradeId == gradeId) == 4` for Grade 1; subjects named Math, Science, Arabic, English present | AC-1 |
| `SeedAsync_TreeIsFullyLinked_NoOrphans` | Every Unit has a SubjectId > 0 that exists; every Lesson has a UnitId > 0 that exists; every Concept has a SubjectId > 0; every Skill has a ConceptId > 0 | AC-2 |
| `SeedAsync_LessonsLinkToSkills_WhereSet` | At least one Lesson in Math Grade 1 has `SkillId != null`; that SkillId exists in Skills | AC-3 |
| `SeedAsync_Math_HasDeepestTree` | Math unit count > Science/Arabic/English unit counts (for the same grade); Math concept count > others; Math skill count > others | AC-5 |
| `SeedAsync_IsIdempotent_SecondRunDoesNotDuplicate` | Call `LearningSeeder.SeedAsync` twice on the same InMemory DB; assert `db.Grades.Count()`, `db.Subjects.Count()`, `db.Units.Count()`, `db.Lessons.Count()`, `db.Concepts.Count()`, `db.Skills.Count()` are identical before and after the second call | AC-4 |

**InMemory DB setup:** Use `DbContextOptionsBuilder<LearningDbContext>().UseInMemoryDatabase(Guid.NewGuid().ToString())` per test (fresh DB per test). Call `LearningSeeder.SeedAsync(serviceProvider)` directly — the test's service provider provides the InMemory `LearningDbContext`.
