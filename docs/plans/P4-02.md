## Acceptance criteria (verbatim from story)

1. **AC1** — XP is awarded per event (e.g., correct +10, quiz +20, lesson +50, streak bonus +30) via event handlers.
2. **AC2** — Each award writes an `XPTransaction` ledger entry (amount, reason, timestamp).
3. **AC3** — Level is computed from total XP and updates immediately on the dashboard/XP bar.
4. **AC4** — XP totals are consistent (no double-award for the same event).

**B1-1 — Entities + DbContext**

`StudentXpProfile.cs : AggregateRoot`
- Fields: `Id (int, PK identity)`, `StudentId (int, NOT NULL, unique)`, `XpTotal (int, default 0)`, `Level (int, default 1)`, `UpdatedAt (DateTime)`.
- No FK to Identity — `StudentId` is a plain `int` (module isolation rule 1).
- Static factory: `StudentXpProfile.CreateFor(int studentId)` initializes `XpTotal=0, Level=1, UpdatedAt=DateTime.UtcNow`.
- Mutation method: `ApplyAward(int amount, int newLevel)` — increments `XpTotal`, sets `Level`, updates `UpdatedAt`; raises `StudentLeveledUpDomainEvent(StudentId, oldLevel, newLevel)` only when `newLevel > oldLevel`.
- Derived from `AggregateRoot` so `StudentLeveledUpDomainEvent` can be collected by `UnitOfWorkBehavior` after commit.

`XpAward.cs : FullAuditedEntity`
- Fields: `Id (int, PK identity)`, `StudentId (int, NOT NULL)`, `Amount (int, NOT NULL)`, `Reason (XpReason, stored as int)`, `OriginEventId (Guid, NOT NULL)`, `OriginLessonId (int?)`, `OriginSkillId (int?)`, `CreatedAt (DateTime)`.
- Static factory: `XpAward.Create(int studentId, int amount, XpReason reason, Guid originEventId, int? originLessonId, int? originSkillId)`.
- **No mutation methods** — append-only ledger.
- NOT derived from `AggregateRoot` (it is a ledger row, not an aggregate root with domain events; `FullAuditedEntity` is sufficient).

`GamificationDbContext`
- `public const string Schema = "gamification";`

- `DbSet<XpAward> XpAwards`
- EF conventions for most config; explicit unique index `UX_StudentXpProfiles_StudentId` on `StudentId` and `UX_XpAwards_OriginEventId_Reason` on `(OriginEventId, Reason)` using `OnModelCreating` Fluent API (these cannot be expressed by attribute convention alone).

**B2-1 — Domain pure layer**

`GamificationConstants.cs`
```csharp
// backend/src/Modules/Gamification/Learnexia.Modules.Gamification.Domain/Constants/GamificationConstants.cs
namespace Learnexia.Modules.Gamification.Domain.Constants;

public static class GamificationConstants
{
    public static class XpRewards
    {
        public const int CorrectAnswer  = 10;
        public const int QuizCompleted  = 20;   // stub — no producer this cycle
        public const int LessonCompleted = 50;
        public const int StreakBonus    = 30;   // stub — no producer this cycle

        public static int For(XpReason reason) => reason switch
        {
            XpReason.CorrectAnswer   => CorrectAnswer,
            XpReason.QuizCompleted   => QuizCompleted,
            XpReason.LessonCompleted => LessonCompleted,
            XpReason.StreakBonus     => StreakBonus,
            _                        => 0
        };
    }
}
```

`LevelCurve.cs` — pure static class in `Domain/Services/`, mirroring the shape of `LearningPathEngine`. Public API: `public static int LevelFor(int xp)` and `public static (int Level, int CurrentLevelXp, int XpToNextLevel) InfoFor(int xp)`.
- Table: `private static readonly int[] Thresholds = { 0, 100, 250, 500, 1000, 2000, 4000, 7000, 11000, 16000 };` (10 entries — L1 at index 0 through L10 at index 9).
- `LevelFor(int xp)`: walk the table; if `xp >= Thresholds[9]` then `L10 + ((xp - 16000) / 5000)` (floor integer division). For `xp < 0`, clamp to `L1`.
- `InfoFor(int xp)`: returns the level, the XP within the current level, and XP needed to reach the next level. Used by `GetStudentProfileQuery` for `XpToNextLevel`.
- No DI, no DB access — fully unit-testable in isolation.

`StudentLeveledUpDomainEvent.cs`

**B2-2 — Repository + UnitOfWorkBehavior**

`IGamificationRepository.cs` — interface in `Application/Abstractions/`:
```csharp
Task<StudentXpProfile?> GetXpProfileByStudentIdAsync(int studentId, CancellationToken ct = default);
Task<bool> AnyXpAwardWithOriginEventAsync(Guid originEventId, XpReason reason, CancellationToken ct = default);
Task AddXpAwardAsync(XpAward award, CancellationToken ct = default);
void UpsertXpProfile(StudentXpProfile profile);   // stage only — UoW commits
```

`GamificationRepository.cs` — implementation in `Infrastructure/Repository/`:
- All reads use `AsNoTracking()`.
- `GetXpProfileByStudentIdAsync`: `FirstOrDefaultAsync` on `StudentXpProfiles` where `StudentId == studentId`; returns tracking-enabled result (handler needs to track for the subsequent `ApplyAward` mutation). Note: this is the one read that must NOT use `AsNoTracking` because the handler modifies the entity — use the default tracked query, then call `UpsertXpProfile` to attach if it was created new.
- `AnyXpAwardWithOriginEventAsync`: `AsNoTracking`, `AnyAsync(x => x.OriginEventId == originEventId && x.Reason == reason)` — cheap idempotency pre-check.
- `AddXpAwardAsync`: `await _context.XpAwards.AddAsync(award, ct)` — stage only.
- `UpsertXpProfile`: if profile has `Id == 0` (new): `_context.StudentXpProfiles.Add(profile)`; else: `_context.StudentXpProfiles.Update(profile)` — stage only.

`UnitOfWorkBehavior.cs` in `Infrastructure/Behaviors/` — verbatim copy of Learning's with `LearningDbContext` swapped for `GamificationDbContext`. No other change.

**B2-3 — `AwardLessonCompletedXpCommand` + handler + validator**

Command: `record AwardLessonCompletedXpCommand(Guid OriginEventId, int StudentId, int LessonId, int SkillId) : ICommand<BaseResponse<int>>`.

Handler steps (inside `UnitOfWorkBehavior` transaction):
1. Idempotency pre-check: `if (await _repo.AnyXpAwardWithOriginEventAsync(OriginEventId, XpReason.LessonCompleted, ct)) { _logger.LogInformation("P4-02: duplicate LessonCompleted event {EventId} for student {StudentId} — ignored", OriginEventId, StudentId); return Success(0); }`
2. Row-lock (Q7): `await _context.Database.ExecuteSqlInterpolatedAsync($"SELECT 1 FROM gamification.\"StudentXpProfiles\" WHERE \"StudentId\" = {StudentId} FOR UPDATE", ct);` (no-op if no row yet — Postgres `FOR UPDATE` skips missing rows, so this is safe for the "first event" path).
3. Load profile: `var profile = await _repo.GetXpProfileByStudentIdAsync(StudentId, ct) ?? StudentXpProfile.CreateFor(StudentId);`
4. Create award: `var award = XpAward.Create(StudentId, GamificationConstants.XpRewards.LessonCompleted, XpReason.LessonCompleted, OriginEventId, LessonId, SkillId);`
5. Stage award: `await _repo.AddXpAwardAsync(award, ct);`
6. Update profile: `var newLevel = LevelCurve.LevelFor(profile.XpTotal + GamificationConstants.XpRewards.LessonCompleted); profile.ApplyAward(GamificationConstants.XpRewards.LessonCompleted, newLevel);`
7. Stage profile: `_repo.UpsertXpProfile(profile);`
8. Return `Success(GamificationConstants.XpRewards.LessonCompleted);`
9. Catch `DbUpdateException` with unique-constraint code: log + return `Success(0)` (defense-in-depth for the idempotency race window).

Validator: `RuleFor(x => x.StudentId).GreaterThan(0); RuleFor(x => x.LessonId).GreaterThan(0); RuleFor(x => x.OriginEventId).NotEqual(Guid.Empty);`

**B2-4 — `AwardAnswerSubmittedXpCommand` + handler + validator**

Same shape as B2-3. Key difference: awarded reason = `XpReason.CorrectAnswer`, amount = `GamificationConstants.XpRewards.CorrectAnswer`.
