### Batch 2 — PARALLEL — `backend-feature` agent (two threads)

These sub-batches are independent and touch disjoint files.

#### Batch 2a — BE-3 (MasteryEngine + unit tests)

**Files (all NEW):**
- `Learning.Domain/Services/MasteryEngine.cs` — pure static class, single public method `Compute(int totalAnswers, int correctAnswers, int masteryThreshold) → (int masteryPercentage, MasteryStatus status)`. State machine: `NotStarted` when totalAnswers==0; `NeedsReview` when pct<50; `InProgress` when 50≤pct<masteryThreshold; `Mastered` when pct≥masteryThreshold.
- `tests/Modules.Learning.UnitTests/MasteryEngineTests.cs` — xUnit + FluentAssertions, 8+ cases: zero-answers → NotStarted; exactThreshold → Mastered; belowThreshold → InProgress; below50 → NeedsReview; reproducibility (same inputs twice = same output); per-skill threshold variation (70 vs 80 vs 85); boundary at exactly 50; boundary just below threshold.

#### Batch 2b — BE-4 (Repository additions)

**Files (EDIT):**
- `Application/Abstractions/ILearningRepository.cs` — add four method signatures in a `// ── Mastery (P3-09) ──` region.
- `Infrastructure/Repository/LearningRepository.cs` — implement all four with `AsNoTracking()` for reads; `UpsertStudentSkillMasteryAsync` uses EF `AddOrUpdate` or Npgsql upsert pattern.

**File isolation check:** Batch 2a touches only `Domain/Services/` and test project. Batch 2b touches `ILearningRepository.cs` + `LearningRepository.cs`. No shared files between the two threads.

**Completion gate (each thread):** `dotnet build` green; unit tests for `MasteryEngine` all pass (thread A); interface + implementation compile (thread B).

### Batch 3 — PARALLEL — `backend-feature` agent (two threads)

Both depend on Batch 2 (both threads) completing. These sub-batches touch different files.

#### Batch 3a — BE-5 (Write path + explicit transaction)

**File (EDIT):** `Application/Features/Attempts/Commands/CompleteAttempt/CompleteAttemptCommandHandler.cs`

After the attempt is marked Completed, within an **explicit `IDbContextTransaction`** (ADR 0001 escape hatch):
1. Collect distinct `Question.SkillId` values from the attempt's `StudentAnswer` rows.
2. For each skill, aggregate correct + total answer counts.
3. Fetch the skill's `MasteryThreshold` from `Skill` entity.
4. Call `MasteryEngine.Compute(total, correct, threshold)`.
5. Upsert `StudentSkillMastery` row (`UpsertStudentSkillMasteryAsync`), setting `AttemptsCount++`, `LastPracticedAt = UtcNow`.
6. Commit the transaction.

Transaction boundary is explicit — the attempt completion and the mastery upsert are a single atomic write. Document the boundary clearly in code comments.

#### Batch 3b — BE-6 (Read path)

**Files (NEW):**
- `Application/Features/Mastery/Queries/GetStudentMastery/` — query + handler (returns all mastery rows for `ICurrentUserService.UserId`)
- `Application/Features/Mastery/Queries/GetSkillMastery/` — query + handler (single skill for current student; returns `NotStarted` default if no row, never 500)
- `Api/Controllers/MasteryController.cs` — `[Authorize(Roles="Student")]`; `GET /api/Learning/Mastery` and `GET /api/Learning/Mastery/Skill/{skillId}`.

**Files (EDIT):** `SharedResourcesKey.cs`, `SharedResources.en-US.resx`, `SharedResources.ar-EG.resx` — keys: `MasteryRetrievedSuccessfully`, `SkillMasteryRetrievedSuccessfully`, `SkillMasteryNotFound`.

**File isolation:** Batch 3a touches only `CompleteAttemptCommandHandler.cs`. Batch 3b touches the new files + shared localization. No collision.

### Batch 5 — SEQUENTIAL — `api-tester` agent

**Depends on:** Batch 4 complete (full system wired).

**File to create:** `backend/tests/Learnexia.IntegrationTests/P3_09_StudentMastery_Tests.cs`

Mirror `P2_08_RecordGranularAnswers_Tests.cs` (xUnit + Testcontainers PostgreSQL + Student-role JWT via parent→child onboarding flow).

**Minimum 8 integration test cases:**

| # | Test | Assertion |
|---|---|---|
| 1 | New student, no answers → `GET /Mastery` returns empty (or all NotStarted) | 200, empty array or all `status=0` |
| 2 | New student, single skill → `GET /Mastery/Skill/{id}` → NotStarted | 200, `status=0`, `masteryPercentage=0` |
| 3 | Complete attempt with ≥80% correct (threshold 80) → `GET /Mastery/Skill/{id}` → Mastered | `status=2`, `masteryPercentage≥80` |
| 4 | Complete attempt with <50% correct → NeedsReview | `status=3`, `masteryPercentage<50` |
| 5 | Complete attempt with ~60% correct (threshold 80) → InProgress | `status=1`, `50≤masteryPercentage<80` |
| 6 | Reproducibility: complete the same attempt pattern twice → identical `masteryPercentage` and `status` | Second call matches first |
| 7 | IDOR: Student B cannot read Student A's mastery (different JWTs, same skillId) | Student B's call returns empty/NotStarted, not Student A's data |
| 8 | Unknown `skillId` → 200 with NotStarted defaults, never 500 | `status=0`, `masteryPercentage=0` |

**Completion gate:** All 8 cases pass; api-tester reports PASS.
