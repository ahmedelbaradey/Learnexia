## Execution batches

### Batch 1 — PARALLEL — `backend-feature` agent — BE-1, BE-2, BE-3, BE-4 (all independent)

**Agent:** `backend-feature`
**Mode:** Parallel — all four touch different files.
**Shared-file warnings:**
- BE-3 touches `Shared.Contracts/Learning/` — serialize against P3-04-BE-2 if it is still in progress (P3-04 also adds to `Shared.Contracts/Learning/`). Best to co-develop on the same branch.
- BE-4 touches `Shared.Contracts/AiTutor/` (new path) + `Learning.Application` — serialize against any concurrent Learning changes.

BE-1 — `GetHintCommand`:
- `record GetHintCommand(int QuestionId, int AttemptId, int? HintLevel) : ICommand<void>` (or streaming result — mirror P3-04).
- Validator: `QuestionId` + `AttemptId` required; if `HintLevel` supplied, must be 1..N (OQ-5 max); grade/age/language from JWT in handler.

BE-2 — `SimplifyExplanationCommand`:
- `record SimplifyExplanationCommand(int? ConceptId, int? LessonId, string? PreviousExplanationRef) : ICommand<void>`.
- Validator: at least one of ConceptId/LessonId required.

BE-3 — `IQuestionAnswerContract` in `Shared.Contracts/Learning/`:
- `Task<QuestionAnswerDto?> GetQuestionAnswerAsync(int questionId, int attemptId, CancellationToken ct)`.
- `QuestionAnswerDto { string CorrectAnswer, int CurrentHintLevel }`.
- Learning.Infrastructure adapter: queries `LearningDbContext.QuizQuestions` (for `CorrectAnswer`) + `LearningDbContext.StudentAnswers`/`Attempts` (for `CurrentHintLevel` from `HintsUsedCount`).

BE-4 — `HintUsedIntegrationEvent` + Learning handler:
- Event: `record HintUsedIntegrationEvent(int QuestionId, int AttemptId, int HintLevel, int StudentId)` in `Shared.Contracts/AiTutor/HintUsedIntegrationEvent.cs`.
- Learning handler `HintUsedIntegrationEventHandler : INotificationHandler<HintUsedIntegrationEvent>`: finds `StudentAnswer` by (QuestionId, AttemptId), sets `HintUsed = true`; finds `Attempt`, increments `HintsUsedCount`; calls `SaveChangesAsync` (no UoW — direct save per ADR 0001).
- Mirrors the existing `AnswerSubmittedIntegrationEvent` direct-publish pattern (ADR 0002).

**Gate after Batch 1:** `dotnet build` green; all four artifacts exist and compile.

### Batch 2 — PARALLEL — `backend-feature` agent — BE-5 and BE-6 (independent)

**Depends on:** Batch 1 complete + P3-01/02/03/07 merged.
**Agent:** `backend-feature`
**Mode:** Parallel — BE-5 and BE-6 touch different files.

BE-5 — `GetHintCommandHandler` — orchestration:
1. Resolve grade/age/language from `ICurrentUserService`.
2. Call `IQuestionAnswerContract.GetQuestionAnswerAsync(questionId, attemptId)` — get `CorrectAnswer` + `CurrentHintLevel` (server-side escalation state — OQ-2b).
3. Determine effective `HintLevel`: if command carries `HintLevel`, use it; else use `CurrentHintLevel + 1` (next escalation level). Clamp to `[1, OQ-5 max]`.
4. Call `IChunkRetrievalContract.RetrieveAsync` for the question's concept/skill/grade.
5. Call P3-03 Prompt Builder — hint template: inject grade/age/language, chunks, child-safe tone, explicit instruction "DO NOT reveal the correct answer", scale specificity to `HintLevel` (level 1 = general nudge, level 3 = specific but still no answer).
6. Call P3-01 Gateway — cheap model per NFR-9.
7. **Buffer full response** (same OQ-2a as P3-04).
8. **Post-generation check (OQ-4):** inspect buffered text for the `CorrectAnswer` string (case-insensitive, substring). If found → regenerate once with a stronger "absolutely do not reveal" instruction. If second attempt also fails → return a generic "Try thinking about [key concept]" nudge (do not stream the leaking hint).
9. Call P3-02 Safety Layer. Failure → typed SSE error event.
10. Stream pre-checked hint via SSE; include `hintLevel` and `nextHintLevel` in a preamble SSE metadata event (e.g. `event: meta\ndata: {"hintLevel":2,"nextHintLevel":3}\n\n`) so P3-12 can show "Hint 2 of 3."
11. Fire-and-forget: publish `HintUsedIntegrationEvent`.

BE-6 — `SimplifyExplanationCommandHandler`:
- Reuses `ExplainConceptCommandHandler` from P3-04 but adds a "simplify / lower reading level" directive to the P3-03 prompt.
- Same buffer-safety-stream strategy (OQ-2a).
- No hint-level metadata, no usage recording.
- Cheap model routing (same as hints per NFR-9).

**Gate after Batch 2:** Handlers compile with stubbed cross-cluster deps; orchestration flow reviewable.

### Batch 4 — SEQUENTIAL — `api-tester` agent

**Depends on:** Batch 3 complete. Use **stubbed gateway + safety** for determinism.
**Agent:** `api-tester`

Required test cases:
1. **Hint level 1 nudges, no reveal:** seeded MCQ question; `POST /api/AiTutor/Hint` → hint text is non-empty, does NOT contain the `CorrectAnswer` string.
2. **Escalation:** call again for the same question (or pass `hintLevel=2`) → SSE `meta` event shows `hintLevel=2`, text is more specific than level 1 (assessor judgment or longer/more detailed output).
3. **Simplify:** `POST /api/AiTutor/Simplify` with valid LessonId → SSE streams lower-complexity text (non-empty, no raw error).
4. **Usage recorded:** after a successful hint → assert `StudentAnswer.HintUsed=true` and `Attempt.HintsUsedCount` incremented (query Learning DB state).
5. **Safety block:** stub safety to block → SSE `event: error`, no text streamed; usage NOT recorded (event not published on safety failure).
6. **Hint-level max:** `hintLevel = OQ-5 max + 1` → validator 400 error.
7. **Auth:** non-Student JWT → 403; no bearer → 401.
8. **Wire format:** preamble `event: meta` carries `hintLevel`/`nextHintLevel` as documented; verify with curl.

### Batch 5 — `security-auditor` (HARD GATE)

**Depends on:** Batch 3 complete.
**Agent:** `security-auditor`

AI text shown to children — **security-auditor is a hard gate; Critical/High findings block.**

Audit:
- **No-reveal enforcement (AC-1):** confirm the post-generation check (OQ-4) is wired and cannot be bypassed. Verify a hint cannot be coerced into stating the answer via repeated requests or prompt injection.
- **Escalation abuse:** hint level is server-derived (OQ-2b) — client cannot supply an arbitrarily high level to reach an effective-full-answer. Verify the clamp is enforced.
- **No Safety-Layer bypass (AC-4):** same as P3-04 audit; same buffer → safety → emit chain.
- **Usage-recording integrity (AC-5):** `HintUsedIntegrationEvent` is published only on successful hint delivery (not on error or safety failure). Client cannot suppress or spoof it.
- **Cost/abuse:** rate limit applied; hint-level max enforced.
- **No secret leakage:** gateway/safety adapter logs.
