## Acceptance criteria (verbatim from story)

1. **AC1** — Completing a qualifying activity on a day increments the streak; the streak state is visible (animated flame). Backend gate: `LessonCompletedIntegrationEventHandler` also sends `AdvanceStreakCommand`; `CurrentStreak` advances by exactly 1 when `OccurredOnUtc.Date > LastActivityDateUtc.Date` and the gap is 1 day; "visible" = real `Streak` value on `GET /api/Learning/Dashboard`. FE animation is P4-08.
2. **AC2** — Missing the required activity resets the streak per the configured rule. Backend gate: on next activity after a gap > 1 day, handler sets `CurrentStreak = 1`, preserves `LongestStreak`, raises `StreakBrokenDomainEvent`. No grace window (SRS FR-GM-2 rider; freeze in P4-11).
3. **AC3** — Streak count is stored on the student profile and surfaced on the dashboard. Backend gate: streak lives in `gamification.StudentXpProfiles` (`CurrentStreak`, `LongestStreak`, `LastActivityDateUtc`); dashboard reads via `IStudentStreakQuery` cross-module seam.
4. **AC4** — A daily background job evaluates streak continuity reliably across time zones. Backend gate: Hangfire `RecurringJob` "gamification:streak-sweep" runs at `00:05 UTC daily` (`"5 0 * * *"`); scans profiles where `CurrentStreak > 0 AND LastActivityDateUtc < today - 1 day`; sets `CurrentStreak = 0`; logs count reset; idempotent.

## Locked decisions recap

| # | Decision |
|---|---|
| D1 | **UTC day-boundary.** All streak computation uses `OccurredOnUtc` converted to `DateOnly` via `StreakDayCalculator.DayOf(utc, "UTC")`. `LastActivityDateUtc` stored as `DateOnly?` (maps to PG `date` natively via Npgsql 8+). `ISystemClock` seam introduced in `Shared.Kernel` for test injection. |
| D2 | **Lesson-completion only.** Only `LessonCompletedIntegrationEvent` advances the streak. `AnswerSubmittedIntegrationEventHandler` is left entirely unchanged. |
| D3 | **StreakBonus +30 XP on every advance day** (including reset day-1 after a miss). Same-day second lesson: no advance, no bonus. Via `XpReason.StreakBonus = 4` (already in enum — confirmed on disk). `XpAward` unique index `(OriginEventId, Reason)` prevents double-award. |
| D4 | **Sweep job ships P4-03.** Hangfire `RecurringJob` "gamification:streak-sweep" at `"5 0 * * *"` (00:05 UTC daily — 5-minute buffer). Batched `Take(1000)` writes. Sets `CurrentStreak = 0` (does NOT touch `LongestStreak`). Registration in `GamificationModule.InitializeAsync` via `RecurringJob.AddOrUpdate`. Job uses `IServiceScopeFactory` + fresh `GamificationDbContext` scope. |
| D5 | **Extend `StudentXpProfile`** with `CurrentStreak (int, default 0)`, `LongestStreak (int, default 0)`, `LastActivityDateUtc (DateOnly?, nullable)`. No new entity. New `AddStreakColumns` EF migration. |
| D6 | **Pattern A — extend existing handler.** `LessonCompletedIntegrationEventHandler` sends `AwardLessonCompletedXpCommand` first, then sends `AdvanceStreakCommand` in an independent `try/catch`. Each `Send` opens its own `UnitOfWorkBehavior` transaction — streak failure never rolls back XP award. |
| D7 | **`IStudentStreakQuery` cross-module seam** in `Shared.Contracts/Gamification/`, mirroring `IStudentXpQuery`. Impl in `Gamification.Infrastructure/Queries/StudentStreakQuery.cs`. Brand-new student (no profile) → `null` → `Streak = 0` (graceful zero-state). |
| D8 | **No dedicated streak endpoint.** Streak exposed only via `GET /api/Learning/Dashboard`. Any future standalone endpoint is a follow-up. |

**Extend `StudentXpProfile.cs`** — add 3 mutation methods (the 3 properties were added in B1-1):

```csharp
/// <summary>
/// Advances the streak by 1 for <paramref name="activityDate"/>. Updates LongestStreak.
/// Raises <see cref="StreakAdvancedDomainEvent"/>. Call only when the handler has confirmed
/// activityDate is strictly the next consecutive day after LastActivityDateUtc (or first ever).
/// Does NOT award XP — the handler does that.
/// </summary>
public void AdvanceStreak(DateOnly activityDate)
{
    CurrentStreak = (LastActivityDateUtc is null || CurrentStreak == 0) ? 1 : CurrentStreak + 1;
    LastActivityDateUtc = activityDate;
    LongestStreak = Math.Max(LongestStreak, CurrentStreak);
    RaiseDomainEvent(new StreakAdvancedDomainEvent(StudentId, CurrentStreak, LongestStreak, activityDate));
}

/// <summary>
/// Resets the streak to 1 (the new activity is day-1 of a fresh streak) after a gap > 1 day.
/// Raises <see cref="StreakBrokenDomainEvent"/> for the old streak, then
/// <see cref="StreakAdvancedDomainEvent"/> for the new day-1.
/// LongestStreak is preserved (never decreases).
/// Does NOT award XP — the handler does that.
/// </summary>
public void ResetStreakAndStart(DateOnly activityDate)
{
    var previousStreak = CurrentStreak;
    CurrentStreak = 1;
    LastActivityDateUtc = activityDate;
    LongestStreak = Math.Max(LongestStreak, CurrentStreak);
    RaiseDomainEvent(new StreakBrokenDomainEvent(StudentId, previousStreak, activityDate));
    RaiseDomainEvent(new StreakAdvancedDomainEvent(StudentId, CurrentStreak, LongestStreak, activityDate));
}

/// <summary>
/// Called by the sweep job to flag a broken streak when the student went silent.
/// Sets CurrentStreak = 0 (does NOT touch LongestStreak or LastActivityDateUtc).
/// Raises <see cref="StreakBrokenDomainEvent"/>.
/// Idempotent: no-op when CurrentStreak is already 0.
/// </summary>
public void BreakStreak()
{
    if (CurrentStreak == 0) return;
    var previousStreak = CurrentStreak;
    CurrentStreak = 0;
    RaiseDomainEvent(new StreakBrokenDomainEvent(StudentId, previousStreak, LastActivityDateUtc ?? DateOnly.MinValue));
}
```

**`AdvanceStreakCommandHandler.cs`** — steps inside `UnitOfWorkBehavior` transaction:

1. **Idempotency pre-check:** `if (await _repo.HasXpAwardAsync(request.OriginEventId, XpReason.StreakBonus, ct)) { _logger.LogInfo("P4-03: duplicate StreakBonus event ..."); return Success(Unit.Value); }` — defense-in-depth; the date-based check below is the primary guard.
2. **Row-lock:** `await _repo.AcquireProfileLockAsync(request.StudentId, ct);`
3. **Compute day-bucket:** `var activityDate = StreakDayCalculator.DayOf(request.OccurredAtUtc, _streakOptions.Value.TimeZoneId);`
4. **Load or create profile:** `var profile = await _repo.GetProfileByStudentIdAsync(request.StudentId, ct) ?? StudentXpProfile.CreateFor(request.StudentId); _repo.UpsertXpProfile(profile);`
5. **Branch on `LastActivityDateUtc` vs `activityDate`:**
   - `== activityDate` (same day): log "P4-03: same-day activity — streak unchanged", `return Success(Unit.Value)`. No XP write.
   - `null` OR `== activityDate.AddDays(-1)` (first ever or consecutive day): `profile.AdvanceStreak(activityDate);`
   - `< activityDate.AddDays(-1)` (gap > 1 day): `profile.ResetStreakAndStart(activityDate);`
   - `> activityDate` (out-of-order stale event): log warning "P4-03: out-of-order activity event ignored", `return Success(Unit.Value)`. No write.
6. **Award StreakBonus XP** (only reached on advance or reset branches):
   ```csharp
   var award = XpAward.Create(profile, XpReason.StreakBonus,
       GamificationConstants.XpRewards.StreakBonus, request.OriginEventId,
       request.OccurredAtUtc, request.LessonId, request.SkillId);
   await _repo.AddXpAwardAsync(award, ct);
   ```

**B2-5 — `StreakSweepJob`**

Path: `Application/Jobs/StreakSweepJob.cs`

```csharp
public sealed class StreakSweepJob
{
    private readonly IServiceScopeFactory _scopeFactory;
    private readonly ILoggerManager _logger;
    private readonly ISystemClock _clock;
    private readonly IOptions<StreakOptions> _options;

    public StreakSweepJob(IServiceScopeFactory scopeFactory,
        ILoggerManager logger, ISystemClock clock, IOptions<StreakOptions> options)
    { /* assign */ }

    public async Task RunAsync(CancellationToken ct)
    {
        var today = StreakDayCalculator.Today(_options.Value.TimeZoneId, _clock);
        var threshold = today.AddDays(-1);    // "yesterday or older = broken"
        var totalReset = 0;

        await using var scope = _scopeFactory.CreateAsyncScope();
        var repo = scope.ServiceProvider.GetRequiredService<IGamificationRepository>();

        List<StudentXpProfile> broken;
        do
        {
            broken = await repo.GetBrokenProfilesAsync(threshold, ct);
            foreach (var profile in broken)
                profile.BreakStreak();
            if (broken.Count > 0)
            {
                await repo.SaveChangesAsync(ct);
                totalReset += broken.Count;
            }
        } while (broken.Count == 1000);   // keep paging while a full batch came back

        _logger.LogInfo($"P4-03: streak-daily-sweep reset {totalReset} broken streaks (threshold={threshold}).");
    }
}
```

Important design notes:
- The job uses `IServiceScopeFactory` to create a **fresh DI scope** with its own `GamificationDbContext` — it does NOT share the HTTP request scope (there is none under Hangfire). This is how all Hangfire jobs must handle DbContext in scoped DI (the host registers DbContext as Scoped, not Singleton).
- `BreakStreak()` is idempotent (`if (CurrentStreak == 0) return;`) — running the job twice same day is safe.
- Domain events (`StreakBrokenDomainEvent`) raised by `BreakStreak()` will be dispatched by `SaveChangesAsync` if `GamificationDbContext.SaveChangesAsync` calls `IDomainEventDispatcher` (mirror P4-02's UoW pattern). Verify the `GamificationDbContext.SaveChangesAsync` override dispatches `AggregateRoot.DomainEvents`. If it does not (direct `base.SaveChangesAsync`), the events are silently dropped — which is acceptable this cycle (no consumer yet for `StreakBrokenDomainEvent`). Note in HANDOFF.
- Sweep job does NOT go through `UnitOfWorkBehavior` (it's not a MediatR command) — `repo.SaveChangesAsync` is called directly.

## Risks — top 3 with mitigations

| Rank | Risk | Mitigation |
|---|---|---|
| R1 (HIGH) | **Date-vs-DateTime timezone bugs.** Storing `LastActivityDateUtc` as `DateOnly` but comparing against `OccurredOnUtc DateTime` is exactly where TZ bugs appear. A lesson completed at 23:45 UTC might land on a different calendar day if Cairo TZ is ever introduced, causing a streak to be counted or skipped incorrectly. | All date conversion funnels through `StreakDayCalculator.DayOf(utc, timeZoneId)` — the only place in the codebase that touches TZ conversion. Unit-tested at boundary values (00:00 UTC, 23:59 UTC, and 23:59 Cairo if Cairo TZ is tested). Never use `.Date` elsewhere. |
| R2 (HIGH) | **Same-day double-advance.** Two lessons on the same day each have different `EventId`s — the `(OriginEventId, XpReason.StreakBonus)` unique index does NOT catch this (different EventIds). Only the `LastActivityDateUtc == activityDate` branch prevents it. If that branch has a bug (e.g., `<=` instead of `==`), the streak increments twice. | Branch condition is `== activityDate` (strict equality on `DateOnly`); the pre-check `HasXpAwardAsync(originEventId, StreakBonus)` is for redelivery of the same event only. Gate: T3 asserts `Streak == 1` after two lessons same day. If T3 fails, the branch condition is broken. |
| R3 (MED) | **Sweep job DbContext scope leak.** If `StreakSweepJob` resolves `GamificationDbContext` from the root container (Singleton scope) instead of a fresh Scoped container, EF throws `InvalidOperationException` (Scoped from Singleton). | Job uses `IServiceScopeFactory.CreateAsyncScope()` and resolves `IGamificationRepository` from within the scope. The scope is `await using` — disposed when the method exits. Verified pattern from Hangfire + EF Core best practices. T10 (sweep job integration test) will surface this if the scope wiring is wrong. |
