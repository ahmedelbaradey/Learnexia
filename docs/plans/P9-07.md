## Execution batches

### Batch 1 — SEQUENTIAL — `db-migration` — BE-1

Verify `Payment.Kind` + `TargetChildId` from P9-06-BE-1/BE-2. If present: no migration needed (1h confirm). If missing: add the fields + generate `AddPaymentPackFields` migration (serialized after `AddPaymentAndWebhookTables`). Coordinate per PARALLELISM.md.

**DoD:** `billing.Payments` has `Kind` (int) + `TargetChildId` (nullable int) columns.

### Batch 2 — PARALLEL — `backend-feature` — BE-2, BE-3

BE-2 (`StartPackCheckoutCommand`) and BE-3 (extend webhook handler for `Kind=Pack`) are independent of each other — both depend only on BE-1 and `IPaymentProvider` from P9-06. Run in parallel. BE-4 (`PackController`) follows BE-2 immediately (trivial — 1h).

**DoD:** build green; pack checkout creates `Payment{Kind=Pack, TargetChildId}`; webhook on success appends `Purchase` ledger row + `PurchasedBalance` increment; duplicate webhook is no-op.

### Batch 3 — SEQUENTIAL — `api-tester`

After Batch 2. Provider sandbox required. Cases: pack checkout → correct `Payment` created; webhook success credits child once; duplicate webhook no double-credit; failed payment credits nothing; non-owned child rejected; child JWT rejected; purchased credits survive simulated cycle rollover (never expire); `BaseResponse<T>`/`Successed`.

### Batch 4 — SEQUENTIAL (after Batch 3) — `security-auditor` (MANDATORY)

**Critical/High block.** Focus: no-double-credit (idempotency is the core invariant), amount = configured pack price (server-set), family-scope (parent cannot credit non-owned child), parent-gated (child JWTs rejected), webhook signature (inherited from P9-06).

### Batch 5 — PARALLEL with Batch 3 — `frontend` — FE-1, FE-2, FE-3, FE-4, FE-5

No separate designer stage — mirrors P9-06 checkout. FE-1 (hook) → FE-2 (screen) → FE-3 (return) → FE-4 (CTA placement, D5) → FE-5 (i18n). Requires live backend (Batch 3 done or mocked) and security-auditor PASS.

### Batch 6 — SEQUENTIAL — `frontend-e2e-tester` — FE-6

After Batch 5. Assert no purchase surface on child routes.

### Batch 7 — SEQUENTIAL — `reviewer` then `committer`

Reviewer gates all ACs + CONVENTIONS + tester results. PASS → `committer` → branch `feat/P9-07-buy-energy-pack`, PR to `main`, HANDOFF.md update (pack credit-add idempotency, never-expire confirmed, refund context for P9-09). Never merge.
