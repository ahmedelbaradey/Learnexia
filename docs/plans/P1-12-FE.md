## PR / Execution Mode Recommendation

### Recommendation: THREE stacked PRs (split by risk and reviewability)

The localization wave ran strictly sequential (one PR per story, one reviewer gate). P1-12-FE is larger and has heterogeneous risk profiles — the OAuth flow and password-reset screens are net-new and security-sensitive, while the register consent patch is a two-line change. Splitting into three PRs keeps each review focused and lets a security failure in the OAuth batch not block the lower-risk profile/register work.

**PR 1 — Foundation + Profile/Avatar + Register** (`feat/P1-12-FE-batch1`)
- FE-0a (transport fix)
- FE-0b, FE-0c, FE-0d, FE-0e, FE-0f, FE-0g (all api-client hooks + schemas exports)
- FE-1 (profile save verification)
- FE-2 (avatar upload/remove)
- FE-7 (register consent + country)
- security-auditor on this batch (avatar upload, transport fix, consent)
- reviewer gate 1

**PR 2 — Password-Reset + Edit-Child** (`feat/P1-12-FE-batch2`, stacked on PR 1)
- FE-4 (forgot-password + reset-password screens)
- FE-5 (edit-child on web)
- security-auditor on this batch (password-reset token/no-enumeration)
- reviewer gate 2

**PR 3 — Google OAuth + QA** (`feat/P1-12-FE-batch3`, stacked on PR 2)
- FE-3 (Google OAuth flow)
- FE-6 (RTL/dark/light QA across all surfaces)
- security-auditor on this batch (OAuth token handling, account-takeover, PKCE)
- reviewer gate 3 (final)

**Rationale:**
- PR 1 is medium-risk: transport fix is load-bearing but straightforward; avatar upload has file-type/size risk; consent is trivial. Smallest security surface.
- PR 2 is medium-risk: new screens with no OAuth complexity; password-reset token flow is security-sensitive but well-defined.
- PR 3 is highest-risk: OAuth is the most novel, requires the most security scrutiny, and has the "wired, pending client ID" verification caveat. Isolating it last means PRs 1+2 can merge even if the OAuth client-ID situation delays PR 3.

If the lead prefers a single PR for simplicity, that is acceptable given the story is otherwise self-contained — but the security audit scope would be larger and a single failure blocks everything.
