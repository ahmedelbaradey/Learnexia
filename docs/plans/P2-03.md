## Schema gap analysis

**Result: MIGRATION REQUIRED.**

The current `Lesson.cs` entity (confirmed by reading the file) has no `IsBoss` field. A Grep over `backend/` for `IsBoss|Boss` returns zero matches. The `learning.Lessons` table must gain one non-nullable `boolean` column.

| Column | EF type | DB type | Nullable | Default |
|---|---|---|---|---|
| `IsBoss` | `bool` | `boolean` | NO | `false` |

**Migration name:** `AddLessonIsBoss` — mirrors PascalCase convention of `AddLessonContent`, `AddQuizTables`, `AddSkillGraphTables`.

**`Up()` body:**
```csharp
migrationBuilder.AddColumn<bool>(
    name: "IsBoss",
    schema: "learning",
    table: "Lessons",
    type: "boolean",
    nullable: false,
    defaultValue: false);
```

**`Down()` body:**
```csharp
migrationBuilder.DropColumn(
    name: "IsBoss",
    schema: "learning",
    table: "Lessons");
```

The `defaultValue: false` is load-bearing: it backfills all 162 existing seeded rows to `false` deterministically, so the seeder's boss-mark pass produces a clean 66-row delta on first run. No index needed — `IsBoss` is never a filter target; all reads are per-`UnitId` or per-`Id`, both already indexed.

**`LessonConfig.cs` update** (one line after the `Visual` block):
```csharp
builder.Property(x => x.IsBoss)
    .IsRequired();
```

**`LearningDbContextModelSnapshot.cs`** must be updated by EF tooling as part of `dotnet ef migrations add`. This is automatic — the db-migration agent must verify the snapshot diff includes `IsBoss`.

**Three migration-related files** (same as P2-05 precedent): `<timestamp>_AddLessonIsBoss.cs`, `<timestamp>_AddLessonIsBoss.Designer.cs`, `LearningDbContextModelSnapshot.cs`.

#### BE-3b — `LearningSeeder.MarkBossLessonsAsync`

**File:** `backend/src/Modules/Learning/Learnexia.Modules.Learning.Infrastructure/Persistence/Seed/LearningSeeder.cs` (EDIT)

Add a new private async method `MarkBossLessonsAsync`. The method is called at the END of `SeedAsync`, after the `SeedDemoLessonContentAsync` call (per brief Q3 and Q10). The method must be the last seeder step.

**Method signature:**
```csharp
private static async Task MarkBossLessonsAsync(
    LearningDbContext db,
    ILoggerManager? logger)
```

**Logic:**

1. Load all `Unit` rows with their `Lessons` (AsNoTracking — read first), filtered to only include `Lessons` that are tracked/exist.
2. For each unit, find the lesson with the highest `SequenceOrder`. If two lessons share the same `SequenceOrder` (should not happen given the seeder invariant, but be defensive), pick the one with the lowest `Id`.
3. Mark that lesson `IsBoss = true` in the change tracker — re-fetch it as tracked (not AsNoTracking) so EF can update it.
4. Mark all other lessons in the unit `IsBoss = false` (prevents drift if a future curriculum change moves the boss).
5. Commit only when `db.ChangeTracker.HasChanges()`.
6. Log a summary line: `"P2-03 seed: marked {markedCount} lesson(s) as boss; {alreadyCorrectCount} already correct."` — using `ILoggerManager` if non-null.

**Idempotency:** On a fresh dev DB (first run), 66 lessons are updated (`IsBoss = true`). On subsequent runs, `IsBoss` is already correct for all 162 rows, so `HasChanges()` is false and `SaveChangesAsync` is not called. This satisfies the seeder idempotency contract.

**Invariant constraints the agent must NOT violate:**

- `SaveChangesAsync` is only called inside the seeder (seeder is explicitly exempt from the "no SaveChanges outside GenericRepository" rule — it pre-dates the UoW ADR and uses `LearningDbContext` directly).
- Do NOT call `SaveChangesAsync` from any handler, DTO, or mapping file.
- `ILoggerManager` is used for logging (not `ILogger<T>`).
- No new NuGet packages.
