## Lead decisions applied

1. **Single `QuizQuestion` entity + `QuestionType` enum discriminator.** `Options` and `CorrectAnswer` stored as serialized jsonb (no TPH/inheritance — no design pattern introduced per CLAUDE.md rule 8). Per-type shape enforced in FluentValidation only.
2. **No `Quiz` entity.** Route param `{id}` = `LessonId`. Questions grouped by `LessonId` (loose int ref). `POST /api/Assessment/Quizzes/{lessonId}/Attempt` creates `Attempt{StudentId, LessonId, Status=InProgress, StartedAt=now}` and returns `attemptId`.
3. **`StudentId` resolved from JWT via `ICurrentUserService.UserId`.** Endpoint is `[Authorize]`. Client never supplies StudentId.
4. **Forward-compatible entity field set** — `Attempt` and `StudentAnswer` carry all fields that P2-07/P2-08 will populate (see entity spec in Pipeline Brief §Affected modules). No rewrite next wave.
5. **Enums stored as `int`** via `HasConversion<int>()` — `QuestionType`, `DifficultyLevel`, `GeneratedBy`, `AttemptStatus`.
6. **New module scaffolded as 4 csproj files** under `backend/src/Modules/Assessment/`, added to `backend/Learnexia.Modular.sln`, schema `assessment`. Mirrors Learning module exactly.
7. **Pipeline gates:** `security-auditor` (child data + auth) before reviewer gate 2; `api-tester` (HTTP endpoint exposed) after backend-feature completes; no designer stage (backend-only slice).

### Batch 5 — sequential: `security-auditor`

**Agent:** `security-auditor`
**Mode:** sequential (after reviewer gate 1)
**Prerequisite:** Reviewer gate 1 passed.

Security-sensitive surface in this story: **child data** (Attempt records belong to a child/student), **auth** (JWT + `ICurrentUserService.UserId` — StudentId must never be client-supplied), **auth/authz** on the start-attempt endpoint.

Audit checklist:
- [ ] `[Authorize]` is present on `POST {lessonId}/Attempt`; unauthenticated call returns 401.
- [ ] `StudentId` is resolved **only** from `ICurrentUserService.UserId`; no route param, query string, or body field allows a caller to override it.
- [ ] `ICurrentUserService.UserId` is null-safe — handler/validator must guard against a null claim (anonymous caller bypassing Authorize).
- [ ] `LessonId` is validated as a positive integer; no SQL-injection surface via ORM.
- [ ] `Options`/`CorrectAnswer` jsonb columns: confirm Npgsql parameterizes the jsonb write (no raw concatenation risk).
- [ ] No sensitive data (StudentId, AttemptId correlation) leaked in error responses or logs beyond appropriate `ILoggerManager` calls.
- [ ] Enum-as-int storage does not expose an injection surface (int conversion is typed, not parsed from raw string at the DB boundary).

**Critical/High findings block gate 2 and must be resolved before api-tester.**
