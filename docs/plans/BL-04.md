BE-12 (entity prop) is folded with BE-11 (column + config) so the migration maps a real property; BE-13 backfills after the column exists.
- **BE-6** (test gate) depends on the **curriculum chain only** for its net-new assertions (provenance/version/KGSuggestion round-trips) plus the already-shipped chunk + embedding tables. It does not depend on the learning chain, but is scheduled after both for a single clean gate.

Within-chain order is forced by the shared `*ModelSnapshot.cs` file — never parallelize two migrations in the same chain.

## Execution batches

> BL-04 is essentially **one `db-migration` agent doing all schema work sequentially**, then a `reviewer` gate. The two chains *could* be split across two `db-migration` agents in separate worktrees (they share no file), but the cost/coordination of splitting 6 small ordered tasks is not worth it — recommend a **single `db-migration` agent** running the chains back-to-back. If the lead wants wall-clock parallelism, Batch 1 and Batch 2 are independent and can run as two agents per PARALLELISM.md (different module / schema / snapshot — no shared-file contention).

- **Batch 1 — Curriculum schema (db-migration, sequential):** `BE-8 → BE-9 → BE-10`.
  - BE-8 `AddProvenanceTree`: `ContentSource`(+`ContentSourceType {Book,Image,Worksheet,VideoTranscript}`), `Chapter`, `ProvenanceMapping`. Enum cols `HasConversion<int>()`. `PedagogicalNodeId` + `GradeId` plain int (no FK/nav); `ChunkId`/`ChapterId`/`ContentSourceId` intra-curriculum FKs OK. Indexes per brief §BE-8. Reuse existing `ContentLanguage` enum.
  - BE-9 `AddCurriculumVersionLifecycle`: **ALTER TABLE only** — add `PublishedAt?`, `PublishedByUserId?`, `ArchivedAt?`, `Notes?`. Keep `SubjectId` canonical (Q-A). Preserve `Name`, `{Draft,Active,Archived}` enum, filtered-unique-Active index. Config comment per Q4 (separate from `learning.ContentVersions`).
  - BE-10 `AddKGSuggestionTable`: `KGSuggestion` + `KGSuggestionStatus {Pending,Approved,Rejected}` + local mirrored `RelationshipType` enum (Q-B). `SourceNodeId`/`TargetNodeId` plain int (no nav). `SourceCurriculumDocumentId` nullable plain int, no FK (Q-C). Indexes on `Status` and `(SourceNodeId,TargetNodeId,RelationshipType)`. Config comment: suggestions never auto-flow to `KnowledgeEdge`.

- **Batch 2 — Learning schema (db-migration, sequential; independent of Batch 1, may run in parallel as a second agent):** `BE-11 → BE-12 → BE-13`.
  - BE-11 + BE-12 (combined change) `AddSkillKeyToKnowledgeNode`: add `SkillKey varchar(200) NULL`; partial unique index `UX_KnowledgeNodes_SkillKey` with filter `"SkillKey" IS NOT NULL` (mirror the existing `UX_KnowledgeNodes_SkillId` filter syntax exactly).
