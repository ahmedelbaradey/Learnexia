### Batch 1 — PARALLEL — `backend-feature` agent (two threads)

These sub-batches are independent and touch disjoint files.

#### Batch 1a — BE-1 (records)

**Files (NEW):**

- `Learning.Domain/Services/AdaptivityDecision.cs` — record `(DifficultyLevel Difficulty, bool IsDefault, double Score)`.

Confirm `DifficultyLevel` enum is accessible (already exists on `QuizQuestion`); no new enum needed.

#### Batch 1b — BE-2 (options)

**Files (NEW):**
- `Learning.Application/Options/AdaptivityOptions.cs` — POCO bound from `Adaptivity:Engine` config section (mirror `StreakOptions` pattern): `WeightAccuracy=0.5`, `WeightTime=0.2`, `WeightHint=0.2`, `WeightRetry=0.1`, `HighBand=0.8`, `LowBand=0.5`, `ExpectedAttempts=2`.
- `appsettings.json` — add `Adaptivity:Engine` section with default values.

**Completion gate:** Build green (both threads).

### Batch 2 — SEQUENTIAL — `backend-feature` agent — BE-3

**Depends on:** Batch 1 (both threads) complete.

**Files (NEW):**
- `Learning.Domain/Services/AdaptivityEngine.cs` — pure static class: `DecideDifficulty(AdaptivitySignals signals, AdaptivityOptions options) → AdaptivityDecision`. Weighted-score band implementation. Cold-start path when `signals.IsDefault || totalAnswers == 0` → return `(Medium, IsDefault=true, Score=0)`. Time normalization: if `signals.AvgTimeSeconds <= 0`, set time component to 0 (degrade gracefully). P3-13 optional fatigue hook: no hard dependency; the engine is called with the signals it has; leave a nullable `FatigueSignalWeight` extension point in options (defaulted 0).
- `tests/Modules.Learning.UnitTests/AdaptivityEngineTests.cs` — 8+ cases: cold-start → Medium+IsDefault; high-accuracy/fast/no-hint → Hard; low-accuracy/slow/high-hint → Easy; monotonicity (increasing accuracy never lowers score); reproducibility (same inputs twice = same output); Medium band (mid-range score); time-normalization degradation (AvgTimeSeconds=0 → still returns valid result); per-weight variation.

**Completion gate:** Build green; all `AdaptivityEngineTests` pass; engine is a plain static class.

---

### Batch 3 — SEQUENTIAL — `backend-feature` agent — BE-4

**Depends on:** Batch 2 complete AND P3-09's `IMasteryService` is available.

**Files (NEW):**
- `Learning.Application/Services/IAdaptivityService.cs` — `Task<AdaptivityDecision> GetTargetDifficulty(int studentId, int? skillId, CancellationToken ct = default)`.
- `Learning.Application/Services/AdaptivityService.cs` — implementation: (a) if `skillId is null`, return `(Medium, IsDefault=true)`; (b) fetch signal aggregates by reusing `GetSkillStats`-style query from `ILearningRepository` (answer aggregates for `(studentId, skillId)`); (c) fetch `StudentSkillMastery` via `IMasteryService.GetMasteryForStudent`; (d) resolve `AdaptivityOptions` from `IOptions<AdaptivityOptions>`; (e) call `AdaptivityEngine.DecideDifficulty`; (f) return `AdaptivityDecision`.

**File (EDIT):** Learning module DI extension — register `IAdaptivityService` as scoped.

**Completion gate:** Build green; `IAdaptivityService` resolves from DI.

### Batch 5 — SEQUENTIAL — `api-tester` agent

**Depends on:** Batch 4 complete.

**File to create:** `backend/tests/Learnexia.IntegrationTests/P3_08_AdaptivityEngine_Tests.cs`

**Minimum 6 integration test cases:**

| # | Test | Assertion |
|---|---|---|
| 1 | New student (no history) → `GET /Adaptivity/Skill/{id}` → `Medium` + `isDefault=true` | Cold-start AC3 |
| 2 | Seeded high-performance history (≥80% accuracy, low hints, few retries) → `Hard` | AC1/AC3 direction |
| 3 | Seeded struggle history (<40% accuracy, high hints, many retries) → `Easy` | AC1/AC2 direction |
| 4 | Reproducibility: same seeded history called twice → identical `difficulty` + `score` | AC2 |
| 5 | Null `SkillId` (via a lesson with no skill) — call service directly or via a test endpoint → `Medium+isDefault` | AC3 null-skill handling |
| 6 | IDOR: Student B's difficulty not influenced by Student A's data | Student B gets correct decision based only on their own history |

If the inspection endpoint is not included, AC1-AC3 are fully covered by unit tests; api-tester validates AC4 indirectly via P3-11. Either outcome acceptable — document in the test file.

**Completion gate:** All cases pass; api-tester reports PASS.
