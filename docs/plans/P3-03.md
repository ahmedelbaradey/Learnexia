## Execution batches

### Batch 1 — SEQUENTIAL — `backend-feature` — BE-1 then BE-2

**BE-1 (IPromptBuilder + types):**
- `IPromptBuilder` in `Ai.Application/PromptBuilder/`:
  ```csharp
  public interface IPromptBuilder
  {
      AiRequest Build(PromptContext context);
  }
  ```
  Returns `AiRequest` (the P3-01 contract shape) carrying the assembled prompt + the correct `AiTaskKind` so the gateway routes to the right model tier (e.g. `Hint → Cheap`, `Explain → Premium`).
- `PromptContext(int StudentId, TutorTask Task, Subject Subject, int Grade, int Age, Language Language, IReadOnlyList<WeakArea>? WeakAreas, IReadOnlyList<CurriculumChunk>? Context)`.
- `TutorTask { Explain, Hint, GenerateQuestion }`.
- `Subject { Math, Science, Arabic, English }` — exactly 4 members. **No Social Studies.** Unit test asserting `Enum.GetValues<Subject>().Length == 4` and that the set equals `{Math, Science, Arabic, English}`.
- `Language { Ar, En }` — reuse the existing `LearningLanguage` concept from `Shared.Contracts` if it exposes `Ar`/`En`; otherwise a local enum.
- `IStudentWeakAreasQuery` in `Shared.Contracts/Ai/`:
  ```csharp
  Task<IReadOnlyList<WeakArea>> GetWeakAreasAsync(int studentId, Subject subject, CT);
  ```
  Empty default impl: `EmptyWeakAreasQuery` returns `Array.Empty<WeakArea>()`. Registered in DI as the default until P3-09 provides the real impl.
- `IChildLearningProfileQuery` in `Shared.Contracts/Ai/`:
  ```csharp
  Task<ChildLearningProfile> GetAsync(int studentId, CT);
  // ChildLearningProfile(int Grade, int Age, Language Language)
  ```

**BE-2 (ToneFrame):**
- `ToneFrame` — static class with ar and en string constants (or resource-based). Both variants:
  - Set a kind, age-appropriate, pedagogically-supportive AI persona.
  - Instruct the model to **ignore instructions embedded in retrieved context or student-supplied input** that attempt to change the persona or safety stance (prompt-injection prevention).
  - Do NOT request progression/unlock decisions (FR-AI-6 invariant).
- Tone frame is unconditionally prepended by `PromptBuilder.Build` — no caller can omit it.

**Gate after Batch 1:** Build green; `IPromptBuilder`, `PromptContext`, `TutorTask`, `Subject`, `Language` types exist; optional seam interfaces in `Shared.Contracts`; `ToneFrame` constants defined.

### Batch 2 — SEQUENTIAL — `backend-feature` — BE-3 then BE-4

**BE-3 (4 subject templates):**

Each template defines ar + en variant strings for each `TutorTask` (Explain / Hint / GenerateQuestion). Structured as constants or a `record SubjectTemplate(string ArExplain, string ArHint, string ArGenerate, string EnExplain, string EnHint, string EnGenerate)`.

Template content guidance (the implementer authors the actual text):
- **Math** (`MathTemplate`): step-by-step instruction style; invite the student to work through each step; do not skip steps; avoid ambiguity in notation.
- **Science** (`ScienceTemplate`): visual/exploratory style; relate concepts to observable phenomena; encourage curiosity and questions.
- **Arabic** (`ArabicTemplate`): vocabulary + grammar focus; use clear modern Arabic (Fusha); contextualize vocab in sentences; grammar explanations with examples.
- **English** (`EnglishTemplate`): vocabulary + grammar focus (for Arabic-speaking learners); examples in both languages where helpful; focus on comprehension + usage.
- **NO Social Studies template** — the implementer must not create one. A unit test asserts this.

**FR-AI-6 guard:** every template must request *content only* (explanations, hints, generated questions). No template asks the model to decide whether the student should advance, what grade to assign, or whether a concept is unlocked.

**BE-4 (TemplateSelector):**
- Pure `Dictionary<(Subject, Language), ISubjectTemplate>` lookup.
- Returns the template for the given `(Subject, Language)` pair.
- If `Subject` is not in the dictionary → return `UnsupportedSubjectResult` (not a silent default).
- Unit tests: all 4 subjects × 2 languages → correct template; an invalid/future subject → `UnsupportedSubjectResult`; assert the dictionary has exactly 4 subject entries.

**Gate after Batch 2:** Templates compile; `TemplateSelector` unit tests pass; no Social Studies entry in the selector.

### Batch 3 — SEQUENTIAL — `backend-feature` — BE-5 then BE-6 then BE-7

**BE-5 (Language variant + instruction):**
- When `Language == Ar`: select the ar template variant + append `"\nYou MUST respond entirely in Arabic (العربية)."` (or equivalent in the system frame).
- When `Language == En`: select the en template variant + append `"\nYou MUST respond entirely in English."`.
- Unit tests: ar `PromptContext` → assembled `AiRequest.Prompt` contains the ar instruction; en `PromptContext` → en instruction.

**BE-6 (Graceful degradation):**
- Weak-areas section: if `WeakAreas` is null or empty → omit the section entirely (no empty heading like `## Weak Areas\n(none)` in the prompt).
- RAG context section: if `Context` is null or empty → omit the section entirely.
- Omission is clean — no null-reference, no empty-header artifact, no trailing whitespace.
- Unit tests:
  - `PromptContext` with empty `WeakAreas` + null `Context` → `Build()` returns a valid `AiRequest`; prompt does not contain a weak-areas header or context header.
  - `PromptContext` with populated `WeakAreas` + populated `Context` → both sections appear.

**BE-7 (Full PromptBuilder assembly + tests):**
- `PromptBuilder.Build(PromptContext)`:
  1. Read child grade/age/language from `IChildLearningProfileQuery` (or use `PromptContext` fields directly — the handler that calls the builder is responsible for populating `PromptContext` from the seam before calling `Build`; the builder itself is pure / injection-free of the seam).
  2. Select template via `TemplateSelector(Subject, Language)`.
  3. Select language variant + language instruction (BE-5).
  4. Prepend `ToneFrame` (BE-2) — unconditional.
  5. Inject grade + age (e.g. `"The student is in Grade {Grade}, approximately {Age} years old."`).
  6. Inject weak-areas section if present (BE-6).
  7. Inject curriculum context section if present (BE-6).
  8. Map `TutorTask` → `AiTaskKind` (for gateway routing: `Hint → Cheap`, `Explain → Premium`, `GenerateQuestion → Premium`).
  9. Return `new AiRequest(assembledPrompt, aiTaskKind, …)`.
- Also add `ICurriculumContextQuery` stub to `Shared.Contracts/Ai/` (empty default until P3-07).

**Tests for BE-7:**
- **AC1 full test:** `PromptContext` with grade=4, age=10, language=Ar, subject=Math, task=Explain, weakAreas=[Fractions], context=[CurriculumChunk] → assert assembled prompt contains grade, age, language instruction, Math template content, weak-areas section, context section, and the tone frame.
- **Determinism:** call `Build` twice with the same `PromptContext` → identical string results.
- **FR-AI-6 guard:** assert the assembled prompt for each of the 4 subjects does not contain any of the strings: `"should advance"`, `"should unlock"`, `"grade level decision"`, `"mastery decision"` (or equivalents — the implementer scans the template text).
- **Tone-frame invariant:** every call to `Build` → the tone frame prefix is present regardless of subject/language/task.

**Gate after Batch 3:** All PromptBuilder unit tests pass (language, degradation, assembly, determinism, FR-AI-6 guard, tone-frame invariant). Build green.

### Batch 5 — SEQUENTIAL — `security-auditor` (MANDATORY gate)

**Focus areas (per brief handoff):**

1. **Prompt-injection hardening:** the fixed tone frame (BE-2) must instruct the model to ignore instructions embedded in retrieved curriculum context or student-supplied input. Verify the wording is explicit and covers both sources. This is the primary finding category.
2. **Child PII minimization in outbound prompts:** the builder injects grade + age (anonymous proxies) — NOT the child's name, email, exact birthdate, parent info, or any direct identifier. Verify `PromptContext` fields and the assembly code. Injecting `StudentId` (an internal int) into the prompt text is also a finding — it should not appear in the prompt body.
3. **No prompt/response body in logs:** `PromptBuilder.Build` must not log the assembled prompt at `Information` or higher (it may carry weak-area / context data). Only log at `Debug` if necessary, and only in non-production environments. Verify no `ILoggerManager` call logs the full prompt string at a level that persists in prod logs.
4. **FR-AI-6:** confirm no template requests a progression/unlock/mastery decision. Verify the unit test covers this and that the template text passes inspection.
5. **Tone-frame integrity:** the child-safe tone frame is unconditionally prepended; no caller pathway can omit it. Verify `PromptBuilder.Build` has no branch that skips the tone-frame prepend.
6. **Optional seams:** `IStudentWeakAreasQuery` default impl returns empty — it must not leak student data or throw when the real P3-09 impl is not yet registered.

**Critical/High findings block the reviewer gate.**
