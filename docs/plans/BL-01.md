## Lead decisions baked in (Q1–Q7 — resolved, not open)

| Q | Decision |
|---|---|
| Q1 — Storage | NEW dedicated `"curriculum"` MinIO bucket, **auto-created/ensured at app bootstrap**. Do NOT reuse `avatars`. (Note: there is NO existing bucket-ensure routine in the repo — `avatars` is assumed pre-provisioned — so backend-feature builds the ensure-bucket bootstrap from scratch, hooked into the same Host startup path that runs module `InitializeAsync`.) |
| Q2 — KGSuggestion FK | Do NOT wire `KGSuggestion.SourceCurriculumDocumentId → CurriculumDocument` FK in BL-01. Leave nullable plain int. Deferred to BL-03. |
| Q3 — Max file size | **100 MB** cap; STREAM to storage (do not buffer in memory); raise the multipart/request-size limit ONLY on the upload route, not globally. |
| Q4 — PipelineJob.Id | `int` identity (module consistency), not bigserial. |
| Q5 — Status/JobType storage | `PipelineJob.Status` + `JobType` persisted as **strings** (cross-process contract with Python poller), NOT int enums. `DocumentStatus` stays an **int-mapped enum** (`HasConversion<int>()`) — it is the .NET-internal doc lifecycle, never read by Python. |
| Q6 — Auth | Admin-only via the existing `[Authorize(Policy = AuthorizationPolicies.AdminOnly)]` (requires roles `Admin`/`SuperAdmin`, from `Identity.Domain/Constants/Roles.cs`). Mirror the P7 admin-controller pattern (policy, not bare `Roles=`). |
| Q7 — Atomicity | BE-5: write `CurriculumDocument` row AND enqueue the `PipelineJobs` (`JobType='parse'`, `Status='Pending'`) row inside an explicit `BeginTransactionAsync` so a job-insert failure rolls back the document. No Unit of Work (CLAUDE.md rule 3). |

Both append after `20260623011907_AddKGSuggestionTable`. Both mutate `CurriculumDbContextModelSnapshot.cs` → single-threaded db-migration pass.

### Batch 3 — api-tester (after Batch 2) ∥ Batch 4 — security-auditor (after Batch 2)
These two run **in parallel** — both read the Batch-2 code, neither edits feature code.

- **Batch 3 — `api-tester`** (REQUIRED, HTTP endpoints): extend `backend/tests/Curriculum.IntegrationTests/` (WebApplicationFactory + Testcontainers PostgreSQL; mock/stub `IStorageService` since the suite has no storage harness yet). Cases: admin upload valid PDF/DOCX/JPEG/PNG → 201 + doc `Received` + exactly one `PipelineJobs` `parse`/`Pending` row; wrong magic bytes / spoofed content-type → 422; over 100 MB cap → 422; non-admin (Student/Parent) → 403; anonymous → 401; list filters by status/grade/subject + pagination; detail 404 unknown id; `BaseResponse`/`Successed` envelope shape.

- **Batch 4 — `security-auditor`** (REQUIRED, file upload + admin authz): magic-byte validation present and ordered BEFORE storage; DOCX-as-generic-zip residual risk; server-side size enforcement (not just declared `Content-Length`); GUID object key with detected content-type, original filename never used as key (path-traversal/sniffing); `AdminOnly` enforced on every endpoint, no IDOR on list/detail; object key not leaked to non-admins (prefer presigned over bare key); `PayloadJson` carries only `object_key` + `content_type` (no secrets / unsanitized client input the Python worker would trust). Critical/High findings BLOCK R2.
