### Batch 5 — PARALLEL — `api-tester` + `security-auditor` agents

**Agent:** `api-tester` (validates HTTP endpoints against a running API) + `security-auditor` (file upload + admin authz surface)
**Mode:** Parallel (independent scopes)
**Depends on:** Batch 4 complete.

**`api-tester` validations:**
1. Admin uploads a valid PDF → HTTP 200, `Status = Received`, object key stored in DB (not a URL), `CurriculumDocumentUploaded` event fired.
2. Oversized file (> configured max) → 422 envelope, not 500.
3. Wrong MIME type → 422.
4. Valid extension but bad magic bytes (e.g. `.pdf` extension, actual ZIP content) → 422.
5. Non-admin token → 403; no token → 401.
6. `GET /api/curriculum/documents` (admin) → paged list with correct `Status` field; `GET /{id}` → detail.
7. Response envelope key is `Successed` (capital S — CONVENTIONS §5).

**`security-auditor` checklist (REQUIRED — file upload + admin authz):**
- Magic-byte validation enforced (not just MIME/extension check).
- Size cap enforced and config-driven.
- `[Authorize(Roles="Admin")]` on all upload and management endpoints.
- GUID object keys (no user-controlled filename in the storage path — no path traversal).
- Uploaded files not served inline without content-type pinning.
- `IStorageService` bucket is not publicly accessible.
- `CurriculumDocumentUploaded` event does not carry file content — only the object key (no data leak in the event bus).

Critical/High security findings block the gate.

### Batch 6 — SEQUENTIAL — `reviewer` gate, then `committer`

**Agent:** `reviewer`
**Depends on:** Batch 5 (api-tester PASS + security-auditor PASS).

Reviewer checklist:
1. All ACs from brief: upload + metadata (AC-1); type/size/magic-byte validation → 422 (AC-2); admin-only (AC-3); durable storage + object key (AC-4); `Received` status + BL-02 trigger (AC-5); status visible (AC-6).
2. CONVENTIONS.md: `BaseResponse<T>` via `BaseResponseHandler`; `Successed`; `ILoggerManager`; module isolation; `NewResult(...)` in controller; no cross-module FK.
3. Mirror `UploadAvatarCommandHandler` pattern exactly (validation order, `ServerError<T>` on exception, store key not URL).
4. `CurriculumDocumentUploaded` is in `Shared.Contracts` (not in the module's own contracts — cross-module event).
5. No `ILogger<T>` (use `ILoggerManager`).
6. No design pattern introduced without prior approval.
7. `docs/dev/HANDOFF.md` updated: new endpoints, event contract, FE deferral status.

If reviewer PASSES:
