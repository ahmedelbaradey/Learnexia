### Batch 1 — backend-feature (sequential, single agent)

Agent: `backend-feature`

Tasks (in order, no splits between them — same agent owns the whole batch to avoid mid-file handoffs):

1. **P1-02-BE-1a** — `AuthenticationIdentityService.GetJwtToken`: call `GenerateRefreshToken()` (existing private static helper), build a `UserRefreshToken` object (fields: `UserId`, `Token` = current access token string, `RefreshToken` = generated token, `JwtId` = jti claim, `AddedTime` = now, `ExpiryDate` = now + `_jwtSettings.RefreshTokenExpireDate` days, `IsUsed = false`, `IsRevoked = false`), serialize to JSON, call `_distributedCache.SetStringAsync("userrefreshtoken-{userId}", json, options)` with `AbsoluteExpiration = ExpiryDate`, and return the token on `JwtAuthResponse.refreshToken.TokenString`.

2. **P1-02-BE-1b** — `RegisterParentCommandHandler`: after `GetJwtToken(user)` is called, the returned `accessToken` will already carry `.refreshToken` once BE-1a is done. No handler logic change needed unless the handler strips or ignores `.refreshToken` — verify and preserve it. Note: both handlers call `GetJwtToken` so the fix in BE-1a covers both.

3. **P1-02-BE-1c** — `AuthenticationIdentityService.ValidateDetails`: after `GetById(userId)` succeeds (non-null), add: (a) compare `refreshTken` parameter against `userRefreshtoken.RefreshToken` — if mismatch, return `("RefreshTokenNotFound", null)`; (b) check `userRefreshtoken.ExpiryDate < DateTime.UtcNow` — if true, return `("RefreshTokenIsExpired", null)`. This fills in the two sentinel paths the handler already switches on but the service never reached.

4. **P1-02-BE-1d** — `AuthenticationIdentityService.GetRefreshToken`: on successful rotation, generate a new refresh token string, overwrite `userrefreshtoken-{userId}` in Redis with a fresh `UserRefreshToken` (new token string, same user, new `ExpiryDate = now + RefreshTokenExpireDate days`), set the new `refreshToken.TokenString` on the returned `JwtAuthResponse`. The old cache entry is fully replaced (Redis `SetStringAsync` overwrites), so the old string is immediately invalid.

5. **P1-02-BE-3** — `RefreshTokenCommandHandler`: change the switch branches for `RefreshTokenNotFound`, `RefreshTokenIsExpired`, and `AlgorithmIsWrong` to call `Unauthorized<JwtAuthResponse>("...")` (HTTP 401). Keep `TokenIsRunning` as `BadRequest<JwtAuthResponse>` (access token unexpired = caller logic error, not auth failure). Confirm `BaseResponseHandler.Unauthorized<T>()` is the correct method name (verified in `Shared.Kernel.Responses.BaseResponseHandler`).

6. **P1-02-BE-2** — `SignOutCommandHandler.GetCurrentSessionId()`: change to read the `"SessionId"` claim (the GUID that `SessionManagementService.CreateSessionAsync` stored as the key) instead of `JwtRegisteredClaimNames.Jti`. The storage key is `session:{sessionId}` where `sessionId` = the value of the `"SessionId"` claim. Additionally, after `TerminateSessionAsync` (or regardless of its result), call `_distributedCache.RemoveAsync("userrefreshtoken-{userId}")` to delete the refresh-token cache entry directly. This guarantees AC-3 (refresh token cannot be exchanged post-sign-out) even if the session lookup fails.

7. **P1-02-BE-6** — Verify and enforce TTL: confirm `DistributedCacheEntryOptions.AbsoluteExpiration` uses `DateTime.UtcNow.AddDays(_jwtSettings.RefreshTokenExpireDate)` when writing `userrefreshtoken-{userId}`. Confirm `AccessTokenExpireMinutes = 30` is consumed in `GenerateJwtToken`. Add a note in code about the `UserRefreshToken` EF table being cleanup debt.

### Batch 3 — security-auditor (after Batch 2)

Agent: `security-auditor`

Task: **P1-02-SA** — light targeted pass, not a full audit.

Scope:
- Refresh-token entropy: confirm `GenerateRefreshToken()` uses `RandomNumberGenerator` (32 bytes → base64) — sufficient entropy, no bias.
- Rotation completeness: confirm the old `userrefreshtoken-{userId}` Redis entry is fully overwritten before the new token string is returned. A replay of the old string will fail AC-5 match check.
- Replay attack: confirm that after one successful refresh, calling `/Refresh-Token` again with the first-issued refresh token (not the rotated one) returns 401 (because the stored entry has been replaced).
- Sign-out revocation: confirm `RemoveAsync("userrefreshtoken-{userId}")` is reached regardless of session-termination outcome. A failed session lookup must not prevent refresh-token deletion.
- Session fixation: confirm that the `SessionId` claim used by sign-out lookup is the same GUID that `SessionManagementService.CreateSessionAsync` stored under `session:{sessionId}`. A mismatch would mean sign-out silently does nothing to the session record.
- 401 vs 500 leakage: confirm none of the auth-failure branches return `ServerError` (HTTP 500) which would expose internal state.
- Residual risk (document, do not block): live access tokens (≤30-min window) remain valid after sign-out — the JTI denylist middleware is deferred per Lead Decision 5. Document this in the audit finding as accepted residual risk.

**Blocking threshold:** Critical or High findings block the reviewer gate. Informational/Low findings are documented and handed to the reviewer as context.

### Overall story DoD (tied to acceptance criteria)

- **AC-1:** `/Refresh-Token` with a valid unexpired refresh token → 200, new non-empty access token with ~30-min lifetime.
- **AC-2:** Sign-in and registration responses include a non-empty `refreshToken.tokenString`.
- **AC-3:** After `/Sign-Out`, the same refresh token exchanged at `/Refresh-Token` → 401.
- **AC-4:** Expired or revoked refresh token → HTTP 401, `Successed=false`. Not 500.
- **AC-5:** A tampered or mismatched refresh token string → 401 (stored value check enforced).
- **AC-6:** Access token: 30-min lifetime. Refresh token: 7-day lifetime, expiry enforced in Redis TTL and stored `ExpiryDate`.
- **AC-7:** Missing `accessToken` or `refreshToken` in request → 422 with `Errors[]` (existing `RefreshTokenValidatior` fires via `ValidationBehavior`).
- **AC-8:** Refresh token is cryptographically high-entropy (32-byte CSPRNG) and rotated on each use.
