## Lead Decisions Applied

1. **New `GET /api/Users/Me`** endpoint — `[Authorize]`, self-scoped via `ICurrentUserService`, returns `{ id, roles[], fullName, preferredLanguage, isFirstLogin, hasChildren }`. No migration. Placed in `AuthenticationController` (already authenticated-only methods exist there) or a new thin `UsersController`. Neither AdminOnly nor Parent-gated — any authenticated caller.
2. **`packages/api-client` type regeneration** — after the `Me` endpoint is running locally, execute `pnpm --filter @learnexia/api-client refresh:swagger` (hits `https://localhost:7080/swagger/v2/swagger.json`, self-signed cert accepted via `-k`), then `pnpm --filter @learnexia/api-client gen:api`. This regenerates `packages/api-client/src/generated/api-types.ts` to include `Register-Parent`, `Add-Child`, `Link-Child`, `My-Children`, and `Me`.
3. **Consolidated scope** — P1-01/02/03/04-FE are folded into this single plan. Each screen built exactly once. `apps/student-app` is a bare stub (only `package.json`); the Expo shell is built here.
4. **Designer stage required** — Design Spec at `design-system/ui_kits/student-app/P1-09.md` before frontend batch.
5. **No db-migration** — reads existing Identity schema only.

### BATCH 0 — Parallel kickoff (no prerequisites)

**Batch 0A — backend-feature (sequential: feature → tester → auditor)**

Agent: `backend-feature`
Tasks: `P1-09-BE-Me`

Deliverable: `GET /api/Users/Me` in Identity module.

Implementation notes for the agent:
- Add a `GetMeQuery : IQuery<BaseResponse<MeResponse>>` in `Features/Authentications/Queries/GetMe/`.
- `MeResponse` DTO: `{ int Id, IList<string> Roles, string? FullName, string? PreferredLanguage, bool IsFirstLogin, bool HasChildren }`.
- `GetMeQueryHandler` injects `ICurrentUserService` and `UserManager<ApplicationUser>` (already wired in Identity infrastructure). Read `currentUser.Roles` from `ICurrentUserService.Roles`. Read `FullName`/`PreferredLanguage` from `UserManager.FindByIdAsync(ICurrentUserService.UserId)` (or the user entity directly). `HasChildren` = query the `ParentStudent` table count via the existing `ILinkParentStudentService` or a direct repository call — scoped to the calling parent's userId.
- Controller action: add to `AuthenticationController` (or a new `UsersController` at route `api/Users`) — `[Authorize]` only, NOT `[Authorize(Roles="...")]`, so children and parents can both call it. Route: `GET /api/Users/Me` (or `GET /api/Users/Authentication/Me` if placed in AuthenticationController for route consistency).
- Return `Success(meResponse)` on the happy path. If `UserId` resolves to null → `Unauthorized<MeResponse>()`.
- No migration; no new entity; no UoW change (pure reads).
- Follow `IQuery<>` / `IQueryHandler<,>` / `BaseResponseHandler` conventions. Do NOT run `ValidationBehavior` (queries are not auto-validated).

Followed by (sequential, same sub-batch):

Agent: `api-tester` — verify `GET /api/Users/Me` at runtime:
- Authenticated parent: returns 200 with `roles=["parent"]`, correct fullName, correct language, `hasChildren` true/false depending on state.
- Authenticated child/student: returns 200 with `roles=["student"]`, correct language.
- Unauthenticated: returns 401.
- IDOR check: cannot pass a different userId in query — endpoint reads ONLY from the JWT; there is no id parameter.
- Confirm `FullName` is NOT null when registered with a name; `PreferredLanguage` is correct string (e.g. `"ar"` or `"en"`).

Agent: `security-auditor` — security review of `Me` endpoint (runs after api-tester):
- Confirm no id parameter on the endpoint (no IDOR surface).
- Confirm `[Authorize]` is present (401 for unauthenticated).
- Confirm roles come from `ICurrentUserService.Roles` (JWT claims), not from a user-supplied parameter.
- Confirm `HasChildren` query is scoped to the JWT user's id — cannot enumerate other parents' children counts.
- Confirm no sensitive fields exposed (password hashes, raw tokens, internal audit fields).
- Review `PreferredLanguage` value — confirm it cannot be used to inject content or cause unexpected locale behavior on the client.
- Critical or High findings block Batch 0A completion.

Then: `reviewer` gates Batch 0A (backend Me slice).
