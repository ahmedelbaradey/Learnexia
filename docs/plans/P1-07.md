## Execution Batches

### Batch 1 — Backend Feature (single agent, sequential within)

**Agent:** `backend-feature`
**Mode:** Sequential within a single agent thread (shared-file constraint — `Program.cs`, `Learnexia.Host.csproj`, `Directory.Packages.props`, `docker/docker-compose.yaml`, `docker/Dockerfile` must not be written by concurrent agents)

**Tasks (in this order within the batch):**

1. **BE-1 — Infra files first** (Dockerfile + compose): no Host code edits, so safe to do first; establishes the compose shape BE-4 depends on.
   - Rewrite `docker/Dockerfile`: multi-stage (.NET 10 SDK build → ASP.NET 10 runtime final); build context is repo root (`../` from compose perspective, or compose context set to `../`); COPY `backend/Directory.Packages.props`, `backend/Directory.Build.props`; restore + publish via `backend/Learnexia.Modular.sln`; entrypoint `dotnet Learnexia.Host.dll`.
   - Update `docker/docker-compose.yaml`: rename `jadwa-api` service → `learnexia-api`; rename container → `learnexia-api`; fix `build: context: ../` and `dockerfile: docker/Dockerfile`; retain `depends_on: postgres (healthy) + redis (started)`; add compose-level healthcheck `GET http://localhost:8080/health`; rename network `jadwa-network` → `learnexia-network` (update all service `networks:` entries and the top-level `networks:` definition); add AI-Gateway placeholder service (use `busybox` or `alpine` with a `sleep infinity` entrypoint, clearly commented as Phase 3 stub, exposed on port 8090); add web frontend service entry — commented out block, clearly labelled "uncomment in P1-09 when FE Dockerfile lands".
   - Do NOT duplicate Postgres, Redis, or MinIO service definitions — they are already in the compose file.

2. **BE-2 — Health checks** (Host code, after compose is settled):
   - Add `AspNetCore.HealthChecks.NpgSql` and `AspNetCore.HealthChecks.Redis` to `backend/Directory.Packages.props` (new `PackageVersion` entries) and `Learnexia.Host.csproj` (new `PackageReference` entries, no version attr per central versioning).
   - In `Program.cs` (builder section): `builder.Services.AddHealthChecks()` with `.AddNpgSql(connectionString, name: "database")` where `connectionString = builder.Configuration.GetConnectionString("Default")`; and conditionally `.AddRedis(redisConnectionString, name: "redis", failureStatus: HealthStatus.Degraded)` only when `redisConnectionString` is non-empty.
   - In `Program.cs` (app section, BEFORE `app.UseIpRateLimiting()` and before `app.UseAuthentication()`): `app.MapHealthChecks("/health/live", new HealthCheckOptions { Predicate = _ => false })` (liveness — no deps) and `app.MapHealthChecks("/health", new HealthCheckOptions { ... })` (readiness — all checks). Both must be `AllowAnonymous` — use `RequireAuthorization` with an empty policy or ensure they are mapped with `.AllowAnonymous()`.
   - Exclude `/health` and `/health/live` from IP rate limiting: add the probe paths to the rate-limit whitelist in the configuration (the `IpRateLimiting:GeneralRules` exclusion or `EndpointWhitelist`).
   - Add a note in `appsettings.json` for a `HealthChecks` section if any options (timeouts) are configurable — optional but tidy.

3. **BE-5 — Hangfire** (Host code, same pass as BE-2 since files already open):
   - Add to `Directory.Packages.props`: `Hangfire.Core`, `Hangfire.AspNetCore`, `Hangfire.PostgreSql` with stable latest versions (e.g. Hangfire 1.8.x / Hangfire.PostgreSql 1.20.x — agent must verify latest stable at implementation time).
   - Add the three `PackageReference` entries to `Learnexia.Host.csproj`.
   - In `Program.cs` (builder section): `builder.Services.AddHangfire(config => config.UsePostgreSqlStorage(o => o.UseNpgsqlConnection(builder.Configuration.GetConnectionString("Default"))).SetDataCompatibilityLevel(CompatibilityLevel.Version_180).UseSimpleAssemblyNameTypeSerializer().UseRecommendedSerializerSettings())`. Register Hangfire server: `builder.Services.AddHangfireServer()`.
   - In `Program.cs` (app section, after auth middleware is configured): map Hangfire dashboard — `if (app.Environment.IsDevelopment()) { app.UseHangfireDashboard("/hangfire"); }` — dashboard is inaccessible outside Development; in staging/production the path returns a 404 (the middleware simply is not registered).
   - Add a comment block above the Hangfire registration explaining it is the host for Phase 4 (streaks/leagues) and Phase 5 (report) jobs; no jobs implemented here.

4. **BE-4 — Staging deploy artifacts** (infra files, after compose is finalised in BE-1):
   - Create `docker/docker-compose.staging.yml` as a compose override: sets env vars via environment variable references (`${POSTGRES_PASSWORD}`, `${JWT_SECRET}`, `${MINIO_SECRET}`, `${REDIS_URL}`) — no hardcoded credentials; references the same service names established in BE-1.
   - Create `.github/workflows/deploy-staging.yml` (separate from CI): a manually triggered (`workflow_dispatch`) or tag-triggered job that: (a) builds and pushes the Docker image to a container registry using `${{ secrets.REGISTRY_URL }}` / `${{ secrets.REGISTRY_USER }}` / `${{ secrets.REGISTRY_PASSWORD }}`; (b) has a placeholder deploy step clearly commented with "TODO: replace with Azure/Railway/Render deploy action once provider is confirmed".
   - Add a `docs/deploy/staging-decision.md` documenting the open deploy-provider decision, the required secrets list, and what to fill in once the provider is chosen.

5. **BE-3 — CI workflow** (new file, no shared-file race, but done within same agent batch to avoid context switching):
   - Create `.github/workflows/ci.yml`.
   - Trigger: `on: push` (all branches) + `on: pull_request`.
   - `jobs.build-and-test` on `ubuntu-latest`.
   - Steps:
     1. `actions/checkout@v4`
     2. `actions/setup-dotnet@v4` with `dotnet-version: '10.x'`
     3. `dotnet restore backend/Learnexia.Modular.sln`
     4. `dotnet build backend/Learnexia.Modular.sln --no-restore -c Release`
     5. `dotnet test backend/Learnexia.Modular.sln --no-build -c Release --logger trx` (includes all test projects: unit tests + `Learnexia.IntegrationTests` which spins up Postgres via Testcontainers.PostgreSql — Docker daemon is available on `ubuntu-latest`)
     6. `actions/upload-artifact@v4` to upload `.trx` test results for inspection.
   - Optional (recommended): add a `docker-build` job that runs `docker build -f docker/Dockerfile .` from repo root (validates the rewritten Dockerfile); can run in parallel with `build-and-test`.
   - Test failure exits with non-zero → job fails (default `dotnet test` behavior).
