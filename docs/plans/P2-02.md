## No migration needed — confirmation

The P2-01 migration already created `learning.Grades`, `learning.Subjects`, `learning.Units`, `learning.Lessons`, `learning.Concepts`, and `learning.Skills`. P2-10 seeded the four MVP subjects across all grades. These are **read-only queries over the existing schema**. No new tables, columns, or indexes are required by P2-02.

**Schema gap to note (not a blocker for this story):** `Concept` and `Skill` entities do **not** have a `SequenceOrder` column in the current schema (confirmed against the EF model snapshot and entity files). The plan spec calling for ordering by `Concept.SequenceOrder` / `Skill.SequenceOrder` cannot be satisfied. The backend-feature agent must **order by `Concept.Id` ascending then `Skill.Id` ascending** as a stable surrogate until a dedicated `SequenceOrder` column lands (deferred to P2-11 or a standalone index story). This is a known, scoped limitation — do not block the story on it.

### Batch 1 — implementation spec (self-contained for the backend-feature agent)

#### Pattern to mirror

Every handler:
- Inherits `BaseResponseHandler` and implements `IQueryHandler<TQuery, BaseResponse<T>>`
- Injects `ILearningServiceManager _service`, `IMapper _mapper`, `ILoggerManager _logger`
- Wraps body in `try/catch`; on exception: `_logger.LogError(ex, "Error: in <QueryName>"); return ServerError<T>(ex.Message);`
- Uses `_service.GradeService.GetAllByConditionAsync(g => g.Number == request.Grade, false)` to resolve the grade (returns `IQueryable<Grade>`); call `.FirstOrDefaultAsync()` to get the `Grade?` entity. If null → `return NotFound<T>("Grade not found");`
- Uses `_service.SubjectService.GetAllByConditionAsync(...)` and other service queryables (returns `IQueryable<TEntity>`)
- Queries are NOT validated by `ValidationBehavior` — guard inputs in-handler (e.g. `if (request.Grade < 1 || request.Grade > 6)`)
- Empty list → `return EmptyCollection(new List<T>())` — never 404 for missing content, only for missing resources (subject id / grade number)

**Important — `LearningRepository.GetByCondition<T>` vs `GetAll<T>`:** The service manager exposes `IQueryable<T>` via `GetAllByConditionAsync(expression, trackChanges)` and `GetAllAsync(trackChanges)`. For navigation-property eager loading (Include), bypass the service and query the `LearningDbContext` directly — but `LearningDbContext` is NOT currently injected into handlers. **Preferred approach:** inject `ILearningRepository` directly alongside `ILearningServiceManager`, or inject `LearningDbContext` as a secondary dependency. Mirror how `AttemptService` receives `dbContext` in the service manager constructor. For P2-02, the handlers require EF `Include`/`ThenInclude` for nested loads — the cleanest fit is to inject `LearningDbContext` directly into the handlers (it is already registered Scoped in DI).

#### BE-1 — `GetSubjectsForGradeQuery`

**File locations:**
- Query: `backend/src/Modules/Learning/Learnexia.Modules.Learning.Application/Features/Subjects/Queries/GetSubjectsForGrade/GetSubjectsForGradeQuery.cs`
- Handler: same folder, `GetSubjectsForGradeQueryHandler.cs`

**Query record:**
```csharp
public record GetSubjectsForGradeQuery : IQuery<BaseResponse<List<StudentSubjectDto>>>
{
    public int Grade { get; init; }   // grade number 1–6 from ?grade= query param
}
```

**Handler logic:**
1. Guard: if `Grade < 1 || Grade > 6` → return `BadRequest<List<StudentSubjectDto>>("Grade must be between 1 and 6")`
2. Resolve grade entity: `var grade = await dbContext.Grades.AsNoTracking().FirstOrDefaultAsync(g => g.Number == request.Grade, cancellationToken)`; if null → `return NotFound<List<StudentSubjectDto>>("Grade not found")`
3. Query subjects: `var subjects = await dbContext.Subjects.AsNoTracking().Where(s => s.GradeId == grade.Id).OrderBy(s => s.Name).ToListAsync(cancellationToken)`
4. If empty → `return EmptyCollection(new List<StudentSubjectDto>())`
5. Map to DTOs manually (or via AutoMapper single-level `CreateMap<Subject, StudentSubjectDto>()`)
6. Return `Success(dtos)`

**Response shape — `StudentSubjectDto`:**
```csharp
public record StudentSubjectDto
{
    public int Id { get; init; }
    public string Name { get; init; } = null!;
    public int GradeNumber { get; init; }   // Grade.Number, not GradeId
}
```
Note: `LessonCount` was discussed but is omitted to keep the query simple (no subquery overhead). The FE subject-selection card only needs `Id`, `Name`, and `GradeNumber`. Add it only if the FE explicitly requires it.

**Controller action (add to `SubjectsController`):**
```csharp
[HttpGet("ForGrade")]
public async Task<IActionResult> GetForGrade([FromQuery] int grade)
    => NewResult(await Mediator.Send(new GetSubjectsForGradeQuery { Grade = grade }));
```
Route: `GET /api/learning/Subjects/ForGrade?grade=1`

Why `ForGrade` and not the root `GET /api/learning/Subjects?grade=`? The existing `[HttpGet]` on `SubjectsController` is taken by `GetById(int id)`. ASP.NET Core cannot disambiguate a bare `[HttpGet]` with a `?grade=` param from a bare `[HttpGet]` with an `?id=` int when both use `[FromQuery]`. Using a named sub-route `/ForGrade` avoids the conflict cleanly. The FE and api-tester must use `GET /api/learning/Subjects/ForGrade?grade={n}`.

#### BE-2 — `GetSubjectLessonsQuery`

**File locations:**

- Handler: same folder, `GetSubjectLessonsQueryHandler.cs`

**Query record:**
```csharp
public record GetSubjectLessonsQuery : IQuery<BaseResponse<List<UnitWithLessonsDto>>>
{
    public int SubjectId { get; init; }
}
```

**Handler logic:**
1. Check subject exists: `var subject = await dbContext.Subjects.AsNoTracking().FirstOrDefaultAsync(s => s.Id == request.SubjectId, cancellationToken)`; if null → `return NotFound<List<UnitWithLessonsDto>>("Subject not found")`
2. Load units with lessons: `var units = await dbContext.Units.AsNoTracking().Where(u => u.SubjectId == request.SubjectId).OrderBy(u => u.SequenceOrder).Include(u => u.Lessons).ToListAsync(cancellationToken)`
3. If no units → `return EmptyCollection(new List<UnitWithLessonsDto>())`
4. Project manually:
   ```csharp
   var dto = units.Select(u => new UnitWithLessonsDto
   {
       UnitId        = u.Id,
       Name          = u.Name,
       SequenceOrder = u.SequenceOrder,
       Lessons       = u.Lessons
                        .OrderBy(l => l.SequenceOrder)
                        .Select(l => new LessonInUnitDto
                        {
                            LessonId      = l.Id,
                            Name          = l.Name,
                            Difficulty    = l.Difficulty,
                            SequenceOrder = l.SequenceOrder,
                            IsLocked      = l.IsLocked,
                            SkillId       = l.SkillId
                        }).ToList()
   }).ToList();
   ```
5. Return `Success(dto)`

**Response shape:**
```csharp
public record UnitWithLessonsDto
{
    public int UnitId { get; init; }
    public string Name { get; init; } = null!;
    public int SequenceOrder { get; init; }

}

public record LessonInUnitDto
{
    public int LessonId { get; init; }
    public string Name { get; init; } = null!;
    public DifficultyLevel Difficulty { get; init; }
    public int SequenceOrder { get; init; }
    public bool IsLocked { get; init; }

}
```

#### BE-3 — `GetSubjectSkillTreeQuery` + `NodeState` enum

**File locations:**
- Enum: `backend/src/Modules/Learning/Learnexia.Modules.Learning.Domain/Enums/NodeState.cs`
- Query: `backend/src/Modules/Learning/Learnexia.Modules.Learning.Application/Features/Subjects/Queries/GetSubjectSkillTree/GetSubjectSkillTreeQuery.cs`

**`NodeState` enum (new file in Domain/Enums/):**
```csharp
namespace Learnexia.Modules.Learning.Domain.Enums;

/// <summary>
/// Skill-tree node state visible to the student.
/// P2-02: values are static placeholders derived from Lesson.IsLocked.
/// P2-03/P2-04 will replace the derivation with real per-student progress.
/// </summary>
public enum NodeState
{
    Locked    = 0,
    Available = 1,
    Completed = 2
}
```

**Query record:**
```csharp
public record GetSubjectSkillTreeQuery : IQuery<BaseResponse<List<ConceptNodeDto>>>
{
    public int SubjectId { get; init; }
}
```

**Handler logic:**
1. Check subject exists: `var subject = await dbContext.Subjects.AsNoTracking().FirstOrDefaultAsync(s => s.Id == request.SubjectId, cancellationToken)`; if null → `return NotFound<List<ConceptNodeDto>>("Subject not found")`
2. Load concepts with skills and their lessons:
   ```csharp
   var concepts = await dbContext.Concepts
       .AsNoTracking()
       .Where(c => c.SubjectId == request.SubjectId)
       .Include(c => c.Skills)
           .ThenInclude(sk => sk.Lessons)
       .OrderBy(c => c.Id)    // surrogate order — SequenceOrder column does not exist yet
       .ToListAsync(cancellationToken);
   ```
3. If no concepts → `return EmptyCollection(new List<ConceptNodeDto>())`
4. Derive `NodeState` per skill: if the skill has any linked lesson and all linked lessons have `IsLocked == true` → `NodeState.Locked`; otherwise → `NodeState.Available`. (This is the static placeholder; P2-03/P2-04 replaces this logic.)
5. Project:
   ```csharp
   var dto = concepts.Select(c => new ConceptNodeDto
   {
       ConceptId = c.Id,
       Name      = c.Name,
       Skills    = c.Skills
                    .OrderBy(sk => sk.Id)    // surrogate order — no SequenceOrder column
                    .Select(sk => new SkillNodeDto
                    {
                        SkillId               = sk.Id,
                        Name                  = sk.Name,
                        MasteryThreshold      = sk.MasteryThreshold,
                        EstimatedTimeMinutes  = sk.EstimatedTimeMinutes,
                        State                 = DeriveNodeState(sk),
                        LessonIds             = sk.Lessons.Select(l => l.Id).ToList()
                    }).ToList()
   }).ToList();
   ```
6. Return `Success(dto)`

Private helper:
```csharp
private static NodeState DeriveNodeState(Skill skill)
{
    if (!skill.Lessons.Any())
        return NodeState.Available;   // no lessons mapped → treat as accessible
    return skill.Lessons.All(l => l.IsLocked)
        ? NodeState.Locked
        : NodeState.Available;
}
```

**Response shape:**
```csharp
public record ConceptNodeDto
{
    public int ConceptId { get; init; }
    public string Name { get; init; } = null!;
    public List<SkillNodeDto> Skills { get; init; } = new();
}

public record SkillNodeDto
{
    public int SkillId { get; init; }
    public string Name { get; init; } = null!;
    public int MasteryThreshold { get; init; }
    public int EstimatedTimeMinutes { get; init; }
    public NodeState State { get; init; }
    public List<int> LessonIds { get; init; } = new();
}
```

#### `DbContext` injection pattern for handlers

The three new handlers need `LearningDbContext` for `Include`/`ThenInclude`. Inject it as a constructor parameter:

```csharp
public class GetSubjectsForGradeQueryHandler : BaseResponseHandler, IQueryHandler<...>
{
    private readonly ILoggerManager _logger;
    private readonly LearningDbContext _db;

    public GetSubjectsForGradeQueryHandler(LearningDbContext db, ILoggerManager logger)
    {
        _db = db;
        _logger = logger;
    }
    // ...
}
```

`LearningDbContext` is already registered as `AddDbContext<LearningDbContext>` (Scoped) in Learning's Infrastructure DI — no new registration needed. `ILearningServiceManager` and `IMapper` are not required by these handlers (all projections are manual LINQ); only inject what is used.
