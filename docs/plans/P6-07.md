# Execution Plan — P6-07 Access-token revocation (per-request SessionId validation)

> Brief: [../briefs/P6-07.md](../briefs/P6-07.md) · Story: [../../user-stories/Phase-6-Stabilization/P6-07-access-token-revocation.md](../../user-stories/Phase-6-Stabilization/P6-07-access-token-revocation.md) · Tasks: [../../tasks/Backend/Phase-6-Stabilization/P6-07-BE.md](../../tasks/Backend/Phase-6-Stabilization/P6-07-BE.md)
> Scope: **Identity + Host only.** No new module, no DB migration (sessions are Redis/`IDistributedCache`), no Unit of Work, no new NuGet. Branch: `feat/P6-07-access-token-revocation`.

## Locked decisions (lead, 2026-06-21) — resolving the brief's open questions
- **OQ-1 (store-outage / fail-mode):** **fail-closed in Production/Staging, fail-open-with-warning-log in Development/Testing.** Implement explicitly in `OnTokenValidated` using the existing `IsProtectedEnvironment(configuration)` pattern — do NOT rely on `GetSessionAsync`'s exception-swallow. On a store read error: protected env ⇒ `context.Fail`; dev/test ⇒ log warn + allow.
- **OQ-2 (read-only primitive):** use **`GetSessionAsync(sessionId)` + in-memory `IsActive && !IsExpired`** (zero writes). Per-request sliding-expiration refresh is intentionally dropped (AC5 forbids the hot-path write; session TTL 30m ≈ access-token 30m, so idle-timeout stays effectively aligned).
- **OQ-3 (stale swallow in the 3 issuance handlers):** **keep the `try/catch` but log loudly** (error, not silent) and replace the stale "middleware will create it" comment. Do NOT hard-fail sign-in on session-create failure in this story (revisit only if it bites).
- **OQ-4 (rollout):** **one-time logout-all on deploy is ACCEPTED.** Pre-launch; and stale GUID-A tokens *should* die — that's the fix working. Note it in HANDOFF.

## Batches (backend-feature, dependency-ordered)
- **Batch 1 — BE-1 (serialization point; must land first).** Fix the GUID-A/GUID-B mismatch: 3-arg `CreateSessionAsync(userId, jwtTokenId, sessionId)` keyed on the claim; thread `sessionInfo.SessionId` at all 3 issuance call sites (SignIn, RegisterParent, GoogleSignIn); add `TerminateAllUserSessionsAsync(userId, reason)` to `ISessionManagementService` + impl; log+decomment the stale swallow. **Gate:** a baseline-200 must hold on each of the 3 issuance paths.
- **Batch 2 — BE-2 + BE-3 (parallelizable; distinct files).**
  - BE-2: `OnTokenValidated` in `DependencyInjection.cs` `AddJwtBearer` — read `"SessionId"` claim, resolve scoped `ISessionManagementService` from `context.HttpContext.RequestServices`, read-only validity check, `context.Fail` on absent/terminated/expired, fail-mode per OQ-1. (BE-4 folds in here.)
  - BE-3: `ResetPasswordCommandHandler` → terminate-all via the new helper; optionally DRY Suspend/Delete (already correct).
- **Batch 3 — gates (sequential):** api-tester (BE-5, 6 scenarios + baseline-per-path) → security-auditor (BE-6, mandatory, Critical/High block) → reviewer (7 ACs + CONVENTIONS) → committer (PR; HANDOFF update in same PR).
